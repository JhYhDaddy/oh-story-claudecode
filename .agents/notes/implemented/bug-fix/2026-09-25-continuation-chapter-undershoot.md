# Agent Note: 이어쓰기 장이 지속적으로 짧아지는 문제: 집필자에게 묶음별 분량 기준이 없음

Status: implemented
Date: 2026-09-25
Related: [v0.8 간소화](../../implemented/architecture/2026-09-24-v0-8-lean-writing-loop.md), 토론 #447, #361

## Problem

장편 이어쓰기의 첫 검사에서 대체로 글자 수 하한에 못 미쳐 작가가 매 장 “수락할지 다시 쓸지” 질문받는다. 반면 새 책 제1장은 기준을 충족한다.

- 사용자: 토론 #447(ZCode, 새 책에서 “첫 장을 제외한 뒤의 장은 모두 완료되지 않음”), #361(장별 글자 수 차이가 크고 토큰이 낭비됨).
- 벤치마크(데모 책 mid-daily, 하루 3장, 2026-09-25):

  | 실행 | 최종 글자 수 중 앞 묶음 비중 | 사건 지점당 평균 글자 수 | 최종 / 목표 |
  |---|---|---|---|
  | Codex v0.8 첫 실행(c5) | 82% / 69% / 70% | 281–349 | 0.98–1.06 |
  | Codex v0.8 릴리스 후보 | 25% / 35% / 28% | 224–236 | 0.84–0.88 |
  | Claude Code v0.7.11 | 53% / 46% / 58% | 178–197 | 0.64–0.79 |
  | Claude Code v0.8 릴리스 후보 | 39% / 39%(첫 장은 checkpoint 미실행) | 140–210 | 0.58–0.88 |
  | Claude Code 새 책 제1장 | 64% | 308 | 1.03 |

원인은 두 층위지만 같은 빈틈이다.

1. **묶음 분할**: Codex 후보는 앞 묶음을 첫 두세 사건 지점만으로 너무 작게 나눴다. checkpoint가 계산한 남은 구간은 커졌지만 뒤 묶음을 자연스러운 밀도로 써서는 채울 수 없었다.
2. **밀도**: Claude 집필자는 지점당 약 180자를 쓴다. 사건 지점 10개로 2400자를 쓰려면 지점당 약 240자가 필요하다.

집필자에게 전달된 분량 정보는 장 전체 목표와 “장 전체 분량 척도로 사용, 밀도는 자율 배분, 지점별 할당량으로 나누지 않음, 자체 글자 수 측정 금지, 짧다고 재작성하지 않음, under 보충 금지”뿐이었다. 앞 묶음의 길이와 지점별 서술량은 모델의 감각에 맡겼다. “보충·재작성 금지”는 집필자가 “조금 짧아도 괜찮음”으로 읽었을 수도 있다.

제약(#370과 이전 #187): 장 전체를 쓴 뒤 반복 확장·압축하는 방식으로 돌아가면 안 된다. 지점별 할당량을 하한으로 주면 모든 지점을 최대한 채워 체계적으로 길어진다(데모 실측 +58%). 분량 부족을 자동으로 보충하지 않아 내용 부풀리기를 막는다.

## Decision

Claude Code의 집필자(`narrative-writer`)는 `model: opus`로 고정한다. 묶음 분할, checkpoint, 부족분 보충 금지, 초과 시 삭제 한 번의 마무리 규칙은 유지한다. OpenCode 배포 시 모델 등급 권고에서 집필자는 고급 등급으로 둔다. Codex·OpenCode 모델은 고정하지 않으며 Antigravity는 원래 둘 다 `pro`로 매핑하므로 영향이 없다.

집필자 수준 A/B(2026-09-25): v0.8.0 후보를 Claude Code에서 일일 집필한 프로젝트 상태를 바탕으로 제N장 이후 본문을 지운다. 당시 주 세션이 실제로 준 프롬프트로 제22–24장을 다시 쓴다. 실제 절차대로 앞 묶음 → `wordcount checkpoint` → 뒤 묶음 전달 순서로 실행하고 실험군마다 장별 1회 수행한다.

| 실험군 | 최종 / 목표(22·23·24장) | 평균 | 첫 검사 범위 내 | 장당 비용 |
|---|---|---|---|---|
| a0 현재(Sonnet) | 0.88 / 0.63 / 0.63 | 0.71 | 1/3 | $1.26 |
| a1 사건 지점 비율로 환산한 앞 묶음 범위 제공 | 0.73 / 0.65 / 0.86 | 0.74 | 1/3 | $1.60 |
| a2 지점별 평균 서술량 척도 제공 | 0.77 / 0.77 / 0.65 | 0.73 | 0/3 | $1.24 |
| a3 집필자 지침에서 “짧아도 재작성 금지 / under 보충 금지” 삭제 | 0.90 / 0.77 / 0.58 | 0.75 | 1/3 | $1.61 |
| a4 묶음마다 결정적 측정 1회, 하한 미만이면 보충 1회 | 0.82 / 0.77 / 0.86 | 0.82 | 1/3 | $2.29 |
| **a5 같은 프롬프트, 집필자를 Opus로 변경** | **1.05 / 1.11 / 1.04** | **1.07** | **3/3** | **$1.27** |

- 분량 설명만 바꾼 a1–a3는 효과가 없었다. a1에서 앞 묶음 약 1040–1330자를 명시해도 제23장은 637자만 썼다. 집필자는 숫자대로 쓰지 않으며 정확히 세지도 못한다.
- a5와 a0를 다른 모델 계열의 심사자(GPT)로 비교했다. 세 장의 쌍별 블라인드 평가에서 순서를 바꾼 두 번의 판정이 같을 때만 인정했으며 Opus가 3승했다. 엄격한 “장면으로 구현” 판정은 10/10, 9/10, 10/10(Sonnet 9/10, 9/10, 10/10)이었다. 보상은 모두 구현됐다. 범위를 넘는 새 요소는 제23장 2개 대 1개였고 다른 두 장은 모두 0이었다. 심사 이유는 Opus가 행동·생활 세부로 감정을 표현하는 반면 Sonnet은 직접 요약하는 경우가 많다는 데 집중됐다.
- 묶음 분할 문제(Codex가 앞 묶음을 너무 작게 나눔)는 이번 수정 범위에 포함하지 않는다. Codex 집필자 모델은 고정하지 않고 사용자의 모델 선택을 따른다.

## Alternatives considered

- **분량 설명만 변경(앞 묶음 범위, 지점별 척도, 짧아도 된다는 암시 삭제)**: 변경이 작고 모델·할당량에 영향이 없다. 그러나 세 표현의 실측 평균은 0.73–0.75로 현재 0.71과 차이가 없었으며 집필자는 숫자대로 쓰지 않아 채택하지 않는다.
- **묶음마다 결정적 측정 1회 후 하한 미만이면 보충 1회**: 모델을 바꾸지 않고 기계 계수로 보충을 승인된 사건 지점에 제한할 수 있다. 그러나 평균 0.82, 첫 검사 1/3에 그치고 장당 비용이 거의 두 배다. 보충은 #370이 피하려는 내용 부풀리기의 진입점이기도 하다.
- **지점별 글자 수 할당량 복구**: 가장 직접적인 분량 기준이다. 그러나 #187에서 하한으로 쓰면 체계적으로 +58% 길어졌다. 배분 구간으로 써도 주 세션의 지점별 추정과 상세 개요 항목이 늘어 v0.8 간소화 방향에 어긋나므로 우선 채택하지 않는다. 후보 1·2가 모두 실패했을 때만 재시험한다.
- **부족하면 자동 이어쓰기**: 작가가 매 장 선택할 필요가 없다. 그러나 #370은 장 전체 집필 뒤 확장하는 과정의 내용 부풀리기와 반복 수정을 피하려는 변경이었다. 보충은 설명적 심리와 반복 상호작용을 넣기 쉽다.
- **상세 개요의 사건 지점 수만 조정**: 집필자가 지점별로 쓰므로 수가 늘면 자연히 길어진다. 그러나 지점 수는 사건 설계 문제이며 글자 수 때문에 늘리면 불필요한 사건을 만들게 된다. 지점 수가 비슷해도 분량 차이가 컸다(Codex 두 실행 모두 7–9개 지점, 글자 수 비율 1.0 대 0.85). 우선 대안으로 채택하지 않는다.

## Consequences

- 이점: Claude Code 이어쓰기의 첫 검사 범위 충족률이 1/3에서 3/3으로 올라 작가가 수락·재작성을 고르는 횟수가 줄고 본문 블라인드 평가도 좋아졌다. 장당 비용은 거의 같다.
- 비용: Opus는 Sonnet보다 구독 할당량을 빨리 소모해 할당량이 적은 작가는 한도에 더 일찍 도달한다. 증거는 데모 한 권, 실험군당 세 장뿐이다. 절제된 장르(비극·세태물)는 본래 짧게 쓰는 경향이 있어 별도 재검증이 필요하다. 체계적인 과다 분량이 나타나면 초과분을 한 번만 삭제하는 마무리로 충분한지 다시 확인한다.
