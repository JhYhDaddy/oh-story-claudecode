# Agent Note: 세 단계 영감 라이브러리를 작품 분석 스킬의 내부 파이프라인으로 전환하고 EM 구조 카드 재사용

Status: implemented
Date: 2026-09-22
Issue: PR #387(PR #386에 의존)
Related: [2026-09-22-long-analyze-single-state-runtime](../architecture/2026-09-22-long-analyze-single-state-runtime.md)
Related(인수 마무리): [2026-09-23-inspiration-library-takeover](../simplification/2026-09-23-inspiration-library-takeover.md) — 장별 연결과 부분 문자열 유의어 판정은 이 후속 기록에서 철회했다.

## Problem

세 단계 영감 라이브러리의 초기 설계(PR #387 초안)는 여섯 차원 작품 분석의 `structure_blocks.csv`를 기반으로 했다. 각 구조 블록의 `inspiration_*` 필드 다섯 개로 원자 영감(IA) 파일 하나를 기계적으로 렌더링했다. 검토 이후 #386에서 구조 블록 산출물을 제거하여 기반이 사라졌다. 초안의 실제 시험 실행에서는 구조적 문제 두 개도 드러났다.

1. **블록별 원자화로 인한 중복 관리** — 책 한 권의 IA가 60–148개에 이르렀고 구조 설명이 EM·IA·NM·CBA 네 단계 카드에 반복됐다. 검토에서는 “기존 사례와 구조 분석을 최대한 재사용한 뒤 책 간 비교·검색을 수행하여 같은 내용의 다층 카드 중복 관리를 줄이라”고 요구했다.
2. **출처 경로의 벽** — CBA 카드 하나의 출처 절에 IA 상대 경로 링크가 62개나 나열되어 집필 중 조회할 때마다 이를 읽어야 했다. 검토에서는 “CBA와 원자 카드의 대량 중복 경로를 없애고 필요할 때 조회하도록 바꾸라”고 요구했다.

독립된 14번째 스킬은 패키징, 배포, 명령과 일곱 호스트 목록 전체를 연결해야 한다는 부담도 있었다. 영감 라이브러리의 본질은 작품 분석 산출물을 조직하는 계층이다.

## Decision

1. **story-long-analyze의 선택적 후처리 파이프라인으로 통합**하고 스킬을 추가하지 않는다. 문서는 `references/inspiration-library.md`, 스크립트는 상태 스크립트 세 개와 나란한 `scripts/inspiration_index.py`다. 트리거는 “영감 라이브러리/영감 추출/책 간 영감 집계/영감 라이브러리 갱신”이며 **단일 작품 분석은 자동 등록하지 않는다**. 스킬 수는 13개를 유지하고 패키징·배포·명령은 바꾸지 않는다.
2. **IA의 출처를 Stage 3 EM 구조 카드로 전환**한다. #386의 “세 단계 영감 라이브러리 최소 소비 계약”이 기준 ID `EM-*`를 미리 마련했다. 다섯 필드는 1:1로 대응한다(독자가 보고 싶은 것/감정 사슬＋극적 단위/교체 가능한 요소/그대로 가져오면 안 되는 요소). **IA는 색인 등록 행으로 축소하고 파일을 생성하지 않는다**. 구조 전문은 `剧情/情绪模块.md` 한 곳에서만 관리한다. 책별 IA 수는 블록별 수십~수백 개에서 EM 카드 수로 줄어든다(전체 카드 `grade=full`＋색인 항목 `grade=index`).
3. **카드 내부 경로 참조 금지**: NM/CBA 출처는 `书名/EM-xxx` 형태의 순수 ID 한 줄만 쓴다. `validate`는 카드 안의 `](`, `.md)`, 계층 디렉터리명, `拆文库/`를 기계적으로 거부한다. 경로 해석은 `灵感索引.csv`로 통일하고 필요할 때 역조회하는 `resolve` 하위 명령을 추가한다. CBA가 NM을 참조하면 구성 EM을 연결 관계의 전체 집합에 자동 포함하며 펼쳐 나열하지 않는다. `novel_count`/`atom_count`도 이 집합에서 자동 계산한다.
4. **NM은 같은 책에서 카드 2개 이상이 같은 구조일 때만 생성**한다. 이유·차이·반례 같은 병합 추가 정보만 담고 구조를 반복 설명하지 않는다. 초기의 “모든 IA는 NM 하나에 속해야 함” 범위 충족 요구는 취소한다.
5. **모든 사용 단계에 연결**: 집필 전 조회에 선택 축 (a0)를 추가한다(상위 3개 active CBA → `selected_inspiration_aggregates`; 라이브러리 없음·일치 없음은 gap으로 기록하고 차단하지 않으며 축소 모드에서도 실행). 집필자 프롬프트 조립 스크립트에 “다른 책의 영감” 칸을 추가한다. 스크립트가 `灵感库/灵感索引.csv`를 탐지하여 라이브러리가 없으면 칸을 닫고 있으면 주 세션이 (a0)에 따라 채우도록 빈칸을 둔다. 새 책 시작(적용 단계=설정), 권별 개요(=권별 개요), 상세 개요(=상세 개요)에 각각 선택 조회 안내를 추가한다. cross-book-recall에는 “공통 영감 태그 조회” 절(여덟 태그 축, 핵심 축 기준, 상위 3–8개 예산)을 추가하고 이 경로가 **비교 작품 2권 이상 조건과 독립적**임을 명시한다. story-explorer의 `benchmark_style_load`에도 같은 조회를 추가한다. project-files의 기준 읽기 순서 제6항은 예산과 충돌 판단을 고정한다. 고유명사 유출은 등록할 때 `角色/` 디렉터리로 기계적으로 검사한다. 고유명사를 지목하는 것이 본래 역할인 “그대로 가져오면 안 되는 요소” 필드는 제외한다.
6. **자료 부족은 #386의 필요 시 보강 사용**: `剧情/情绪模块.md`가 없으면 `--intent enhance`를 가리키는 `repair_action`을 반환한다(원문 읽기가 0일 수도 있음). 영감 계층은 대신 분석하거나 내용을 보충하지 않는다. 버전과 릴리스 일정은 유지보수자에게 맡기고 이번에는 `agents_version` / `setup_skill_version`을 바꾸지 않는다.

## Alternatives considered

- **독립 스킬 유지**: 경계가 명확하고 별도 설치할 수 있다. 그러나 모든 입력·출력이 작품 분석 산출물에 기반하며 14번째 스킬은 패키징·배포 전체 연결 비용을 요구한다. 검토 방향도 구조 축소이므로 포기한다.
- **블록별 IA 파일 유지(초안 방식)**: IA 파일을 독립적으로 읽을 수 있다. 그러나 중복 관리와 경로 벽의 원인이며 기반 구조 블록도 #386에서 삭제했으므로 포기한다.
- **IA 등록 없이 CBA가 EM 직접 참조**: 계층이 가장 적다. 그러나 책 간 비교의 작업 기반인 “책별 구조 목록”과 EM↔IA 집합 일치 검사 수단을 잃는다. 색인 행 비용은 매우 작으므로 등록 계층을 유지한다.

## Consequences

이점: 구조 전문을 한 곳에서 관리하며 색인은 시험 라이브러리의 493행 규모에서 책별 몇 행으로 줄어든다. 경로 벽 제거로 CBA 카드가 크게 줄고 집필 조회 컨텍스트에는 자체적으로 이해 가능한 추상화만 담긴다. 등록 재실행은 바이트 단위 멱등성을 가지며 EM 변경은 `ia_em_set_mismatch`로 기계적으로 발견한다.

비용: CBA 출처 추적은 색인을 거쳐 두 단계가 필요하다(`resolve`로 완화). 구조 커버리지의 밀도는 구조 블록별에서 EM 카드 단위(가장 강한 3개 전체 카드＋나머지 색인 항목)로 줄어 약한 구조는 ID 수준으로만 등록된다. 예전 시험 라이브러리는 이전하지 않는다. main에 영감 라이브러리가 배포된 적이 없어 호환성 부담이 없기 때문이다.
