# Agent Note: 장편 집필 검토와 새 책 시작 실측에서 발견한 절차 단절 수정

Status: implemented
Date: 2026-09-26
Related: [작가 확인 지점별 새 책 시작](../architecture/2026-09-26-opening-by-author-moments.md), [중첩 의미와 시점별 solo 읽기 축소](../architecture/2026-09-26-budget-stacking-and-solo-reads.md)

## Problem

v0.8.2에서 새 책 시작을 시점별로 나누고 35K 상한을 구현한 뒤 검토와 장편 solo 새 책 시작 실측에서 절차 사이의 연결이 끊긴 곳을 발견했다.

- 작업 패키지는 실행자에게 “패키지 밖 파일을 읽지 말라”고 하지만 내부 절차는 바깥의 기준과 참조를 요구했다. 상세 개요·권별 개요는 SKILL.md의 “새 요소 세 단계”로 분류해야 하는데 원문이 없어 실측에서 설계자가 값을 만들어 설정에 썼다. 권별 개요 절차도 책 간 조회, 인물 궤적 빠른 참조, 반전 유형과 영감 라이브러리를 지목했다.
- 설정 확정 시 작가가 승인한 한 문장 줄거리, 핵심 갈등, 최종 장애물과 세계관 뼈대를 설정 파일에 저장할 자리가 없어 다음 시점에서 `设定/`만 읽으면 사라졌다. 만들 파일은 세 곳의 설명이 달랐고 solo의 제안·저장 순서도 불명확했다. “여덟 지점 위치”는 설정 단계에서 채울 수 없었다. 실측에서는 1979년 물가·소득 규모를 설정에 바로 쓰고 보고에서만 요약했다.
- 방향 확정의 비교 작품 복사 규칙이 삭제됐는데 두 곳이 존재하지 않는 위치를 가리켰다. 책별 “작가 확정 사항”(선호·금지선)은 집필자에게 전달되지 않았다.
- 상세 개요 작업 패키지는 요청 장의 일부만 사건 전개 단위가 덮어도 성공했다. 범위 행 누락 오류는 “작성할 장 범위”를 적으라고 잘못 안내했다. 새 권별 개요 검수는 `--strict`를 사용하지 않았다.
- 대규모 수정은 workflow-revision만 읽지만 분량 범위 이탈, Node 누락, 한 차례 순수 삭제와 글자 수 질문 문구는 단일 장 절차에만 있었다. 한 장 재작성 프롬프트에는 `style_resolution`과 작가 선호 칸이 없었다.
- “설정 확정”, “권별 개요 작성”은 새 대화 권고에 쓰이지만 진입 트리거가 아니었다. 작가에게 보이는 `Fallback:`／`Notice:` 검사는 “`Fallback:` 보고”라는 한 문형만 인식해 동사를 바꾸면 우회됐다.

## Decision

- **작업 패키지에 기준과 조건부 참조 포함**: 세 패키지 끝에 SKILL.md의 “새 요소 세 단계” 원문을 붙이고 “조건부 읽기”를 나열한다. 절대 경로·절과 조건을 명시하고 충족할 때만 읽는다. 머리말은 “이 패키지와 조건을 충족하는 절만 읽기”로 바꾼다. 권별 개요 패키지의 감정 방법은 “장편 단위 감정 엔진” 절만 포함한다. 요청 장이 전부 포함되지 않으면 종료 코드 2와 누락 장 목록을 반환한다. 단위 카드의 범위 행이 없으면 해당 카드를 지목한다. 새 권별 개요는 `outline_view.py --check --strict`로 검수하고 기존 권별 개요에 단위를 추가할 때는 `--strict`를 뺀다.
- **설정 저장 위치**: 장르 포지셔닝 템플릿에 “핵심 설정” 절을 추가한다. Phase 2는 장르 포지셔닝 보완, 관계, 주인공·핵심 인물 카드, 전권에 영향을 주는 세계관을 전달하고 나머지 인물은 상세 개요 단계에서 보충한다고 명시해 project-files와 맞춘다. solo도 하위 에이전트처럼 먼저 제안하고 저장한다. 물가·힘의 등급 같은 전권 척도는 새 요소 세 단계에 따라 먼저 작가에게 묻는다. “장르 틀”은 권별 개요 작성 때 보충한다고 표시한다. `.active-book`이 없으면 만들고 여성향 설정에는 여성향 지침을 추가로 읽는다. 새 대화 권고는 보고 본문 마지막 문장에 두며 기술 비고는 여전히 최종 행에 둔다.
- **방향 확정의 비교 작품**: 자료 세대는 주 산출물 두 개의 존재 여부만으로 판단한다. 첫 인용 시 복사 규칙을 “비교 작품 발견” 제3항에 복구하고 진입점을 그곳에 연결한다.
- **장 집필**: 조립 스크립트가 장르 포지셔닝의 “작가 확정 사항”을 집필자 프롬프트에 주입한다. 상한은 600자이며 초과하면 자르고 원문을 가리킨다. 작가 메모리보다 우선한다. 수동 조립에도 같은 내용을 발췌한다.
- **대규모 수정**: workflow-revision Step 3에 검사 상태별 처리 표를, Step 4에 분량 범위 이탈 시 작가 질문과 세 선택지의 이동 경로를 추가한다. 한 장 재작성 프롬프트에 누락된 두 칸을 보충한다.
- **진입점과 검사**: description에 “설정 확정”, “권별 개요 작성”을 추가하고 상황 표에 설정 확정 행을 추가한다. 작가 메모리 query 명령을 진입점에 쓰고 장기 선호를 말했을 때만 프로토콜을 읽는다. 장편 진입점의 `Notice:`／`Fallback:` 원문은 기술 비고 행에만 쓰도록 바꾸고 검사에 포함한다. 검사는 모든 `Fallback:`／`Notice:`마다 같은 문장에 기술 비고로 보낸다고 명시하도록 변경한다.
- **작은 수정**: 참조 색인의 하렘 여성 주인공·남성향 연애선을 character-relations로 연결하고 조립 스크립트 docstring의 칸 설명을 갱신한다.

## Alternatives considered

- **패키지 밖 참조 전체를 붙임**: 실행자가 조건을 판단하지 않고 한 번에 받을 수 있다. 그러나 책 간 조회·인물 궤적·반전 파일 전체를 권별 개요 패키지에 더하면 35K를 넘고 대부분의 책에는 필요 없다. 조건과 절을 지정하면 최악 중첩도 32K다.
- **새 요소 세 단계를 workflow-outline에 복사**: solo 주 세션과 작업 패키지가 같은 곳을 읽는다. 그러나 SKILL.md와 workflow-outline이 어긋날 수 있다. 패키지 조립 스크립트가 SKILL.md 원문을 추출하며 solo 주 세션은 원래 진입 문서를 읽는다.
- **작가 확정 사항을 `设定/文风.md`에 기록**: 문체 파일은 이미 집필자 프롬프트에 포함된다. 그러나 연애선 금지나 기각한 도입부 같은 줄거리 금지선은 표현 차원이 아니므로 style-resolution이 표현 기준으로 잘못 판단할 수 있다.
- **대규모 수정에서 단일 장 절차의 마무리 부분을 빌려 읽음**: 텍스트 중복을 피한다. 그러나 빌려 읽으려면 단일 장 절차 6K 전체를 읽어야 해 시점별 분리 목적에 어긋난다. 원고 복구 같은 수정용 질문도 새 장 집필과 다르다.

## Consequences

- 이점: 실행자가 기준·참조를 못 받아 임의로 만들지 않는다. 설정 단계에서 승인한 핵심 요소와 책별 금지선이 저장되어 집필로 전달된다. 대규모 수정에서 분량 이탈과 Node 누락의 처리법이 명확해진다. 작가용 텍스트의 기계적 상태 행 검사를 우회하기 어려워진다.
- 비용: 작업 패키지에 절대 경로가 있어 설치 위치가 바뀌면 예전 패키지가 무효다(원래 매번 새로 조립한다). 일부 범위 포함을 더 엄격히 검사하므로 기존 권별 개요 카드의 범위가 불완전하면 먼저 보완해야 한다. 작가 확정 사항이 600자를 넘으면 잘리므로 집필자가 원문을 읽어야 한다.
- 할 일: story-review 진입점에는 “`Fallback: …` 보고”라는 표현이 아직 세 곳 있다. 검사에 포함하기 전에 고쳐야 하며 원고 검토는 다른 변경에서 담당한다.
