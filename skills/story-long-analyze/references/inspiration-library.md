# 3계층 영감 라이브러리 파이프라인

story-long-analyze의 선택적 후속 파이프라인이다. Stage 3에서 이미 추상화한 EM 메커니즘 카드를 작품 간 검색 자료로 정리한다. 작품을 다시 분석하거나 새 이야기를 쓰지 않는다. **개별 작품 분석 결과는 자동으로 등록하지 않는다.** 사용자가 영감 라이브러리·영감 추출·작품 간 영감 집계·라이브러리 갱신을 요청할 때만 실행한다.

## 재사용 우선 원칙

메커니즘과 사례 분석은 주 분석 파이프라인에서 이미 수행했다. `플롯/감정모듈.md`의 EM 카드가 메커니즘 전문을 **유일하게 유지·관리하는 위치**이며, 플롯 단위가 사례를 유지·관리하는 유일한 위치다. 여기서는 등록(IA), 작품 내 병합(NM), 작품 간 집계와 태그 지정(CBA)만 한다. 어느 계층에서도 EM 카드 본문을 **복사하지 않는다**. 카드의 출처는 경로 없는 ID로 참조하고, 작품 간 참조에는 `书名/EM-xxx`처럼 작품명 접두사를 붙인다. 원자료가 필요할 때 ID로 `灵感索引.csv`를 역조회하거나 `resolve` 하위 명령을 사용한다. 카드 안에 경로 링크를 나열하면 `validate`가 거부한다.

## 입력 범위

읽을 수 있는 자료: 각 작품의 `플롯/감정모듈.md`(완전한 EM 카드와 기타 메커니즘 색인), EM 카드의 관련 리듬·근거 출처를 따라 필요한 부분만 확인하는 `플롯/리듬.md`와 플롯 단위, 기존 `영감자료실/灵感索引.csv` 및 NM/CBA 카드.

**`원문/`, `chapter_index.csv`, 장별 요약 본문은 읽지 않는다.** 등록 전에 작품마다 읽기 전용 검사기(SKILL.md의 Phase 1)를 한 번 실행해 `classification`, `current_capabilities`, `conflicts`와 분석 범위를 확인한다. `플롯/감정모듈.md`가 없거나 완전한 카드의 필드가 부족해 `check-atoms`가 error를 보고하면 멈추고 작가에게 주 분석 흐름으로 돌아가도록 안내한다. 파일이 없으면 Stage 3을 보충하고, 카드가 불완전하면 SKILL.md의 Phase 2 마지막 지침에 따라 고친다. 어느 경우에도 원문은 읽지 않는다. 영감 계층에서 메커니즘 카드를 대신 만들거나 기존 자료를 요약해 정식 주 산출물인 것처럼 꾸미면 안 된다. 원문 추가·부분 변경 후에는 주 파이프라인에서 색인을 재구축하고 분석을 보충하며 요청에 따라 EM 카드를 갱신한 뒤 다시 등록한다. 재등록하지 않은 작품은 `validate`의 `ia_em_set_mismatch`가 알린다.

계층별 참조 기준: 개별 작품의 사례는 `플롯/*.md`의 플롯 단위, 전용 가능한 메커니즘은 `플롯/감정모듈.md`의 `EM-*`를 기준으로 삼는다. `작품분석보고서.md`는 읽기 진입점이며 별도의 사실 출처가 아니다. 객관적 사건·정보 공개 지점·3차원 리듬에는 각각 `EV-*`, `RV-*`, `AX-*`를 사용한다. 메커니즘 카드는 ID로 참조하며 계층 사이에 전문을 복사하지 않는다.

## 공용 디렉터리

현재 작업공간에서 상위로 올라가며 가장 가까운 기존 `영감자료실/`를 찾는다. 없으면 작업공간 루트에 만든다.

```text
영감자료실/
├── 灵感索引.csv                      # 3계층 통합 색인이자 ID → 위치의 유일한 해석 표
├── 单小说灵感合并/{书名}/NM-001.md    # 실제 병합이 있을 때만 생성
└── 跨书灵感聚合/CBA-001_{机制名}.md
```

- 원자 영감(Inspiration Atom), ID `IA-001`: **색인 행만 있고 파일은 없다.** EM 카드 하나의 등록이며 번호는 EM 번호와 같다.
- 작품 내 영감 병합(Single-Novel Merge), ID `NM-001`.
- 작품 간 영감 집계(Cross-Book Aggregation), ID `CBA-001`.

## 파이프라인 3단계

### 1. 원자 영감 등록(결정적 기계 처리)

```text
{PYTHON} "{story-long-analyze skill 根}/scripts/inspiration_index.py" register-atoms --root "{灵感库}" --module "{拆文目录}/플롯/감정모듈.md" --book "{书名}"
```

- 완전한 카드(독자의 기대 `读者想看什么`, 감정 사슬 `情绪链`, 극적 단위 `戏剧单元`, 교체 가능 항목 `可替换项`, 그대로 차용하면 안 되는 요소 `不可照搬`의 5개 필드가 모두 있는 카드)는 `grade=full`, 기타 메커니즘 색인 항목은 `grade=index`로 등록한다.
- 먼저 읽기 전용 `check-atoms`를 register-atoms와 같은 인수로 실행한다. 카드 수·색인 수·인물 명단 규모·모든 문제를 출력하며 파일은 쓰지 않는다. 모든 카드의 문제를 한 번에 보고하고 error가 하나라도 있으면 전체를 저장하지 않는다.
- 한 번에 원자적으로 기록하며 재실행 결과는 바이트 단위로 동일하다. 여러 작품은 한 작품씩 순차 등록하고 `register-atoms`를 병렬 실행하지 않는다. 이 단계에서 모델을 호출해 메커니즘을 다시 요약하면 안 된다.
- 고유명사 검사에 쓰는 인물 명단은 `작품분석실/{书}/인물/`에서 가져온다. `--root`에서 상위로 올라가며 `작품분석실/`가 있는 작업공간을 찾고 출력에는 항상 `character_roster` 수를 포함한다.

error는 모두 Stage 3으로 돌아가 `플롯/감정모듈.md`를 고친 뒤 재등록한다. warning은 사람이 확인한다.

| 오류 | 의미 | 수정 방법 |
|---|---|---|
| `em_fields_missing` / `em_field_value_empty` | 필수 필드 5개 중 누락되거나 빈 값이 있음 | 필드를 보충한다. 표 형식은 값 전체를 셀 안에 쓰고, `- **字段**：` 목록 형식은 필드명 다음 줄부터 여러 줄로 값을 써도 된다. |
| `em_title_missing` / `em_header_unrecognized` / `em_field_duplicate` | 카드 머리글이 `### EM-xxx 名称` 형식이 아니거나 제목을 인식할 수 없거나 필드가 중복됨 | 카드가 잘렸거나 앞 카드에 합쳐진 경우가 많다. 템플릿에 맞춰 머리글을 다시 쓴다. |
| `source_specific_name_in_mechanism` / `replaceable_antipattern` | 차용 금지 필드에 적힌 고유명사가 제목·독자 기대·감정 사슬·극적 단위·교체 가능 항목에 다시 나오거나, 교체 항목을 고유명사→아무 X로 작성함 | 기능적 역할로 바꾼다. 차용 금지 필드 자체에서 고유명사를 명시하는 것은 그 필드의 역할이므로 오류가 아니다. |
| `leak_suspect`(warning) | 인물 카드 파일명의 부분 문자열만 일치하고 뒷받침 근거가 없음 | 해당 필드를 직접 보고 고유명사가 아니면 유지한다. |
| `character_roster_missing`(warning) | 작품 디렉터리는 있으나 `인물/`가 없음 | 카드에 고유명사가 없는지 직접 확인한다. |
| `workspace_not_located` | `작품분석실/`가 있는 작업공간을 찾지 못함 | `--workspace`로 지정한다. 빈 명단으로 검사를 통과시키면 안 된다. |
| `module_book_mismatch` | `--module`이 `작품분석실/{--book}/` 아래에 있지 않음 | 작품명 또는 경로를 바로잡는다. |

### 2. 작품 내 영감 병합

한 작품 안에서 EM 카드 2개 이상이 실제로 같은 구조일 때만 NM을 만든다. 촉발·감정 사슬·보상 실현 메커니즘이 같아야 하며, 단독 메커니즘에는 NM을 만들지 않는다. 카드에는 **병합으로 추가된 정보**를 쓰고 메커니즘 사슬은 옮겨 적지 않는다. 아래 필드명은 기존 데이터 계약을 유지한다.

```markdown
# NM-001：{군집명}

- 合并对象：EM-001、EM-003
- 合并理由：{같은 구조인 이유를 한두 문장으로}
- 差异形态：{각 카드의 촉발 요소·상황·규모 차이}
- 本书特有偏置：
- 共同反例/边界：
```

### 3. 작품 간 영감 집계

각 작품의 IA/NM을 기존 CBA 색인 요약과 비교하고 일치 가능성이 있는 active CBA만 읽는다. 기존 라이브러리의 증분 처리에서는 먼저 읽기 전용 `coverage`를 실행한다. 이 명령은 어떤 active CBA의 참조 폐포에도 포함되지 않은 원자와 기존 단일 작품 가설 카드를 나열한다. 집계 비교는 uncovered 원자만 대상으로 하며, 새로운 근거로 기존 단일 작품 가설을 작품 간 반복 검증 상태로 올릴 수 있는지도 확인한다. uncovered가 비어 있으면 이미 포함된 EM 카드를 다시 비교하지 않는다. 그래도 기존 단일 작품 가설 카드의 검증 상태는 재확인한다. CBA는 **집필에서 반복해서 읽는 유일한 카드**다. 작품 간 귀납으로 얻은 추상화를 자체적으로 완결되게 담아야 한다. 이는 집계에서 새로 만든 산출물이며 EM 원문 복사가 아니다. 아래 스키마의 필드명·상태값은 유지한다.

```markdown
# CBA-001：{메커니즘명}

- 验证状态：{单书假设/跨书重复验证}
- 来源：{甲书/EM-001、甲书/NM-002、乙书/EM-003}（ID로 灵感索引.csv를 조회하거나 resolve 사용）

## 共同机制链
{촉발 → 독자의 인식/감정 변화 → 계속 읽을 동력 → 보상 실현}

## 可变参数
- 人物功能位：／关系动作：／冲突载体：／兑现规模：／节奏位置：

## 可能适用于
- 题材：／读者需求：／情绪：／关系动作（可空）：／剧情功能：／节奏位置（可空）：／适用阶段：／风险：

## 条件、反例与边界
- 成立条件：／反例：／不可照搬：／误用风险：
```

`novel_count`/`atom_count`는 카드에 직접 쓰지 않는다. 색인의 `source_ids` 참조 폐포에서 자동 계산하고 검증한다. 한 작품만 뒷받침하면 집필 재사용 가치가 가장 높은 CBA를 최대 3개 활성화하고 `单书假设`(단일 작품 가설)로 표시한다. 독립적인 출처가 2작품 이상일 때만 `跨书重复验证`(작품 간 반복 검증)으로 표시한다. 태그는 적용 가능성만 나타내며 한 작품의 근거를 시장 전체의 결론으로 쓰면 안 된다.

## 색인과 통제 태그

`灵感索引.csv` 헤더는 정확히 다음과 같다.

```csv
item_id,layer,title,source_book,path,source_ids,novel_count,atom_count,grade,tags,status
```

- IA 행의 `path`는 비우고 `grade`는 `full/index` 중 하나로 한다. NM/CBA 행의 `grade`는 비운다. IA/NM의 `tags`도 비워 집필에서 집계 계층을 우회하지 않게 한다.
- `source_ids` 출처 그래프: IA 행은 단일 `EM-xxx`, NM 행은 같은 작품의 `EM-xxx` 2개 이상(`|` 구분), CBA 행은 `书名/EM-xxx`와 `书名/NM-xxx`의 혼합 목록이다. CBA에는 작품명 접두사가 필수다. NM 참조 시 소속 EM은 자동으로 폐포에 포함되므로 **다시 펼쳐 나열할 필요가 없으며 그렇게 해서도 안 된다**. `novel_count`는 폐포의 서로 다른 작품 수, `atom_count`는 서로 다른 EM 수다.
- 태그 직렬화 형식은 `轴=值1|值2；轴=值`다. CBA 필수 축은 장르 `题材`, 독자 욕구 `读者需求`, 감정 `情绪`, 플롯 기능 `剧情功能`, 적용 단계 `适用阶段`, 위험 `风险`이다. 선택 축은 관계 행동 `关系动作`, 리듬 위치 `节奏位置`다. 동의어는 먼저 통일하고 보기 좋다·재미있다·고급스럽다 같은 실행 불가능한 표현은 쓰지 않는다.
- **태그 값은 라이브러리의 `영감자료실/태그목록.md`로 통제한다.** 축마다 `## 轴` 절을 두고 한 줄에 값 하나를 `- 值` 형식으로 적는다. 최초 집계에서 사용한 값으로 초판을 저장하고, 이후에는 태그를 붙이기 전에 어휘표를 읽는다. 확장은 동의어 판정을 거친다. 후보 값을 해당 축의 기존 값과 하나씩 의미 비교해 겹치거나 하위 개념이면 기존 값을 쓰고, 실제 새 차원일 때만 한 줄 추가한다. query는 값의 정확한 일치로 검색하며 기록과 조회 모두 같은 표를 쓴다.
- `validate`는 헤더·ID 접두사·EM↔IA 집합 일치·NM/CBA 폐포와 수치·필수 태그 축·단일 작품 active CBA ≤3·검증 상태·**카드 내 경로 참조 금지**를 검사한다. 어휘표가 있으면 표 밖 값(`tag_value_not_in_vocabulary`)과 필수 축이 없는 어휘표(`vocabulary_axis_missing`)도 거부한다. 어휘표가 없으면 기존 라이브러리 호환을 위해 이 두 검사를 생략하지만 신속히 보충해야 한다. 동의어는 어휘표 확장 시 사람이 비교하며 단순 부분 문자열로 판정하지 않는다. 열 수가 틀린 색인 행은 `column_count_mismatch`로 보고한다.
- `query --tag 轴=值 …`는 `layer=跨书灵感聚合`이면서 `status=active`인 항목만 검색한다. 핵심 축(장르/독자 욕구/감정/플롯 기능/적용 단계)은 2점, 나머지는 1점이다. 핵심 축에 일치하지 않으면 반환하지 않는다. 점수/출처 수/ID로 안정 정렬해 상위 3–8개를 고른다. 반환값에는 `unmatched_tags`(요청 값이 라이브러리 전체의 해당 축에 한 번도 없음)와 `axis_inventory`(조회한 축의 기존 값)도 포함된다. 결과가 없으면 이 정보를 바탕으로 검색어를 고쳐 한 번 더 조회하고, 그래도 없을 때 라이브러리에 없다고 판단한다.
- `resolve --ref 书名/EM-xxx --ref CBA-001`은 경로 없는 ID를 읽을 수 있는 위치로 해석한다. 필요할 때만 조회하며 어떤 카드에도 미리 펼쳐 넣지 않는다.

## 집필 측 사용 계약

집필 모듈은 태그가 일치하는 active CBA의 전체 카드만 상위 3–8개 읽고 출처를 따라 EM/NM으로 내려가지 않는다. CBA는 문체 샘플로 사용하지 않으며 원문 읽기를 유발하지 않는다. 같은 CBA에서 만드는 변형 후보는 최대 2개다. 사용 진입점은 story-long-write의 작품 시작·권 개요·상세 개요 3곳뿐이다(`适用阶段=설정/卷纲/细纲`). 장별 집필 전 검색과 집필자 prompt에서는 영감 라이브러리를 읽지 않으며 영감은 상세 개요를 거쳐 본문에 반영된다.

## 중단 후 재개와 금지 사항

별도 진행 파일을 만들지 않는다. 색인과 카드의 현재 상태가 진행 상태다. 중단 후에는 멱등적인 등록을 다시 실행하고 `validate` 오류 목록으로 미완료 계층을 찾는다. 금지 사항: 원문 재독, 블록별 의미 재분석, 어느 계층에서든 EM 메커니즘 전문 복사, 카드 내 경로 링크, 이야기 씨앗·인물 조합·완성 장면 자동 생성, 원작 고유명사·문장 복사(작품 간 계층에는 인물명조차 금지), 개수를 채우려고 의미가 다른 메커니즘을 억지로 병합하기.
