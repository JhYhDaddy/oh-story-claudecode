# Agent Note: 역할별 호출당 로드를 35K 이하로 줄이고 예산에 강제 상한 적용

Status: implemented
Date: 2026-09-26
Related: [v0.8 경량화](2026-09-24-v0-8-lean-writing-loop.md), [분기 중첩과 solo 시점별 읽기](2026-09-26-budget-stacking-and-solo-reads.md)

## Problem

v0.8.1 핵심 경로 예산에서 집필자·주 세션은 약 32K지만 세 호출은 크게 초과했다. 문체 제거 검토 45.6K는 약 1K인 두 절 때문에 writing-craft 전체를 읽었다. 주 세션 직접 집필 direct/solo는 제거 세칙·금지어·품질 목록·계약·색인·회상 설명을 보수적으로 전부 세어 68–93K다. 단편 Phase 2는 비교 작품 회상·색인을 필수로 세어 36–42K다. demo 제21장 실측은 주 세션 약 61K, 집필자 약 55.5K이며 조건부를 필수로 세거나 같은 내용을 반복한 부분이 많다. 새 책 시작에서는 실제 읽는 artifact-protocols 약 10K도 빠졌다.

## Decision

- **예산 기준**: `doc-budget.json` 경로에는 무조건 읽는 자료만 등록한다. 전체 회상·계약 실패·파일 누락·이 장의 기법(다섯 중 하나)·집필 후 제거 보완은 각각 기본분을 포함한 분기다. 이후 [중첩 의미](2026-09-26-budget-stacking-and-solo-reads.md)에서 같은 호출에 동시 발생하는 분기를 `stacking`에 등록하여 최악 조합을 검사하도록 수정했고 계약 실패·제거 보완은 reference를 읽지 않게 했다. `path_ceiling`을 추가해 면제 없는 경로·분기의 실제 로드와 예산이 모두 35,000자 이하여야 한다. `check-doc-budget.sh`가 강제하며 `test-doc-budget.py`에 변이 검증한 회귀가 있다.
- **문체 제거 검토**: 집필법 표본 검사 표를 deslop-gates에 합치고 검토는 deslop-gates·anti-ai-writing·banned-words·style-resolution만 읽는다. 채점 파일은 채점할 때만 읽는다. 45.6K → 31.4K다.
- **주 세션 직접 집필**: 집필자와 같은 writing-craft+long-format을 읽고 long-chapter-quality·long-chapter-hooks는 구체적 문제 조사 때만 읽는다. 제거는 탐지기로 하고 사후 보완은 anti-ai-writing 전체 대신 장편에 동기화한 deslop-gates를 읽도록 했다(이후 탐지기별 안내로 수정하며 deslop-gates를 읽지 않도록 변경). 일관성 에이전트가 없으면 주 세션이 한 줄 목록으로 검사한다. SKILL.md 핵심 방법 표에 따라 장당 기법 하나만 읽는다(망신 주기/반전/연애/서스펜스/일상; 이후 결정 경로가 가리키는 절만, 일일 연재 배치당 하나로 수정). 단일 장·일일 연재·대폭 수정 direct/solo 경로가 모두 ≤35K다.
- **중복 제거·이동**: 하위 에이전트 prompt는 `agent-calls.md`로, workflow-daily 초기화·장기 제약·배치 이어가기는 링크로 바꾼다. SKILL.md 경로·경로 규칙을 줄이고 비교 작품 복사 규칙은 workflow-setup의 비교 작품 발견 제3항으로 옮긴다(처음에는 artifact-protocols로 옮겼다고 썼지만 실제 누락되어 검토 후 보충). artifact-protocols 추적 체계는 tracking-transaction을 가리킨다. style-combat-face의 하렘 여주·남성향 연애선은 character-relations로 옮기고 writing-craft 둘은 일반 공유 사본으로 바꾼다. 단편 Phase 4 교정 목록은 workflow-revision, Phase 3 집필 전 로드 목록은 workflow-draft로 옮기며 색인·비교 작품 회상은 간소화·조건부로 바꾼다.
- **검토 시점별 읽기**: solo는 `banned-words.md`로 1급 단어를 개별 확인한다. 사전 검사는 빈출 상투어 밀도와 고정 구문을 보지만 1급 단어를 개별 보고하지 않는다. AI 문체 판단에는 anti-ai-writing의 AI 집필 지문·10가지 패턴 검사 두 절을 읽는다. 공간 확보를 위해 하위 에이전트 배정 때만 쓰는 종합 판정·full/lean 보고·story-explorer 사전 검색을 `agent-prompts.md`로, 여러 장 배치의 저장 계약·배치 간 연속성·순서 뒤섞임 안내를 새 `batch-review.md`로 옮기고 진입부에는 한 줄 링크만 둔다. 작가 보고 검사의 기준점도 agent-prompts.md·solo.md로 옮긴다. 검토 reviewer는 모두 읽기 전용이다. prompt는 모든 파일 변경 금지, narrative-writer의 검토 과업 절은 검토에서 배정 시 보고만 하도록 명시한다. deslop-gates 표본 검사는 삭제 가능 판정·보고로 바꾸고 실제 수정은 문체 제거 담당자가 한다. solo 단일 장 33.4–33.9K·배치 34.8K, full/lean 20.3–21.2K·배치 22.6K다.
- **동반 수정**: workflow-chapter 12단계 제출 명령에 필수 `--input`을 더한다. 일일 연재의 같은 단위는 단일 장과 동일하게 배치 안에서 권 줄거리 구간을 재사용한다.
- **면제**: 장편 새 책 시작·새 책 시작 후 첫 장 집필은 여러 단계 계획 대화이며 누적 약 34–56K(계획 기법 포함)다. 실제로 계산해 면제에 넣고 별도 단계 분리를 예정했다. 이후 [새 책 시점별 처리](2026-09-26-opening-by-author-moments.md)로 면제를 없앴다.

## 검증

데이터 생성 전 `~/.oh-story-bench/prereg/v0.8.2-load35/PROTOCOL.md`에 절차를 고정했다. v0.8.1·이번 변경 두 조건 모두 `.claude/agents`를 지워 solo를 강제하고 같은 prompt의 Opus 하위 에이전트를 집필자로 썼다. demo 제22장 ×3, 현환·여성향 제1장으로 조건당 5장이다.

| 지표 | v0.8.1 | 이번 변경 | 기준 |
|---|---|---|---|
| Q1 사건 노드의 장면화(엄격 판정) | 1.00 | 1.00 | ≥ −0.10 |
| Q2 최종 blocking / 의미 advisory 평균 | 0 / 0 | 0 / 0.2 | blocking 없음, ≤ +1 |
| Q3 최초 검사 분량 범위 이내 | 5/5 | 5/5 | ≥ −1 |
| Q4 짝지은 블라인드 평가(두 번 순서 교환 후 일치만 인정) | 2승 | 1승 2패 2무 | 패 ≤ 승 + 1 |
| tell 인간 구간 이탈 항목 평균(기록만) | 5.2 | 5.4 | — |

네 항목 모두 통과했지만 Q4는 경계다. v0.8.1이 이긴 두 사례의 이유는 구체적 디테일·대사 질감(회상 중 풍향·구내식당 만터우, 권력자의 블랙 유머)이었으며 덜 읽은 품질 목록·장 훅을 지목하지 않았다.

이탈 기록 `DEVIATIONS.md` D1: Antigravity 계정 자격 검사 실패, Codex 할당량 부족, 로컬 Claude CLI 부재로 심사자를 이 대화의 Sonnet 하위 에이전트(집필자와 같은 계열)로 바꿨다. 조건을 모른 채 세부 줄거리·본문만 받았으며 prompt는 judge.py와 글자 그대로 같았다. 엄격 판정은 두 조건 모두 만점이라 변별력이 제한적이다.

**에이전트 대필 A/B**(`~/.oh-story-bench/prereg/v0.8.2-wave1/`): 조건당 5장, 주 세션 하위 에이전트가 집필 prompt를 채우고 집필 에이전트가 앞뒤 두 묶음으로 썼다. 장면화는 둘 다 1.00, 블라인드 5쌍은 순서 교환 후 전부 불일치하여 무승부, blocking 장은 base 4·cand 3이다. **초고 분량 범위 이내는 base 4·cand 2로 실패**했다. 템플릿 중복 제거 때 전 장 세부 줄거리를 먼저 읽고 배치하며 앞 묶음이 뒤 분량을 남기고 뒤는 남은 범위로 마친다는 두 문장을 잃은 것이 원인이다. 복구 후 demo 제22장 3회는 2615 / 2752 / 2647로 모두 통과했다.

**solo 추가 축소 후 A/B**(`prereg/v0.8.2-solo2/`, base는 위 v0.8.1 다섯 장 재사용): 첫 라운드는 최초 분량 2/5로 실패했다. 당시 한 번에 전 장을 쓰고 앞 묶음 측정을 없앴기 때문이다. 앞 묶음 후 checkpoint·뒤 묶음은 남은 범위로 마침을 복구한 재시험은 장면화 1.00 대 1.00, 모두 ready·blocking 0, 최초 분량 4/5, 블라인드 1승 1패 3무로 네 항목을 통과했다. 비교 작품 없는 새 책 첫 장이 색인으로 감정 체계·리듬 약 14K를 통째로 읽는 것도 발견해 본문 집필에서는 색인으로 추가 읽지 않도록 바꿨다.

두 분량 퇴보는 중복 문장뿐 아니라 그 순간 집필자가 알아야 할 분량 감각도 지웠다는 뜻이다. 규칙을 지우기 전에 누가 언제 쓰는지 확인해야 한다.

## Alternatives considered

- **보수적 전체 계산을 유지하고 문장만 삭제**: 조건부 분리를 절약으로 오인하지 않는 가장 보수적인 기준이다. 그러나 solo 68–93K의 절반은 원래 조건부여서 35K까지 지우면 기법 자체를 없애야 한다. 분기마다 기본분을 포함하고 같은 상한을 적용해도 보수성을 유지한다.
- **solo도 집필자의 전체 기법(대화·감정 곡선·도입) 읽기**: 에이전트 방식과 대등하다. 그러나 기본 약 30K에 10K를 더하면 초과하며 v0.8.1 solo도 해당 두 파일을 읽지 않았으므로 이번 변경의 퇴보는 아니다.
- **solo 1급 단어를 사전 스크립트에만 맡김**: 4K와 진입부 이동을 아낀다. 그러나 스크립트는 상투어가 천 자당 12회 초과해야 보고해 등장 즉시 바꿀 단어를 장 안에서 놓친다. anti-ai-writing 요약만으로도 단어 목록을 덮지 못한다.
- **검토 진입부에서 4K 삭제**: 가장 작은 변경이다. 그러나 남은 Phase 0 대체 실행 판단·참조 해석 순서·내장 기준 묶음·사전 검사 규칙은 매 검토 필요하다. 종합 판정·보고는 하위 에이전트 때, 배치 규칙은 여러 장 때만 필요하므로 시점별 이동은 규칙을 잃지 않는다.
- **새 책 시작도 즉시 35K로 제한**: 목표가 통일된다. 그러나 소재·설정·권 줄거리·첫 세부 줄거리를 한 대화에서 연속 작성하고 계획 기법만 10K 넘는다. 흐름·대화를 나눠야 해 줄거리 품질에 영향을 주므로 별도 설계·검증이 필요하다.

## Consequences

- **이점**: 집필 순환의 모든 호출 ≤35K, 제거 검토 14K 감소, OpenClaw·Reasonix 등 skills-only 호스트 직접 집필 로드 절반 감소다. 강제 상한이 생겨 추가하려면 같은 양을 지우거나 면제를 명시해야 한다.
- **비용**: solo는 품질 목록·장 훅을 미리 읽지 않고 사후 탐지·9단계 검사에 의존한다. Q4 경계·소표본·같은 계열 심사자로 큰 퇴보만 배제할 수 있다. 여러 예산이 실제량에 가까워졌다. 중첩 재계산 후 일일 solo 최악 34,218은 32자 여유, 단일 장 solo 최악은 1자 여유다. 이후 변경은 같은 양 삭제나 명시적 예산 조정이 필요하다.
