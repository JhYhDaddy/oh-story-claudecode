# Stage 5: 주 보고서·전체 개요·소재 결정 결과 반영

Stage 5에서는 이 파일과 [synthesis-inputs.md](synthesis-inputs.md)를 읽습니다. `작품분석보고서.md`의 템플릿·작성법은 [author-facing.md](author-facing.md)의 해당 절을 따릅니다.

## 백업·표시

새 `작품분석보고서.md` 생성 전에 실행합니다.

```text
"{PYTHON}" "{story-long-analyze skill 根}/scripts/manage_analysis_run.py" mark-stage --root "{拆文目录}" --stage stage5 --prepare
```

기존 보고서가 있으면 `_analysis_cache/legacy/작품분석보고서.md`로 전체 복사합니다. 이미 있는 첫 백업은 덮어쓰지 않습니다. 기존 보고서가 첫 백업과 다르면 내용 hash를 붙인 이력 백업을 추가로 저장합니다. 다른 옛 산출물·기존 요약은 덮어쓰면 안 됩니다. 새 보고서·전체 개요 저장 후 `--prepare` 없는 `mark-stage`로 완료를 표시합니다.

## 전체 개요

저장된 `플롯/이야기선.md`(이야기 틀 포함)·각 단위에서 500–1000자 전 작품 개요를 작성합니다. 주요 이야기선의 단계·핵심 인물 역할·중요 전환·인과를 포함합니다. `개요요약.md`의 Stage 0 「首版概要」를 「全书概要」로 바꾸고 기본 정보·권 구간 표는 유지합니다.

## 보고서

author-facing의 「작품분석보고서.md」 지침을 따릅니다. 저장된 기초 결과만 종합하고 보고를 위해 원문 전체를 다시 읽거나 장별 요약을 복사하지 않습니다. 결론마다 쉬운 한 문장 뒤 해당 파일·장을 안내합니다. `source_locator`·근거 등급·`EV/RV/AX/EM` 전체 번호는 기초 파일에 두고 보고서의 번호는 이름을 동반할 때만 사용합니다.

문체가 없으면 「文风一句话」에 보완 예정이라고 씁니다. 보고서 저장·`stage5` 표시 후 Stage 6가 [style-profile-generator.md](style-profile-generator.md)의 보고 반영 규칙으로 채웁니다. 재개도 같은 인계를 따릅니다.

## 소재 결정 결과 반영

장편 순위 조사의 `소재선정.md`는 「能爆的原因」에 `待拆文验证`를 표시해 분석 근거를 기다립니다. 보고서 저장 후 먼저 `작품분석실/`가 있는 작업 공간 루트에서 찾고, 이어 작업 공간 `순위조사/*/소재선정.md` 중 가장 최근 날짜 파일을 봅니다. 둘 다 없으면 생략하며 분석에는 영향을 주지 않습니다.

1. 「推荐选题」 절이 없고 순위만 조사했다면 생략하며 무효로 보지 않습니다. 추천 소재는 있지만 「能爆的原因」 등 현 필수 필드가 없으면 멈추고 author-facing의 소재 결정 필드 누락 문안으로 알립니다.
2. 「题材组合」이 이 작품 장르와 맞고 「能爆的原因」에 아직 `待拆文验证`가 있는 소재만 봅니다.
3. 분석이 가설을 뒷받침하면 `已拆文验证`로 바꾸고 같은 행에 `依据：《{书名}》拆文报告·核心发现第 N 条（第 x–y 章）` 형식으로 근거를 추가합니다. 가설과 다르면 `拆文未证实`로 바꾸고 같은 형식으로 불일치를 설명합니다. 이 행만 수정하며 다른 필드는 유지합니다.
4. 작가에게는 어느 소재에 어떤 결론을 반영했는지 한 문장으로 알립니다.
