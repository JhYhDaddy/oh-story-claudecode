# story-review: 여러 장을 묶음으로 검토

여러 장·한 권·전체 작품을 두 묶음 이상으로 나눠 검토할 때 읽는다. full·lean·solo 모두 적용하며 한 번에 검토하면 읽지 않는다.

## 묶음 간 검토 상태 저장 계약

분할할 때 **{프로젝트 루트}/.story-review/state.md**를 관리한다.

1. 첫 묶음에서 전체 검토 범위와 묶음 순서를 정한다. 매 묶음 확인 후 같은 디렉터리의 임시 파일+rename으로 state.md를 원자적으로 다시 쓴다. 결과를 대화에만 남겨서는 안 된다.
2. state.md에는 전체 검토 범위·완료 범위·다음 묶음·‘이전 묶음의 미해결 findings 요약’만 기록한다. 요약마다 location·issue와 확인 또는 회수 예정 장 범위를 남긴다.
3. 다음 묶음 전에 state.md를 읽고 미해결 요약을 reviewer prompt에 넣는다. 해결됐거나 사용자가 명시적으로 처리하지 않기로 한 항목은 이어받지 않되 이번 출력에서 설명한다.
4. 프로젝트별로 동시 진행하는 분할 검토는 하나뿐이다. 새 검토 범위가 state.md의 미완료 범위와 다르면 버려질 이전 진행 상황을 설명하고 사용자 확인을 받는다. 확인 후 첫 묶음 완료 시 덮어쓴다. 재개할 때 state.md가 없거나 손상됐거나 이번 묶음이 정한 범위를 벗어나면 명확히 보고하고 멈춘다. 이전 내용을 추측하지 않는다. 분할 검토가 아니면 만들지 않는다.

**.story-review/**에는 검토 진행 상황만 저장한다. 검토 상태 관리를 이유로 본문·설정·개요·`추적/`을 수정해서는 안 된다.

## 묶음 검토 시작 전

- **묶음 간 연속성(분할 시 필수)**: 매 묶음 전에 `추적/복선.md`에서 상태가 `已埋`이고 회수 예정 장 ≤ 이번 묶음 마지막 장인 현재 행을 읽는다. 필요하면 `추적/장별기록/제NNN장.md`에서 변경 이유를 확인한다. 관련 인물의 개별 스냅샷도 읽고, 위 계약에 따라 state.md의 이전 묶음 미해결 findings 요약을 `继承的开放项`(이어받은 미해결 항목)으로 reviewer / consistency-checker prompt에 넣는다. solo는 직접 항목별로 확인한다. 새로 발견했으나 미등록인 열린 훅은 우선 관리 후보로 적으며 마무리 시 본문 증거가 있어야 수정 트랜잭션에 넣는다.
- **역순/중복 검토 안내**: 뒤쪽 범위(예: 300-400)를 먼저 검토하고 앞쪽(200-300)을 나중에 볼 때, 이번 묶음에서 **미해결 항목을 추가/변경했고 그 회수 예정 장이 이미 검토한 뒤쪽 범위에 속하는 경우에만** ‘200-300의 변경이 이미 검토한 300-400에 영향을 줄 수 있음’을 알린다. 영향받는 장 재검토 / 전체 재검토 / 할 일로만 기록 중 선택하게 한다. **기본값은 할 일로 기록이며 무작정 전체를 다시 돌리지 않는다.** 구체적인 범위 간 의존성이 없으면 알리지 않는다.
