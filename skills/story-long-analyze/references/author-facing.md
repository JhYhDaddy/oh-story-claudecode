# 작가에게 전달하는 말

대화의 진도·확인·보고·오류 설명과 `빠른미리보기.md`·`작품분석보고서.md`·`인물관계도/인물관계도.md` 저장 파일은 이 지침을 따릅니다. 코드 블록은 바로 사용할 수 있는 문안입니다.

## 공통 규칙

1. **시스템보다 이야기 설명**: 작품·장·독자 감정·작가의 활용법을 말합니다. 진도는 ‘전체 몇 장 중 몇 장까지’로 쓰며 단계 번호·묶음·명령은 말하지 않습니다.
2. **구현 세부 노출 금지**: 스크립트·명령·JSON 필드(검사기·계획기의 분류·추천 경로·단계 복구·최종 상태 등), 상태값·묶음 번호·내부 파일(진도·캐시·기계적 장 표), hash, 품질 지표명(신뢰도·포괄률·중복률), 근거 등급 문자, ‘3차원’ 같은 내부 기준은 내부 판단에만 사용합니다.
3. **번호에는 쉬운 이름 동반**: 감정 카드·관계·사건 번호만 보여 주면 이해하기 어렵습니다. 이름만 쓰거나 ‘공개 파혼으로 망신 주기(감정 모듈 카드 EM-003)’로 씁니다. 관계는 ‘린위안 → 쑤칭: 신뢰에서 적대로(제9장 문파 대회)’처럼 쓰고 관계 번호는 쓰지 않습니다.
4. **근거 강도도 쉽게 설명**: 직접 나온 사실은 단정하고 여러 세부에서 추론했다면 ‘제3·5장의 세부를 보면 가능성이 높습니다’, 근거 부족이면 ‘추정이며 원문 확인 필요: …’라고 씁니다.
5. **작가 결정이 필요할 때**: 구체적 질문 하나씩, 권장 선택지·이유를 제시합니다. 추천은 허가가 아닙니다. 확인이 필요한 선택은 답을 기다리고 이미 허가된 범위의 일상 작업은 기본 방식으로 계속합니다.
6. **구현 세부는 기본적으로 생략**: 작가가 묻거나 문제 해결에 필요할 때만 응답 맨 끝 독립 한 줄에 ‘(기술 비고: …)’로 씁니다. 한 줄을 넘지 않습니다.
7. 스크립트 출력에 `author_message`가 있으면 뜻을 작가에게 전달합니다. 다듬을 수 있으나 사실·선택지는 유지하고 JSON·오류 코드·`detail`을 붙여 넣지 않습니다.

## 대화 문안

### 첫 세 장 분석 후 멈추고 확인

```text
《{작품명}》 첫 세 장 분석을 마쳤습니다. 빠른 개요는 빠른미리보기.md에 있습니다.

한 문장 판단: {도입의 흡인력·주인공 구축 방식을 한두 문장으로}.
가장 배울 만한 점: {가장 참고할 만한 작법 한 문장}.

남은 {남은 장 수}장도 분석할까요? {끝까지 계속 / 제1권 끝까지 / 제X–Y장 구간만 / 여기서 종료}를 권합니다. 이유는 {이유}입니다.
계속하면 한 번에 세 구간을 함께 분석합니다(구간당 최대 세 장). 끝까지 약 {회차}회가 필요하며 구간 간 인물 호칭·미완 사건은 마지막 종합에서 맞춥니다.

계속할지는 결정을 기다리겠습니다.
```

### 작가가 분석 방식을 물을 때

기본은 한 번에 세 구간으로 정하며 선택지를 먼저 나열하지 않습니다. 더 빠르거나 안정적으로 가능한지, 방식을 바꾸고 싶다는 질문이 있을 때만 설명하고 선택대로 바꿉니다.

```text
세 가지 방식이 있습니다.
1. 구간별 순차 분석: 앞뒤 인물 호칭·미완 사건을 차례로 이어갈 수 있지만 더 오래 걸립니다.
2. 한 번에 세 구간(현재 방식): 기다리는 시간을 줄입니다. 구간 간 인물·사건 일부는 전체 분석 후 종합에서 맞춥니다.
3. 가능한 많은 구간 동시 분석: 더 빨라지지만 앞뒤 연결은 마지막 종합에 맡겨 종합 작업이 늘어납니다. 컴퓨터·계정이 감당하지 못하면 자동으로 속도를 낮춥니다.
```

### 진행 보고

약 10%를 마치거나 몇 차례 반영한 뒤 한 번 보고하며 매 묶음마다 보고하지 않습니다.

```text
《{작품명}》 전체 {총 장 수}장 중 제{완료 장}장까지 분석했습니다(약 {비율}%).
방금 마친 구간: {볼거리 한 문장}.
다음은 제{시작 장}–{끝 장}장입니다.
```

특정 장이 연속 실패해 범위를 줄여 재시도 중이면 재시도도 실패한 뒤에만 알립니다.

```text
제{시작 장}–{끝 장}장은 두 번 시도했지만 분석하지 못했습니다. {너무 길거나 서식을 식별하지 못하는 등 쉬운 이유}.
다른 장에는 영향이 없어 먼저 뒤를 계속하겠습니다. 이 장들은 {나중에 한 장씩 재시도 / 원문이 완전한지 사용자 확인 필요}합니다.
```

```text
《{작품명}》 분석 결과: 총 {총 장 수}장, 약 {총 글자 수}만 자. {전체 완료 / 제{x}–{y}장 실패: {이유}}.

가장 배울 만한 {1~3}가지:
1. {도입이 어느 장에서 어떤 기법으로 독자를 붙잡는지}
2. {독자가 기대하는 핵심 감정·통쾌함을 반복 실현하는 방식}
3. {어디가 빠르고 느린지·그 이유}

바로 활용할 유형:
- {유형명}: {사용할 장면·효과}.
- {유형명}: {…}.

따라 하지 말아야 할 점: {하나와 이유}.

자료 위치:
- 전체 보고: 작품분석보고서.md
- 첫 세 장의 장별 작법: 장별분석/제1장_심층분석.md ~ 제3장_심층분석.md
- 리듬·정보 공개: 플롯/리듬.md
- 독자가 좋아하는 감정 유형과 재사용 모듈: 플롯/감정모듈.md
- 주선·구간별 줄거리: 플롯/이야기선.md, 플롯/의 각 구간
- 인물·관계: 인물/, 관계도는 인물관계도/인물관계도.md
- 세계관·설정: 설정/
- 문체 참고: 문체.md
- 특정 장 사건 조회: 장별분석/제N장_요약.md

{결정이 필요한 질문 하나+권장안. 없으면 이 문단 생략}
```

일부 분석·파일 보강만 했다면 자료 위치는 이번에 추가·갱신한 파일만 나열하고 이전부터 있던 자료를 구분합니다.

### 중단·오류

발생한 일과 작품에 미치는 영향부터 설명하고 대안을 제시합니다. 선택이 필요하면 공통 규칙 5번을 따릅니다.

```text
분석 디렉터리 없음:
‘작품분석실/{书名}를 찾지 못했습니다. 작품명·경로가 맞나요?’

지난 분석 이후 원문 변경:
‘원문이 이전과 달라졌습니다({바뀐 장 / 교체 파일}). 완료한 장은 그대로 두고 바뀐 장만 다시 읽습니다{이전에 서장을 제1장에 합쳤으면: ; 이번에도 서장은 제1장에 합칩니다}. 새 원문으로 계속할까요?(권장: 계속)’
재구축 후 앞 장 번호가 맞지 않으면 스크립트의 설명·두 선택지를 전달하고 첫 번째를 권합니다.

장 식별 불가:
‘원문에서 “第1章”·“楔子” 같은 장 제목을 알아보지 못했습니다. 원문 시작 부분의 서식을 확인해 주실 수 있나요?’

옛 분석과 이번 장 번호 불일치:
스크립트의 설명·선택지를 전달해 결정받습니다. 서장이 있으면 세 선택지 중 ‘옛 번호로 계속’을, 없으면 두 선택지 중 ‘새 디렉터리 사용’을 권합니다.

소재 결정 필드 누락:
‘소재선정.md에 「能爆的原因」이 없어 이번에는 결과를 반영하지 않습니다. 반영하려면 장편 순위 조사에서 소재 결정을 다시 한 뒤 돌아오세요.’

관계도의 중국어 렌더링 불가:
‘{스크립트가 반환한 이유 그대로: 이미지 생성 불가 / 중국어 글꼴 없음 / 일부 글자 표시 불가}. 관계도 이미지는 만들지 못해 인물관계도/인물관계도.md로 저장했습니다. Markdown 미리보기 편집기로 열면 중국어를 볼 수 있습니다.’

문체 미생성:
‘문체 부분을 만들지 못했습니다: {원문 없음 / 표본 부족}. 다른 결과는 사용할 수 있습니다. {원문 보충 / 몇 장 추가 제공} 후 문체만 보완할 수 있습니다.’
```

## 작품분석보고서.md

전 작품의 읽기 시작점입니다. 저장된 줄거리·리듬·감정 모듈·인물·설정·문체만 종합합니다. 보고서를 쓰려고 원문 전체를 다시 읽거나 장별 요약을 복사하지 않습니다. 세부는 한 문장 결론 뒤 해당 파일을 안내합니다. 후속 단계가 읽으므로 원래 이름을 유지할 절: 「基本信息」(집필은 장르, 가져오기는 장르·목표 플랫폼), 「核心发现」「读者在追什么」「伏笔与冲突」(가져오기, 핵심 발견은 소재 결정 반영에도 사용), 「不建议模仿」(권 개요), 「写法技巧」「可借鉴套路」「文风一句话」(문체).

```markdown
# 拆文报告：{书名}

> 한 문장: {이 작품이 독자를 붙잡는 요소}.
> 분석 범위: 총 {총 장 수}장, 약 {총 글자 수}만 자. {전체 완료 / 제{x}–{y}장 실패: {이유}}.

## 基本信息

书名：{书名}
题材：{장르}
总章数：{총 장 수}
总字数：{총 글자 수} 万
目标平台：{원작 플랫폼, 알 수 없으면 빈칸}

## 核心发现

재미의 이유 3-5개. 각각 ‘발견 + 확인할 장 + 작가의 활용법’으로 씁니다.

## 黄金三章评分

빠른미리보기.md의 다섯 평가 항목을 유지하고 「为什么这么打」에 쉬운 이유 한 문장을 씁니다.

## 读者在追什么

독자가 가장 보고 싶은 것 1-3개, 매번 충족하는 방식, 충족 후에도 계속 읽고 싶은 이유. 감정 유형 상세는 플롯/감정모듈.md 참조.

## 故事怎么推进

주선·주요 지선을 각각 한 문장으로 씁니다. 큰 구간마다 ‘주인공의 욕구 → 장애물 → 자신·타인·우연 중 극복 방식 → 획득·대가 → 다음 구간의 무엇을 여는지’를 정리합니다. 장 범위를 표시하고 세부는 플롯/의 각 줄거리 파일 참조.

## 人物与关系

주인공·주요 상대·핵심 조연마다 누구인지·욕구·역할을 한두 문장으로 씁니다. 기능 인물은 이름·비중만 나열합니다.
관계도는 인물관계도/인물관계도.md 참조. 이미지가 있으면 인물관계도/核心人物关系.png를 여기에 삽입합니다.
핵심 관계 변화는 ‘갑 → 을: …에서 …로(몇 장, 이유 …)’로 개별 기재합니다. 갑의 보호·을의 의존처럼 방향이 다르면 분리합니다.

## 读者知道的和角色知道的

핵심 비밀·진실 몇 개를 골라 실제 발생 장·독자가 안 장·주요 인물이 안 장, 그 차이가 만드는 궁금증·통쾌함을 씁니다. 플롯/리듬.md 참조.

## 节奏

- 사건 진행: 빠른 구간·준비 구간·전환의 장.
- 독자 감정: 정점의 장·저점이 이어진 길이·회복 방식.
- 서술 분량: 크게 다룬 장면·짧게 넘긴 장면과 그 효과.

### 爽点密度

약 {몇 장 / 몇만 자}마다 뚜렷한 통쾌함 한 번, {높음 / 적당 / 낮음}. 가장 긴 공백은 제{x}–{y}장이며 작가는 {요소}로 지탱합니다.

## 伏笔与冲突
```
