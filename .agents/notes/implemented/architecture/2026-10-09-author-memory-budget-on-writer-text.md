# Agent Note: 작가 메모리 예산을 집필자가 실제 읽는 행으로 측정하고 누락은 작가의 원래 표현으로 안내

Status: implemented
Date: 2026-10-09
Related: [읽기 잘림 대신 쓰기 사전 경고](../bug-fix/2026-09-18-author-memory-query-budget.md), [v0.8 집필 절차 간소화](2026-09-24-v0-8-lean-writing-loop.md), [작가 메모리 시점별 분리](2026-09-26-author-memory-by-moment.md); 하위 프로젝트 zenstory-ai/oh-story-dsh#61

## Problem

dsh#61: 기록한 집필 습관 일부만 본문 집필에 전달되며 해당 책에서는 항상 아홉 항목이 빠지고 장 종료 때도 알려 주지 않았다. 적용 습관 19–22개로 세 경로를 로컬 재현하니 모두 정확히 아홉 개가 빠졌다.

- 2048바이트는 #368이 정하고 #429가 유지한 주의력 예산으로 “query 출력을 그대로 프롬프트에 붙임”이 전제였다. v0.8.0부터 장편은 조립 스크립트가 대신 조회하여 “- 단언(번호)”만 집필자 프롬프트에 렌더링하고 id·kind·scope·JSON 따옴표·구분자는 제외한다. 그러나 예산은 항목당 약 100바이트 고정 비용의 JSON 포장을 계속 재어 실제 집필자 읽기량은 2048의 35–46%뿐이었다. 40자 단언은 8개, 20자는 11개부터 누락됐다.
- 누락은 주 세션용 확인 보고에만 있고 단일 장·일일 종료 작가 템플릿에는 해당 행이 없었다. “다른 내부 결과는 작가에게 말하지 않음”이라는 문구도 있었다. 20개 초과 누락은 조립 스크립트가 상한 처리된 번호 목록만 세어 적게 보고했다.
- 프로토콜은 “몇 가지를 챙기지 못할 수도 있음”이라고 했지만 스크립트 응답은 “프롬프트에 들어가지 않음”이었다. 작가에게 실제보다 모호하게 말했다.

## Decision

- `query`에 `lines`를 추가한다. 각 행의 “- 단언(번호)”가 실행자에게 전달할 원문이다. 2048 값은 유지하되 줄바꿈을 포함한 `lines`를 측정한다. `items`, 누락 목록, `book_revision` 등은 주 세션·스크립트 판단용으로 예산에서 제외한다. 쓰기 최악 추정의 부분집합 무게와 실제 적재는 같은 행별 함수로 측정하며 “경고 없음 ⟹ 실제 조회 누락 없음” 속성 검사를 계속 전수 실행한다.
- 누락은 프롬프트에 들어가지 않으므로 `omitted_ids`의 20개 상한을 없애 후보 우선순위대로 전부 나열한다. `omitted_summaries`는 번호→단언 첫 문장(14자로 자름)으로 작가에게 원래 표현을 알려 주게 한다. `omitted_importance`는 번호→중요도로 여러 조회 병합 후 재정렬에 쓴다.
- 조립 스크립트는 `lines`를 그대로 붙인다. 여러 장르·절차별 조회에서 한쪽은 빠져도 다른 쪽에 들어오면 누락으로 세지 않는다. 중요도순으로 재정렬하고 같은 중요도는 순서를 유지한다. 못 담은 항목이 있으면 확인 보고에 모든 번호를 나열하고 작가 안내 문장을 조립한다. 최대 8개를 지목하고 나머지는 “등”으로 묶으며 전체 목록은 “작가 메모리 정리”로 안내한다. 스크립트 조회 실패나 범위 한정으로 주 세션의 보충 조회가 필요하면 그 결과의 누락도 장 종료 때 원래 표현으로 알리라고 보고한다. 단일 장·일일 종료 템플릿에는 조건부 한 줄을 추가한다. 누락이 있으면 원래 표현을 알리고 없으면 줄을 지운다. 단일 장은 확인 보고가 조립한 문장을 그대로 쓰도록 명시한다.
- 각 진입점의 “전체 출력 ≤2KB”를 “실행자에게는 `lines` 전달”로 바꾼다. 장편·단편·AI 문체 제거·원고 검토 진입점과 집필자 프롬프트의 작가 선호 칸을 함께 바꾼다. 단편은 전달 때 누락을 원래 표현으로 알리게 한다. 스크립트 불가 시 수동 조립도 맞추고 현재 책 장르·장편 절차에 한정된 항목은 `--genre`／`--workflow`로 각각 조회해 병합·중복 제거하도록 한다. `author-memory.md`는 실제 조회 누락을 “본문 집필 때 이 항목은 전달되지 않음”, 쓰기 최악 추정(전역＋가장 무거운 장르·절차 부분집합＋현재 책) 경고를 “전달되지 않을 수 있음”으로 구분한다. 저장소의 호스트 중국어·영어 안내 원문과 스크립트 색인도 “출력 절대 상한 2KB” 대신 “집필자에게 주는 습관 원문은 조회당 2KB 이하”로 쓴다.
- 용량(2048바이트, 행당 고정 비용 14바이트): 40자 단언 8 → 15개, 20자 단언 11 → 27개.
- 파일·경로 예산은 올리지 않는다. 일일 종료 템플릿 한 줄은 도입부의 중복 “한 번에 최대 3장”을 삭제해 확보하며 Step 2 상한·검사 기준은 유지한다. 단편 진입점도 문구를 다듬어 공간을 확보한다.

## Alternatives considered

- **프로젝트별 용량 설정(dsh#61 초안)**: 작가가 필요한 양을 알고 책이 커지면 조정할 수 있다. 그러나 집필자의 주의력 배분을 판단할 근거 없는 작가에게 맡기며 설정 진입점·쓰기 경고·실제 조회의 공유 설정·호스트 호환 비용이 든다. 측정 대상을 바꾸면 보고자 규모의 라이브러리는 이미 다 담긴다.
- **못 담으면 조립 중단(dsh#61 초안)**: 조용히 쓰기 시작하지 않는다. 그러나 용량이 늘지 않아 초과 뒤 매 장 멈추고 유효한 습관을 지우게 강요한다. 낮은 우선순위 성향인 메모리 때문에 작업을 중단하지 않는 원칙과도 충돌한다. 장 종료에서 원문으로 지목하면 숨기지 않을 수 있다.
- **4096으로 직접 확대**: 상수 하나면 된다. 그러나 집필자가 읽는 양 자체를 늘려 #429 결정을 뒤집는다. 행별 측정만으로 같은 2048에 약 두 배가 담기므로 먼저 충분한지 본다.
- **본문 조회에만 행별 측정 옵션 추가**: 변경이 작고 AI 문체 제거·검토 출력이 유지된다. 그러나 같은 kind(문체＋이야기 설계)를 수정 경로도 조회하고 쓰기 경고는 한 기준으로 추정해야 한다. 두 기준은 “경고 없으면 누락 없음”을 깨뜨린다. 모든 실행자에게 렌더링된 원문을 주는 통일 방식이 더 간단하다.
- **JSON 포장 압축(#429 후속 과제)**: 약 15줄 변경으로 모든 경로가 이득을 본다. 그러나 포장은 이제 예산에 포함하지 않아 압축해도 용량이 늘지 않는다. 이것만 하면 보고자 규모에서는 여전히 빠진다.
- **이번 장 관련성으로 항목 선택**: 주의력을 더 절약한다. 그러나 매 장 누락이 예측 불가능해 #429의 예측·확인 가능 원칙에 어긋나고 state 버전·매칭 구현도 필요하다.

## Consequences

- 이점: 같은 2048바이트로 습관이 약 두 배 전달되어 보고자 규모는 거의 전부 담긴다. 누락하면 주 세션만 아는 대신 작가도 장 종료에서 구체 항목을 듣는다. 20개 넘는 누락도 정확히 센다.
- 비용: 집필자 선호 블록이 기존 약 300자에서 최대 약 680자로 늘며 본문 품질·선호 준수 영향 데이터는 없다. 주 세션 JSON은 `items`·`lines` 중복과 누락 상한 제거로 최악 수 KB 커지지만 주 세션에만 들어간다. 메모리가 많은 책은 작가가 정리할 때까지 같은 문장을 매 장 반복한다.
- 유지한 동작: 여러 장르이면 조립 스크립트가 “장르 × 절차”를 각각 조회·병합해 합친 주입량은 여전히 2048바이트를 넘을 수 있다. v0.8.0부터의 동작이다. 조회당 용량이 두 배여서 초과 절대량도 커진다. 병합 뒤 다시 자르면 쓰기 경고가 예측하지 못한 누락이 생기므로 자르지 않는다. 문서에는 “단일 조회 ≤2048바이트”라고 쓴다.
- 검사: 단일 장·일일 종료 조건부 행과 단편 진입 문장을 작가 메모리 주입 계약 테스트로 고정한다. 다중 장르 병합의 누적·중복 제거·중요도 정렬·8개 미만에 “등” 미추가, 정확히 2048 경계, 적지만 긴 항목과 많지만 짧은 항목의 무게를 회귀 검사하고 각각 변이 검증했다.
