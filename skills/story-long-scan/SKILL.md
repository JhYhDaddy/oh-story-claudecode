# story-long-scan: 장편 웹소설 순위 조사

장편 순위의 반복 표본에서 소재 후보를 찾고 작가의 조건과 함께 실현 가능성, 실패 위험, 검증 행동을 제시합니다.

**핵심 원칙: 한 작품의 순위는 단서이며, 최근 여러 순위·여러 작품에서 반복되는 패턴이 있어야 추세를 판단할 수 있습니다.**

---

## 순위 조사 원칙

### 원칙 1: 순위만 보지 말고 패턴을 봅니다

표본에서 반복되는 소재, 설정, 전형, 제목 단어, 소개문의 매력을 추출하여 추세 후보를 뒷받침할 수 있는지 판단합니다.

### 원칙 2: 플랫폼마다 인기도 지표가 다릅니다

판치에는 현재 읽는 독자 수, 치뎬은 유료 순위와 총 추천, 진장은 즐겨찾기·영양액·점수, 치마오는 인기도를 봅니다. 완독률, 연재 추적 독자 수, 구독 전환은 작가 관리 화면의 데이터라 수집 스크립트로 얻을 수 없습니다. 작가가 제공하지 않으면 결론을 내리지 않습니다.

### 원칙 3: 작가가 쓸 수 있는 흥행 소재를 찾는 것이 목적입니다

각 방향의 보유 자료, 소재 경계, 계획 분량, 목표 플랫폼 표본을 함께 고려해 실현 가능성을 판단하고 소재를 제안합니다.

---

## 순위 조사 절차

### Phase 1: 플랫폼과 방향 확인

작가가 이미 제시한 조건을 사용하며 빠진 정보는 선택지를 주어 한 번에 묻습니다.

- 플랫폼: 치뎬 / 판치에 / 진장 / 치마오 / 츠웨이마오 / 여러 플랫폼 비교
- 채널(판치에·치마오만 구분): 남성향 / 여성향 / 모두
- 조사 대상: 떠오르는 신작(신작 표본을 더 수집) / 성숙한 전체 시장(기본 순위만 수집)
- 관심 있는 소재 방향(없으면 전체 순위 개관)

---

### Phase 2: 데이터 출처 결정

| 우선순위 | 모드 | 설명 | 사용 시점 |
|--------|------|------|--------|
| 1 | **스크립트 수집** | 플랫폼 페이지 데이터를 직접 수집해 구조화된 순위 파일 생성 | 우선 사용; 치뎬 순위에는 Chrome이 필요 없음 |
| 2 | **작가 제공** | 작가가 붙여 넣은 순위 텍스트·스크린샷 또는 기존 순위 파일 | 작가가 데이터가 있거나 스크립트 수집이 불가할 때 |
| 3 | **내장 지식** | 과거 소재 후보만으로 분석 | 인터넷 연결이 불가하고 작가도 데이터가 없을 때 |

#### 스크립트 수집 모드

명령의 `scripts/`는 이 스킬의 루트를 기준으로 합니다.

1. 매 조사마다 작업 디렉터리에 `순위조사/{YYYYMMDD}/`를 새로 만듭니다(같은 날 다시 조사하면 `-2` 추가). 아래 `{outdir}`는 이 디렉터리입니다. 이전 디렉터리에 추가하면 집계에 과거 순위가 섞이므로 추가하지 않습니다.
2. 선택한 플랫폼 참고 자료만 읽습니다: [치뎬](references/platform-qidian.md) / [판치에](references/platform-fanqie.md) / [치마오](references/platform-qimao.md) / [진장](references/platform-jjwxc.md) / [츠웨이마오](references/platform-ciweimao.md). Phase 1의 채널·조사 대상에 맞춰 기본 명령을 실행합니다. Chrome이 필요한 플랫폼은 먼저 `/browser-cdp`로 시작합니다.
3. 집계: `node scripts/aggregate-rank.js {outdir} --out {outdir}/순위조사집계.md`. **주 세션은 우선 집계 파일만 읽습니다.** 소재 분포, 중복 제거 작품 수, 인기도·글자 수 중앙값, 태그, 제목 단어, 여러 순위의 중복, 대표작을 확인합니다.
4. 집계의 `采集情况`(수집 상황)를 봅니다. 문제가 표시된 순위(제목 해석 실패, 수집 실패, 도서 목록만 있음, 상세 정보 미수집)는 플랫폼 자료의 “수집이 안 될 때”에 따라 조사한 뒤 다시 수집합니다. 재수집이 불가하면 보고에 해당 순위를 결론에서 제외했다고 씁니다.
5. 새로운 인물 설정, 진입 설정, 에피소드를 분석할 때 필요에 따라 표본을 뽑습니다: `node scripts/aggregate-rank.js {outdir} --sample {题材/标签/书名词} --n 5`. 한 번에 한 방향만 조사합니다. 검색 건수에는 여러 순위의 중복이 포함되므로 표본 작품 수는 같은 플랫폼의 제목+작가 기준으로 중복 제거합니다.

#### 작가 제공

기존 순위 파일은 `{outdir}`에 넣어 집계합니다. 작가가 링크를 주면 페이지 내용을 복사하거나 스크린샷으로 제공하도록 요청합니다(판치에·치뎬은 수집 방지가 있어 직접 페이지를 수집해도 자주 실패함). 텍스트·스크린샷은 다음 형식으로 정리합니다. 첫 줄은 `# {平台} · {榜单名}`이며 플랫폼 이름은 起点 / 番茄 / 晋江 / 七猫 / 刺猬猫만 사용해야 스크립트 데이터와 합칠 수 있습니다. 작품마다 `### #{排名} {书名}` 한 단락을 만들고 다음 줄에 `*作者 · 题材 · 连载中 · 120万字 · 3.5万收藏*`를 씁니다(작가·소재·연재 상태·글자 수·즐겨찾기 수의 예시). 인기도는 “숫자+지표”로 쓰고 태그가 있으면 `**标签：** a、b`를 추가합니다. `{outdir}`에 저장한 뒤 같은 방식으로 집계합니다.

#### 내장 지식

[references/genre-trends.md](references/genre-trends.md)를 읽고 보고 첫머리에 “다음 분석은 과거 소재 후보를 바탕으로 하며 실시간 순위 검증이 없어 검증할 가설로만 사용할 수 있습니다”라고 명시합니다. 다시 조사해야 할 순위도 나열합니다.

### Phase 3: 데이터 분석

집계 결과를 중심으로 선택한 플랫폼 자료의 “분석 차원”부터 보고 다음 공통 차원을 확인합니다.

1. **소재 분포**: 작품 수, 비율, 인기도 중앙값. 판치에는 소재별 동일 수량을 표집하며 집계에 표시됩니다. 작품 수는 표집 상한이므로 소재 인기도는 인기도 중앙값과 플랫폼 P75로 판단합니다.
2. **새 소재 신호**: 신작 순위, 서고 신작 표본, 여러 순위의 중복을 봅니다. 신작 순위와 다른 순위를 함께 수집했을 때만 집계에 `新书榜`(신작 순위) 열이 나타납니다. 이전 날짜 디렉터리에 `순위조사집계.md`가 있으면 같은 플랫폼·순위·필터 범위로 비교합니다.
3. **상위권 기존 작품**: 월표·베스트셀러·읽기 순위에서 수백만 자에 이르고 수년 연재한 책은 해당 소재의 기존 독자를 나타냅니다. 지금 신작을 시작해도 성공한다는 뜻은 아닙니다. 새 방향은 신작 순위·서고 신작 중심으로 판단합니다.
4. **기존 소재의 변화**: 상승·안정·하락 여부. 이전 데이터가 없으면 현재 상태만 씁니다.
5. **글자 수**: 분포와 소재별 글자 수 중앙값.
6. **제목 패턴**: 제목의 빈출 단어와 대표작 제목.
7. **소개문의 매력**: 인기 태그와 대표작 소개문. 데이터는 소개문뿐입니다(집계는 30자, 수집은 100자로 잘림). 도입부 작성법은 작품 분석으로 검증합니다.
8. **새 요소**: 후보 방향의 원본 항목을 표집하여 새로운 인물 설정, 진입 설정, 에피소드 전형을 표시합니다.

### Phase 4: 순위 조사 보고 작성

이번 표본이 뒷받침하는 결론과 작가가 쓸 수 있는 방향을 설명합니다. 비교 가능한 이전 자료가 없으면 추세란은 “비교하지 않음”으로 쓰고 상승·하락을 채우지 않습니다. 스크립트명, 명령, 수집 상태는 보고에 넣지 않습니다. 빠진 순위는 “XX 순위는 이번에 얻지 못해(이유) 결론에 포함하지 않았습니다”라고 설명합니다. 소재 인기 순위는 인기도 중앙값 내림차순이며 숫자가 없는 플랫폼은 작품 수 순입니다. 전체 플랫폼과의 비교는 “플랫폼 전체 작품의 4분의 3보다 인기가 높음”처럼 쉽게 쓰고 P75라고 쓰지 않습니다.

보고를 작가에게 보여 주면서 `{outdir}/소재선정.md`에도 저장합니다. 파일이 없으면 먼저 [references/topic-decision.md](references/topic-decision.md)의 템플릿으로 파일 머리말을 만든 뒤 `扫榜结论`(순위 조사 결론) 절에 보고를 씁니다. 같은 이름의 절이 있으면 전체 절을 교체합니다. 작가가 소재를 고르지 않고 순위만 조사하더라도 결론은 저장돼 있어야 합니다. 아래 `扫榜结论` 절 표식은 후속 읽기를 위해 유지합니다.

**파일에서 이어가기:** 먼저 `{outdir}/소재선정.md`의 `扫榜结论` 절과 `순위조사집계.md`를 읽고 대화 기억에 의존하지 않습니다. 둘 다 없으면 Phase 2로 돌아갑니다.
