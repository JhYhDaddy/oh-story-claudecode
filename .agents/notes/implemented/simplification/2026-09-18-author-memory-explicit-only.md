# Agent Note: 작가 기억은 명시적인 표현만 수집하고 추론 기반 쓰기 경로를 제거한다

Status: implemented
Date: 2026-09-18
Issue: #436(#429 검토 논의에서 나온 확장안 B)
Related: [2026-09-18-author-memory-two-level-store](../architecture/2026-09-18-author-memory-two-level-store.md)

## Problem

기존 수집 표에는 에이전트가 능동적으로 추론해 기록하는 두 경로가 있었다. `repeated_correction`은 같은 수정이 반복되지만 작가가 장기 규칙이라고 말하지 않은 경우이고, `inferred_pattern`은 완성 원고나 작업 이력에서 패턴을 추론한 경우다. 이를 `pending`으로 기록해 확인 대기 목록에 넣었다. 실제 사용에서는 작가가 명확하게 요청할 때만 선호를 기록했다. 추론 경로의 실질적인 산출물은 기억 품질 향상이 아니라 확인 대기 목록을 검토하는 부담이었다. 문서에는 전체 메시지 hook을 설치하지 않는다고도 명시되어 있으므로 암묵적 수집은 애초에 완전성을 보장할 수 없다. 어설프게 관찰하기보다 관찰하지 않는 편이 낫다. 이는 #412의 '일시적 요구를 장기 기억에 기록하지 않는다'는 방향과도 같다.

제품 차원의 판단은 '작가가 말하지 않았는데도 도구가 작가를 관찰해야 하는가'이다. 답은 아니오다.

## Decision

1. 모든 신규 쓰기의 진입점인 `normalize_preference`는 `WRITE_SOURCES = ("explicit_user", "accepted_suggestion", "manual")`만 받는다. `repeated_correction` / `inferred_pattern`을 전달하면 즉시 오류를 내고 대안을 안내한다. 작가의 말에서 적용 범위가 모호하면 `explicit_user`와 `status=pending`을 사용한다. 기존 '추론 출처는 반드시 pending이어야 한다'는 검사도 제거한다.
2. `SOURCES` 열거형에는 두 값을 남긴다. 기존 state가 `validate_state`를 통과하고 `decide` / `forget`을 계속 사용할 수 있게 하기 위해서다. state를 읽는 `normalize_item`은 계속 `SOURCES`로 검증한다.
3. 수집 표에서 두 행을 삭제하고, '작가의 말이 장기 선호처럼 보이지만 범위나 안정성이 모호함 → `pending`, 확인 대기의 유일한 출처'와 '같은 수정의 반복이나 완성 원고에서 발견한 패턴 → 기록하지 않고 추론하지 않음'으로 바꾼다. 충돌 후보와 모호한 범위 처리에 필요하므로 `pending` / `decide`는 유지한다.
4. story / story-review / story-deslop의 SKILL.md 세 곳에서 '반복 수정/추론은 우선 확인 대기'라는 문장을 '작가가 명확히 말한 것만 기록하고 반복 수정에서 추론하지 않는다'로 바꾼다. docs/architecture의 확인 대기 설명도 맞춘다. 회귀 테스트는 참조 사본 다섯 개와 SKILL 세 개에 두 출처명이 더 이상 나오지 않는지 검사한다.

## Alternatives considered

**문서만 바꾸고 도구는 두 출처를 계속 허용한다.** 변경 범위가 가장 작고 이슈 원문도 '문서에서 더 이상 사용을 유도하지 않는다'고만 요구했다. 채택하지 않았다. 제품 판단이 '관찰하지 않는다'라면 도구가 이를 보장해야 한다. 에이전트는 지시에서 벗어날 수 있으며, 문서가 유도하지 않는다고 실제로 기록하지 않는 것은 아니다. 쓰기를 거부해야 결정을 실행하고 테스트할 수 있다. 기존 자료 호환은 읽기 쪽에 열거형을 남기는 것으로 충분하다.

**`SOURCES` 열거형에서도 삭제한다.** 가장 철저한 방법이다. 채택하지 않았다. 기존 저장소에 이미 이런 항목이 있어 열거형을 지우면 `validate_state`가 바로 실패하고 작업 공간 전체의 기억을 사용할 수 없게 된다. 열거형 값 두 개를 더 유지하는 것보다 훨씬 나쁘다.

**`pending` 상태를 삭제한다.** 추론 경로가 사라지면 확인 대기 목록에는 충돌 후보만 남는 것처럼 보인다. 채택하지 않았다. '작가의 말에서 범위는 모호하지만 지속적인 선호일 수 있는 내용'에는 prompt에 넣지 않고 임시 보관할 자리가 여전히 필요하다. 충돌 후보도 같은 장치에 의존한다. `decide` 확인 절차는 작가가 결정권을 가진다는 원칙을 구현한다.

## Consequences

- 확인 대기 목록은 작가의 말로만 늘어난다. 검토 부담이 작가의 표현량에 비례하며 에이전트의 관찰로 채워지지 않는다.
- 호환성을 깨는 변경: 신규 쓰기에 이전 출처를 전달하면 바로 실패한다. 저장소 내부에는 두 출처를 생성하는 호출 지점이 없다. 사용자 프로젝트에 배포한 스킬 사본은 `/story-setup` 재실행 후 스크립트와 문서 버전이 일치한다. CHANGELOG의 `Changed`에 기록한다.
- 기존 항목의 `source`에는 이전 값이 계속 표시된다. `作者画像.md`는 source를 렌더링하지 않으므로 작가가 보는 화면에는 영향이 없다.
- '작가가 말한 적은 없지만 행동은 일관된' 선호를 자동 발견할 가능성을 포기한다. 이번 판단에 따르면 이것은 애초에 도구가 작가 대신 결정할 일이 아니다.
