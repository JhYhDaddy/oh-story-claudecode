# Agent Note: 단일 책 배치에서 책 저장소를 하위 폴더로 옮기고 쓰기 후 다른 계층 읽기 실패는 경고 처리

Status: implemented
Date: 2026-09-24
Related: [2026-09-18-author-memory-two-level-store](../architecture/2026-09-18-author-memory-two-level-store.md), [2026-09-18-author-memory-query-budget](2026-09-18-author-memory-query-budget.md)

## Problem

두 계층 저장소(#435)는 기본적으로 프로젝트 `{工作区}/.story/作者记忆/`, 책 `{书}/.story/作者记忆/`다. `正文/`, `大纲/`, `追踪/`이 작업 공간 루트에 있는 단일 책 배치(story-setup 진단·hook 책 루트 탐색에서 지원)는 책 루트가 작업 공간이라 같은 `_author-memory-state.json`에 겹친다.

1. v0.7.10 데이터가 있으면 `--book-root`가 작업 공간인 `query` / `migrate` / 책 계층 `record`가 프로젝트 state를 책으로 검사해 `state.book must be a string`으로 실패하고 전역 취향도 못 읽는다.
2. 새 공간에서 첫 책 `record`가 같은 파일에 책 state를 쓰면 이후 모든 `query`·프로젝트 쓰기가 `project-level state must not carry state.book`으로 실패하며 복구 방법이 없다. 실제 대화에서는 모델이 설치 스크립트를 임의 수정해 우회했다.

같은 경로에는 더 위험한 문제가 있다. `record` / `commit`이 저장 후 `visible_states`로 다른 계층을 읽어 예산을 추산한다. `--book-root` 부재·`--book` 불일치·state 손상으로 읽기 실패 시 이미 저장했는데 `ok:false`·종료 2를 반환한다. 에이전트가 기억하지 못했다고 말하고 다른 `event_id`로 재시도하면 중복 항목이 생긴다.

경로만 보면 여러 책 공간도 오판한다. 책 폴더도 `.story/作者记忆/`가 있어 이를 가진 가장 가까운 조상을 우선하는 옛 규칙이 `--workspace 长篇/甲书 --book-root 长篇/甲书`로 유도한다. 단일 책으로 처리하면 정상 책 state를 `书级/`로 옮기고 빈 프로젝트 state를 원위치에 써 올바른 호출까지 `state.book must be a string`으로 실패한다.

## Decision

1. **책 루트=작업 공간이면 하위 저장소**: `{工作区}/.story/作者记忆/书级/`와 상수 `SINGLE_ROOT_BOOK_DIR`를 쓴다. `--book-root`·`--workspace`가 모두 존재하면 `os.path.samefile`로 비교(대소문자 비구분 APFS의 `…/Book`·`…/book` 포함), 아니면 resolve 경로를 비교한다. state·파생 뷰·개정 이력은 계속 둘이며 `AP` / `BP` 경로·검사·검색 병합·`migrate`는 재사용한다. `book_memory_root` 위치만 바꾼다.
2. **책을 작업 공간으로 잘못 전달하면 무쓰기 거부**: `is_single_root`는 먼저 `enclosing_workspace`로 실제 창작 공간을 찾는다. 부모 이름이 `长篇` / `短篇`, 조상에 `.active-book`, 또는 조상에 `book` 없는 프로젝트 state 중 하나면 오류로 파일을 건드리지 않는다. 단, 현재 공간에 이미 프로젝트 state가 있으면 마지막 조건은 무시해 홈의 잘못 만든 저장소가 정상 공간을 막지 않게 한다. 자동 복구·`书级/` 위치·기본 책 이름 모두 이 판정을 거친다. `validate_state` 프로젝트 오류는 먼저 작업 공간 루트 전달을 안내하고 단일 책일 때만 `--book-root {工作区}` 자동 복구를 안내한다. `author-memory.md`는 가장 가까운 프로젝트 state 조상/창작 루트를 쓰고 책 폴더는 절대 `--workspace`로 삼지 않게 한다.
3. **기본 책 이름**: 단일 책의 책 state가 없고 `--book`도 없으면 기존 프로젝트 book 항목이 한 책만 가리킬 때 그 이름, 아니면 폴더명을 쓴다. 공간 폴더명은 책 이름과 다를 수 있어 그렇지 않으면 `migrate`가 기존 항목을 못 찾아 조용히 0개 이전한다.
4. **손상된 배치 자동 복구**: 모든 명령 진입의 `prepare_workspace`는 단일 책 프로젝트 위치의 state에 `state.book`이 있으면 책 규칙으로 전체 검사 후 `os.replace`로 `书级/`에 원자 이동한다. 책 뷰를 다시 만들고 프로젝트 위치에 빈 state를 써 낡은 뷰를 덮는다. 내용·개정은 유지한다. `query`도 수행해야 읽기 경로에서 복구된다. 양쪽 모두 책 state면 추측하지 않고 두 파일을 명시해 실패한다. `--book-root`가 없으면 `--book-root {工作区}`로 재실행하면 자동 정리된다고 오류에 적는다.
5. **쓰기 후 다른 계층 읽기 실패는 경고**: `visible_states`가 `AuthorMemoryError`를 잡아 `warnings` 첫 항목에 어느 저장소에 썼으며 다른 계층 실패로 이번 예산에서 빠졌다고 설명한다. 명령은 `ok:true`와 영수증을 반환한다. 문서는 영수증이 있으면 기억한 것이므로 `event_id`를 바꿔 재시도하지 않게 한다.
6. `author-memory.md`의 코드와 다른 저장소 간 최근 순서를 제출 시각으로 비교한다는 설명을 지운다. 같은 범위는 같은 저장소에 있으므로 그 개정 번호로 비교한다. 단일 책·쓰기 후 읽기 실패 설명을 추가하고 스크립트·문서 다섯 사본을 동기화한다.

## Alternatives considered

- **단일 state에 AP/BP를 함께 두고 scope·접두사 구분**: 물리적으로 하나이며 추가 폴더·프로필이 없다. 그러나 `book`, `next_item_number`, 개정, journal, `validate_state`의 접두사·scope, 뷰 제목, `migrate` 두 단계 제출은 저장소당 state 하나로 설계되어 십여 곳의 분기와 같은 state 이전의 실패 구간 멱등성 재설계가 필요하다. 하위 폴더는 불변식을 그대로 쓴다.
- **경로 중복 시 `book` 유무로 판정하는 실제 대화의 패치**: 두 줄이면 된다. 그러나 여전히 한 파일이라 먼저 쓴 계층이 차지하고 다른 계층은 쓸 곳이 없어 오류를 조용한 유실로 바꿀 뿐이다.
- **부모가 `长篇` / `短篇`인지로만 오전달 판정**: IO가 없고 홈의 잘못 만든 저장소도 무관하다. 그러나 `.active-book`은 다른 곳을 가리킬 수 있어 한 번 놓쳐도 책 state 이동 사고다. 다른 두 징후는 읽기 전용이다.
- **현재 프로젝트 state보다 조상의 state를 우선**: 규칙은 짧다. 그러나 가장 가까운 것은 현재 공간의 state이며 홈의 잘못 만든 저장소 하나가 아래 모든 정상 단일 책 공간을 막는다.
- **쓰기 전에 다른 계층을 읽고 실패하면 무쓰기 오류**: 썼는데 실패했다는 모순은 없다. 그러나 다른 계층은 예산용일 뿐 현재 쓰기와 무관하다. 잘못된 `--book-root` 때문에 전역 취향 기록을 막는 것은 무관한 오류로 작가 요청을 거부하는 것이다.
- **쓰기·`migrate`만 복구하고 `query`는 순수 읽기**: 읽기 전용 약속을 지킨다. 그러나 가장 먼저·자주 실행되는 `query`가 못 고치면 작가가 우연히 기억하라고 할 때까지 전역 취향을 못 읽는다. 내용은 그대로인 일회성 위치 정리다.

## Consequences

- 단일 책도 두 계층을 쓴다. v0.7.10 단일 루트는 `query`·책 `record`가 정상이고 `migrate`는 기존 책 이름으로 항목을 `书级/`에 옮긴다.
- 옛 버전이 잘못 쓴 공간은 다음 `--book-root {工作区}` 명령에서 항목 유실 없이 복구한다.
- 경로 기반이므로 같은 폴더를 단일 책 공간에서 여러 책의 책 폴더로 바꾸거나 반대로 하면 저장소 위치가 달라 수동 이동이 필요하다. 양쪽에 책 state가 있으면 수동 처리한다.
- 손상 단일 공간의 `query`는 한 번 저장하며 문서에 밝혔다.
- 다른 계층 읽기 실패 때 예산이 그 계층을 빠뜨릴 수 있으나 `warnings` 첫 항목이 설명하고 기억 실패로 오보고하지 않는다.
- 책 폴더 오전달은 무쓰기 오류이고 올바른 호출은 계속 된다. 다만 `长篇` / `短篇` 또는 `.active-book` 있는 폴더 아래의 단일 책 공간도 책으로 거부되어 여러 책 배치 인수를 써야 한다. 조상 state를 읽을 수 없으면 징후로 세지 않아 놓칠 수 있다.
- 유지한 제한: 기존 book 항목이 한 책이면 그 이름이 기본이다. 이번 항목은 다른 이름인데 `--book`이 없으면 범위·이름 불일치다. 이번 이름을 우선하면 `migrate`가 기존 항목을 못 찾아 0개 이전하므로 바꾸지 않았다. 오류는 `--book`으로 고치지만 조용한 유실은 안 된다.
- 테스트는 새 단일 저장소, v0.7.10 이전, 손상 복구, 다른 계층 읽기 실패, 책 오전달의 세 징후·무쓰기·올바른 후속 호출, 대소문자 다른 루트(비구분 파일시스템만)를 다룬다. 마지막 두 함수는 수정 전 실패했다.
