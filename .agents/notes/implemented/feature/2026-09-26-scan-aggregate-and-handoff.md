# Agent Note: 순위 조사 결과를 먼저 집계하고 결론을 파일로 저장해 집필에 인계

Status: implemented

## Problem

작가의 각 시점에 필요한 정보만 주입한다는 기준으로 두 순위 조사 스킬을 감사하여 낭비 세 곳과 연결 단절 하나를 발견했다.

- **원시 순위 전체가 주 세션에 들어감**: 판체는 기본 37장르, 장르당 약 20권으로 독서 순위 한 파일에 700개 넘는 항목이 있다. 작가·현재 독자 수·글자 수·태그·bookId·링크·약 100자 소개를 포함한다. 수집 형식대로 만든 같은 규모 예시는 약 18.6만 문자(공백 제외 16.7만)로 읽으면 10만 토큰을 넘고 남녀 채널·신작까지 더하면 몇 배가 된다. 실제 분석에는 분포와 대표작이 필요하고 도입 판매 포인트·새 인물 설정을 볼 때만 몇 작품의 원문이 필요하다.
- **플랫폼 세칙이 진입부에 상주**: story-long-scan SKILL.md에는 치뎬·판체·치마오·진장 URL 표·명령·수동 정리 규칙 약 3.4K자가 있고 `scan-output-format.md`는 다섯 플랫폼 필드·템플릿 3.6K를 모았다. 한 번에 플랫폼 하나만 고르며 정리·품질 표시는 이미 스크립트가 한다.
- **보고가 저장되지 않음**: 장편 Phase 4 보고는 대화에만 있어 Phase 5 소재 선택은 대화 기억에 의존한다. 다음 날 선택하면 결론을 잃는다. 단편 결과는 전부 미저장이고 story-short-write도 읽지 않는다.
- **단편 질문과 스크립트 불일치**: Phase 1은 즈후 옌옌/판체 단편/치마오 단편을 묻지만 스크립트는 뎬중·헤이옌만 지원해 선택한 뒤에야 수집 불가를 알게 된다.

## Decision

- **결정적 집계 스크립트**: 의존성 없는 Node `skills/story-long-scan/scripts/aggregate-rank.js`를 만들고 `scripts/shared-assets.json`의 `scan-rank-aggregator`로 `skills/story-short-scan/scripts/`에 바이트 동일 동기화한다. 입력은 첫 줄 `# 平台 · 榜单名`, 항목 `### #排名 书名`, 메타정보 `*作者 · 题材 · …*` 형식의 순위 파일이다. `扫榜聚合.md`, `选题决策.md`, `短篇扫榜结论.md`와 일반 메모는 건너뛴다. 출력은 수집 상황(품질·문제 요약·제목 미해독 수·못 모은 장르), 플랫폼별 장르 표(권수·비율·신작 수·인기/글자 수 중앙값·빈출 태그·표본 충족), 인기·분량 분포, 태그·제목 빈출어, 다중 순위 겹침, 장르별 상위 대표작 세 권(소개 30자)이다. 같은 플랫폼에서 제목＋작가가 같으면 한 번만 세고 인기는 각 순위 최댓값을 쓴다. 기준은 판체 현재 독자, 치마오 인기, 진장 즐겨찾기, 치뎬 총 추천, 츠웨이마오 순위 값, 뎬중 점수를 자동 선택한다. 수동 표는 `2.3万收藏` 같은 숫자＋기준을 인식한다. `--out`은 저장과 stdout을 함께, `--sample {题材/标签/书名词} --n 5`는 원시 항목 조회, `--json`은 테스트·기계 읽기, `--sparse`는 표본 기준(기본 15, 소형 플랫폼 10)을 조절한다.
- **진입부에는 절차만**: 장편 Phase 2는 선택 플랫폼 참조 읽기, 같은 출력 디렉터리 저장, 집계 실행, 수집 상황 확인, 필요 시 표본 조회의 다섯 단계다. 세칙은 `references/platform-{qidian,fanqie,qimao,jjwxc,ciweimao}.md`로 나누어 URL·명령·필드·기본 조합·문제 해결·분석 관점을 담는다. `scan-output-format.md`는 삭제하고 내용을 다섯 파일로 분배한다. 단편도 `platform-dianzhong.md`, `platform-heiyan.md`, `manual-rank-input.md`(스크립트 없는 플랫폼에서 스크린샷·텍스트 요청, 집계 형식 정리, 옌옌 분석 관점)를 분리한다.
- **결론 저장**: 장편은 `选题决策.md`를 유지한다. Phase 4 보고를 보여 주면서 `{outdir}/选题决策.md`의 “조사 결론”에 저장하며 없으면 머리말부터 만든다. Phase 5는 그 절과 `扫榜聚合.md`를 읽은 뒤 추천 소재를 쓴다. 재실행은 절 전체를 교체한다. `topic-decision.md`에 집계 표 필드·조사 결론 절을 추가하고 추천 소재 필드는 유지한다. 조사만 하면 추천 소재 절이 없으며 story-long-write는 미선택으로 보고 일반 질문, story-long-analyze는 갱신 생략으로 처리한다. 단편은 `{outdir}/短篇扫榜结论.md`를 추가하고 `references/topic-match.md` 템플릿을 쓴다. 머리말은 조사일·재조사일·출처·집계 표, 조사 결론은 Phase 4 보고, 소재 매칭은 방향별 목표 감정·장르/설정·도입 훅·확산 엔진·복잡도·실현 가능성·분량/플랫폼·검증 행동이다. story-short-write Phase 1은 프로젝트 루트·상위에서 파일을 발견하면 소재 매칭을 먼저 읽고 첫 방향과 목표 감정을 후보로 물으며 재조사일이 지났으면 알린다.
- **플랫폼 선택 정렬**: 단편 Phase 1은 뎬중·헤이옌 수집 가능(헤이옌은 작가 관리 화면 로그인 선행), 즈후 옌옌·판체 단편·치마오 단편은 작가의 화면·텍스트 제공 필요를 바로 설명한다. 장편 Phase 1에는 기존 스크립트가 있는 치마오·츠웨이마오를 추가한다.
- **테스트**: `scripts/test-scan-aggregate.py`는 각 수집기의 렌더링 형식을 모방한 플랫폼별 픽스처와 수동 순위 하나를 공개 CLI로 처리해 파싱·중복 제거·기준·구간 분포·문제 표시·표본 조회·비순위 제외·압축률을 단언한다. Linux / Windows / macOS CI에서 실행한다.

## Alternatives considered

- **Python 집계기**: 저장소의 결정적 도구와 테스트 대부분이 Python이다. 그러나 두 조사 스킬은 Node만 요구하며 Python 호출에는 python3 → python → py 탐지가 필요하다. Node로 추가 런타임을 피한다.
- **수집기가 집계 표를 직접 출력**: 한 명령으로 짧은 표를 얻는다. 그러나 일곱 수집기에 로직이 복제되며 수동 표·플랫폼 비교·여러 표 중복 제거는 수집 뒤에만 가능하다. 원본도 표본·재집계를 위해 저장해야 한다.
- **`scan-output-format.md`를 플랫폼 총표로 유지하고 해당 절만 읽게 함**: 파일·변경 수가 작다. 그러나 모델은 참조 전체를 읽기 쉬워 절 제한이 약하다. 선택한 플랫폼 파일만 읽는 분리가 직접적이다.
- **장편 `扫榜报告.md` 별도 생성**: 보고와 소재 파일 책임이 분리된다. 그러나 새 책·분석 갱신은 이미 `选题决策.md` 발견·확인 절차가 있고 파일이 늘면 찾아 복사할 산출물도 늘어난다. 결론 절로 합치면 인계 파일이 하나다.
- **단편 결론을 소설 프로젝트에 직접 저장**: 집필자가 반드시 찾는다. 그러나 조사는 프로젝트 생성 전에도 하므로 장편처럼 조사 출력 디렉터리에 두고 집필자가 루트·상위에서 발견한다.

## Consequences

- 이점: 판체 전체 장르 독서 순위 740항목에서 주 세션 입력이 약 18.6만→1.3만 문자(공백 제외 16.7만→1.1만)로 줄었다. 실제 수집 형식의 같은 규모 예시 측정이며 표본 5개는 약 1.5K다. long-scan 진입부는 7807→4940자, short-scan은 4131→4095자이고 선택 플랫폼 참조 0.4K–1.4K를 추가로 읽는다. 결론·소재 파일로 다음 날·다른 세션에도 이어가며 단편 집필도 처음으로 조사 결론을 사용한다.
- 비용: 집계는 현재 Markdown 형식에 의존하므로 수집 출력 변경 시 집계·픽스처도 맞춰야 한다. 플랫폼별 인기 기준이 달라 장르 표를 분리하고 플랫폼 간 인기 비교는 하지 않는다. 원래 장편 보고의 갱신 빈도는 순위 데이터로 얻을 수 없어 제거하고 새 요소 추출 세 절은 세 행으로 합쳤다. 단편 집필은 결론 읽기 문장을 넣기 위해 핵심 방법에서 필수 읽기·Phase 2와 중복인 “비교 작품이 있으면 분석, 없으면 장르 참조”를 삭제하여 진입부가 순감 37자다.
- 동작 변화: 장편 Phase 4와 단편 Phase 4/5가 파일을 쓰고 단편 집필 Phase 1이 파일을 발견한다. 집계기는 입력을 읽기만 하며 `--out` 외에는 파일을 쓰지 않는다.
