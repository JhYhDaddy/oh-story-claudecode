# story: 웹소설 도구 모음 라우터

사용자의 집필 요구를 파악해 해당 스킬로 연결합니다.

**한국 시장 기본값**: 새 작품은 목적부터 확인한다. 직접 연재는 문피아·네이버 웹소설·노벨피아, 시장 조사는 네이버 시리즈·카카오페이지·리디도 후보, 단편·개인 발행은 포스타입을 먼저 제시한다. 특정 플랫폼은 자동 확정하지 않는다. 기존 목표와 작가의 명시적 선택을 우선하고 중국 플랫폼은 선택 기능으로 유지한다. 한국 작품에 중국 플랫폼의 분량·태그·유료 전환·평가 기준을 대신 적용하지 않는다.

## 라우팅 표

호스트별 호출 방식: Claude Code와 OpenCode는 `/story-*`(Claude 플러그인 설치 시 `/oh-story:story-*`) 또는 `Skill("story-*")`를 사용합니다. Codex와 ZCode는 `$story-*`(Codex는 `/skills`도 가능), OpenClaw는 `/skill story-*`를 사용합니다. Antigravity와 Reasonix는 스킬 진입점에서 선택하거나 자연어로 이름을 지정합니다. 아래 표는 `/story-*` 형식이며 다른 호스트에서는 이에 맞게 바꿉니다. 이 문서의 나머지 부분도 같습니다.

| 사용자 의도 | 키워드 예시 | 연결 대상 |
|---|---|---|
| 장편 기획 / 집필 | 장편 구조 논의, 줄거리 기획, 새 책 시작, 대강 작성, 세부 개요 보완, 장편, 연재 | `/story-long-write` |
| 게시 준비 | 게시 자료, 작품 등록 양식, 플랫폼 제목·소개·태그, 작품 등록 자료 | `/story-publish` |
| 단편 집필 | 단편, 포스타입, 단편 투고 | `/story-short-write` |

| 단편 순위 조사 | 단편 시장 조사, 포스타입 작품 조사 | `/story-short-scan` |

명확히 일치하면 해당 스킬을 바로 호출합니다. 일치하지 않으면 빠진 정보만 묻습니다. 사용자가 “소설을 쓰고 싶다”고만 하고 장편인지 단편인지 말하지 않으면 분량을 먼저 물은 뒤 연결합니다.

### 인수 없는 호출과 초보자

`/story`만 입력해 의도를 알 수 없으면 라우팅 표를 붙이지 않습니다. 쉬운 말로 네 가지를 제시합니다. “장편을 시작하거나 이어 쓰기” → `/story-long-write`, “단편 쓰기” → `/story-short-write`, “한 장의 AI 티 줄이기” → `/story-deslop`, “더 보기(작품 분석, 순위 조사, 기존 원고 가져오기, 원고 검토, 표지)” → 추가 항목 표시. 아직 배포한 적이 없으면(프로젝트 루트에 `.story-deployed` 없음) 먼저 `/story-setup`을 권하며, 배포 후 새 세션을 열어야 집필 보조 에이전트가 적용된다고 설명합니다.

작가가 플랫폼 작품 등록 자료(제목·소개·태그)를 명시적으로 요청하면 `/story-publish`로 연결합니다. 단순히 “책 시작”이라고 하면 평소처럼 장편 집필로 연결합니다. ClawHub에서 `story`만 설치한 경우 story-publish가 포함되지 않습니다. 찾을 수 없으면 작가에게 알리고 전체 스킬 패키지를 설치하도록 안내하며, 플랫폼 태그를 기억에 의존해 제시하지 않습니다.

### 가져오기와 이어 쓰기 순서

사용자가 “가져와서 이어 쓰려면 setup과 import 중 무엇이 먼저인가”라고 묻는다면 바로 답합니다. **먼저 `/story-setup`, 새 세션을 연 뒤 `/story-import`를 권합니다. 장편을 가져온 뒤 `/story-long-write 写第N章`(N은 가져온 원고 다음 장)으로 이어 쓰고, 단편은 `/story-short-write`에서 구상을 먼저 보완합니다.** 이미 `/story-import`를 직접 호출했다면 story-import 자체의 환경 검사로 계속합니다. setup이 안 되어 있으면 먼저 setup으로 갈지, 순차 가져오기를 계속할지 선택하게 합니다.

## 책 디렉터리 판별

이 문서의 “책 디렉터리”, “현재 책”은 다음 방식으로 찾습니다.

1. 프로젝트 루트에 `.active-book`이 있고 프로젝트 내부의 기존 디렉터리를 가리키면 그것을 사용합니다.
2. 그렇지 않으면 프로젝트 루트부터 최대 4단계 아래까지 찾습니다. `.`으로 시작하는 디렉터리, `node_modules`, `작품분석실/`, `비교작품/`는 제외합니다.
   - `추적/`, `본문/` 하위 디렉터리 또는 `본문.md` 파일을 포함한 디렉터리(집필 훅과 동일한 기준).
   - 방향만 정하고 아직 본문이 없는 장편: `설정/소재방향.md`가 있는 디렉터리.
   - 구상 중이며 아직 본문이 없는 단편: `설정.md`와 `구간개요.md`가 모두 있는 디렉터리.
   여러 권을 찾았는데 `.active-book`이 없으면 “현재 책”이 필요한 시점에 어느 책인지 작가에게 묻습니다(「여러 책 사이 전환」과 같은 방식).
3. 분량: `본문/` 또는 `설정/` 하위 디렉터리가 있으면 장편, `본문.md` 또는 `설정.md` 파일이 있으면 단편입니다.

책 디렉터리를 찾지 못한 경우: 집필 프로젝트를 만들려면 먼저 `/story-setup`을 실행합니다. 구조·소재를 논의하거나 순위 조사·작품 분석만 원하면 바로 연결합니다. 찾은 경우: 대상 스킬 자체의 환경 검사에 따라 계속하고, 초기화나 추가 배포가 필요하면 `/story-setup`을 실행합니다.

## 작가 습관 관리

사용자가 장편·단편을 명시했으면 해당 집필 스킬을 선택하고, 명시하지 않았으면 현재 책의 분량을 따릅니다. 현재 책이 없는 일반적인 습관은 `/story-long-write`가 관리합니다. 특정 책에 관한 요청인데 책을 찾지 못하면 어느 책인지 묻고 먼저 책을 만들도록 요구하지 않습니다. 라우팅 계층은 전달만 하며 작가 기억 파일을 읽거나 쓰지 않습니다.

## 조회

### 어떤 보조 에이전트에 무엇을 전달할지

“이야기 자료 조회”는 `story-explorer`에 전달하며 프롬프트는 세 줄입니다. 필드명은 호출 계약에 맞춰 유지합니다.

```text
项目目录：{책 디렉터리의 절대 경로}
查询类型：{아래 표에서 선택}
查询参数：{사용자가 물은 인물 이름, 복선, 설정 키워드 또는 장 범위}
```

| 사용자 질문 | 조회 유형 |
|---|---|
| 특정 인물의 현재 상태 | `character_status` |
| 특정 인물이 등장한 장 | `character_appearances` |
| 특정 복선의 상황 | `foreshadow_status` |
| 남은 복선, 아직 회수하지 않은 복선 | `foreshadow_list` |
| 특정 설정의 내용 | `setting_detail` |
| 특정 설정이 등장한 장 | `setting_appearances` |
| X장부터 Y장까지 일어난 일 | `timeline`(조회 매개변수의 기본값은 `perspective: reader`. 작가가 배후 진실을 명시적으로 물으면 `author`) |
| 어디까지 집필했는지 | `progress` |
| 두 인물의 현재 관계 | `relationship` |

한 문장에 여러 유형이 있으면 나누어 호출하거나 가장 중요한 유형 하나만 선택합니다. 기존 내용 조회가 아니라 창작 조언을 묻는다면 넘기지 않고 주 세션이 직접 답합니다.

“자료 조사”는 `story-researcher`에 전달합니다. 프롬프트는 아래와 같이 쓰고 값이 없는 선택 항목은 줄 전체를 생략합니다.

```text
query：{조사할 주제}
type：{선택: 역사 고증, 지리/환경, 직업 지식, 문화 관습, 기물/복식, 묘사 참고, 작명 참고, 체계 구성, 시·고사, 시각 참고, 실제 사례, 독자 선호}
context：{선택: 조사 이유, 예를 들어 현재 집필 중인 부분}
project_dir：{책 디렉터리의 절대 경로. 책 디렉터리가 없으면 프로젝트 루트}
cdp_port：{선택: Chrome 디버그 포트가 9222가 아니면 기재}
```

### 보조 에이전트 사용 가능 여부

> Spawn 버전 알림(spawn을 차단하지 않음): 먼저 프로젝트 루트 `.story-deployed`의 `agents_version`을 읽습니다. 이 버전의 `agents_version: 38`과 다르면(표식 없음, 필드 없음/정수 아님, 38보다 작거나 큼) **현재 호스트의 역할 출처를 평소처럼 확인하고 spawn합니다.** (계약 문구: `照常按当前宿主角色来源检查并 spawn`) 동시에 “자료 조사 보조 에이전트가 이전 버전입니다. /story-setup을 실행하고(ZCode는 플러그인을 먼저 업데이트) 새 세션을 열어 주세요”라고 쉽게 안내합니다. `Notice: agents bundle 版本不匹配（项目 {N}，本版 38）` 원문은 답변 마지막의 “技术备注：” 한 줄에 기록합니다. `大于 38 时额外提示先更新 oh-story-claudecode` — 38보다 크면 먼저 oh-story-claudecode를 업데이트하도록 덧붙이고, 오래된 로컬 setup으로 다운그레이드해 덮어쓰지 않습니다. `只有当前宿主角色缺失或不暴露调用能力时才降级 solo/direct` — 현재 호스트의 역할이 없거나 호출 기능이 노출되지 않을 때만 solo/direct로 전환합니다. `Fallback: ... -> solo`도 `技术备注`(기술 참고) 줄에만 넣습니다.

보조 에이전트를 쓰기 전에 해당 호스트의 가용성만 확인합니다. 현재 하위 에이전트 안이 아니며 호스트 호출 도구가 있고 해당 역할을 사용할 수 있으면 spawn을 시도할 수 있습니다. 역할 위치: Claude `.claude/agents/*.md`, OpenCode `.opencode/agents/*.md`, Codex `.codex/agents/*.toml`, Antigravity `.agents/agents/agent-name/agent.md`. ZCode는 플러그인에 등록된 동명 역할을 확인하며 `.zcode/agents`를 요구하지 않습니다. Antigravity는 `invoke_subagent`와 동명 `TypeName`, ZCode는 실제 스키마에 맞춰 `Agent`로 전달합니다. 다른 호스트의 기준으로 잘못 판정하지 않습니다. 하나라도 충족하지 않거나 unknown agent가 반환되면 다음과 같이 대체합니다.

- `story-explorer` 사용 불가 → 주 세션이 Read/Grep으로 책 디렉터리의 인물 상태, 복선, 진행 상황, 설정을 직접 찾습니다. 답변 전에 “자료 조회 보조 에이전트가 활성화되지 않아 이번에는 프로젝트 파일을 직접 살펴보겠습니다”라고 알립니다. 프로젝트가 아직 배포되지 않았으면 먼저 `/story-setup`을 안내합니다.
- `story-researcher` 사용 불가 → 주 세션이 현재 사용 가능한 검색 기능으로 답합니다. 답변 전에 “자료 조사 보조 에이전트가 활성화되지 않아 이번에는 직접 검색하겠습니다”라고 알리고, 찾지 못하면 사실대로 설명합니다.

### 작가에게 답하는 방법

이야기 속 사건(누가, 어느 장에서, 무슨 일이 있었는지)을 설명합니다. 파일 필드명이나 복선·사건 번호를 단독으로 제시하지 않고, 번호는 반드시 이야기 설명과 함께 씁니다. 보조 에이전트가 반환한 영문 필드와 누락 설명은 주 세션이 쉬운 말로 바꿔 전달합니다.

## 여러 책 사이 전환

사용자가 집필 중인 책을 바꾸거나 보고 싶어 할 때(한 프로젝트에 여러 권 가능):

1. 「책 디렉터리 판별」의 2번에 따라 모든 책 디렉터리를 나열하고 현재 `.active-book`이 가리키는 책을 표시합니다.
2. 사용자가 선택하면 선택한 책의 상대 경로를 프로젝트 루트 `.active-book`에 씁니다(기존 내용 덮어쓰기).
3. 한 권만 발견하면 묻지 않고 바로 활성 책으로 정합니다.

## 대시보드 작업대

사용자가 `/story dashboard`를 실행하거나 작업대 열기·프로젝트 파일 보기를 명시적으로 요청하면 이 스킬의 로컬 대시보드를 실행합니다.

1. **현재 작업 디렉터리**를 기본 작업 공간으로 사용합니다. 사용자가 디렉터리를 명시하면 그것을 사용하며 해당 디렉터리가 존재해야 합니다.
2. 현재 로드된 `story` 스킬 디렉터리에서 `scripts/dashboard-server.mjs`를 찾습니다. 저장소 경로, 전역 스킬 경로, 사용자 홈 경로를 하드코딩하지 않습니다.
3. `node`를 사용할 수 있는지 확인한 뒤 장시간 실행 프로세스로 시작합니다.

   ```bash
   node "<story-skill-dir>/scripts/dashboard-server.mjs" --root "<workspace>" --open
   ```

4. 출력에 `本机地址`(로컬 주소)가 나타날 때까지 기다린 뒤 전체 URL을 사용자에게 전달합니다. 도구가 백그라운드 프로세스/PTY를 지원하면 서비스를 계속 실행합니다. 브라우저를 자동으로 열지 못해도 실패로 보지 않고 클릭 가능한 URL을 반환합니다.
5. 대시보드는 기본적으로 `127.0.0.1`에서만 수신 대기합니다. `--allow-network`를 임의로 추가하거나 작업 공간을 로컬 네트워크·인터넷에 노출하지 않습니다.

작업대는 위의 「책 디렉터리 판별」과 다른 자체 규칙을 사용합니다. 표준 `작품분석실/{书名}/`와 기존 `拆文库-{书名}/`를 인식합니다. 집필 프로젝트는 다음 두 구조를 모두 지원합니다.

- 장편 디렉터리 구조: 내부에 `본문/`, `개요/`, `설정/`, `추적/` 중 하나 이상의 일반 하위 디렉터리가 있음.
- 단편 단일 파일 구조: 일반 파일 `본문.md`가 있고 동시에 `구간개요.md` 또는 `설정.md`가 있음.

심볼릭 링크는 프로젝트 표식으로 사용하지 않으며, `본문.md` 하나만 있는 자료 디렉터리는 집필 프로젝트로 인식하지 않습니다. 브라우저에서 `.md`, `.txt`, `.json`, `.yaml`, `.yml`, `.toml`을 편집할 수 있습니다. 저장 또는 삭제 확인 시 파일 내용 버전을 대조해 외부 변경을 덮어쓰지 않습니다.

서비스를 중지하려면 해당 Node 장시간 실행 프로세스를 종료합니다. 사용법만 묻는 경우 대신 실행하지 말고 `/story dashboard`를 사용하라고 안내합니다(호스트별 호출 방식 적용).

## 버전 업데이트 확인

“새 버전이 있나”, “업데이트 확인”, “업그레이드” 요청 시 수행합니다. **먼저 버전을 보고하고 설치 여부는 사용자가 결정합니다.**

1. **현재 버전**: 이 스킬과 같은 디렉터리의 `VERSION`을 읽습니다. 없으면 알 수 없음으로 처리합니다. 이 스킬이 집필 프로젝트 안에 있으면(프로젝트의 `skills/`, `.agents/skills/`, `.zcode/skills/` 등) 읽은 버전은 프로젝트 사본의 버전입니다.
2. **최신 버전**: 우선 `gh release view --json tagName,name,url -R zenstory-ai/oh-story-claudecode`의 `tagName`을 사용합니다. gh가 없으면 `curl -fsS --max-time 5 https://api.github.com/repos/zenstory-ai/oh-story-claudecode/releases/latest`로 `.tag_name`을 가져옵니다(jq 또는 grep). 조회할 수 없으면 “지금은 최신 버전을 가져올 수 없습니다. [Releases](https://github.com/zenstory-ai/oh-story-claudecode/releases)에서 직접 확인할 수 있습니다”라고 알리며 오류로 처리하지 않습니다.
3. **비교**: 현재 버전을 알면 `v` 접두사를 제거하고 의미적 버전(major.minor.patch)으로 비교합니다. 모르면 최신 안정 버전만 표시하고 최신 상태인지 판정하지 않습니다. `gh release`는 기본적으로 시험판을 제외한 최신 안정 버전을 가져옵니다.
4. **안내**:
   - 이미 최신 → “최신 버전 vX.Y.Z입니다.”
   - 새 버전이 있거나 현재 버전을 모름 → 확인된 버전과 [Releases](https://github.com/zenstory-ai/oh-story-claudecode/releases)/[CHANGELOG](https://github.com/zenstory-ai/oh-story-claudecode/blob/main/CHANGELOG.md)를 표시합니다. 릴리스 노트가 있으면 주요 변경을 덧붙이고 호스트의 질문 기능으로 “지금 업데이트할까요?”라고 묻습니다. 나중에 하겠다고 하면 변경하지 않고 언제든 다시 요청할 수 있다고 안내합니다.
5. **업데이트**(사용자 동의 후): 이 스킬 디렉터리의 위치로 설치 방식을 판단합니다.
   - 플러그인 디렉터리(경로에 `plugins/` 포함): Claude Code는 `claude plugin marketplace update oh-story-skills` 다음 `claude plugin update oh-story@oh-story-skills`를 실행하며 재시작 후 적용됩니다. ZCode는 Plugin Management에서 마켓을 새로 고친 뒤 `oh-story`를 업데이트합니다.
   - `npx skills`로 전역 또는 현재 디렉터리에 설치: `npx skills add zenstory-ai/oh-story-claudecode -y -g`를 다시 실행합니다(현재 디렉터리에 설치했다면 `-g` 제외).
   - 그 외 설치 방식(예: ClawHub): 원래 방식으로 최신 버전을 다시 설치합니다.
   - 이 스킬이 집필 프로젝트 안에 있음: 먼저 해당 방식으로 설치 패키지를 업데이트한 다음 새 패키지로 프로젝트 루트에서 `/story-setup`을 실행해야 프로젝트 사본이 교체됩니다. OpenClaw, Reasonix, 일반 파일 모드에서는 프로젝트의 이전 사본이 실행 중이므로 새 패키지로 프로젝트 `skills/` 아래의 스킬 디렉터리 14개를 수동 교체해야 합니다.

   업데이트 후 안내: 이미 배포한 프로젝트는 루트에서 `/story-setup`을 다시 실행해 훅·에이전트·참고 자료를 동기화하고 **새 세션을 열어야** 집필 보조 에이전트가 다시 로드됩니다.
