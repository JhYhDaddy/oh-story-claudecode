# Agent Note: 작품 분석 런타임 인수 마무리: 사건 지점 복구, 최종 상태 기록, 불필요한 상태 분기 제거

Status: implemented
Date: 2026-09-23
Issue: PR #386 / #438(유지보수자 인수)
Related: [2026-09-22-long-analyze-single-state-runtime](../architecture/2026-09-22-long-analyze-single-state-runtime.md), [2026-09-24-long-analyze-legacy-prologue-alignment](../bug-fix/2026-09-24-long-analyze-legacy-prologue-alignment.md)(기존 분석 라이브러리의 신원 검사와 장별 대조 결정은 이 후속 기록에서 변경됨)

## Problem

단일 상태·세 스크립트 런타임(Related 참조)을 인수해 다시 시험하면서 병합을 막는 문제 네 개를 발견했다.

1. 장별 요약의 사건 지점이 main의 장당 10–40개에서 구조적으로 `P1` 하나만 생성하는 방식으로 바뀌었다. 장소·물건·시간·비트별 분위기·원문 인용도 사라졌다. 사건 지점은 장편 연결의 기초 데이터다. 비교 장 선택은 사건 지점 수로 동점을 처리하고 구조 핵심 지점은 “유형=전환점”으로 고정하며 가져오기는 분포로 감정 곡선·복선을 역추론한다.
2. 런타임은 `最终状态`를 쓰지 않는데 세션 훅은 그 필드만 인식하므로 새 파이프라인으로 분석한 책도 세션마다 “분석 미완료”로 보고됐다.
3. 원문 변경 후 `plan`은 재열람 배치를 만들지만 `commit`은 “기존 요약 덮어쓰기 금지” 때문에 모든 쓰기를 건너뛰고 무효 신호를 지워 갱신 성공처럼 보였다.
4. 장 신원 검사가 이번 Stage 1에서 색인대로 쓴 황금 첫 세 장도 예전 요약으로 취급해 서장으로 시작하는 새 책은 세 장 분석 후 `plan`이 영구 차단됐다.

실제로 거의 없는 상황을 위한 복잡성도 있었다. 명시적 재분석(`reanalyze` + `request_id`)은 전권을 다시 읽지만 요약은 하나도 덮어쓰지 않았다. `migrate-legacy`와 여섯 스크립트 진행 인식은 배포된 적 없는 버전을 지원했다. `v2/章节卡`는 작가의 독립 프로젝트 형식으로 main이 만든 적 없다. 원문 국소 변경의 정밀 무효화 추적(`chapter_index.previous.csv`, 과거 색인 대조, stale 파생 뷰)은 분석 원문을 바꾸는 드문 상황을 위해 전체 분기를 유지했다.

## Decision

- **다중 사건 지점 복구**: 모델 출력은 장 수준 압축 필드＋`**情节点**：` 아래 `P1..Pn` 목록으로 바꾼다. main 형식(유형 | 간결한 묘사 | 관련 대상 | 장소 | 물건 | 시간, 선택적 인용 행, 지점별 `主题标签X | 基调：Y` 한 행)을 따른다. 원문 블록은 장당 10–20개, 긴 장은 최대 30개다. `commit`은 10–30을 기계 검증하고 범위를 벗어나면 배치 전체를 거부한다. 황금 첫 세 장에서 파생 뷰를 보충하는 기존 결과 블록은 최소 1개다. 유형·주제·분위기는 지점별 열거값에 매핑하며 부분 문자열 대신 “정확 일치 → 별칭 → 접두어”를 쓴다. `不紧张`이 `紧张`으로 들어가지 않는다. 출력 증가에 따라 원문 배치 상한은 10장에서 3장으로 줄이고 25,000자 상한은 유지한다. 계획에는 장별 `chapter_chars`를 제공한다. 템플릿에 main의 밀도 규칙(글자 수÷150–200), 세 열거값 전체 목록·구분, 여섯 구획을 모두 쓴 P 행 예시 두 개를 복구한다.
- **형식에는 관대하고 구조에는 엄격한 파싱**: `类型 X`, `基调` 뒤 콜론 누락, 다중값(처음 매핑 가능한 값 선택), P 행 끝의 태그를 허용한다. 번호·묘사·필드명·수량은 계속 강제 검증한다.
- **관리 구역에 `最终状态` 기록**: 단계 기록이 있고 Stage 3–6이 모두 완료(오류 포함 완료도 허용)되면 `completed` / `completed_with_errors`, 아니면 `pending`을 쓴다. 훅의 `analysis_incomplete`가 바로 읽을 수 있다. Stage 1/2도 표식 명령은 있지만 판정에 포함하지 않는다. 문서 절차가 보장하는 것은 3–6의 각 1회 기록뿐이다. 기존 프로젝트에 `最终状态` 행이 있으면 두 번째 행을 만들지 않고 3–6 모두 완료일 때만 완료 값으로 바꾸며 낮추지 않는다. Stage 1 후 중단은 `paused_after_stage1` 대신 `pending`으로 통일한다.
- **기존 요약은 절대 덮어쓰거나 갱신하지 않음**: 원문 변경은 해당 배치 캐시만 무효화하고 다음 계획에서 다시 읽는다. `commit`은 보존한 장을 `kept_existing_summary_chapters`에 정직하게 나열한다. 특정 장을 갱신하려면 요약과 해당 배치 캐시를 함께 지운 뒤 재개한다. 요약만 지우면 캐시에서 그대로 복구된다.
- **신원 검사는 `upstream_summary`만 대상으로 함**: 황금 첫 세 장과 런타임 파생 결과는 색인대로 작성하므로 제외한다. `build_chapter_index.py`의 예전 요약 충돌 검사도 `_摘要.md`만 본다. 중간 외전 때문에 어긋난 경우의 장별 신원 대조는 하지 않는다.
- **삭제**: `--intent reanalyze`, `--request-id`, 관리 구역 “이번 요청” 절, 캐시 `request_id/request_intent`, `migrate-legacy` 하위 명령과 여섯 스크립트 진행·캐시 인식, `v2/章节卡` 압축 형식, `chapter_index.previous.csv`, 과거 색인 대조와 stale 파생 결과 탐지. 전권 재분석은 새 디렉터리를 사용한다.
- chapter-extractor의 세 호스트 템플릿에 “자료 적법성과 분석 경계”(#143의 거절 방지 선언)를 복구한다.
- 황금 첫 세 장에서 요약을 보충하는 `existing-results` 배치는 **반드시 장 블록을 출력**한다. 그렇지 않으면 요약을 영원히 보충하지 못한다. 분할한 하위 블록은 제출 전까지 계속 대기 작업으로 센다. 이미 분할되었거나 다른 배치가 덮은 예전 캐시는 `repair-progress`가 오류 없이 건너뛴다.

판룡 실제 배치 실행(Haiku, 템플릿 지정 모델) 네 차례: ① 배치당 5장, 글자 수 미제공은 장당 3–10개로 형식·열거값 위반이 많았다. ② 글자 수와 밀도 규칙을 주니 3장 배치는 13–27개였지만 5장 배치의 마지막 장은 9개로 줄어 두 배치 중 하나만 통과했고 열거값은 여전히 임의 단어가 많았다. ③ 열거값 목록을 보완하니 값은 맞았으나 P 행에서 묘사가 사라졌다. ④ 완전한 예시 두 개와 “여섯 구획·묘사 생략 금지”를 추가하니 RAW-4-6, RAW-21-23, REUSE-1-3 세 배치 모두 장당 10–20개, 여섯 구획 완비, 유형·분위기 열거값 준수로 첫 제출에 통과했다.

## Alternatives considered

- **장당 핵심 사건 하나＋장 수준 인과 필드**: 출력이 짧아 한 배치 10장이 가능하다. 그러나 세 소비자가 비트 시퀀스를 사용해 하나만 남기면 모두 퇴보하며 두 차례 검토에서도 논의한 적 없는 변경이다.
- **main의 10–40 유지**: main과 완전히 일치한다. 그러나 다장 배치에서 상한 40은 단일 출력을 너무 늘려 유지보수자 의견에 따라 상한 30, 일반 10–20으로 줄인다.
- **파생 표식별 네 상태로 요약 갱신**(누락 시 쓰기, hash 일치 시 건너뜀, hash 무효 시 백업 후 덮기, 표식 없으면 덮지 않기): 원문 변경을 자동 추적한다. 그러나 원문 수정은 드물어 백업 경로·덮어쓰기 규칙을 추가할 가치가 적다.
- **장별 신원 대조 검사**: 중간 외전으로 인한 어긋남을 막는다. 그러나 서장·외전 자체가 드물고 제목 정규화·신원 매핑이 필요해 포기한다.
- **`reanalyze` 유지**: 명시적 진입점이 친절하다. 그러나 기존 요약을 덮지 않는 조건에서는 전권을 다시 읽고 캐시만 갱신하며 산출물은 그대로여서 오해를 준다.

## Consequences

이점: 사건 지점 계약이 main으로 돌아가 세 소비자의 퇴보를 막는다. 훅이 완료 책을 정확히 인식하고 서장으로 시작하는 새 책도 막히지 않는다. `manage_analysis_run.py` 1074→965줄, `inspect_existing_assets.py` 631→490줄, `build_chapter_index.py` 445→428줄로 상태 분기가 크게 줄었다.

비용: 원문 일부를 바꿔도 요약은 자동 갱신되지 않아 요약·캐시를 수동 삭제해야 한다. 중간 외전 삽입 시 기존 요약이 조용히 한 장씩 어긋날 수 있다. 3장 배치로 배치 수는 약 세 배가 된다. 여섯 스크립트 시험판과 `v2/章节卡` 프로젝트는 더는 인식하지 않지만 둘 다 main으로 배포된 적 없다.
