# Agent Note: 저장소 검사는 문구를 고정하지 않고 동작을 기준으로 삼는다

Status: implemented

## Problem

초기 검사 도구는 grep으로 'UPGRADING / README에 특정 문장이 있어야 한다'고 확인했고, 추적 계약은 고정 문장을 어휘 수준에서 매칭했다. 단어 하나를 바꾸거나 changelog 항목 하나를 빠뜨려도 실패했지만, 그 누락이 실제 실행을 망가뜨리지는 않았다. 반대로 문구가 맞아도 동작은 틀릴 수 있었다. #283에서 다른 세 환경에 추적 검사를 추가할 때 Claude 쪽은 한 버전 전체를 조용히 놓쳤으며, 규범 문자열의 grep 일치 검사로는 이를 발견하지 못했다(issue #305).

## Decision

- 정적 검사와 계약 검사는 반드시 '실제로 실행하면 깨지는 것'만 기준으로 삼는다. 파일 간 일치해야 하는 임계값(`agents_version`), 사용자에게 배포하는 에이전트 템플릿의 핵심 동작 규칙, 배포 동작의 기준점이 대상이다. UPGRADING 보완 여부나 README 문단 순서 같은 문서 완전성은 릴리스 체크리스트와 사람이 확인하며 절대로 CI에 넣지 않는다.
- 동작은 실제 실행으로 검증한다. hook은 합성 stdin/stdout으로 실행한다(`test-codex-hooks.sh`, `test-zcode-hooks.sh`, 배포 검사의 가짜 node 중계 프로그램). 네 환경의 동등성은 같은 프로젝트에 같은 쓰기를 했을 때 bash의 차단 여부와 JS 코어의 차단 여부가 같은지 시나리오별로 비교한다. 각 시나리오의 기대 방향도 고정해야 한다. 그렇지 않으면 양쪽 모두 차단을 놓쳐도 diff가 비어 있을 수 있다.
- 집필 후 문제 문형 검사망의 js↔py 동기화는 동작과 소스 텍스트를 함께 고정한다. `test-prose-net-parity.sh` A절은 정규식별 양성 예제로 탐지 여부를 고정하고, 메시지는 findings와 함께 글자 단위로 diff한다. Claude bash의 미완료 작업 차단(면제 범위, 전각 콜론, 차단 메시지)은 D절 시나리오에서 검사한다. fixture는 문자 클래스의 일부 선택지와 선택 그룹만 포괄한다. 한쪽에서 선택 문자 하나를 지우거나 수량자의 경계를 바꿔도 fixture가 모두 통과하는 경우가 변이 테스트에서 확인되었다. 따라서 `check-hook-regex-sync.sh`는 정규식 본체, 상수 표(문서 끝 검사 범위 길이, 구절 경계 집합, 질문형 어미/확인 표현 제외 집합), 미완료 작업 차단 표식을 js↔py 소스 수준에서도 비교한다. 메시지 문구는 여기서 고정하지 않는다.
- 격리 테스트로 입증할 수 없는 의존 방향에만 소스 정책 검사를 쓴다. scraper 출력 파일명이 로컬 날짜 helper에 의존하는지, CDP 탐지 소스 정책을 지키는지 등이 해당한다. 무관한 코드나 죽은 코드의 키워드로 속일 수 없음을 입증하는 변이 테스트를 반드시 함께 둔다.
- agent / skill / plugin / hook 프로토콜 관련 검증은 먼저 해당 프로젝트의 공식 문서를 확인한 뒤 실제 CLI 출력으로 재확인한다. 다른 에이전트의 비슷한 필드에서 추론하지 않는다.

## Alternatives considered

- **세 환경의 규범 문자열을 grep으로 비교한다**(이전 parity A계층) — CI에서 안전하고 런타임 의존성이 없으며 한쪽만 고치면 바로 실패한다는 장점이 있다. 채택하지 않았다. 텍스트가 같다는 것만 입증할 뿐 동작의 동일성을 입증하지 못하며, 한 환경 전체의 누락도 잡지 못한다. 6af0529에서 삭제하고 fixture의 결과를 글자 단위로 비교하는 기능 동등성 검사로 바꿨다.
- **UPGRADING 문구를 검사한다**(이전 배포 검사 TS10) — 유지보수자에게 업그레이드 설명을 보완하도록 강제한다는 장점이 있다. 채택하지 않았다. 동작이 아니라 문구를 검사하기 때문이다. 12a9655에서 삭제하고 TS10을 '버전 임계값 + 배포 동작 기준점'으로 바꿨다.
- **어휘 기반 추적 계약 검사**(`test-tracking-workflow-contracts.py`) — 같은 문제가 있어 6af0529에서 삭제했다. `test-tracking-commit.py`의 동작 회귀 검사만 유지한다.

## Consequences

- **이점**: 문구를 바꿨다고 실패하지 않는다. 한 환경의 누락을 잡을 수 있고 검사 실패 메시지가 실제 동작 문제를 가리킨다.
- **비용과 알려진 한계**: 동작 테스트는 더 느리다(`check-story-setup-deployment.sh`는 2분 이상 걸림). 문서의 불일치는 CI가 막아 주지 못하므로 사람이 확인해야 한다. 소스 정책 검사는 속임수를 막는 변이 테스트가 필요해 유지보수 계층이 하나 늘어난다. cmd.exe 경로처럼 CI에서 실행할 수 없는 동작은 정적 형태 보존 검사로 대체하고 최선의 근사 검사임을 주석에 밝혀야 한다. 문제 문형 정규식의 소스 고정은 js 리터럴과 py raw string에 같은 표기를 요구하므로 의미가 같더라도 표기를 바꾸면 양쪽을 함께 바꿔야 한다.
