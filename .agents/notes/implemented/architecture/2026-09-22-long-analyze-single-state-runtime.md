# Agent Note: 장편 작품 분석 런타임을 단일 상태·스크립트 세 개로 통합

Status: implemented
Date: 2026-09-22
Issue: PR #386
Related: [2026-09-23-long-analyze-runtime-takeover](../simplification/2026-09-23-long-analyze-runtime-takeover.md)(인계 후 마무리: 플롯 노드 밀도, `reanalyze`, `migrate-legacy`, 장 카드 계열, 부분 무효화 추적에 관한 결정은 해당 기록에서 뒤집힘)

## Problem

장편 분석의 옛 구현은 계획 JSON, checkpoint, 배치별 receipt, Stage receipt, 진행 파일을 동시에 관리했다. 기존 프로젝트 보강, 배치 분할, 원문 일부 변경, 단계 중단 후 이 상태들이 충돌하여 완료한 배치를 다시 분석하거나 잘못된 요약을 재사용하거나 단계를 완료한 것으로 오판할 수 있었다. 장별 요약과 ‘장 카드’라는 두 가지 파생 표현도 공존하여 소비자가 존재하지 않는 필드를 참조한 적이 있었다.

## Decision

1. **운영 실행을 스크립트 세 개로 통합**: `build_chapter_index.py`(장 경계, 물리 행, 전체·장별 hash, 명시적 rebuild), `inspect_existing_assets.py`(기존 산출물의 읽기 전용 판정, 정확한 누락 장, 출처 혼재, 단계 복구), `manage_analysis_run.py`(읽기 전용 계획, 범위 배치, 원자적 제출, 인접 분할, 캐시 복구, 단계 상태).
2. **유일한 실행 상태는 `_progress.md`의 관리 구역**에 둔다. `chapter_index.csv`는 현재의 기계용 색인이며 배치 캐시는 복구 근거일 뿐이다. 새 실행은 계획 JSON, checkpoint, 배치별 receipt, Stage receipt를 만들지 않는다. 배치 ID는 `RAW-{起章}-{止章}` / `REUSE-{起章}-{止章}`로 고정한다.
3. **장별 요약을 사실 필드 14개의 스키마로 교체**한다(개요, 인과, 핵심 행동, 상황 결과, 관련 인물, 정보 변화, 상태 변화, 3차원 리듬, 장 끝 후킹, 근거, 플롯 노드 유형, 플롯 노드 제목, 주제 태그, 기조). 장 카드는 폐지한다. 장별 확장 집필 기법 계층은 `剧情/节奏.md`로 올려 통합한다. 이곳은 원래 project-files.md가 지정한 ‘장 확장 집필 기법 통합’의 권위 위치다. 핵심 첫 세 장의 심층 분석은 장별 서술을 유지한다.
4. **신구 혼재를 현재 위치에서 호환**한다. inspect는 `mixed_sources`와 장별 `preferred_by_chapter` 출처를 보고한다. `schema_version`은 보고만 하고 신구 버전 통과 조건으로 쓰지 않는다. 소비 측은 필드별 대체 경로를 사용한다(핵심 행동·상황 결과가 없으면 핵심 사건 등으로 대체). 기존 산출물만 있으면 `--intent enhance`로 필요에 따라 보강한다(Stage 3+는 기존 요약을 집계하므로 원문을 전혀 읽지 않아도 됨). 명시적 재분석은 `--intent reanalyze`와 안정적인 `request_id`를 사용한다. 기존 요약이 서장·0장·첫 장이 아닌 곳에서 시작하여 정체를 확인할 수 없으면 `chapter_mapping_ambiguous`를 반환하며 조용한 오대응을 금지한다.
5. **Stage 6은 단독 재생성 가능**하다. `_style-sample.txt`를 우선 사용하고 표본이 없으면 색인을 따라 원문 4~6개 구간만 지정해서 읽는다. 전체 작품을 다시 스캔하지 않는다. 새 보고서를 만들기 전에 기존 보고서를 `_analysis_cache/legacy/`에 바이트 그대로 백업한다.

6. **배치 제출 형식을 스킬 자체의 reference에 기록**한다. `output-templates.md`의 ‘배치 제출 형식’에 `CHAPTER_START/END`, `REUSED_CHAPTERS`, `BATCH_OBSERVATIONS_START/END`의 감싸기 규칙을 명시한다. 원래는 chapter-extractor 템플릿에만 있어 하위 에이전트를 사용할 수 없으면 주 세션이 볼 수 없었다. v0.7.11 출시 전 solo로 기존 라이브러리의 분석을 이어 가는 실제 시험에서 제출이 세 번 거부되었으며 스크립트 소스를 읽고서야 표식을 채웠다. 배치 입력 파일은 `{拆文目录}/_analysis_cache/输入-{批次ID}.md`로 고정하며 시스템 `/tmp`에는 쓰지 않는다.

## Alternatives considered

- **스크립트 6개 + 상태 저장소 3곳 유지(검토 전 형태)**: 책임 구분이 세밀하고 단계별로 독립 테스트할 수 있다는 장점이 있다. 그러나 상태 분산이 중복 분석·단계 오판의 근원이며 hash 검사 46곳을 감사하기도 어려워 검토 의견에 따라 포기한다.
- **기존 라이브러리를 새 스키마로 일괄 이전**: 소비 측을 한 번에 맞추는 것이 가장 깔끔하다. 그러나 ‘기존 산출물 원본 바이트 유지’라는 호환성 하한선을 어기고 이전 비용을 기존 사용자에게 넘긴다. 현재 위치에서의 호환 + 필요 시 보강 + 읽기 전용 이전 근거로 바꾼다(`migrate-legacy`는 캐시만 추가하고 기존 파일을 건드리지 않음).

## Consequences

이점: 상태 충돌 지점이 없어지고 중단 후 복구가 모델을 중복 호출하지 않는다. 완성된 기존 프로젝트 보강에서는 원문 읽기가 0이며 보호 파일도 바이트 단위로 유지된다. 신구 요약을 장별로 섞어 쓰되 출처가 보이며 새 장을 추가하면 새 장만 처리 대기가 된다.

비용: 장별 요약의 기법 계층(확장 기법 표·표현 공식)이 통합 위치로 올라간다. 플롯 노드 밀도는 장마다 10~40개에서 보통 1개로 줄고 핵심 첫 세 장 외에는 원문 인용 위치가 없어진다. 유일하게 이를 행별로 소비하던 story-import의 상세 개요 매핑은 기존 필드 대체 경로를 포함해 함께 개편했다. (e)의 동률 신호 둔화는 검토 2항을 참조하며 나중으로 미룰 수 있는 작은 수정이다.
