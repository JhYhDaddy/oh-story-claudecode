# Agent Note: ZCode 전문 하위 에이전트를 플러그인으로 등록하고 호스트 이름에 따른 일괄 기능 축소 제거

Status: implemented
Date: 2026-10-26
Related: [토론 #497](https://github.com/zenstory-ai/oh-story-claudecode/discussions/497), [호스트별 배포](../architecture/2026-09-26-setup-by-host.md)

## Problem

ZCode 사용자는 업데이트 때마다 하위 에이전트를 이미 지원한다고 에이전트에게 알려야 했다. 저장소는 예전의 “프로젝트/plugin custom agents를 실행하지 않음”을 호스트의 고정 특성으로 적었고 플러그인에도 전문 역할이 없었다. 문구 한 줄만 바꿔서는 검토와 집필을 실제로 위임할 수 없다.

## Decision

- [ZCode 플러그인 문서](https://zcode.z.ai/en/docs/plugin)와 [하위 에이전트 문서](https://zcode.z.ai/en/docs/subagents)를 근거로 Claude 역할 원본에서 플러그인 역할 7개를 결정적으로 생성하고 ZCode manifest에 디렉터리를 선언한다. 도구 허용 목록, 금지 도구와 턴 수를 유지하며 모델은 현재 세션을 상속한다. Claude 모델 별칭이나 inline hooks를 그대로 복사하지 않는다.
- 역할을 위임하는 스킬 7개(story 라우터의 자료 조회 도우미 포함)는 현재 ZCode에 등록된 역할과 Agent 도구를 확인한다. 역할 누락, 호출 실패 또는 재귀 제한일 때만 대체 방식으로 전환한다. setup은 프로젝트의 skills/commands/hooks/AGENTS만 유지하며 공식 문서 근거가 없는 `.zcode/agents`를 만들거나 사용자 home에 쓰지 않는다. 플러그인 역할은 workspace의 `.zcode/skills` 자료를 읽고 누락되면 setup을 안내한다.
- 배포·사용·기여 문서와 검사를 현재 기능에 맞춘다. 가져오기의 deep-analysis와 원고 검토의 선택적 검색 담당자도 등록 상태에 따라 분기한다. 모든 호출 측 조건부 참조에는 대상 역할과 프롬프트만 남기고 도구 매개변수는 상단의 호스트 매핑을 통일해서 따른다. 호스트 조건 없는 Claude 호출 문법은 제공하지 않는다. 버전이 맞지 않으면 ZCode에서 먼저 플러그인을 업데이트하고 workspace를 갱신하라고 안내한다.
- 병합 전 아키텍처 재검토에서 단편 구상·교정과 가져오기 검증·상세 개요 역추론에 예전 호출 문법 또는 디렉터리만 확인하는 조건이 남아 있었다. 호출 측 검사는 진입점 7개와 모든 Markdown references를 재귀적으로 검사한다. 회귀 검사로 예전 호출·디렉터리 조건 아홉 곳을 먼저 찾은 뒤 수정하고 양성·음성 사례를 통과해 진입점과 생성물만 검사하는 일을 피한다.
- v0.9.1 릴리스 검토에서 기존 workspace Skills가 plugin보다 우선하여 출처를 명시하지 않은 setup이 계속 구버전을 배포함을 확인했다. 배포 규약과 업그레이드 가이드는 업데이트된 플러그인 복사본에서 실행하도록 요구한다. 이전 복사본이 계속 가리면 관리 대상 story-setup 디렉터리를 skill root 밖으로 옮겨 백업하고 새 배포로 재생성한다. 다른 사용자 Skills는 삭제하지 않는다. 어댑터 검사는 두 출처 안내를 함께 고정한다.
- current-contract의 공유 spawn 사전 검사도 “현재 호스트의 역할 출처”를 기준으로 검증해 프로젝트 파일뿐 아니라 플러그인 등록도 포함한다. 해당 fixture의 실패를 먼저 확인한 뒤 통과시켰다. 재검토에서 story, 장편 집필, 원고 검토의 버전 안내에 남은 “canonical 디렉터리만 검사”도 제거하고 음성 사례를 추가했다. 버전 안내가 플러그인 등록 판단을 파일 검사로 되돌려서는 안 된다.
- 생성기는 기존 Codex의 frontmatter·도구 파싱과 롤백 가능한 게시 기능을 재사용한다. 게시 helper에는 파일 일치 매개변수만 추가하며 Codex 기본값은 계속 `*.toml`이다. 도구 허용 목록, deny 우선순위, 모델 상속, 잘못된 입력의 쓰기 금지, 폐기 파일 정리와 드리프트를 모두 회귀 검사한다. 배포 목록의 중복 Hook 검증을 합치고 기존 예산을 상향하지 않는다.

## Alternatives considered

- **“미지원” 문구만 삭제**: 변경이 가장 작고 오해도 즉시 없앨 수 있다. 그러나 플러그인에 역할이 없으면 사용자는 여전히 같은 이름의 전문 역할로 위임할 수 없으므로 게시 구성을 보완한다.
- **역할을 프로젝트 `.zcode/agents`나 사용자 home에 복사**: 전자는 다른 호스트의 배포 방식을 재사용할 수 있고 후자는 공식 지원되는 사용자 수준 위치다. 그러나 프로젝트 디렉터리 탐색은 공식 근거가 없으며 자동 home 쓰기는 setup의 프로젝트 범위를 넓힌다. 따라서 플러그인 등록을 사용한다.

## Consequences

- 이점: 플러그인 역할을 지원하는 ZCode가 같은 전문 분업을 사용할 수 있다. 호스트 이름이나 다중 호스트 프로젝트의 `.zcode` 디렉터리 때문에 직렬 실행이 강제되지 않는다.
- 비용: 결정적 생성·검사 진입점이 추가된다. 독립 skills만 설치하고 플러그인을 활성화하지 않은 프로젝트는 여전히 대체 방식으로 전환한다. ZCode의 에이전트별 inline hooks 인터페이스는 확인되지 않았다. 작품 분석 도우미가 배치 입력 파일 하나에 쓰도록 하는 범위는 역할 본문으로 제한하므로 Claude/OpenCode와 동등한 역할별 경로 격리를 보장한다고 말할 수 없다.

## 검증

대상 생성 검사, ZCode/Codex/OpenCode 어댑터·Hook 검사와 본문 검사기의 호스트 간 동등성 검사를 통과했다. 정적 검사, 번호, 문서 예산과 공유 검사도 통과했다. 독립 문서 시뮬레이션은 “역할 7개 등록, 프로젝트 agent 디렉터리 없음, 혼합 호스트 표식”과 “독립 Skills에 플러그인 역할 없음” 두 경로를 검토했다. 여기서 찾은 예전 직렬 분기를 수정했다. ClawHub는 origin/main을 기준으로 수정 패키지 7개와 story의 정확한 companion을 합친 8개 항목의 패치 버전을 올리고 해시를 다시 고정했다. 고정된 중앙 제어기의 오프라인 검증은 통과했으며 게시하지 않았다.

ZCode GUI에서 역할 발견, 병렬 위임과 workspace reference 읽기는 실측하지 않았다. 플러그인 버전은 정식 릴리스 때 일괄 상향하며 이 패치에서는 제품 버전을 변경하지 않는다.
