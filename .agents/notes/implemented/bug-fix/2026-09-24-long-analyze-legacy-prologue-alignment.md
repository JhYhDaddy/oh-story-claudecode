# Agent Note: 도입부가 있는 기존 작품 분석 라이브러리의 장 번호 대조와 해결 경로

Status: implemented
Date: 2026-09-24
Issue: 출시 전 재검토(합성 책 재현 스크립트＋실제 Claude Code 실행)
Related: [2026-09-23-long-analyze-runtime-takeover](../simplification/2026-09-23-long-analyze-runtime-takeover.md)(기존 분석 라이브러리에 대해서는 이 기록이 “신원 검사는 예전 요약만 대상”, “장별 신원 대조 안 함” 결정을 뒤집음), [2026-09-24-long-analyze-author-facing-report-and-chart](../feature/2026-09-24-long-analyze-author-facing-report-and-chart.md)

## Problem

v0.7.10의 장 정규식은 “楔子”(도입부)를 인식하지 않아 그때 쓴 “제1장 심층 분석”은 본문 첫 장이었다. 새 색인은 도입부를 제1장으로 센다. 도입부로 시작하고 황금 첫 세 장만 분석한 기존 라이브러리를 업그레이드하면 REUSE-1-3＋RAW-4-6이 계획되지만 새 색인 제4장은 원문 “제3장”이다. 도입부는 영원히 분석하지 않고 제3장은 두 번 분석하며 제1–3장 요약은 한 장씩 어긋나도 오류가 없다. `inspect_existing_assets.py`와 `build_chapter_index.py`의 신원 검사가 예전 `_摘要.md`만 보고 황금 첫 세 장 심층 분석을 제외했기 때문이다.

같은 유형의 책에 기존 장별 요약이 있으면 차단하지만 `chapter_mapping_ambiguous`만 반환하고 계획은 이어서 `chapter_index_required`를 보고한다. 문서는 “멈추고 보고”만 지시해 작가에게 진행 방법이 없다.

`build_chapter_index.py`는 stdout/stderr를 UTF-8로 설정하지 않아 cp1252 콘솔의 오류 경로에서 종료 코드 1로 중단되고 GBK 콘솔에서는 글자가 깨졌다.

## Decision

- **대조 대상**: 예전 요약은 항상 대조한다. 황금 첫 세 장도 `_progress.md`가 구버전인 경우(v0.7.x “장 경계” 표가 있거나 런타임 상태 관리 구역이 없음) 대조한다. 이번 Stage 1에서 색인대로 쓴 황금 세 장과 런타임 파생 결과는 제외하여 새 책이 자기 산출물에 막히지 않게 한다.
- **대조 방식**: 예전 장 경계 표가 있으면 장별로 찾는다. 이전 시작 행이 새 색인의 장 제목 행과 정확히 같으면 바로 인정한다. 아니면 제목을 NFKC로 전·반각 통일하고 “제X장/권/도입부/1.” 접두어, 문장부호, 괄호를 제거한다. 정확 일치를 우선하고 “(즐겨찾기 부탁)”, “【두 장 합본】” 같은 끝 주석 제거 후 일치 또는 상호 포함을 다음으로 본다. 제목에 장 번호만 남으면 번호를 비교한다. 여러 후보 중 이전 시작 행과 가장 가까운 것을 택하고 동률은 미확인으로 처리한다. 예전 표에 제목조차 없을 때만 시작 행을 포함하는 장을 쓴다. 모두 같은 장 번호로 대응되어야 통과하므로 이미 도입부를 제1장으로 센 라이브러리나 끝 주석·괄호·전반각·“1.” 번호만 다른 표는 오차단하지 않는다. 표가 없으면 기존처럼 원문 첫 장이 제1장이 아니면 확인할 수 없다.
- **두 관문은 같은 함수 사용**: `inspect_existing_assets.legacy_mapping_check`를 `build_chapter_index.py`가 새 색인 저장 전에 호출한다. 맞지 않으면 저장하지 않는다. 검사기와 `plan`은 이미 만든 색인도 다시 확인한다.
- **해결 경로**: 오류에 쉬운 `author_message`로 어긋남의 결과와 세 선택지를 주고 ①을 기본 추천한다. ① `--fold-prologue`로 색인을 다시 만들어 처음의 도입부·서장·머리말·제0장을 첫 정규 장에 합친다. 예전 번호와 결과를 그대로 재사용하며 `folded_into_first_chapter`를 출력한다. ② `原文/` 외 예전 번호로 쓴 모든 산출물(`章节/`, `剧情/`, `角色/`, `设定/`, `人物关系图/`, 빠른 미리보기·요약·분석 보고서·문체, `_analysis_cache/批次-*.md`, 이전 `_progress.md`)을 `_analysis_cache/legacy/旧章号/`로 옮겨 새 번호로 재분석한다. 예전 번호 파일과 새 결과를 섞지 않는다. 이동은 모델이 문서에 따라 하고 스크립트는 사용자 파일을 건드리지 않는다. ③ 새 디렉터리에서 전권 재분석한다. 잘못된 기준으로 색인이 이미 만들어졌으면 순수 기계 표인 `chapter_index.csv`를 먼저 지우고 다시 만든다.
- **재생성 시 기존 기준 유지**: `--rebuild`에서 기존 색인 제1장은 정규 장인데 원문 시작에는 도입부·서장·제0장이 있으면 이전 `--fold-prologue` 사용으로 판단해 자동으로 합친다. 결정은 색인 첫 행의 원문 장 번호 자체에 남기고 별도 열·상태를 만들지 않는다. 재생성한 앞 장들이 기존 색인과 다르면(`position=N` 또는 `index_would_shrink`) 저장하지 않고 원래 원문으로 되돌리기 / 새 디렉터리의 두 경로를 `author_message`로 반환한다.
- **UTF-8 출력**: 런타임 스크립트 세 개와 새 관계도 스크립트는 `main()` 시작, 인수 파싱 전에 stdout/stderr를 UTF-8로 재설정한다. cp1252 콘솔의 `--help`와 인수 오류도 중단되지 않는다.
- 함께 수정: chapter-extractor의 기존 결과 예시는 `REUSE-1-20`에서 3장 상한의 `REUSE-1-3`으로 바꾼다. 출력 전 검사 제2항은 “요약 누락이 있으면 장 블록 필수”에 맞춘다. 예전 “explicit reanalysis”, “six stages” 주석 두 곳도 고친다.

## Alternatives considered

- **질문 없이 예전 표로 파일을 새 장 번호에 매핑**: 작가를 방해하지 않는다. 그러나 `第1章_深度拆解.md`가 새 제2장을 가리키게 되며 가져오기·비교 장 선택·문체 표본은 파일명으로 읽는다. 분석 런타임 안에서만 매핑이 유효하고 다른 곳은 여전히 어긋나며 도입부도 분석되지 않는다.
- **색인 제0장 지원**: 도입부를 제0장으로 두면 본문 번호가 유지되어 직관적이다. 그러나 색인·범위 hash·계획·검사기는 1부터 연속된 번호를 가정하므로 변경 범위가 병합 옵션보다 훨씬 넓고 새 번호 형식이 생긴다.
- **제목만 대조**: 행 번호에 의존하지 않아 원문 변경에도 대응한다. 그러나 상·하편이나 동명 외전처럼 제목 중복이 흔하므로 행 위치와 제목을 함께 쓰는 편이 안정적이다.
- **병합 결정을 새 CSV 열 또는 `_progress.md`에 기록**: 가장 명시적이다. 그러나 CSV 열 집합·파서 버전이 재사용 판단 기준이라 열을 더하면 모든 기존 색인이 무효가 되어 재생성이 필요하다. 색인 스크립트는 진행 상태를 쓰지 않는 설계이며 첫 행만으로 두 기준을 구분할 수 있다.
- **이전 시작 행이 장 범위 안이면 인정**: 구현이 간단하다. 그러나 예전 표는 빈 행·CRLF로 한두 행 어긋날 수 있어 앞 장으로 들어가 잘못된 불일치를 보고한다. 제목 행과 정확히 같을 때만 즉시 인정하고 나머지는 제목으로 처리한다.
- **예전 표 없으면 항상 작가에게 수동 매핑 요청**: 가장 보수적이다. 그러나 v0.7.10 이전 라이브러리는 원래 표가 없고 작가도 답하기 어렵다. 실용적인 경로는 여전히 병합 또는 재분석이다.

## Consequences

이점: 도입부로 시작하는 기존 라이브러리가 조용히 어긋나지 않는다. 기존 요약이 있으면 단순 중단 대신 추천 기본값이 있는 세 선택지를 제공한다. 표와 색인이 같거나 제목 끝 주석·괄호·전반각만 달라도 오차단하지 않는다. 도입부 병합 후 장을 추가해 재생성해도 막히지 않으며 Windows/GBK 콘솔의 오류·도움말도 읽을 수 있는 JSON으로 출력된다.

비용: ①을 선택하면 도입부를 따로 분석하지 않으므로 보고의 “아직 불확실한 점”에 밝혀야 한다. 표 없는 더 오래된 라이브러리는 첫 장 번호로만 판단해 중간 외전 삽입에 따른 불일치를 못 찾는다. 검사기가 `_progress.md`와 장 디렉터리를 한 번 더 읽는다. 제목 포함 관계가 있으면 이전 시작 행의 거리로 구분해야 한다. 색인 생성 뒤 원문 앞에 도입부를 추가해도 재생성 시 첫 장에 합쳐지며 번호는 유지되고 첫 장은 대기 상태가 된다.
