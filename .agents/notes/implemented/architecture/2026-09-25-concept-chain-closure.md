# Agent Note: 개념 통일 마무리와 기능 연결 완결(v0.8.1)

Status: implemented
Date: 2026-09-25
Related: [v0.8 간소화](../../implemented/architecture/2026-09-24-v0-8-lean-writing-loop.md)

## Problem

v0.8.0 출시 뒤 장편·에이전트 템플릿 개념 목록, 다른 스킬의 개념 일관성, 핵심 기능 여덟 개의 전체 연결을 세 갈래 읽기 전용 감사로 확인했다. v0.8 개념 정리는 각 개념의 본거지 파일에만 적용됐고 여러 연결이 끊겨 CI가 보지 못했다.

- **작가를 막거나 조용히 실패**: AI 문체 제거 면제 표식을 검사기가 blocking 대시로 인식해 장을 제출하지 못했다. 스킬 세 개의 작가 메모리 query에 필수 `--workspace`가 없었다. Claude 훅은 `.deslop-whitelist`를 읽지 않았다. 상세 개요 검사와 storyctl의 “목표 글자 수” 파싱 규칙이 달랐고 작가의 범위도 storyctl이 인식하지 않았다. 수정 draft는 추가 기준으로 안내해 따르면 이번 장 추적 기록을 비웠다. review는 advisory를 “안 고쳐도 됨”으로 낮추고 품질 목록 다섯 개는 “분량 이탈→보충”이라고 했다. import가 역추론한 단편 절 개요는 short-write 계약을 통과하지 못하고 장편 개요에는 필수 세 항목이 없었다. deslop은 단편 분기가 없어 판매 포인트를 지웠다. 작품 분석 문체 프로토콜은 공유 문체 판단과 반대였고 라우터는 단편 프로젝트를 못 알아봤다.
- **에이전트가 필요한 정의를 읽지 못함**: story-architect는 권별 개요를 만들어야 하지만 사건 단위 카드 템플릿을 못 보고 필수 목록에 단위 위치·주인공 목표가 없었다. 집필자는 deslop에만 있는 “진단·등급 판정”으로 연결됐다. “새 요소 세 단계”는 solo / skills-only 경로에서 blocking으로 처리되고 “먼저 작가에게 질문”은 집필자·주 세션에서 의미가 달랐다. “판정 대기”도 정의가 없었다.
- **이름 분기**: 심각도 척도가 최소 다섯 종류이며 1차 구조/단위극/사건 단위, 계약 위험/위험 등급, 네 의미의 비트, 주 스레드/주 세션/writer, 남은 수렴 상태 등이 혼재했다.
- **텍스트에만 있는 기능**: 계약 네 질문은 검사·작가 표시가 없고 “의미 advisory 3개 이상”은 스크립트 출력으로 판단할 수 없었다. 본문 쓰기 검사는 상세 개요 파일명만 봤다. chapter check의 문서 상태와 실제 출력이 달랐다. 작품 분석 쓰기 보호는 Claude에만 있었고 CLI 예시는 실행 검증된 적이 없었다.

## Decision

v0.8.1에서 파일 소유에 따라 다섯 갈래 병렬 수정으로 한 번에 마무리한다. 동작 수정마다 수정 전에 실패하는 회귀 검사를 하나씩 둔다.

- **검사기·훅**: `check-ai-patterns.js`는 HTML 주석을 같은 길이 공백으로 바꾼 뒤 검사하여 면제 표식을 대시로 인식하지 않는다. 각 결과에 `review: semantic|mechanical`을 붙이고 미분류 유형은 오류로 처리한다. Claude의 `story_hook_cli.js`도 다른 호스트처럼 `.deslop-whitelist`를 읽는다. 본문 쓰기 검사는 상세 개요에서 #과 공백을 제외한 글자가 30자 미만이면 차단한다(JS 핵심 네 복사본, Codex Python, bash를 함께 변경하고 parity로 방향 고정). 유해 문장 패턴 동기화 검사는 양쪽 상수 표의 전문·플래그·순서를 비교하고 변이 자체 검사를 갖춘다.
- **글자 수·추적**: `wordcount_core.py`와 `check-outline-contract.js`는 “목표 글자 수”를 같은 방식으로 파싱하고 공유 예시 30개로 일치시킨다. 작가 범위는 개요의 “글자 수 범위” 행 또는 `--min-chars/--max-chars`로 주며 우선순위는 매개변수 > 개요 > 기본 ±15%다. `chapter check` 최상위 `status`는 ready / needs_decision / blocked / invalid / tool_unavailable이고 종료 코드는 0/0/1/1/3, 잘못된 schema는 2다. `quality.semantic_advisories`는 의미 판단이 필요한 안내 수다. `accept-current-length`는 목표 절반 미만이거나 초과 상태에서 한 번도 압축하지 않았으면 거부하며 작가가 고집하면 `--force`를 쓴다. 수정 `draft`는 이번 장의 전체 기록을 사전 채우고 수정도 `storyctl.py chapter commit`으로 보낸다. `<!-- 去味:跳过 -->`가 있는 장은 AI 문형 blocking을 명시적 면제 안내로 낮추지만 퇴화 문제는 계속 필수 수정한다. 상세 개요는 “계약 위험” 값(이전 “위험 등급”도 허용)을 검사·출력한다.
- **개념 통일**: 새 요소 세 단계는 장편 SKILL.md에서만 정의한다. “먼저 작가에게 질문”은 주 세션의 새 요소 처리 표에 합치고 작성 전·후 질문을 구분한다. 설계자는 권별 개요 템플릿과 필수 아홉 필드를 받으며 집필자는 비율 상한·필드 해석을 읽을 수 있다. 심각도 대조표를 통일하고 사건 단위, 계약 위험, 목표 감정, 일일 집필 묶음 종료 확인 / 개요 묶음 종료 재검토, 주 세션, 집필자 명칭을 통일한다. 계약 위험이 보강 필요·계약 파괴면 작가 보고에 넣는다.
- **다른 스킬**: 원고 검토·AI 문체 제거·단편의 작가 메모리 명령을 그대로 실행할 수 있게 한다. 검토 검사기 안내는 S3로 분류하고 품질 목록의 글자 수 행은 각 스킬 규칙을 따른다. 가져오기가 역추론한 단편 절 개요·장편 상세 개요는 각 계약을 충족한다. AI 문체 제거는 단편을 식별해 판매 포인트를 보존한다. 작품 분석 문체 프로토콜은 공유 판단과 일치시키고 `/story`는 단편 프로젝트를 인식한다.
- **장편 작품 분석**: OpenCode 생성 extractor는 `_analysis_cache/输入-*.md`만 편집한다. 생성기는 템플릿의 검사기 이름으로 변환하며 미등록 검사기는 생성 실패다. `plan`은 배치마다 `min_plot_points`, `input_file`, `handoff_cache`를 제공하고 `--chapters A-B`는 한 구간만 계획한다. 사건 지점 하한은 `max(1, min(10, round(字数/200)))`다.
- **재검토 패치**: 집필 후 훅 두 구현도 검사기와 같은 HTML 주석 제외 규칙을 쓴다. “글자 수 기준/목표/범위” 세 행은 JS·Python에서 같은 방식으로 처리하고 숫자 없는 목표·범위 행은 설명으로 무시한다. 잘못된 UTF-8 개요는 세 호스트 모두 비어 있지 않은 것으로 허용한다. 검사기·문장부호 스크립트가 중단되거나 출력을 파싱할 수 없으면 `chapter check`가 통과 대신 tool_unavailable(종료 3)을 보고한다. `wordcount checkpoint --project`는 개요의 목표·작가 범위를 읽어 앞 묶음 남은 범위와 장 전체 검사를 맞춘다. 두 매개변수가 모두 있으면 개요 범위 행을 파싱하지 않는다. BELOW_ACCEPT_FLOOR / COMPRESSION_REQUIRED 거부 후 주 세션은 사유에 맞춰 묻고 목표 절반 미만에서는 “현재 길이 수락”을 추천하지 않는다. `sync-opencode.py`는 CRLF를 정규화하고 matcher가 `*`, 빈 값, 누락이면 모두 쓰기 도구를 덮는 것으로 처리한다. OpenCode 권한 와일드카드 `*`는 s 플래그의 `.*`로 컴파일되어 여러 디렉터리 깊이를 건널 수 있다(상류 `util/wildcard.ts`).
- 알려진 미수정 사항: 초과 분량 기준은 `.story/work/`에 있다. 긴 원고를 먼저 측정하고 원래 길이로 줄이면 “한 번 압축” 판정을 우회할 수 있다. 의도적 조작이 필요해 당장은 처리하지 않는다.
- `agents_version` 32 → 33, `setup_skill_version` 1.3.1로 올리고 어댑터를 다시 생성한다.

## Alternatives considered

- **A 계층만 수정하고 이름·연결 누락은 다음 버전으로 연기**: 변경 범위와 회귀 위험이 작고 급한 문제를 빨리 해결한다. 그러나 감사에서 A 계층 오류의 대부분은 같은 개념을 여러 곳에서 설명하며 생긴 이름 분기·연결 누락의 증상이었다. 증상만 고치면 다시 어긋나며 작가도 이번에 전체 해결을 요구해 채택하지 않는다.
- **공유 개념을 스킬 간 공통 파일 하나에 집중**: 정의가 한 곳이면 어긋나지 않는다. 그러나 저장소 규칙은 스킬 간 참조를 금지하고 각 스킬의 독립성을 요구한다. 공유는 바이트 동일 복사본과 검사로 처리하므로 그 기반 위에서 보완한다.

## Consequences

- 이점: 작가가 면제 표식, 잘못된 명령·심각도 때문에 막히지 않고 에이전트가 주 세션과 같은 정의를 본다. 새 실행형 테스트가 문서 명령과 스크립트를 맞춘다.
- 비용: 수십 파일·배포 템플릿·훅 문구가 바뀌는 넓은 변경이다. `agents_version` 33을 받으려면 모든 호스트에서 `/story-setup`을 다시 실행해야 한다. 훅 문구를 바꾸면 검사 단언도 동기화해야 한다.
