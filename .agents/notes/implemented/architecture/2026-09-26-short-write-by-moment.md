# Agent Note: 단편을 작가 시점별로 읽고 설계 파일로 구상과 본문 집필 인계

Status: implemented
Date: 2026-09-26
Related: [35K 로드 상한](2026-09-26-per-call-load-ceiling-35k.md), [새 책 확인 지점별 시점](2026-09-26-opening-by-author-moments.md), [단편 집필 전 검수 회귀](../bug-fix/2026-09-24-short-write-precheck-regression.md)

## Problem

story-short-write는 구상(Phase 2)과 본문 집필(Phase 3–4)을 기본적으로 한 문맥에서 마친다.

- 구상에서 workflow-design·writing-workflow·submission-craft·short-craft·short-reversal·장르 묶음, 조건부로 반대 인물·비교 작품 회상까지 27.5–35K를 읽는다. 이어 workflow-draft·short-format·short-deslop·workflow-revision을 읽고 단계마다 short-craft·장르 묶음을 전부 다시 읽으므로 누적 약 42.6–60K, 감정·훅까지 68K다.
- 실제 본문 경로가 등록되지 않았다. doc-budget에는 진입부+Phase 3/4의 실행 지시 13.4K만 있고 형식·공통 기법·장르·제거 목록은 빠졌다. 실제로 가장 큰 장르 묶음은 34.1K, 비주류 장르 공식 전체는 35.8K, 반대 인물·감정까지 39.3K, 회상·훅 둘까지 약 49K다.
- workflow-draft는 집필 때 villain-and-reveal의 폭로법, hooks-chapter / hooks-paragraph의 훅, genre-writing-formulas의 장르, submission-craft의 도입문, benchmark-recall / cross-book-recall의 비교 작품을 다시 읽게 한다. 구상에서 이미 결정했지만 파일에 기록하도록 하지 않아 문맥 교체 후 전체를 다시 읽는다. 작가의 인칭·취향·금지 사항도 대화에만 있다.
- Phase 3는 “像/好像/仿佛/如同”이 10회 넘으면 기능을 개별 검토하고 일괄 삭제하지 말라고 하지만 교정 목록은 “像”을 전체 10회 이하로 제한한다.
- 작가에게 `Fallback: ... -> solo`, `Notice: agents bundle 版本不匹配…`를 직접 보고하게 하며 story-deslop도 같다.

## Decision

- **세 시점**: 첫 화면의 집필 전 필수 읽기를 감정 결정(Phase 1, 진입부만)→구상(Phase 2, 기존 방식)→본문 집필(Phase 3–4, workflow-draft 사전 로드+workflow-revision) 표로 바꾼다. 각 행은 작가 확인·읽기·저장 대상을 명시한다. check-reference-gates.js의 세 경로는 첫 12행 안에 그대로 둔다.
- **파일로만 인계**: 구상 전달 전 `设定.md`에 본문용 정보를 전부 쓴다. 기본 정보에 submission-craft 플랫폼 표의 플랫폼 기조, 새 작가 확정 사항(인칭·취향·금지·기각안), 비주류 장르 기법 절에 공식의 감정 박자·필수 장면·규칙 요점, 반대 인물 설계에 폭로법을 넣는다. 확인 지점에서 바뀐 사항은 두 파일에 먼저 저장하고 구상 검사를 다시 한다. workflow-design의 设定.md 템플릿은 집필에서 이 파일과 절별 줄거리만 읽는다고 명시한다.
- **구상 방법에 재의존하지 않음**: workflow-draft는 저장된 두 설계 파일의 반전·반대 인물·폭로·유료 전환·플랫폼 기조를 따르고 workflow-design·short-reversal·submission-craft·villain-and-reveal·공식 전체를 다시 읽지 않는다. 사전 로드는 short-format·short-craft·设定.md의 장르 묶음 하나(비주류는 공식 미로드)이며 유대·여운 때만 emotional-methods를 추가한다. 도입 훅은 자체 표·장르 도입 유형, 문단 훅은 절별 줄거리의 끝 연결/훅 열, 비교 작품은 비교 작품 요약으로 회상한다. 본문에서는 보조 비교 작품을 추가 회상하지 않아 cross-book-recall 예산 0과 맞춘다. 도입문 요점은 자체 파일에 넣는다. short-deslop은 Phase 4에서 읽고 집필 중 AI 문체는 장편 직접 집필처럼 완료 탐지기로 보완한다.
- **문맥 교체**: 구상 보고 끝에 새 대화에서 본문 집필을 요청하도록 권한다. 새 대화에서 두 설계 파일이 검사를 통과했으면 바로 집필하며 같은 대화에서 계속하라는 요청도 따른다. 단편은 기본적으로 주 세션이 배치별로 전체를 쓰며 보통 한 번에 끝낸다. 여러 대화로 나누거나 narrative-writer에게 기본 위임하지 않는다.
- **중복 제거**: workflow-draft의 집필 지시 아홉 개·장면 정보 통합은 short-craft 2/3/10/11절·short-format 구두점의 반복이라 링크 문단과 고유 두 요구(줄거리 문체 복사 금지, 감정 강도·과업의 핵심 순간)만 둔다. 강도는 `设定.md`·장르 어조를 따르고 없으면 강한 쪽이 기본이다. 교정 형식 여섯 항목은 short-format 마지막 빠른 검사, 삭제 원칙 앞 셋은 진입부 실행 규칙 3으로 연결한다. 형식 규범은 구상에 불필요해 workflow-draft 앞으로 옮긴다.
- **“像” 기준**: 진입부를 기준으로 네 비교 표현을 몰아서 쌓지 않으며 10회 초과나 비유 밀도 경고 때 기능을 개별 검토한다. 기능이 있으면 남기고 전체 상한·기계적 삭제를 금지한다. 교정 목록도 맞춘다. 탐지기는 원래 밀도로 안내하며 고정 횟수로 차단하지 않는다.
- **작가용 안내**: short-write·deslop의 Agent 호환·버전 안내를 쉬운 한 문장과 마지막 기술 비고의 `Fallback` / `Notice` 원문으로 나눠 story-review와 맞춘다. 단편 주 세션 직접 집필·정리는 기본이므로 대체 실행 보고·비고를 하지 않는다. 작가가 명시적으로 도우미를 요구했는데 불가할 때만 쉽게 설명한다. current-contract 기준 문구는 보존한다. deslop 결과 템플릿 끝에 기술 비고를 넣고 단편도 실행 상세는 그 행에만 쓴다.
- **보호 검사**: `check-reference-gates.js`는 파일만으로 인계, workflow-draft에서 구상 방법 열 파일명 제거(옛 villain-and-reveal.md 등은 실패), workflow-design의 플랫폼 기조·작가 확정 사항, workflow-revision의 전체 10회 이하 금지를 검사한다. `check-current-skill-contracts.py`의 새 `author-note-preflight`는 두 진입부의 직접 보고 `Fallback:` / `Notice:` 문구를 막고 기술 비고 목적지를 요구한다. 옛 두 파일은 실패하며 `test-current-skill-contracts.py`에 정상·실패 회귀를 더한다.
- **단편 e2e 후 기준 통일**: 반전 공개는 기능으로 정하고 백분율은 기록만 한다. villain-and-reveal의 세 기준을 지우고 workflow-design의 반전 정보 차 검증을 가리킨다. 독자가 추측 가능한가는 되읽으면 도출 가능·처음에는 예측 불가로 통일한다. 관통 소품은 선택 사항이며 쓰면 세 번 등장한다(short-craft·workflow-design·workflow-draft 동일). 도입 길이·제1절 연결은 submission-craft 기준이며 이후 자료에 따라 약 150–300자, 멈춘 지점에 따라 이어가기·회상으로 변경했다([10월 17일 노트](2026-10-17-write-references-by-moment.md)). 절 표시·따옴표는 플랫폼 기조와 함께 정하고 플랫폼 표는 submission-craft에만 둔다. 작가가 장르·소재만 말하면 추천 감정 하나와 함께 한 번 묻는다. 반대 인물이 있으면 Phase 2 설계 검증 블록의 해당 없음 행을 다섯 필드 각 한 행으로 대체한다.
- **设定.md 보완**: 장르 기법 절에는 기법 2–3개의 사용법, 비주류면 공식 요점도 쓴다. 검사 필드보다 먼저 일치하지 않게 “核心招式：”라는 표기는 쓰지 않는다. 인물 스케치는 사람마다 한 행에 목소리·입버릇·금기를 담는다. character-designer는 완료 검사 전에 실행하여 결과를 압축한다. 템플릿에 플랫폼 기조·인물 스케치·장르 기법을 명시한다.
- **집필·교정의 새 대화 진입**: workflow-draft는 구상 완료 검사를 먼저 하고 실패하면 작가에게 구상으로 돌아가도록 요청하며 방법을 자체 재독하지 않는다. 교정은 새 대화도 short-format 필수다. 비주류 공식 대조에서 원문을 다시 읽어야 하는 분량 준수·남녀 채널 구분 둘을 지운다. 절 수는 줄거리·전달 검사, 채널 차이는 구상 때 장르 기법 기록으로 다룬다. 비교 작품 상세 경로에 `对标/{书}/`가 없으면 `拆文库/{书}/`를 쓰도록 추가하고 analyze-output-usage는 요약 회상만, 원문 재독 금지로 한다.
- **추가 시점별 이동**: short-craft의 장면 세 차원 통합·밀도 배분과 동정 변화는 집필만 쓰므로 새 `scene-craft.md` 사전 로드로 옮겨 구상 약 0.9K를 줄인다. narrative-writer 본문·교정 prompt는 새 `agent-calls.md`로 옮겨 위임 때만 읽는다. 일관성 검사 한 줄은 workflow-revision에 남기고 작가 기억 주입 테스트 기준도 새 파일로 옮긴다.
- **본문 e2e 후 정렬**: 장르 어조·도입·감정 강도가 short-craft 기본보다 우선(서스펜스의 차분함 등)하며 강한 감정은 기본 원칙일 뿐이다. 즈후 옌옌 도입은 본문 첫 문단들이며 별도 표시하지 않는다(short-format·submission-craft·workflow-draft 동일). 절 표시·따옴표는 `设定.md`의 플랫폼 기조, 없으면 기존 `正文.md`, 그것도 없으면 `###1.`·`""`다. 플랫폼 표는 submission-craft로 합쳐 집필에서 읽지 않는다. 반전 후는 승인된 절별 분량에 맞춰 실현·여운만 쓰며 workflow-revision·emotional-methods의 500자 내 마무리·2000자 끌기 고정선을 없앤다. workflow-draft 다섯 부분 비율은 참고다. 배치별 완료 절 요약은 단편 디렉터리 `.story/work/已写小节摘要.md`에 저장해 새 대화에서 잇고 전달 후 삭제 가능하다. 교정 중 복사 탐지된 기능성 대사(맹세·핵심 원문)는 `小节大纲.md` 끝의 `复沓锚句：` 아래 등록하고 재검사한다. check-outline-copy.js는 파일명별 분기하여 단편에는 절별 줄거리와 등록 형식을 안내하고 장편 원문은 유지한다. style-resolution 3단계는 작가 기억이 있으면 query, 없으면 생략으로 진입부와 맞춘다. 비주류 공식 검사는 한 문장, 견인·도입은 공통 교정 목록에 합친다.
- **예산**: 단편 Phase 2를 단편 구상(Phase 1–2, 주 세션)으로 바꾸되 분기는 같다. 단편 실행 지시는 단편 본문 집필(Phase 3–4, 주 세션)로 바꾸고 장르×제거 담당×감정 장면의 13분기를 등록하며 short-format·short-deslop·emotional-methods 파일 예산도 추가한다.

프로젝트 설정·줄거리 등을 제외한 주 세션 공백 제외 로드:

| 시점 | 이전 | 이후 |
|---|---|---|
| 구상 | 27.5–34.9K | 26.9–34.3K(인계 필드·템플릿 추가, 장면 기법 이동) |
| 별도 대화 본문 집필 | 미등록, 실제 32.3–35.8K, 반대 인물·감정 포함 39.3K, 회상·훅 포함 약 49K | 25.8K(비주류)–31.7K(최대 장르), 감정 포함 32.6K(제거 위임 prompt 포함) / 34.6K(주 세션 제거, 최악 조합) |
| 구상 후 같은 대화 집필 | 약 42.6–60K, 감정·훅 포함 68K | 여전히 약 46K 이상 누적되어 확인 지점에서 새 대화를 권함 |

## Alternatives considered

- **story-architect 구상 묶음**: 가장 큰 구상을 위임하면 주 세션은 작가와 대화만 한다. 그러나 구상은 이미 35K 이하이고 이야기 핵심·인물·반전·유료 전환을 작가와 조정하는 과정이라 위임하면 개입이 어렵다. private references와 열 장르 묶음을 agent-references로 동기화해야 하므로 배포·관리 비용도 크다. 기존 선택적 구조 설계 보조는 유지한다.
- **기본 narrative-writer 위임**: 새 문맥에서 쓰므로 주 세션이 기법을 읽지 않는다. 그러나 집필자는 장편 writing-craft만 읽고 단편 기법·장르를 못 읽어 어조가 흔들린다. 보통 한 번에 끝나므로 새 대화만으로 충분하다. 명시 요청·문맥 부족 때 위임은 유지한다.
- **실제 예산만 등록**: 최소 변경이다. 그러나 반대 인물·감정 39K, 비주류 공식 35.8K라 의존성을 바꾸지 않으면 기법을 삭제해야 하고 누적 문제도 남는다.
- **구상에서 도입문 먼저 확인**: 투고의 첫인상을 미리 볼 수 있다. 그러나 본문 첫 문단이라 같은 호흡으로 써야 하며 이동은 결과 형태를 바꾸어 실측이 필요하다. 이번에는 요점만 옮기고 순서를 유지한다.
- **기본 직접 집필도 `Fallback` 기록**: 위임하지 않았음을 추적할 수 있다. 그러나 단편 기본 동작은 대체 실행이 아니며 매번 나오는 잡음이 진짜 안내를 묻는다.
- **반전 후 기본 분량 상한 유지**: 검사 가능한 수치다. 그러나 승인된 절별 분량과 충돌하면 실현 장면을 지우게 된다. 지연은 실현·여운만 쓰고 새 설명을 열지 않는다는 기능으로 판정한다.
- **교정 Phase 4도 별도 시점**: 초고를 먼저 확인하고 로드를 줄인다. 그러나 자동 마무리이지 작가 확인 지점이 아니며 왕복만 늘어난다. 집필+교정은 이미 35K 이하다.

## Consequences

- 이점: 실제 집필 경로가 등록되어 모두 ≤35K다. 구두 결정까지 `设定.md`에 남아 새 대화·다음 날 이어지고 구상 방법 약 다섯 파일을 덜 읽는다. 비교 표현 기준이 하나가 되며 작가는 쉬운 안내, 실행 상세는 마지막 기술 비고로 본다.
- 작가가 느끼는 변화: 구상 확인 후 새 대화에서 본문 집필을 권하고 새 대화는 재구상 없이 시작한다. `设定.md`에 플랫폼 기조·작가 결정·비주류 공식이 남고 감정법은 유대·여운 때만 읽는다. 비교 표현 10회 초과만으로 삭제하지 않는다. 기본 직접 집필 안내를 반복하지 않고 차분한 장르를 억지로 격하게 만들지 않으며 반전 후 승인 장면을 500자 제한 때문에 자르지 않는다.
- 비용: 집필 전에 short-deslop을 읽지 않아 중간에는 탐지기에 의존하지만 Phase 4 정리는 유지한다. `设定.md`의 비주류 공식 요약이 너무 짧으면 세부를 잃으며 short-craft 링크는 실제로 읽어야 효과가 있다. 같은 대화를 유지하면 누적 35K를 넘는다. 최악 집필 조합 여유 약 440자, 구상 분기 약 710자라 이후 진입부·흐름 추가 때 삭제도 필요하다.
- 실측(v0.8.3, 2026-09-27): 아내 되찾기·서스펜스·복수 응징·달콤한 연애·민속 괴담 다섯 장르를 각각 구상하고 저장본을 복사해 같은 대화 집필과 새 대화의 본문 집필 요청을 비교했다. 이 대화의 Opus 하위 에이전트가 주 세션을 맡고 .claude/agents를 지워 직접 집필을 강제했다. 인칭·금지·결말 세 요구 위반은 양쪽 0, 절의 장면화 0.962 대 0.960, 전달 검사 모두 5/5다. Sonnet의 순서 교환 일치만 인정한 전체 블라인드에서 새 대화 2승 3무, 중국어 자연스러움 1승 4무로 열등하지 않았다. `~/.oh-story-bench/prereg/v0.8.3-short/`에 절차·결과가 있다. 심사자와 집필자는 같은 계열이며 조건당 다섯 작품이다.
