# 작품 간 검색

## 실행 조건

먼저 현재 프로젝트 디렉터리명·`.active-book`·작품 설정으로 현재 작품을 식별한다. 같은 이름이거나 출처가 현재 본문을 가리키는 `작품분석실/{当前书}/`와 과거에 잘못 만든 `비교작품/{当前书}/`는 제외한다. 이것들은 현재 작품을 가져와 분석한 자료이며 작품 간 표본이 아니다. 제외 후 프로젝트 루트의 `작품분석실/` 또는 프로젝트의 `비교작품/`에 작품이 2개 이상일 때만 사용한다. 주 벤치마크는 `설정/소재방향.md`의 `主对标书` 필드에서 가져온다. 없으면 제외 후 후보 중 사전순 첫 작품을 고르며 `비교작품/`를 우선하고 없을 때 `작품분석실/`를 사용한다. `gaps.main_benchmark_unspecified: true`로 사용자에게 보충을 요청한다.

> **수량 규칙:** 주 벤치마크는 최대 1작품으로 문체와 최종 본문 입력에 사용한다. 보조·참고 벤치마크의 **등록 수는 제한하지 않는다**. 실행 시 장르 관련성·참조 강도·단계 예산으로 작품마다 검색한다. 예산 초과 시 항목을 줄이고 작품 목록은 삭제하지 않는다.

## 3가지 방어선

1. 보조 벤치마크의 `문체.md`를 읽지 않아 여러 작품의 문체가 섞이지 않게 한다.
2. 인물·플롯·설정 모듈은 모든 보조 작품에서 검색할 수 있으나 관련성 다음 참조 강도로 정렬하며 아래의 작품당·전체 예산을 지킨다.
3. narrative-writer의 본문 prompt에는 주 벤치마크 문체/원문 근거 조각과 예산으로 선별한 `副对标召回摘要`만 넣는다. 보조 작품의 `문체.md`와 원문은 읽거나 전달하지 않는다.

## 다른 장르의 판단

프로젝트 `설정/소재방향.md`의 `对标书列表` 필드에서 보조 작품마다 `题材类型`(장르 유형)과 `引用强度`(참조 강도)를 읽는다. 미등록 작품은 `参考`로 처리하고 `gaps.benchmark_registry_missing: true`를 출력한다.

- 같은 장르 + 강도 `辅`: 모든 단계에서 검색할 수 있으며 작품당 상한을 따른다.
- 같은 장르 + 강도 `参考`: 가장 관련 있는 항목만 가져오고 기본적으로 작품당 상한의 절반을 넘지 않는다.
- 약한 관련성: 설정/개요에서만 작품당 ≤1개.
- 무관: 건너뛴다.

정렬은 관련성(같은 장르 > 약한 관련성), 참조 강도(`辅` > `参考`), 사용자가 `对标书列表`에 적은 순서다. 목록이 없거나 일부 작품이 미등록이면 남은 보조 작품은 디렉터리명/작품명의 Unicode 사전순으로 안정 정렬하고 `gaps.benchmark_registry_missing: true`로 목록 보완을 알린다. 보조 작품 수는 무제한이며 전체 항목 수가 단계 예산을 넘으면 항목만 줄이고 작품 등록은 줄이지 않는다.

## 단계별 사용

아래 숫자는 **보조 벤치마크 한 작품당 검색 상한**이다. 작품이 많을 때 컨텍스트가 넘치지 않도록 단계 총예산도 둔다. `—`가 있는 행은 해당 형식에 그 단계가 없으므로 행 전체를 무시한다.

| 단계 | 장편 산출물 | 단편 산출물 | 같은 장르 작품당 상한 | 약한 관련성 작품당 상한 | 단계 총예산 |
|------|---------|---------|----------------|----------------|------------|
| 설정 | `작품분석보고서.md` | `작품분석보고서.md` + `사건노드.md` | ≤2 | ≤1 | ≤8 |
| 개요 | `장별분석/*_요약.md` + `플롯/*.md` | `사건노드.md` + `집필기법.md` | ≤3 | ≤1 | ≤10 |
| 모듈 | `인물/` + `플롯/` + `설정/` | — | ≤2 | 0 | ≤8 |
| 본문 | `문체.md` + 원문 | `집필기법.md` + 원문 | 0 | 0 | 0 |

> **개요 단계는 플롯 단위로 검색한다.** 첫 키는 필수 열거값인 단위의 `类型`, 둘째 키는 `桥段标签、套路框架位置`다. 같은 장르 안에서 같은 유형의 일치 항목을 예산에 우선 넣는다. 이는 개요 단계의 플롯 단위 검색에만 적용하며 다른 단계의 정렬·예산 숫자는 바꾸지 않는다. 같은 유형이 하나도 없으면 주 벤치마크 출처 항목으로 돌아가고 비차단 알림 `gaps.similar_plot_not_found: true`를 출력하며 계속한다.

## 출력 요구

작품 간 검색에는 다음을 반드시 포함한다. 출력 제목·열·열거값은 연계 계약이므로 원형을 유지한다.

```markdown
## 副对标召回摘要
| 书名 | 引用强度 | 相关性 | 召回阶段 | 召回条数 | 使用方式 |
|---|---|---|---|---|---|
| {작품명} | 辅/参考 | 同题材/弱相关 | 설정/개요/模块 | {n} | {어떤 구조를 보충하는 데 쓰며 문체/원문 근거 조각에는 넣지 않음} |
```

보조 작품이 많으면 이번 단계에서 실제 검색된 항목만 출력한다. 검색되지 않은 작품은 삭제된 것이 아니라 이번 단계 예산에 선택되지 않은 것이다. 본문 단계에 이 표를 구조·감정·설정 참고로 전달해도 되지만 보조 작품이 문체·원문 근거 조각에 들어가지 않는 경계는 유지한다.

## 분석 필드 → 집필 참고

`_meta.json.structure_counts`를 읽을 때 아래 표로 현재 skill에 등록된 집필 reference를 조회한다. 단편은 genre-styles 장르 패키지와 short-craft, 장편은 같은 종류의 장편 이론 파일을 우선한다. 현재 skill의 참고 자료 표에 등록되지 않은 파일을 다른 skill에서 가져오지 않는다.

| 분석 필드 | 의미 | 집필 참고 |

## 公共灵感标签召回

공용 영감 태그 검색 (절명은 자료 추출 계약 원형 유지).

**이 절은 앞의 ‘작품 2개 이상’이라는 다중 벤치마크 조건과 독립적이다. 작업공간에 `영감자료실/`가 있으면 벤치마크가 하나뿐이거나 없어도 사용할 수 있다.**

`영감자료실/`와 보조 벤치마크 검색은 별도 경로다. 영감 라이브러리는 **고유명사를 제거한 작품 간 메커니즘 추상화**, 즉 태그가 붙은 active CBA 카드만 제공한다. 보조 벤치마크는 개별 작품의 구조화 요약을 제공한다. 라이브러리가 없으면 이 절 전체를 건너뛰고 `gaps.inspiration_library_missing`만 기록하며 진행을 막지 않는다.

설정·권 개요·상세 개요 작업마다 먼저 요구 태그를 만든다. 장별 본문 집필 전 검색에서는 이 경로를 쓰지 않으며 영감은 상세 개요를 거쳐 본문에 들어간다. 축은 `영감자료실/灵感索引.csv`의 태그 축 계약을 따른다. **값은 반드시 `영감자료실/태그목록.md`의 통제된 값에서 고른다.** 아래 표로 작품 맥락을 파악한 뒤 어휘표에서 가장 가까운 값에 매핑해 조회한다. 값을 새로 만들거나 동의어로 고쳐 쓰지 않는다. query는 정확히 일치하는 값으로 검색하므로 임의로 만든 값은 검색되지 않는다. 어휘표 파일이 없으면 query의 `axis_inventory`에 있는 기존 값을 기준으로 한다.

| 축(원래 식별자) | 값의 출처 |
|---|---|
| 题材(장르) | `설정/소재방향.md` |
| 读者需求(독자 욕구) | 작품의 독자 계약과 현재 기대 부채 |
| 情绪(감정) | 이번 단계/장의 목표 감정 |
| 关系动作(관계 행동) | 현재 인물 관계에서 일어날 행동, 비워도 됨 |
| 剧情功能(플롯 기능) | 도입의 약속·성장 보상·관계 역전·정보 공개·절정 결산 등 |
| 节奏位置(리듬 위치) | 초반 3장·초기·중반·권말·절정 전후, 비워도 됨 |
| 适用阶段(적용 단계) | 설정·권 개요·상세 개요 |
| 风险(위험) | 현재 피할 획일화·불균형·사전 축적 부족·인물의 억지 판단력 저하·보상 지연 등 |

사용 규칙:

1. `layer=跨书灵感聚合`이면서 `status=active`인 것만 검색하고 태그 점수로 상위 3개를 고른다. 설정/권 개요 단계는 최대 8개다.
2. 일치한 CBA 전체 카드만 읽는다. 카드 자체에 메커니즘 사슬·가변 인수·성립 조건·반례·위험이 모두 있다. **출처 ID를 따라 EM/NM을 역조회하지 않는다.** 출처는 감사·추적용일 뿐이다.
3. `selected_inspiration_aggregates`에 CBA ID·일치 태그·메커니즘 사슬·가변 인수·성립 조건·위험·출처 수를 출력한다. 설계 선택에만 영향을 주며 상세 개요의 사실·프로젝트 설정·맞춤 문체를 덮어쓰지 않는다. CBA를 문체 샘플로 삼거나 어떤 원문 읽기도 유발하지 않는다.
4. 결과가 없으면 query의 `unmatched_tags`와 `axis_inventory`를 보고 검색어를 고쳐 한 번 다시 조회한다. 그래도 없으면 `gaps.inspiration_tag_no_match`를 기록하고 계속한다. 같은 CBA에서 한 작품 안에 파생할 변형 후보는 최대 2개다.
