# Agent Note: 장편 분석 주 세션의 내용 중계를 없애고 하위 에이전트 직접 입출력·digest 집계 적용

Status: implemented
Date: 2026-09-24
Related: [2026-09-23-long-analyze-runtime-takeover](2026-09-23-long-analyze-runtime-takeover.md)

## Problem

장별 여러 사건 노드를 복구한 뒤 배치 출력이 커졌다. 백여 장 책 재분석 실측은 배치 평균 1.3만 문자, 장별 블록 약 70%·장 간 관찰 약 30%, 장당 노드 평균 16개다. 주 세션이 불필요하게 내용을 중계하는 곳이 셋이다.

1. chapter-extractor의 전체 원문 제공 요구 때문에 주 세션이 배치 원문을 읽어 prompt에 다시 쓴다.
2. Write 권한이 없어 결과를 메시지로 반환하고 주 세션이 `输入-{批次ID}.md`로 그대로 써 제출한다. 전체 약 64만 문자를 받아 가장 비싼 모델 출력 요금으로 다시 쓰며 1M 문맥에서도 반복 압축된다.
3. `material-decomposition.md`는 축약한 장 간 관찰만 읽는다고도 하고 Stage 3–5는 전체 배치 결과를 한 번에 읽는다고도 한다. 후자는 장별 요약과 중복된 블록까지 다시 읽어 전체 책을 한 문맥에 담지 못한다.

또한 입력의 확인된 별칭은 아무 호출자도 제공하지 않고, 사건 밀도는 원문과 옛 결과 보완을 구별하지 않는다. #438의 옛 제외 목록 삭제 후 장편에서 일반 명칭을 인물로 세지 않는 규칙이 사라졌으며 단편은 없는 목록을 참조한다. story-setup은 여전히 extractor 읽기 전용을 요구한다. 이전 배치의 미완 사건 등 인계는 문서만 있고 plan/commit·배분 단계에 없어 주 세션이 중계하며 발췌해야 한다. 병렬이면 끊기지만 story-import는 병렬로 안내한다.

## Decision

- **계획의 경로만 그대로 전달**: `plan`은 배치별 `batch_id`, `input_kind`, `source_files`(원문은 장별 `source_locator`), `chapter_chars`, `min_plot_points`, 출력 `input_file`, 인계 `handoff_cache`를 준다. 재배정도 이 전체를 그대로 준다. extractor가 행 번호로 원문을 Read하고 캐시의 `### 跨批状态`를 Grep한다. 계획에 없는 `plan_mode` 요구는 없앤다.
- **직접 입력 파일 작성**: 템플릿 `tools`에 Write·Edit를 더하고 Bash는 금지한다. 자가 검사·거부 후에는 Edit로 문제 행만 고친다. 최종 답은 `BATCH_WRITTEN: 批次ID | 路径 | 各章情节点数` 한 줄이다. 주 세션은 파일을 Read하지 않고 `commit`하며 거부 코드만 돌려준다. 인계 캐시는 `plan`이 고른다. 현재 시작 장보다 앞에서 가장 늦게 끝난 제출 완료 배치이며 에이전트가 `### 跨批状态`를 직접 조회한다.
- **세 배분 방식, Stage 1 후 작가 선택**:
  - 순차: 이전 제출 뒤 다음 배정, 바로 이전 배치 인계.
  - 제한 병렬: 회당 3배치, 모두 회 시작 전 최근 제출 배치를 읽고 전체 제출 후 다음 회.
  - 순서 무제한: 최대 동시 12개(환경 상한이 낮으면 그것), 절반 미만이면 상한까지 보충. `plan --next`로 더 받아 실행 중 번호를 건너뛴다. 제한·시간 초과·오류면 상한을 반으로 줄인다. 각 배치는 시작 장 이전 최근 제출 배치를 읽는다.
  - 미선택·전체 분석 요청·여러 책 분석·import 자동 재개는 두 번째이며 뒤 세 경우는 묻지 않는다. 세 번째는 명시 선택만이다. 인계 배치가 인접하지 않으면 중간 연결을 가정하지 않고 새 사건 ID를 만들어 Stage 3에서 합친다.
  - 어떤 방식이든 주 세션이 `commit`을 하나씩 실행한다. 하위 에이전트가 없으면 기존처럼 직접 작성한다.
- **인라인 hook 경로 제한**: extractor frontmatter의 PreToolUse(Write)가 `story_hook_cli.js analysis-input-guard`를 호출한다. 프로젝트 안에서 분석 폴더에 `chapter_index.csv` 또는 `_progress.md`가 있는 `_analysis_cache/输入-{RAW|REUSE}-{起章}-{止章}.md`만 허용하고 나머지는 exit 2와 이유로 차단한다. hook 입력을 못 읽으면 허용, node가 없으면 hook 명령이 실패하여 역시 차단하지 않으며 제출 스크립트 전체 검사로 보완한다. OpenCode는 단일 agent 인라인 hook이 없어 2.x edit 경로 규칙을 쓴다. `sync-opencode.py`가 `analysis-input-guard`를 인식해 edit 전체 deny 후 `_analysis_cache/输入-{RAW|REUSE}-*.md`와 모든 상위 경로를 허용한다. resource는 대화 디렉터리 상대 경로이고 `*`는 폴더를 가로지른다. `check-opencode-adapter.sh`가 2.x `evaluate()`를 독립 재현한다. OpenCode 2.0.18 실측에서 입력 저장은 되고 `章节/` 요약은 `permission.rejected`였다.
- **필요한 계획만 출력**: `plan --chapters 起-止`는 지정 범위만 계획하고 `remaining_batches`도 그 범위만 센다. `plan --next N`은 앞 N배치, `--next 0`은 진행만 보며 둘 다 `remaining_batches` 남은 총수를 보존하고 `summary_gaps`를 구간으로 줄인다. 전체 계획은 배치 약 540문자, 49배치 책은 호출 약 2.7만, 약 5배치 제출마다 확인하면 누적 12–15만이라 전체 관찰 집계와 비슷하다. 개별 배정은 `--next 1`, 무인수 출력은 유지한다.
- **digest 자료 조회**: 읽기 전용 `manage_analysis_run.py digest`는 Markdown을 출력하고 두 유형 모두 `--chapters` 창을 지원한다. `--part observations`는 진행표에서 완료되고 캐시가 온전한 배치의 장 간 관찰을 장순으로 모은다. 옛 프로젝트에 상태 행이 없으면 온전한 캐시를 검색한다. `--part chapters`는 장 요약의 라벨별 필드, `--points brief|full`은 제목｜유형｜기조 요약 또는 간결한 묘사 포함 전체 노드다.
- **읽기 통일**: SKILL.md·pipeline-ops·material-decomposition·output-templates를 같은 방식으로 맞추고 흩어진 사건 보완은 창별 노드 요약 조회로 바꾼다.
- **출력 전 기계 검사**: 실운영 15배치 중 거부 3건은 굵은 노드 제목·장 필드 “涉及人物”·독립 행 “主题标签｜基调” 누락이었다. 템플릿은 이미 요구했지만 에이전트가 빠뜨렸다. 새 10번 검사는 Grep count로 노드 행·제목 있는 행·태그 행·장 필드 열 개의 수를 비교하고 Edit로 보충한 뒤 일치할 때만 영수증을 반환한다. 자가 검사와 제출 허용 형식은 회귀로 고정한다.
- **계약 보완**: 확인된 별칭은 `### 跨批状态`에 넣어 배치 간 전달하며 agent와 직접 작성용 output-templates를 함께 바꾼다. 노드 10–20·분량 기준은 원문만 적용한다. `min_plot_points`는 글자 수÷200 반올림, 최소 1·최대 10(약 540자 프롤로그 3, 1900자 이상 10), 상한 30이다. 계획·제출은 같은 함수를 쓴다. 옛 결과 보완은 최소 1이며 기록된 사건만 나누고 억지로 늘리지 않는다. `涉及人物`·Stage 4 기록에서 집단·무명 행인·일반 명칭을 제외하고 단편은 자체 완전한 목록을 둔다.
- **주변 정렬**: setup의 Codex/Antigravity 읽기 전용 목록에서 extractor를 빼고 import 자동 재개는 회당 3배치다. Codex/OpenCode를 재생성하고 두 어댑터 검사도 맞춘다.
- **이 PR은 버전 유지**: UPGRADING·CHANGELOG `[Unreleased]`에 재배포 필요를 적고 출시 때 `agents_version`을 올린다.

## Alternatives considered

- **읽기 전용 유지·주 세션 중계**: 결과 폴더를 망칠 수 없어 안전하지만 가공 가치 없는 재출력이 문맥 대부분과 가장 비싼 모델 요금을 차지한다.
- **Write만 주고 수정 때 전체 덮기**: 권한은 작지만 행 한둘 누락에도 1.3만 자를 재출력한다. Edit도 같은 경로 제한으로 자체 입력만 바꾸므로 위험이 늘지 않는다.
- **템플릿만 제한하고 hook 생략**: 변경이 작고 제출 형식은 검사된다. 그러나 `章节/第N章_摘要.md` 등 다른 파일에 잘못 쓰면 제출 검사가 감지하지 못해 기존 결과가 손상된다.
- **공유 `story_hook_core.js`에 검사**: 구현 하나지만 단일 agent 인라인 hook은 Claude Code만 지원한다. 네 바이트 동일 사본을 이 전용 연결 때문에 바꾸기보다 Claude 연결 `story_hook_cli.js`가 적합하다.
- **순수 bash 검사**: node 없이 막지만 JSON 해석이 취약하다. node 부재 허용의 영향은 제한적이고 제출·템플릿 검사가 남는다.
- **Stage 3–5에서 장 요약만 직접 읽기**: 명령 하나가 줄지만 장 간 관찰은 캐시에만 있고 백여 파일을 열어도 양이 줄지 않는다.
- **순차만 허용**: 사건 ID·미완 상태·별칭 인계가 완전해 Stage 3가 쉽다. 그러나 3장씩 수십 배치라 시간이 길다. #438 전 독립 추출도 Stage 3 병합을 썼으며 병렬은 무효 데이터가 아니라 사후 연결 의존 증가다. 선택은 작가에게 둔다.
- **세 번째 기본**: 가장 빠르지만 운영 검증은 순차·회당 3배치뿐이다. 처음 십여 배치에 인계가 없어 Stage 3/4에 병합을 몰아준다. 검증했고 최대 한 회만 뒤처지는 두 번째가 기본이며 더 빠른 방식은 명시 선택이다.
- **동시성 무제한**: 이론상 빠르지만 호스트·계정 제한으로 실패·재실행 비용이 늘 수 있다. 최대 12와 환경 상한, 절반 미만 보충, 오류 시 반감으로 제한한다.

## Consequences

이점:

- 주 세션 토큰 약 75%, Opus 요금 약 86% 절약($20 → $2.8)이다. 49배치·행 번호만 배정 기준, 배치 고정 비용은 운영 실측, 중계·집계는 1문자≈1토큰 추산이다. 이전은 입력 약 159만(고정 5.8천×49≈28만, 결과 중계 67만, 전체 캐시 64만), 출력 약 70만(입력 파일 재작성). 이후는 입력 약 54만(고정 28만+digest 26만), 출력 약 3만(배정 설명)이다. 고정 비용은 영수증 외 시스템 포장 약 1.3천, 배정 630, 제출 410, `plan --next` 800문자와 주 세션 추론·도구 호출이며 전후 모두 든다.
- 이어 분석한 실대화는 5.75만 토큰에서 약 13배치 후 13.3만으로 압축 없이 전체를 한 대화에서 처리할 수 있었다.
- 66장 집계 실측은 관찰 7.8만, 노드 요약과 자주 쓰는 네 필드가 각각 약 1.9만 문자로 전체 캐시 28.8만의 약 40%이며 창별로 나눠 받을 수 있다.

비용:

- extractor가 쓰기 권한을 갖는다. Claude는 hook, OpenCode는 edit 경로로 제한하지만 Codex는 전체 `sandbox_mode`만, Antigravity는 도구 목록만 있어 지시·제출 검사에 의존한다.
- 기존 프로젝트는 setup 재실행이 필요하며 출시 때 `agents_version`을 올려야 한다.
- 주 세션이 배치 내용을 못 보므로 표본 품질 확인은 요약을 별도 Read해야 한다.
- 병렬 두 방식은 경계 연결이 약해 Stage 3 사건 병합·Stage 4 별칭 병합이 늘어난다. 기본 제한 병렬은 속도·연결 절충이며 안정성 우선은 순차, 속도 우선은 세 번째를 작가가 선택한다.
