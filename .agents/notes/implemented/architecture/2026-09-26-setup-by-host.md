# Agent Note: story-setup을 호스트별로 나눠 현재 호스트 문서만 읽기

Status: implemented
Date: 2026-09-26
Related: [호출별 로드를 35K로 제한](2026-09-26-per-call-load-ceiling-35k.md), [OpenCode 버전 관문](../bug-fix/2026-09-24-opencode-version-gate-fail-closed.md), [후속 수정: 호스트 변경 재배포와 단일 프로젝트 표식](../bug-fix/2026-09-26-scan-setup-review-fixes.md)

## Problem

처음 배포할 때 `skills/story-setup/SKILL.md`의 공백 제외 약 40K자를 한꺼번에 읽었다. 약 25K는 다른 일곱 호스트의 배포 목록, 알고리즘, 검증과 보고 안내였으며 호스트 하나를 쓰는 작가에게 실제 필요한 것은 약 12K였다. 절차도 유지보수자 관점이었다. 실행 환경에서 현재 호스트를 판단할 수 있어도 새 프로젝트 작가에게 호스트 8개 중 선택하게 하고 배포 위치를 다시 물었다. OpenCode 모델 선택 질문에는 chapter-extractor, consistency-checker 같은 내부 에이전트 이름이 나와 작가가 이해하기 어려웠다.

## Decision

- 진입 `SKILL.md`에는 공통 절차만 남기고 첫 배포 순서로 정렬한다. 현재 호스트 판단 → 프로젝트 루트 확인 → 호스트별 배포 → 검수 → 설치 보고다. 경로 안전 검사, 자기 중첩 잔여물 정리, 배포 표식, 템플릿 자리표시자, AGENTS.md 병합 전략과 재배포 규칙은 진입 파일에 둔다.
- 호스트 전용 내용은 `references/deploy-{target_cli}.md` 8개(claude-code, opencode, codex, antigravity, zcode, openclaw, reasonix, generic)로 나눈다. 각 파일은 `Source path`/`Target path` 머리글을 보존한 배포 목록, 알고리즘, “검증”, “설치 보고 필수 안내”를 포함한다. Phase 2 Step 1의 `target_cli → 文件`(호스트에서 파일로) 표로 연결하고 여러 호스트면 각 파일을 읽되 다른 호스트 파일은 읽지 않는다.
- 호스트 판단 순서: 배포된 프로젝트는 sentinel의 `target_cli`를 기준으로 한다. 없으면 자체 실행 환경(시스템 지침, 도구명, 호출 문법)과 실행 중인 SKILL.md 설치 경로를 본다. 그래도 모르겠으면 프로젝트 표식이 정확히 하나일 때 이를 사용한다. 모두 불명확할 때만 “지금 어느 프로그램에서 저와 대화하시나요?”라고 묻고 제품명과 쉬운 한 문장 설명을 선택지로 제공한다. 현재 호스트가 정해졌는데 다른 호스트 표식도 있으면 함께 갱신할지만 한 번 묻는다.
- 프로젝트 루트는 현재 작업 디렉터리를 기본값으로 하며 현재 위치가 홈, 드라이브 루트, 시스템 디렉터리나 스킬 패키지 자체일 때만 묻는다.
- OpenCode의 세 등급 모델 질문은 역할명(작품 분석 도우미·자료 검색 담당·교정 담당 / 집필자·인물 설계자·자료 조사 담당 / 총괄)을 사용한다. 내부 에이전트명은 “기술 비고” 열과 배포 내역에만 쓴다. 집필자(narrative-writer)는 모델 등급 표와 같이 총괄과 동일한 고급 등급에 두고 “낮은 등급 모델은 본문 품질에 영향을 주니 사용하지 마세요” 안내도 이 등급에 둔다.
- 공백 제외 글자 수: 진입 파일 10,101, claude-code 5,390, opencode 7,860, codex 4,032, antigravity 6,433, zcode 4,453, openclaw 1,978, reasonix 2,179, generic 1,617. 진입 파일＋가장 큰 OpenCode 파일은 17,961이다.
- 검사도 내용 위치를 따른다. `check-story-setup-deployment.sh`의 TS2a는 파일 8개의 존재, 진입점별 연결, 각 파일의 목록·검증·보고 안내 세 절과 표 머리글, 정확히 8개라는 수, 진입 파일에서 “사용자에게 대상 환경 선택”·“배포 위치 확인” 제거, 자체 검사 행의 배포 파일 요구를 검사한다. 기존 SKILL.md 기준은 소속 호스트 파일로 옮기고 자기 복사 탐지기는 진입 파일과 8개 파일을 모두 훑는다. skills-only 세 호스트의 타 호스트 AGENTS 템플릿 혼용 금지, Reasonix `.agents/skills` 링크 생성, Claude 재시작 표식도 검사한다. `check-{opencode,codex,zcode,antigravity}-adapter.sh`의 story-setup 기준은 해당 파일로 옮기고 라우팅을 검사한다. OpenCode는 “모델을 먼저 캐시하고 덮어쓰기”, “작가 질문에 내부 에이전트명 없음”도 추가한다. `check-current-skill-contracts.py`의 fallback 경로 금지 범위는 `skills/story-setup/references`로 확장한다.

## Alternatives considered

- **파일을 나누지 않고 텍스트만 삭제**: 단일 파일을 관리하기 쉽고 검사 위치도 유지한다. 그러나 40K의 대부분은 다른 호스트의 필수 절차(버전 관문, 훅 상호 배제, symlink 이전 동의)라 삭제할 수 없다. 하나만 쓰는 작가에게는 순수한 부담이다.
- **훅 지원 호스트 / skills-only 호스트로 두세 파일 분리**: OpenClaw·Reasonix·generic이 비슷해 중복을 줄인다. 그러나 AGENTS 템플릿, symlink, 보고 안내가 달라 합치면 남의 절차를 읽게 된다. 중복은 목록 세 행 정도라 비용이 작다.
- **질문 없이 탐지만 사용**: 작가를 방해하지 않는다. 그러나 웹 AI나 자체 에이전트는 자신이 어느 호스트인지 모를 수 있고 프로젝트에 표식이 여러 개일 수 있다. 잘못 추정하면 파일 전체를 잘못 설치하므로 쉬운 질문 한 번이 낫다.

## Consequences

- **이점**: 첫 배포 읽기량은 기존 40K에서 약 12–18K로 준다. 호스트를 알면 선택·배포 위치를 다시 묻지 않고 모델 질문을 작가가 이해할 수 있다. 호스트별 절차가 한 파일에 모여 550줄에서 흩어진 문단을 찾지 않아도 된다.
- **비용**: 경로 안전·AGENTS.md 병합 같은 공통 규칙은 진입 파일에 남고 호스트 파일과 서로 이름으로 참조하므로 이름 변경 때 함께 수정해야 한다. skills-only 파일 세 개에 소량의 중복 행이 생긴다. 호스트 판단은 모델의 실행 환경 인식에 의존하므로 잘못 판단하면 작가가 보고에서 발견해야 한다. 여러 호스트는 여전히 여러 파일을 읽는다.
- **동작 변화**: 배포 단계·검증·업그레이드 안내는 항목별로 보존한다. 호스트를 알면 질문하지 않음, 배포 위치를 기본적으로 묻지 않음, 모델 질문에 역할명 사용의 세 가지가 바뀐다. OpenClaw / Reasonix / generic 알고리즘의 “설치 보고 안내는 Phase 3 제N단계 참조”가 모두 한 단계씩 어긋나 있어 해당 파일의 “설치 보고 필수 안내”로 바꿨다.
- **처리된 할 일**: 집필자가 단계별 질문·설정 요약에서는 중급이고 등급 표에서는 고급이던 불일치를 고급으로 통일했다. 재배포에서 캐시한 집필자 모델이 예전 중급(이번 분류에서 낮음·중간)이면 고급 모델 질문이나 설치 보고에서 재선택을 안내한다.
