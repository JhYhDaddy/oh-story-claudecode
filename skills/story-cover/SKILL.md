# story-cover: 소설 표지 생성

제목과 장르에 따라 제목·필명이 포함된 완성형 표지를 만들어 독자가 장르와 분위기를 한눈에 알아보게 합니다.

**프롬프트 전용 모드**: 사용자가 프롬프트만 원하거나 `story-publish`에서 프롬프트 전용을 선택하면 Step 1-3만 수행하고 전체 프롬프트를 전달합니다. 이미지 생성 도구, API 키, 출력 디렉터리는 필요하지 않습니다. 표지 이미지를 원할 때만 Step 4-6으로 진행합니다. `story-publish`에서 호출한 경우 전달된 확정 제목, 소개, 필명, 플랫폼, 장르를 다시 묻지 않습니다. 종료 시 전체 프롬프트 원문을 반환하고, 이미지 생성에 성공하면 이미지 경로와 품질 검사 결과를 추가합니다. 실패하면 이유를 설명합니다.

---

## 생성 경로

- **Codex 내장 기능(우선)**: 현재 Codex CLI 세션에서 `$imagegen` / `image_gen`을 호출할 수 있다면 도구로 바로 생성하고 저장합니다. `OPENAI_API_KEY`나 `GPT_IMAGE_API_KEY`가 필요 없고 `curl`도 실행하지 않습니다.
- **API 대체 경로**: 세션에 내장 도구가 없거나 사용자가 API를 명시적으로 지정한 경우에만 사용하며 `GPT_IMAGE_API_KEY`가 필요합니다. 환경 변수와 명령은 [references/api-fallback.md](references/api-fallback.md)에 있으며 이 경로를 사용할 때 읽습니다. 도구가 없다고 해서 Codex 구독이 이미지 생성을 지원하지 않는 것은 아닙니다. 내장 호출이 실패하면 먼저 오류를 보고하며, 비용이 발생할 수 있는 API로 알리지 않고 전환하지 않습니다.

## 생성 절차

### Step 1: 정보 수집

먼저 현재 책을 찾습니다. 프로젝트 루트의 `.active-book`이 프로젝트 내부의 기존 디렉터리를 가리키면 그것이 현재 책입니다. 그렇지 않으면 프로젝트 루트부터 최대 4단계 아래까지 찾습니다(`.`으로 시작하는 디렉터리, `node_modules`, `작품분석실/`, `비교작품/` 제외). `추적/`, `본문/`, `설정/` 하위 디렉터리나 `본문.md`, `설정.md` 파일을 포함한 곳이 책 디렉터리이며, 여러 권이면 작가가 선택하게 합니다. `본문/` 또는 `설정/` 하위 디렉터리가 있으면 장편, `본문.md` 또는 `설정.md`가 있으면 단편입니다. 찾은 뒤 다음을 읽습니다.

- 장편: `설정/소재방향.md`의 `基本信息`(기본 정보)에서 제목, 장르 유형, 대상 플랫폼, 핵심 소재.
- 단편: `설정.md`의 `基本信息`(기본 정보)에서 제목, 대상 플랫폼, 목표 감정과 `一句话梗概`(한 줄 줄거리), `题材招式`(장르 기법).

이미 있거나 호출자가 전달한 확정 필드는 다시 묻지 않습니다. 필명이 명시되지 않았을 때만 묻습니다. 책 디렉터리가 없거나 정보가 부족하면 호스트의 질문 기능으로 누락된 제목, 필명, 대상 플랫폼을 한 번에 묻습니다.

> **제목과 필명은 표지의 필수 정보입니다.** 둘 중 하나라도 없으면 작가에게 보완을 요청하며, 지어내거나 비워 두지 않습니다.

선택 사항: 참고 이미지 `REF_IMAGE`(로컬 경로 또는 URL), 스타일 선호. 참고 이미지 사용법은 Step 4를 참조합니다.

**저장 위치**: 책 디렉터리가 있으면 묻지 않고 `{书目录}/封面/`에 저장합니다. 없으면 `./covers/{书名}/封面/`을 사용합니다. 아래의 `BOOK_DIR`는 `封面/`의 상위 디렉터리입니다.

**대상 플랫폼에 따라 비율과 업로드 크기 결정**: 판체(番茄)는 600×800, **3:4** 비율입니다. 생성 비율이 다르면 플랫폼에서 다시 자르면서 제목이나 필명이 잘릴 수 있습니다. 다른 플랫폼에는 세로 2:3으로 전달하며, 작가가 업로드 픽셀 크기를 제시하면 해당 크기로 내보냅니다. 플랫폼별 화풍 키워드는 [references/cover-styles.md](references/cover-styles.md)의 「플랫폼 스타일」을 참조합니다.

### Step 2: 장르 판별

[references/cover-styles.md](references/cover-styles.md)의 「스타일 라이브러리」에서 장르를 하나 선택합니다.

프롬프트 전용 모드에서 장르를 판단할 근거가 없으면 먼저 작가에게 묻습니다. 아래 2번의 「도시물」 기본값을 적용하지 않습니다.

1. `题材类型`(장편의 장르 유형), 줄거리나 장르 기법(단편)이 있으면 내용에 가장 가까운 스타일 라이브러리 항목을 고릅니다.
2. 정보가 없거나 어떤 항목에도 맞지 않으면(예: 시대물, 영지·농경물, 무한류, e스포츠) 제목과 필요한 경우 소개를 「장르 추론 규칙」과 대조합니다. 하나만 맞으면 그것을 사용하고, 여러 개면 표 아래 우선순위로 하나를 고릅니다. 아무것도 맞지 않으면 우선 「도시물」을 사용합니다.
3. 2번에서 추론한 장르는 Step 4에서 작가에게 시안을 보여 줄 때 함께 알리며 작가가 바꿀 수 있습니다.

### Step 3: 프롬프트 구성

프롬프트 = **텍스트 층** + **스타일 층** + **화면 층**. 디자인 지시는 영어로 작성하고 제목과 필명은 작가가 제공한 원문을 유지합니다. 선택한 장르의 글꼴, 태그, 색상, 인물, 배경, 조명은 「스타일 라이브러리」의 같은 항목에서 찾습니다.

**텍스트 층**: GPT-Image-2는 중국어를 직접 렌더링할 수 있습니다. 제목은 상단 중앙에 해당 장르의 제목 글꼴로, 필명은 하단 중앙에 해당 장르의 필명 글꼴로 배치합니다. 필명은 제목 스타일과 조화를 이루고 명확하게 읽히되 시선을 빼앗지 않아야 합니다.

- 크기는 `small`, 위치는 `at bottom center`이며 화면 아래쪽과 간격을 둡니다.
- 선, 테두리, 작은 아이콘, 빛 효과 중 하나를 반드시 장식으로 넣습니다.
- 배경과 대비되면서 눈부시지 않은 색상을 사용합니다.

**스타일 층**: 대상 플랫폼이 「플랫폼 스타일」 표에 있으면 해당 키워드 문자열을 사용합니다. 해당 항목이 없으면(예: 헤이옌, 훙궈, 미니앱) 이 층을 생략하고 장르 스타일만 사용합니다.

**화면 층**: 장르의 스타일 태그, 인물, 배경, 색상, 조명에 구도 하나를 더합니다(「구도 변형」 참조).

전체 프롬프트 템플릿은 다음 하나만 사용하며 예시와 수정본도 이 틀로 구성합니다. 영어는 이미지 생성에 전달하는 디자인 지시입니다.

```
Chinese web novel cover design, [플랫폼 스타일].
Title text '{책 제목}' at top center in [제목 글꼴].
Author name '{필명}' at bottom center in [필명 글꼴].
[장르 스타일 태그]. [구도 키워드]. [인물 묘사]. [배경 묘사].
[색상 지시]. [조명 지시].
Professional book cover, high detail digital painting, portrait [플랫폼 비율: 판체=3:4, 기본=2:3] ratio, keep title and author name inside the central safe area away from edges (inner ~85%), no watermark
```

프롬프트 전용 모드는 여기서 완성된 프롬프트 시안 1~3개를 전달하고 종료합니다. 확정되지 않은 화면 세부 사항은 선택 가능한 방향으로 제시하며 소설 속 사실로 취급하지 않습니다.

작성 요점:
- 인물 묘사는 의상, 자세, 머리 모양, 표정, 소품을 구체적으로 쓰고 `a man`만 쓰지 않습니다.
- 배경은 전경의 인물·소품, 중경의 장면, 원경의 분위기로 나눕니다.
- 조명은 `dramatic golden light from above`처럼 광원의 방향과 색상을 명확히 씁니다.
- `photo` 대신 `digital painting style`을 사용해 실사 사진 느낌을 피합니다.

### Step 4: 시안 선택과 생성

먼저 「구도 변형」에서 장르에 어울리는 구도 2~3개를 고릅니다. 각 화면을 구도, 주조색, 제목 글꼴을 포함한 한 문장으로 설명하고 Step 2에서 정한 장르와 함께 작가에게 제시합니다. 작가가 선택하면 해당 이미지 한 장만 생성합니다. 모두 생성하라고 하면 시안마다 별도로 한 번씩 생성합니다.

#### Codex 내장 ImageGen(우선)

1. Step 3의 전체 프롬프트로 `image_gen`을 호출합니다. 비율과 안전 영역은 프롬프트에 쓰고 `GPT_IMAGE_MODEL`, `GPT_IMAGE_SIZE`, `response_format` 같은 API 매개변수는 전달하지 않습니다.
2. `REF_IMAGE`가 있으면 로컬 파일은 이미지 보기 도구로 먼저 세션에 불러옵니다. URL은 다운로드한 뒤 불러옵니다. 편집 대상인지 스타일 참고인지 설명하고 반드시 유지할 내용을 나열합니다.
3. 먼저 `BOOK_DIR/封面/`을 만들고 도구가 반환한 이미지를 `封面_vN.png`로 복사합니다. `N`은 증가시키며 기존 버전을 덮어쓰지 않습니다. `$CODEX_HOME/generated_images/`의 원본을 보존하고 같은 이름의 `.prompt.txt`도 저장합니다. 참고 이미지가 있으면 `.ref.txt`도 저장합니다. 이미지가 읽히는지 확인하고 원본 이미지의 절대 경로를 Step 5에 전달합니다.

#### API 대체 경로

[references/api-fallback.md](references/api-fallback.md)를 읽고 해당 환경 변수와 명령으로 생성합니다. 참고 이미지가 없으면 텍스트로 이미지 생성, 있으면 이미지 기반 생성을 사용합니다. 생성 후 원본 이미지의 절대 경로를 Step 5에 전달합니다.

### Step 5: 플랫폼 업로드 크기로 내보내기(고정 픽셀 크기가 있을 때)

플랫폼의 업로드 크기가 고정되어 있으면(판체 600×800), 원본을 **중앙 자르기 + 크기 조정**으로 정확한 크기에 맞춥니다. 화면 비율을 유지하고 원본을 보존하며 `_上传` 버전으로 따로 저장합니다. `SRC`에는 Step 4의 원본 절대 경로, `TARGET`에는 Step 1의 업로드 크기를 넣습니다. 앞선 셸의 임시 변수에 의존하지 않습니다.

```bash
SRC='<Step 4에서 생성한 원본 이미지의 절대 경로>'
TARGET='<Step 1에서 정한 플랫폼 업로드 크기. 없으면 빈 값>'
[ -f "$SRC" ] || { echo "封面原图不存在: $SRC" >&2; exit 1; }
if [ -n "$TARGET" ] && [ -f "$SRC" ]; then
  UP="${SRC%.png}_上传.png"; W="${TARGET%x*}"; H="${TARGET#*x}"
  if command -v magick >/dev/null 2>&1; then M=magick
  elif command -v convert >/dev/null 2>&1; then M=convert; else M=""; fi
  if [ -n "$M" ]; then
    "$M" "$SRC" -resize "${W}x${H}^" -gravity center -extent "${W}x${H}" "$UP"  # 채우도록 크기를 조정한 뒤 중앙 자르기
  elif command -v sips >/dev/null 2>&1; then
    cp "$SRC" "$UP"
    sw=$(sips -g pixelWidth "$UP" | awk '/pixelWidth/{print $NF}')
    sh=$(sips -g pixelHeight "$UP" | awk '/pixelHeight/{print $NF}')
    if [ $((sw*H)) -ge $((sh*W)) ]; then sips --resampleHeight "$H" "$UP" >/dev/null
    else sips --resampleWidth "$W" "$UP" >/dev/null; fi
    sips -c "$H" "$W" "$UP" >/dev/null   # sips -c의 인수 순서는 높이, 너비이며 중앙을 자름
  else
    echo "无 magick/convert/sips，跳过；手动把 $SRC 居中裁剪+缩放到 $TARGET 再上传" >&2
  fi
  [ -f "$UP" ] && file "$UP"
fi
```

코드의 오류 출력은 각각 “표지 원본이 없음”과 “magick/convert/sips가 없어 건너뜀. 원본을 대상 크기로 중앙 자르기·크기 조정한 후 업로드”를 뜻합니다.

> 프롬프트의 중앙 안전 영역은 잘림 위험을 줄이기 위한 것입니다. 내보낸 뒤에도 Step 6에 따라 제목과 필명이 온전히 보이는지 확인합니다.

### Step 6: 품질 검사와 반복 수정

| 검사 항목 | 기준 |
|:-------|:-----|
| 문자 렌더링 | 제목·필명이 명확하게 읽히고 글꼴 스타일이 장르에 맞음 |
| 장르 적합성 | 시각적 스타일이 이 책의 장르와 일치 |
| 구도 | 주제가 잘 드러나고 글자가 핵심 화면을 가리지 않음 |
| 플랫폼 적합성 | 대상 플랫폼의 표지 스타일에 부합 |
| 플랫폼 크기 | 비율이 플랫폼에 맞고 업로드 크기로 조정한 뒤에도 제목·필명이 잘리지 않고 온전히 보임 |

기준에 미달하거나 작가가 조정을 원하면 구도, 색조, 글꼴, 플랫폼 스타일을 바꾼 뒤 새 이미지를 생성할 수 있습니다.

전달 시 아래와 같이 안내합니다. 명령, 환경 변수, API 오류를 그대로 붙이지 않습니다. 실패하면 이유와 해결책을 한 문장으로 설명합니다(예: “이미지 생성 API가 설정되지 않아 먼저 API 키를 설정해야 합니다”).

