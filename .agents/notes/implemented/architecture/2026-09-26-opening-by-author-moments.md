# Agent Note: 새 책 시작을 작가 확인 지점별로 나누고 무거운 단계는 새 컨텍스트에서 실행

Status: implemented
Date: 2026-09-26

## Problem

새 책 시작은 같은 세션에서 소재 선정, 핵심 설정, 권별 개요, 첫 상세 개요 묶음을 연속 처리하고 때로 제1장까지 쓴다. 각 단계 설명·템플릿·기법 참조가 컨텍스트에 남아 규칙만 약 34–56K가 된다. workflow-setup 12K, artifact-protocols 9K, project-files 5K에 outline-structure-theory 8K, 감정 방법 4K, 독자 계약 4K, 도입 설계 5K 등이 더해져 35K 상한의 예외로 둘 수밖에 없었다.

작가의 시간 순서에서는 방향 확정 → 설정 확정 → 권별 개요 확인 → 첫 상세 개요 확인 → 제1장 확인이다. 다음 시점에 필요한 것은 장르 포지셔닝·설정·권별 개요·상세 개요의 저장 파일이며 이전 단계의 작업 지침은 필요 없다. 반면 작가가 구두로 정한 내용이 파일에 없으면 컨텍스트를 바꿀 때 사라진다.

## Decision

- **시점별 절차 파일 분리**: `workflow-setup.md`는 방향·설정 확정(시점 표, “작가 확정 사항”을 포함한 설정 템플릿, 인계·컨텍스트 전환 규칙)만 남긴다. 권별 개요는 `workflow-volume.md`(전권 분량, 권별 개요, 비교 작품 리듬 반영, 개요 자체 검사 1–4), 상세 개요는 `workflow-outline.md`(묶음 단계, 템플릿·검수, 공급 자체 검사, 개요 보충, 설정 보완)로 분리한다. `outline-structure-theory`의 긴장·이완과 비교 작품 전이 두 절은 workflow-volume에 합쳐 전체를 읽지 않는다.
- **파일로만 인계**: 확인 지점마다 작가의 구두 결정을 `设定/题材定位.md`의 “작가 확정 사항”에 먼저 쓰고 다음 시점은 파일만 읽는다. 장르별 본문 안내 카드는 제1장 집필 시 생성한다.
- **무거운 시점은 컨텍스트 전환**: 하위 에이전트 지원 호스트에서는 설정 확정, 권별 개요, 상세 개요 각 묶음을 story-architect에 맡긴다. 주 세션은 `scripts/build_architect_brief.py --task world|volume|outline`으로 책 안의 `.story/work/排纲/`에 해당 시점의 절차·템플릿·기법만 있는 패키지를 만들고 경로를 넘긴다. story-architect는 명령 실행 권한이 없다. 상세 개요 패키지는 대상 장을 덮는 사건 전개 단위의 전체 연결 집합을 스크립트가 붙이며 한 권에 단위가 여럿이면 권 계약·상시 규칙은 한 번만 제공한다. `--check`와 `check-outline-contract.js`는 전달 후 주 세션이 실행한다. 하위 에이전트가 없는 호스트는 확인 지점 보고에서 새 대화를 권하되 강제하지 않는다.
- **예산**: 주 세션의 방향·설정·권별 개요·상세 개요와 story-architect의 설정·권별 개요·상세 개요 패키지를 각각 등록하고 모두 ≤35K로 제한한다. 새 책 시작 예외를 취소했다. 검사는 패키지 조립 스크립트를 직접 실행해 측정하고 패키지 밖 조건부 읽기는 중첩으로 등록한다.
- **검토 후 보완**: 방향 확정의 비교 자료 세대는 주 산출물 두 개의 존재로만 판단한다. 첫 인용 복사 규칙을 “비교 작품 발견” 제3항에 쓰고 project-files / artifact-protocols를 전체 읽지 않는다. 설정 단계에서 만들 파일을 명시한다. 장르 포지셔닝의 “핵심 설정”에 한 문장 줄거리·세계관 뼈대·핵심 갈등·최종 장애물을 담고 관계·주인공·핵심 인물 카드·전권 세계관을 만든다. solo도 먼저 제안하고 작가 승인 후 저장하며 물가·힘의 등급 같은 전권 척도는 먼저 묻는다. 새 대화 권고는 보고 본문의 마지막 문장, 기술 비고는 그 뒤에 둔다. 하위 에이전트가 있어도 상세 개요 전달 후 제1장은 새 대화에서 쓰도록 권한다. 모든 패키지에 SKILL.md의 “새 요소 세 단계” 원문을 붙인다. 다중 비교 작품 조회, 여성향, 인물 궤적 빠른 참조, 반전 유형, 영감 라이브러리 같은 조건부 참조는 절대 경로로 끝에 나열한다. 권별 개요의 감정 방법은 “장편 단위 감정 엔진” 절만 담는다. 요청 장이 일부만 단위에 포함되면 누락 장을 보고하고 단위 카드에 범위 행이 없으면 해당 카드를 지목한다.

## 검증

데이터 생성 전에 프로토콜을 고정했다(`~/.oh-story-bench/prereg/v0.8.2-opening/PROTOCOL.md`). 비교군은 v0.8.1 주 세션의 일괄 개요 작성, 후보군은 방향 확정 뒤 새 컨텍스트의 story-architect가 패키지별로 설정·권별 개요·첫 10장 상세 개요를 만드는 방식이다. 현환과 여성향 새 책 두 권에 군별·책별 1회 실행하고 작가는 항상 “추천대로 처리”라고 답했다.

| 지표 | 결과 | 기준 |
|---|---|---|
| Q1 첫 10장 상세 개요 계약 첫 검사 | 두 군·두 책 모두 10/10 | cand ≥ base − 1 |
| Q2 권별 개요＋첫 10장 상세 개요 쌍별 블라인드 평가 | 현환은 base 두 번 승리, 여성향은 두 판정 불일치(무승부) | 두 책 모두 패하면 안 됨 |
| Q3 같은 집필 규칙으로 쓴 제1장 쌍별 블라인드 평가 | 현환은 cand 두 번 승리, 여성향은 base 두 번 승리 | 두 책 모두 패하면 안 됨 |

세 기준은 통과했지만 개요와 첫 장에서 각각 한 책씩 졌으므로 명확한 퇴보만 배제할 수 있고 개선은 확인할 수 없다. 현환 권별 개요의 패인은 한 권을 100장으로 늘림, 중반 17장 연속 패배, 단위가 스스로 보강 필요라고 표시한 점이었다. 두 군의 권별 개요 지침은 같아 표본 차이로 분류하고 자체 검사 관찰 항목으로 남긴다. 이탈은 `DEVIATIONS.md`에 기록했다. 당시 권별 개요 architect는 아직 스크립트를 직접 실행했다(이후 패키지에 주 세션 검수를 명시). 현환 상세 개요 architect는 작가가 정할 영근 표현 하나를 남겼으며 프로토콜상 추천 선택으로 간주하고 파일을 바꾸지 않았다. 심사자는 현재 세션의 Sonnet 하위 에이전트로 집필자와 같은 모델 계열이었다.

## Alternatives considered

- **주 세션 일괄 실행을 유지하고 글자만 삭제**: 개요 작성 주체가 바뀌지 않아 위험이 가장 작다. 그러나 누적 내용의 대부분은 시점별로 나눠야 할 설명과 기법이며 35K까지 지우려면 개요 기법 자체를 잘라야 한다.
- **story-architect가 새 책 시작 전체를 담당**: 주 세션이 가장 가벼워진다. 그러나 방향·설정 확정은 작가와 주고받는 과정이므로 하위 에이전트에 넘기면 작가가 개입할 수 없다.
- **파일만 나누고 컨텍스트 유지**: 변경 범위가 작다. 그러나 같은 세션에서 이미 읽은 파일은 컨텍스트에서 사라지지 않아 누적량이 그대로다.

## Consequences

- 이점: 새 책 시작의 호출별 읽기량이 ≤35K이며 해당 시점의 규칙만 읽는다. 작가의 구두 결정도 반드시 저장된다.
- 비용: 지원 호스트에서 권별·상세 개요 작성자가 story-architect로 바뀌어 개요 스타일도 달라진다(A/B 두 책에서 각각 한 평가 패배). 주 세션이 보고하려면 하위 에이전트 산출물을 읽어야 한다. solo에서 작가가 대화를 바꾸지 않으면 누적량은 여전히 초과한다.
