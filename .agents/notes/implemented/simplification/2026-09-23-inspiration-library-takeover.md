# Agent Note: 영감 라이브러리 인수 마무리: 장별 연결 철회, 무관한 변경 분리, 등록 관문 결함 보완

Status: implemented
Date: 2026-09-23
Issue: PR #387 / #439(유지보수자 인수)
Related: [2026-09-22-inspiration-library-em-pipeline](../feature/2026-09-22-inspiration-library-em-pipeline.md), [2026-09-22-inspiration-pipeline-hardening](../bug-fix/2026-09-22-inspiration-pipeline-hardening.md), [2026-09-23-long-analyze-runtime-takeover](2026-09-23-long-analyze-runtime-takeover.md)

## Problem

영감 라이브러리 파이프라인의 방향(작품 분석에 통합, IA는 색인 행으로만 사용, EM 카드를 한 곳에서 관리, 카드 내부 경로 금지)은 타당하다. 그러나 인수 후 재검증에서 세 종류의 문제가 발견됐다.

1. **장별 상시 로드 경로가 무거워짐**: 집필 전 조회에 (a0)가 추가되고 축소된 짧은 경로에서도 그대로 실행됐다. 집필자 프롬프트에 “다른 책의 영감” 칸이 추가되고 story-explorer의 장별 `benchmark_style_load`에도 CBA 조회가 붙었다. 작업 공간에 `灵感库/`가 있으면 매 장 최대 세 개의 CBA 카드 전체를 추가로 읽게 됐다.
2. **무관한 변경 포함**: 같은 브랜치에서 인물 관계도의 기본 형식을 바꾸고 `节奏.md`의 네 절을 개요 작성에 연결하며 소비 지점을 감사했다. 비교 작품의 장 선택 동점 처리와 구조상 핵심 지점 기준도 “단일 사건 요약”에 맞췄지만 작품 분석 쪽에서는 이미 다중 사건으로 복구하기로 했다.
3. **등록 관문의 조용한 오류**(모두 재현): 제목 없는 `### EM-002`가 ID를 `EM-00`으로 잘라도 통과했다. `#### EM-002`나 `### **EM-002**`는 다음 카드를 통째로 앞 카드에 합치고도 `ok:true`를 반환했다. `--book`과 `--module`이 다른 책을 가리킬 수 있었다. 인물 카드가 하위 디렉터리에 있거나 번호 접두어가 있으면 정보 유출 검사 목록이 비었다. 책별 active CBA 상한은 자유 텍스트 `source_book` 열로 세므로 빈 값이면 우회할 수 있었다. 열 수가 잘못된 색인 행은 `validate` / `coverage`를 중단시켰다. 같은 축의 부분 문자열 유의어 판정은 “절정 전/절정” 같은 정상 어휘도 오류로 차단했다.

## Decision

- **영감 라이브러리는 기획 단계에서만 사용**한다. 새 책 시작(적용 단계=설정), 권별 개요, 상세 개요의 세 선택적 조회를 유지한다. 집필 전 (a0) 조회, 집필자 프롬프트의 “다른 책의 영감” 칸, story-explorer의 CBA 조회와 해당 계약 검사는 삭제한다. 영감은 상세 개요를 통해 본문으로 전달한다. 자주 읽는 경로의 문서 예산을 영감 라이브러리 때문에 올리지 않는다.
- 원래 브랜치의 리듬 네 절 연결, 관계도 mermaid 기본값, 소비 지점 감사, 동점 처리 변경은 **포함하지 않는다**. 해당 커밋 전체를 cherry-pick하지 않았으며 필요하면 별도 PR로 검토한다.
- **등록 관문 수정**: 카드 머리글 정규식은 번호를 정확히 고정하고 굵은 글씨·전각 구분자를 허용한다. 이름이 없으면 `em_title_missing`, 인식할 수 없는 EM 제목 행이면 `em_header_unrecognized`, 같은 카드의 중복 필드면 `em_field_duplicate`를 보고한다. `--module`은 `拆文库/{--book}/` 아래에 있어야 한다. 인물 목록은 하위 디렉터리를 재귀적으로 읽고 숫자 접두어를 제거하며 색인 항목 제목에서도 유출을 알린다. 책별 CBA 상한은 출처의 전체 연결 관계를 기준으로 센다. 잘못된 열 수는 `column_count_mismatch`로 보고하고 후속 검증에서 제외한다. CLI 출력은 UTF-8로 통일하고 I/O 예외는 구조화된 오류를 반환한다. `coverage`의 NM 구성원 기준을 `validate`와 맞추며 어휘 목록은 `* 值`를 허용한다.
- 같은 축의 부분 문자열 유의어 판정(`tag_vocabulary_near_duplicate`)을 **삭제**한다. 유의어 판정은 어휘 목록을 확장할 때 수동 비교로 되돌린다.
- **새 관문은 실제 문제만 차단**한다(재검토 후 범위 축소). `em_header_unrecognized`는 EM 번호로 시작하지만 `### EM-xxx` 형식이 아닌 제목만 잡는다(`## EM-002` 포함). EM 번호를 언급하는 일반 제목은 차단하지 않는다. `em_field_duplicate`는 관문 필드 다섯 개만 검사한다. 표 구분 행, 필드 이름 행 뒤의 들여쓴 이어쓰기 행, `***字段***`, 굵은 카드 제목은 원래 의미대로 파싱한다. `--book`은 `.`, `..`, 경로 구분자가 있는 값을 거부한다. 잘못된 행은 실제 파일 행 번호로 보고하며 I/O 오류에는 `error`와 `errors`를 함께 제공한다.
- 동시 등록에는 잠금을 추가하지 않고 문서에서 책별 직렬 실행을 명시한다.

## Alternatives considered

- **(a0)를 전체 조회에서만 실행하고 축소 모드에서는 건너뜀**: 장별 영감 진입점을 보존하며 비용도 일부 줄일 수 있다. 그러나 영감 카드는 설계 수준의 추상화이며 상세 개요가 이미 이를 받아들인다. 매 장 다시 조회하는 이점은 작고 컨텍스트 비용은 매번 든다.
- **무관한 변경을 이 PR에서 함께 검토**: PR 하나를 줄일 수 있다. 그러나 영감 라이브러리와 의존성이 없고 동점 처리 변경은 이미 폐기한 단일 사건 전제를 기반으로 한다. 섞으면 검토와 롤백이 어려워진다.
- **부분 문자열 유의어 판정을 warning으로 완화**: 유의어 증가 경고를 유지할 수 있다. 그러나 부분 문자열 관계와 유의어 관계가 일치하지 않으므로 경고도 상시 잡음이 된다.
- **등록에 파일 잠금 추가**: 병렬 등록의 행 유실을 막을 수 있다. 그러나 등록은 드문 유지보수 작업이므로 직렬로 충분하고 잠금 파일을 도입하면 남은 잠금의 정리도 처리해야 한다.

## Consequences

이점: 영감 라이브러리 때문에 장별 집필 컨텍스트와 프롬프트 구조가 바뀌지 않는다. 이 PR에는 영감 라이브러리 자체만 포함된다. 등록 관문은 카드를 조용히 삼키거나 ID를 자르거나 유출 검사를 빈 목록으로 수행하지 않는다.

비용: 본문 단계에서 CBA를 직접 조회할 수 없고 상세 개요를 통해 간접 사용해야 한다. 기존 브랜치의 리듬 연결 등은 별도 검토가 필요하다. 병렬 등록은 여전히 행을 잃을 수 있어 문서의 제약에 의존하며 어휘 목록의 유의어 증가는 수동으로 관리한다.
