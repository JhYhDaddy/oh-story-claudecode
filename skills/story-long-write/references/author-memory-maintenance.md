# 작가 기억 유지·관리

선호의 추가·확인·교체·삭제와 우선순위는 [author-memory.md](author-memory.md)를 따른다. 다음 상황에서 이 파일을 읽는다.

- 작가가 기억 정리를 요청하거나 `warnings` / `omitted_ids`가 컨텍스트에 넣지 못한 선호를 알릴 때.
- `작가프로필.md`가 가득 차거나 도구가 `state.book` 또는 단일 작품 배치 오류를 보고할 때.
- 기존 항목 마이그레이션, 다중 이벤트 `commit`, 파생 뷰 `check`, 충돌 후보·옛 항목 처리가 필요할 때.

## 파일

```text
{工作区}/.story/작가기억/          # 프로젝트 store: global / genre / workflow 항목, AP 번호
├── _author-memory-state.json  # 유일한 구조화 권위 자료
├── 작가프로필.md               # active 항목만 표시, 작가의 조회·관리용
├── 확인대기.md                 # pending / conflict, 제약으로 적용하지 않음
└── 변경기록.md               # 최근 100개 트랜잭션을 최신순으로 표시
{书}/.story/작가기억/            # 작품 store: 해당 작품의 book 항목만 저장, BP 번호, 같은 4개 파일
```

Markdown 파일 3개는 모두 state에서 생성하므로 직접 수정하지 않는다. state에는 전체 이력을 보존하고 `변경기록.md`에는 최근 100개만 표시한다. 작가는 `작가프로필.md`에서 항목을 관리한다. 창작할 때는 `query`를 호출해 이번 작업에 관련된 선호만 전달한다.

## 작업 매핑 표

집필 흐름의 `query`는 아래 표로 kind를 고른다. 후속 AI 말투 제거와 원고 검토는 집필 호출자가 넘긴 결과를 사용하며 독립적으로 조회·기록하지 않는다. 쓰기 시 예산 경고도 이 4종 작업 조합으로 추정한다.

| 작업 | query kinds | 주입 위치 |
|---|---|---|
| 본문 초고 / 이어쓰기 | `prose_style` + `story_design` | 주 세션과 실제 본문 에이전트 |
| 집필 중 AI 말투 제거 / 재작성 | `prose_style` | 주 세션과 실제 재작성 에이전트 |
| 설정 / 개요 | `story_design` + `workflow` + `interaction` | 주 세션만, 본문 에이전트에는 전달하지 않음 |
| 집필 중 검토 준비 | `delivery` + `interaction` + 필요한 `prose_style` | 주 세션, rubric 기준은 낮추지 않음 |

검토에서 일치한 항목은 납품 형식·협업 방식·작가가 의도적으로 선택한 표현의 설명에만 사용한다. 문제의 심각도와 PASS/FAIL은 계속 rubric이 결정한다.

## 주입 예산과 용량

- **주입 예산 때문에 쓰기가 실패하지 않는다.** `record` / `commit`은 정상 성공하고 영수증을 반환한다. 도구는 위 4종 작업 조합으로 최악의 조회 상황을 추정한다. 전역 항목과 각 scope 차원에서 가장 무거운 단일 슬라이스를 합산하며, 슬라이스는 대소문자 구분 없이 병합하고 무게는 실행자가 실제 읽는 행으로 계산한다. 실제 조회와 같은 기준이다. 2048바이트에 담기지 않는 조합은 `warnings`에 생략될 항목과 진술 첫 문장을 명시한다. 2048바이트는 실행자에게 주는 `lines`, 즉 항목마다 한 줄인 ‘- 진술(번호)’와 줄바꿈의 크기이며 JSON 포장이 아니다. `items`의 번호·유형·범위는 주 세션과 스크립트의 판단용이며 실행자 prompt에는 넣지 않는다.
- 저장 후 다른 계층 store를 읽지 못해도(작품 디렉터리 없음, `--book`과 작품 기록 불일치 등) 영수증은 정상 반환하고 이번 경고 계산에서 제외했다고 `warnings`에 적는다. 작품 항목을 쓸 때는 작품+전역을 실제 항목으로 정확히 계산한다. 프로젝트 항목을 쓸 때는 프로젝트 store만 보지만 `--book-root`도 주면 현재 작품을 경고 계산에 포함한다.
- 조회는 **중요도 → 현재 작품 예외 → 최근 갱신** 순서로 채운다. 같은 범위의 항목은 반드시 같은 store에 있으며 최근 여부는 해당 store의 수정 번호로 비교하고 store 간에는 비교하지 않는다. 중요도가 낮은 항목부터 제외하므로 `importance`가 초과 시 prompt에 남을 항목을 정한다. 담을 수 없는 항목은 건너뛰고 계속하므로 긴 항목 하나가 뒤의 짧은 항목을 막지 않는다. 빠진 ID는 같은 우선순위로 모두 `omitted_ids`에, 진술 첫 문장은 `omitted_summaries`에, 중요도는 `omitted_importance`에 보고한다. 주 세션은 어떤 항목을 못 넣었는지 원래 표현으로 작가에게 알린다. 장편 집필에서는 조립 스크립트가 이 문장을 검증 보고서에 만들며 장 마무리 보고에서 템플릿대로 말한다.
- 주입 예산 외에 하드 상한도 있다. `작가프로필.md`가 12288바이트를 넘으면 쓰기가 바로 실패하고 먼저 정리하도록 요구한다. active 항목이 수십·수백 개 쌓여야 닿는 상한으로 주입 예산보다 훨씬 뒤에 발생한다. 도달하면 작가 기억 정리 절차를 따른다. `forget` 같은 축소 작업은 가득 차도 정상 사용한다.

## 작가 기억 정리

작가가 기억 정리를 요청하거나 영수증의 `warnings` / 조회의 `omitted_ids`가 초과를 알리거나 프로필 용량 초과로 쓰기가 실패하면 프로젝트와 현재 작품의 `작가프로필.md`를 읽는다. 각 항목에는 범위·중요도·확신도·확인 횟수가 표시되며 중요도가 초과 시 유지 기준이다. 동의 항목 병합(`replace`로 다대일), 오래된 항목 폐기(`forget`), 잘못 `high`로 지정한 중요도 하향, 긴 진술을 한 문장으로 압축하는 안을 제시한다. 프로젝트 프로필에 `本书：` 항목이 남아 있으면 해당 작품에 `migrate --book-root`를 실행하는 것을 기본 제안에 넣는다. 목록을 원래 표현으로 하나씩 제시해 작가의 확인을 받고 번호는 괄호 안에만 쓴다. 확인 후 store별로 하나의 `commit` 트랜잭션으로 묶으며 한 트랜잭션은 store 하나만 쓴다. 병합 시 부정어·한정어·적용 범위를 보존한다. 합칠 수 없으면 하나를 폐기하며 한정어를 지워 억지로 합치지 않는다. 정리는 작가가 시작하거나 확인할 때만 하며 자동 실행하지 않는다.

## 충돌 후보

충돌 후보(`conflict`)는 기존 규칙을 우회해 바로 `decide=activate`할 수 없다. 작가가 새 표현을 고르면 `replace`의 `old_ids`에 기존 active 항목과 충돌 후보를 함께 넣는다. 새 항목은 바로 active가 되고 옛 항목 둘은 `superseded`가 된다. 기존 규칙을 유지하면 후보에 `decide=reject`를 적용한다. 기존 항목이 `replace` / `forget`으로 내려가면 더 이상 어떤 후보의 충돌 대상도 아니며, 충돌 대상이 사라진 후보는 `pending`으로 돌아간다.

## 단일 작품 배치

작품 루트가 작업공간 자체인 경우(`--book-root`와 `--workspace`가 같은 디렉터리) 작품 store는 `{工作区}/.story/작가기억/书级/`에 두고 프로젝트 store와 state를 분리한다. 최초 작품명은 프로젝트의 기존 작품 항목에서 유일하게 확인되는 작품명을 우선하고 그다음 디렉터리명을 쓴다. 옛 버전이 작품 state를 프로젝트 위치에 썼다면 프로젝트 읽기·쓰기가 `state.book` 오류를 낸다. `--book-root {工作区}`를 붙여 query를 포함한 아무 명령이나 실행하면 먼저 내용을 바꾸지 않고 그대로 `书级/`로 옮긴다. 실제로는 다른 작업공간 안의 한 작품인 디렉터리라면, 즉 상위가 `장편/` 또는 `단편/`이거나 조상 디렉터리에 `.active-book` 또는 프로젝트 state가 있으면 도구는 오류를 내고 파일을 전혀 건드리지 않는다. 오류에 따라 `--workspace`를 바로잡는다.

## 기존 항목 마이그레이션

양쪽을 중복 조회하지 않는다. 업그레이드 전 프로젝트 store에 쓴 book 항목은 조회·예산 추정에서 제외하며 프로젝트 store에 새 book 항목도 쓰지 않는다. 기존 항목은 `작가프로필.md`에 계속 보이며 `decide` / `forget`할 수 있다. 작품마다 `migrate --book-root {书目录}`를 한 번 실행하면 일괄 이동한다. 진술·증거·확인 횟수·중요도를 그대로 보존하고 번호를 `BP`로 바꾸며 원래 `AP` 항목에는 `superseded`와 이동 목적지를 표시한다. 전역 항목과의 충돌 관계는 이동 후 성립하지 않으므로 해당 후보는 `pending`으로 돌아간다. 원본 항목 하나당 작품 store 트랜잭션 하나를 사용하며 재실행하면 미완료 부분만 보충한다. 기억 정리 시 프로젝트 프로필에 `本书：` 항목이 남아 있으면 마이그레이션을 기본 제안에 넣는다.

## 옛 항목

- 업그레이드 전의 긴 진술은 새 항목의 120바이트 상한을 적용받지 않는다. 그대로 재확인하면 기존 항목을 **강화**해 확인 횟수를 1 늘리며 길다는 이유로 거부하지 않는다. 실제 새 항목을 만들 때만 120바이트를 검사한다.
- 기존 state에 추론 기반의 옛 source 항목이 있어도 읽기·확인·폐기는 가능하다. 새 쓰기에는 계속 `explicit_user`, `accepted_suggestion`, `manual`만 허용한다.

## 기타 명령

`python3`, `python`, `py -3` 순서로 Python 3을 찾은 뒤 현재 집필 skill 루트의 로컬 복사본을 실행한다. `record` / `query`는 author-memory.md를 참조한다.

```text
{PYTHON} {当前 skill 根}/scripts/author_memory_commit.py init    --workspace {工作区} [--book-root {书目录}]
{PYTHON} {当前 skill 根}/scripts/author_memory_commit.py commit  --workspace {工作区} [--book-root {书目录}] --input {工作区}/.story/work/作者记忆-事务.json
{PYTHON} {当前 skill 根}/scripts/author_memory_commit.py migrate --workspace {工作区} --book-root {书目录}
{PYTHON} {当前 skill 根}/scripts/author_memory_commit.py check   --workspace {工作区} [--book-root {书目录}]
```

- `commit`: 여러 행동을 하나의 원자적 제출로 묶어야 할 때만 쓰는 고급 일괄 진입점이다. 작가 기억 정리가 예다. 최상위에 `schema_version`, 고유한 `transaction_id`, 현재 `expected_state_revision`, 1–32개 항목의 `operations`를 전달한다. 각 항목은 단일 이벤트의 `operation`과 같은 형태다. 트랜잭션 하나는 store 하나만 쓴다. 먼저 메모리에서 schema·참조·용량·모든 뷰를 검사하고 배열 순서대로 적용한다. 어느 단계든 실패하면 전체 트랜잭션은 아무것도 쓰지 않는다. 마지막에 state를 원자적으로 교체하며 오래된 수정 번호는 어떤 쓰기보다 먼저 실패한다. 트랜잭션 파일은 성공 전까지 보존하고 성공 후 삭제한다. 명시적 기억 요청에는 author-memory.md의 영수증 전달 방식으로 답한다.
- `migrate`: 프로젝트 store에 남아 있는 특정 작품의 book 항목을 `--book-root`의 작품 store로 일괄 이동한다. 멱등적이며 중간 실패 시 바로 재실행한다. `migrated`에 원래 번호→새 번호를 반환하고 기존 항목이 없으면 빈 값이다.
- `check`: state에서 모든 파생 뷰를 재구축해 글자 단위로 검증한다. `--book-root`를 주면 양쪽 계층을 함께 검사한다.
- `init`: store의 명시적 초기화다. 보통은 필요 없으며 첫 `record`가 트랜잭션과 함께 만든다.
