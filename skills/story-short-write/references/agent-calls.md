# agent-calls.md: 단편 집필자 호출 방식

narrative-writer를 배정할 때 읽는다. 아래는 대상 역할과 prompt만 제시하며 호출 매개변수는 SKILL 상단의 현재 호스트 매핑을 따른다.

## 본문 집필

`narrative-writer`에 프로젝트 디렉터리, 출력 파일, 목표 감정, 장르 패키지 요점, 소절 개요, 인물, 주·보조 비교 작품 회수 요약, 작품 문체 전문 경로와 style_resolution, 작가 선호 query 출력의 lines, 형식 필수 제약, 집필 필수 제약만 전달한다. 검사 분담도 전달한다. 이번 묶음에서는 내용 포함 여부와 형식만 자체 점검하고 완전한 의미 기반 AI 문체 제거는 Phase 4, 최종 파일 검사는 주 세션이 담당한다.

집필자는 이 skill의 references를 읽을 수 없으므로 주 세션이 요점을 prompt에 옮긴다. 장르 요점은 `설정.md`의 `题材招式`(장르 기법) 및 장르 패키지의 말투·도입과 결말 기법·감정 강도에서 가져온다. 집필 제약은 `short-craft.md` 2·8절과 `scene-craft.md` 요점에서 가져오고 인칭·말투·서술 태도는 장르 패키지를 따른다. 형식 제약은 `설정.md`의 `平台基调`(플랫폼 기조)와 `short-format.md`에서 가져온다. 결과를 받으면 workflow-draft.md 형식 규칙으로 재배치한 뒤 `본문.md`에 쓴다.

## 정밀 수정과 AI 문체 제거

`narrative-writer`를 spawn한다. 아래 필드명과 작업 표식 `审查+去AI味`는 호출 계약이므로 유지한다. 순서대로 프로젝트·작업 설명·검사 분담·검사 범위·탐지 분류·문체 판단·작가 선호·분량·매력 보존·실행 경계·검수를 뜻한다.

Prompt: `项目目录：{dir}\n任务描述：审查+去AI味\n检查分工：이번 정밀 수정 목록과 탐지된 위치의 의미 수정·형식 검사를 담당한다. 최종 파일 검사는 주 세션이 실행한다\n检查范围：{본문 파일·수정 위치·문제 분류}\n检测类别：{탐지 분류를 그대로 기록. 대응은 deslop-gates.md「按检测类别或问题限定范围」 참조. 불명확하면 모든 표현·서술 항목으로 적되 이번 수정 문제만 처리}\nstyle_resolution：{집필과 같은 문체 판단, 전문 경로 포함}\n作者偏好：{query 출력의 lines}\n篇幅：단편\n卖点保留：1인칭 심판, 뒤늦은 후회의 예고, 마음이 식은 뒤의 여운은 구체적 기능에 따라 보존한다. 막연함·반복은 줄이고 반응을 강제로 덧붙이지 않는다\n执行边界：deslop-gates.md의 범위·권한에 따라 수정한다. 이야기 전체 재작성으로 넓히지 않는다. 동기·증거·사건 추가 또는 선택·결과·공개 시점 변경이 필요하면 구체적 설계안을 제시하고 이미 승인된 것은 실행한다\n验收：전체 장면과 소절 연결을 다시 읽고 원문 문제·수정 행동·보존 이유를 설명한다. 고정 삭제율은 쓰지 않으며 분량이 부족하면 그대로 보고한다`
