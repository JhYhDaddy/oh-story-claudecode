# workflow-outline.md: 줄거리 묶음별 상세 개요 작성·보완

## 주 세션: 상세 개요 단계와 보고

작가가 여러 장의 전개를 보거나 상세 개요를 보완·수정하려 할 때 읽습니다. 권 개요는 `outline_view.py --unit {单元ID}`로 권 전체 상시 결정과 해당 단위 관련 내용만 가져옵니다. 옛 개요에 「作用域：批次底稿」 구간이 있으면 `--stage outline`을 추가합니다. 설정은 `설정/`에서 필요한 곳만 읽고 대화를 되짚지 않습니다. 목표 감정·주인공 선택·통쾌함·5단 구성을 채울 때 [plot-core-methods.md](plot-core-methods.md)를 읽습니다. 첫 3장 상세 개요는 [opening-design.md](opening-design.md)의 「开篇规划」, 인물 카드 생성은 character-basics.md, 감정선이 있으면 character-relations.md의 「感情线阶段」도 읽습니다.

story-architect가 배포되어 있으면 묶음마다 새 맥락에서 작성하게 합니다([agent-calls.md](agent-calls.md) 참조). 없으면 주 세션이 아래 방법대로 묶음의 방향을 먼저 제안하고 작가 확인 후 저장합니다.

**회수·검증**: 각 장을 저장한 뒤 `node scripts/check-outline-contract.js --json --project {书目录} --chapter {N}`을 실행합니다. exit 1이면 `repair_scope`에 명시된 필드만 보완해 최대 두 차례 재검사합니다. 그래도 실패하면 검사 ID를 보고하고 멈추며 다른 장은 바꾸지 않습니다. advisory는 개별 판단하고 강제로 0개를 만들지 않습니다. exit 2·스크립트 누락·node 사용 불가면 검증 미완료를 사실대로 알리고 준수 완료를 주장하지 않습니다. 묶음 끝에 `node scripts/check-outline-contract.js --json --supply {卷纲路径} {单元ID}`를 한 번 더 실행해 공급 점검이 배치 초안에 기록됐는지 확인합니다(「无缺口」도 포함). 스크립트는 절의 존재만 확인하며 내용은 사람이 판단합니다. 새 작성·보완·역기입에만 이 검사를 수행하며 기존 프로젝트의 옛 상세 개요 때문에 본문 집필을 막지 않습니다.

**도중 개요 보완·확장 절차**(기존 전체 개요가 있는 프로젝트, 상세 개요만 수정하고 본문 대수정은 하지 않음):
1. 요청 범위·집필 진도·소속 단위를 찾습니다. `개요/개요.md`를 읽고 권 개요는 `outline_view.py --toc {卷纲路径}`로 찾은 뒤 `--unit {单元ID}`로 관련 범위를 가져옵니다. 단위가 없으면 `--contract`로 계약을 가져오며 전문을 읽지 않습니다. `설정/소재방향.md`와 기존 `추적/문맥.md`도 읽습니다. 본문은 있는데 추적이 없으면 보완을 멈추고 workflow-daily에 따라 복구·이전하도록 안내하며 진도를 추측하지 않습니다. 본문·추적이 모두 없으면 기존 개요·설정으로 기획하며 상태를 읽으려고 초기화하지 않습니다.
2. 요청 장이 기존 단위에 속하면 카드를 재사용하고 지목한 상세 개요만 보완·수정합니다. 단위를 새로 만들지 않으며 잠금 규칙을 유지합니다. 새 단위가 정말 필요하면 workflow-volume.md에 따라 같은 유형의 비교 단위를 선택해 새 카드를 권 끝에 **추가**하고 감정 곡선·이야기선·복선 계획도 추가합니다. 잠긴 내용은 바꾸지 않습니다. 개요 보완 요청이 다른 장 수정 권한을 뜻하지 않습니다. 이번 권의 규모를 넘으면 권 확장·새 권 개설을 먼저 확인합니다.
3. 단위 추가 시 workflow-volume.md의 자체 점검 1–4를 단위 내부 1/4·중간·3/4 기준으로 답합니다. 상세 개요 단계에서는 아래 3번 공급 점검을 수행합니다.
4. 요청한 전달 수준에서 멈춥니다. 상세 개요가 필요하면 묶음 경계에 따라 요청 범위만 작성하고 작성 후 설정 보완·묶음 최종 검토를 마칩니다.
5. 계획 사건·미래 공개는 권·상세 개요에만 저장하며 미리 추적 사실로 만들지 않습니다. 기존 본문이 있는 프로젝트의 개요 보완은 `추적/`를 쓰거나 init/commit을 수행하지 않습니다. 다음 장에서 이행해야 할 약속은 다음 본문 트랜잭션의 `next_chapter_commitments`로 들어갑니다.

**기획 전달 후 작가 보고**: 상세 개요 작성·보완·수정 모두 SKILL.md의 작가 대상 보고 지침을 따릅니다. 공급 점검·최종 검토는 내부 확인이므로 결론만 이야기의 말로 전달합니다. 작가 확인이 필요한 누락·설정 충돌은 결정할 사항으로 묻습니다. 마지막 문장에 새 대화에서 ‘제N장 집필’을 요청하도록 권하고 기술 비고는 그 뒤에 둡니다.

## 排纲方法：批次、细纲模板与设定补全

구성 방법: 묶음·상세 개요 템플릿·설정 보완 (절명은 자료 추출 계약 원형 유지).

요청 범위의 모든 장에 `개요/상세개요_제XXX장.md`가 있어야 하며 장을 건너뛰지 않습니다. 줄거리 묶음별로 작성합니다. 범위를 지정하지 않은 전체 작품 개시만 첫 10장을 기본값으로 하며 나머지는 SKILL.md의 범위·정지 지점을 따릅니다.
1. **묶음 경계**: 장 수 미지정이면 한 묶음 ≈ 줄거리 단위 하나, >10장이면 두 묶음으로 나눕니다. 첫 묶음은 10장 이하이며 여러 단위에 걸쳐도 됩니다. 단위 카드 생성 때 한 번 조회하고 후속 묶음은 결론을 공유합니다. 사용자가 장 수·범위를 정했다면 그 범위만 작성하며 단위가 안 끝났거나 남은 장이 ≤2여도 확대하지 않습니다. 단일 묶음은 여전히 ≤10장 권장. 본문 집필 중 개요가 없으면 workflow-chapter 시작 부분을 따릅니다.
2. **묶음 위치·단계 제약**(보완 전 먼저 작성): 현재 장 구간의 단계·단위 ID, 이번 묶음 추진 목표, 공개 가능한 정보·미리 공개하면 안 되는 정보, 장 끝 후킹의 경계를 씁니다.
3. **공급 자체 점검**(개요 점검 5번): 작성 전 여섯 항목을 확인합니다. ① 상대역은 누구인가? 이름 있는 상대역 간격 >2장은 검토 신호입니다. 상대역은 동료·가족도 가능하며 환경·관계 장에 간격을 맞추려고 악역을 추가하지 않습니다. ② 향후 3장 등장 인물의 카드가 모두 있는가? ③ 능력 증가와 기존 보유량이 이어지는가? ④ 사용할 숫자·제도·규칙·거리·이동 시간이 실제로 존재하는가? 참조 전에 구체적 파일 항목을 검색·대조하며 파일이 있을 것이라 짐작만 하지 않습니다. ⑤ 사용할 장소의 공간 속성을 먼저 기록합니다. 이름만 언급하면 지도를 강제로 보완하지 않습니다. 이전 단위와 같은 장소·상대·승부수가 이어져 조정이 필요한가? ⑥ 어떤 이야기선이 진행되고 조정할 기존 재료가 있는가? 결과는 `개요/개요초안_{单元ID}.md`의 「供给自查」에 쓰며 권 개요에는 쓰지 않습니다. ‘쓰고 보고’ 등급은 새 내용·설정 경로를 등록하고 ‘작가에게 먼저 질문’은 후보·영향을 작가에게 결정받습니다. 누락이 없으면 「无缺口」. 이전 묶음의 「本章没写成的」·「建纲追加」 미해결 누락도 확인합니다.
4. **단위 자료 사용**: 카드 생성 묶음은 「对标剧情参照」가 가리키는 단위 자료 ≤3개(구조 분포·사건 색인 포함)를 읽습니다. 단위 박자→장 매핑으로 배치하고 사건 소재를 바꿉니다. 같은 단위의 후속 묶음은 카드의 확정 결론을 공유하며 자료를 다시 읽지 않습니다. 권 개요에 필수 단위 필드가 없으면 먼저 보완하고 누락된 채 일일 연재로 넘어가지 않습니다.
5. **작성 중 발견한 누락**: 아래 3등급으로 처리합니다. 바로 쓸 것은 상세 개요에, 쓰고 보고할 것은 먼저 설정에 기록한 뒤 참조, 작가에게 물을 것은 영향받는 내용만 보류하고 나머지는 진행합니다. 묶음 끝에 뒤의 두 등급을 같은 초안의 「建纲追加」에 장 번호·누락·등급·설정 경로 또는 제안으로 모읍니다. 추가가 없으면 「无」. 바로 쓴 현장 재료는 중복 기록하지 않습니다.
6. **묶음 최종 검토**(매 묶음 필수): `visible_chars_v1` 기준, 필수 필드 9개, 조기 공개 금지, 실행 가능한 사건 항목을 확인합니다. ‘사건 하나=고정 글자 수’로 분량을 예측하거나 사건을 자동 보충하지 않습니다. 구조 검사는 주 세션이 실행하고 지적된 필드만 보완합니다. **옛 상세 개요는 필드 누락이 흔하므로 같은 디렉터리의 기존 필드 구성을 복사하지 말고 아래 템플릿을 따릅니다.** 의미 검사 checker는 두지 않습니다.

30장 상세 개요를 한 번에 강제로 만들지 않습니다. 전체가 ≤30장이고 사용자가 전 작품 상세 개요를 명시적으로 원하면 묶음별로 계속 전달할 수 있습니다.

### 상세 개요 템플릿과 검증

상세 개요는 본문의 장별 설계도이며 사건·후킹뿐 아니라 감정·선택·사건 항목을 명시합니다. 아래가 유일한 권위 템플릿입니다. 필수 필드 9개·소절 4개·항목별 글자 수 없는 4열 사건 표를 포함하고 단계 위치·구조 공식 등은 끝의 선택 블록에 둡니다. 새 작성·보완·역기입 모두 이 템플릿을 채웁니다. 모르는 필드는 `[待补充]`로 두고 필드를 채우려고 지선·관계를 지어내지 않습니다.

`目标情绪`·`主角目标/关键选择`는 실제 내용을 쓰며 `[待补充]`로 남기면 안 됩니다. 시작·끝 후킹은 long-chapter-hooks.md의 「章首钩子 7 式」·「章尾钩子 13 式」에서 유형만 고르고 예문을 그대로 복사하지 않습니다.

`check-outline-contract.js`는 필드·4개 소절·5단 구성·사건 표 구조와 글자 수 목표 기준의 존재만 판단하며 품질은 판단하지 않습니다. 표는 기본 4열 `# / 情节点 / 功能标签 / 执行边界（禁＋放）`이며 필요하면 기능 태그 뒤에 「分辨率」 열을 추가할 수 있습니다. 아래 중국어 제목·필드·열거값은 검증·조회 계약 표식입니다.


**누락은 새 요소 3등급으로 처리합니다. 억지로 쓰거나 무조건 모두 멈추지 않습니다.** 기준은 SKILL.md의 새 요소 3등급 지침이며 story-architect 과제 패키지 끝에도 원문이 붙습니다. 필요한 인물·능력·물가·규칙·척도·장소가 설정에 없으면 먼저 찾아본 뒤 분류합니다.

0. **먼저 검색**: `설정/세계관/`·`설정/세력/`·`설정/소재방향.md`의 성장 단계에 이미 있는지 확인합니다. 파일마다 이름이 다르거나 다른 표현으로 등록됐어도 같은 요소면 인정합니다. 없을 때 아래 등급으로 처리합니다.
1. **바로 작성**: 상세 개요에만 쓰고 별도 기록·보고하지 않습니다.
2. **쓰고 보고**(발명+기록): 기존 결정과 충돌하지 않으면 직접 보완합니다. 먼저 설정에 증분 기록한 뒤 상세 개요에서 참조하고 초안의 공급 점검에 등록합니다. 프로젝트 참조는 작품 디렉터리 상대 경로(예: `설정/인물/张三.md`)를 씁니다. `./`·`../`는 상세 개요 디렉터리 기준이며 단순 파일명은 검증하지 않습니다. 장소는 이번 묶음에 필요한 구획·출입구·상대 위치·이동 시간만 보완합니다. 개요 보완 권한으로 새 이야기선을 만들면 권 개요의 이야기선 표에서 L 번호를 먼저 배정하고 주선 연결점을 명시한 뒤 참조합니다. 일일 연재에서 자동 확장하지 않습니다.
3. **작가에게 먼저 질문**(제안·결정): 임의 결정하지 않습니다. 초안 공급 점검에 구체적 누락·후보 1-2개·관련 설정 영향을 적고 묶음 끝에 보고 템플릿으로 쉽게 질문합니다. 결정은 먼저 설정에 기록한 뒤 참조하며 임시 표식·지어낸 숫자로 대신하지 않습니다. 설정끼리 충돌하면 출처를 나열해 작가에게 판단받습니다.

기존 설정 파일은 새 정보를 **덧붙이며 덮어쓰지 않습니다.** 일회성 행인·후속 비중 없는 조연은 정적 카드·동적 스냅샷을 만들지 않습니다. 상세 개요에서 확정된 것만 채우고 미정 필드는 자리표시자로 두며 미리 지어내지 않습니다.

### 줄거리 묶음별 상세 개요 경계

한 묶음 = 권 개요의 줄거리 단위 하나. 단위 글자 수 ÷ 장 목표 글자 수로 장 수를 환산합니다. 장 목표는 기존 상세 개요 관행을 따르고 없으면 장르 리듬 기본값(빠른 전개 약 2000, 균형형 약 3000)을 씁니다. >10장이면 두 묶음으로 나누되 같은 한 번의 조회를 공유합니다. 첫 묶음은 10장 이하이며 여러 단위에 걸쳐도 됩니다. 걸쳐 들어가는 단위는 카드 생성 시 한 번 조회하고 남은 장은 후속 묶음이 카드 결론을 공유합니다. 정지 규칙은 위 1번을 따릅니다.

카드 생성 시 **줄거리 묶음 조회**를 한 번 합니다. 「对标剧情参照」가 가리키는 단위 자료 ≤3개의 「结构分布」·「情节点索引」를 읽고 해당 작품 `플롯/리듬.md`의 같은 장 구간 통쾌함 순환·감정 자극점과 인용 감정 모듈 카드를 확인합니다. 공통 박자 5-8개를 카드의 「单元节拍/章功能分配」에 씁니다. 감정 동력 필드는 주 비교 작품 `플롯/감정모듈.md`의 재현 가능한 모듈로 조정합니다. 주 산출물은 있지만 특정 카드만 없으면 그 카드만 생략합니다. `플롯/감정모듈.md`·`플롯/리듬.md` 파일이 없으면 workflow-volume.md의 리듬 이전 규칙에 따라 즉시 멈추고 복구합니다. 소재 교체·약점 보완은 해당 절 3/4번과 같습니다. 감정 연쇄·기능적 자리는 유지하고 대상·장소·사건을 모두 바꾸며 약점은 그 자리에서 고칩니다. 카드에 결론을 확정하면 각 장 상세 개요는 카드만 사용하고 원래 단위를 다시 읽지 않습니다.

**‘카드만 사용’은 비교 작품을 다시 읽지 말라는 뜻이며 장별 개요 작성을 동결하지 않습니다.** 상대역 없음·수치 미검증·장소 지도 없음·인물의 기존 규칙이 장면을 막음 등의 누락은 위 3등급으로 처리합니다. 바로 작성 / 쓰고 보고는 먼저 기록 후 참조 / 작가 질문은 제안을 보류합니다. 처리 후 한 줄씩 적고 묶음 끝에 초안의 **「建纲追加」**로 모읍니다. 다음 묶음의 공급 점검은 이 절을 고정 입력으로 읽고 누락 유형에 따라 사전 점검 항목을 더합니다.

일일 연재 중 권 개요에 「对标剧情参照」 등 현 프로토콜 필수 필드가 빠졌으면 먼저 보완하고 상세 개요를 만듭니다. 잠긴 권 개요에 자동 반영하지 않고 보완 경계에서 멈춰야 합니다. 단위 박자 분석 과정은 추적 파일에 쓰지 않습니다. 미래 연속성에 실제로 영향을 주는 최종 제약·다음 장 약속만 이번 장 트랜잭션에 넣습니다.
