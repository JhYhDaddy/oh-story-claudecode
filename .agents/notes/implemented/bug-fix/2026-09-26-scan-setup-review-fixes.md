# Agent Note: 순위 조사와 배포 검토에서 발견한 수정 사항

Status: implemented
Date: 2026-09-26
Related: [순위 조사 결과를 먼저 집계한 뒤 읽기](../feature/2026-09-26-scan-aggregate-and-handoff.md), [story-setup 호스트별 분리](../architecture/2026-09-26-setup-by-host.md)

## Problem

v0.8.2의 순위 조사 집계·저장과 story-setup 호스트별 분리를 병합한 뒤 연결 단절과 조용한 실패를 발견했다.

- 장편 순위 조사 Phase 4는 항상 `选题决策.md`를 쓰지만 소재를 고르지 않고 조사만 하면 “추천 소재”가 없다. 새 책 시작은 소재 선택 출발점으로 취급하고 작품 분석 갱신은 계약 무효로 판단해 양쪽이 잘못 진행한다.
- 기존 프로젝트는 sentinel의 `target_cli`를 읽으면 호스트 판단을 건너뛰어 작가가 프로그램을 바꿔도 새 호스트를 설치하지 못한다. 판단 불가일 때 프로젝트 표식이 하나면 현재 호스트로 단정해 전체 파일을 잘못 설치할 수도 있다.
- 판체 서고는 0권이어도 빈 파일을 쓰고 `--channel all`의 일부 채널이 검증 페이지로 이동해도 로그 한 줄만 남기며 성공 코드였다. 집계기는 항목 없는 순위 파일을 건너뛰어 “수집 상황”에도 실패가 보이지 않았다. 상세 페이지에서 첫 `readCount` / `lastChapterTitle`을 찾으므로 추천 작품이 먼저 나오면 그 값을 현재 책에 붙였다.
- 조사마다 새 디렉터리를 만들라는 규칙이 없어 같은 디렉터리에 두 번째 결과를 쓰면 이전 순위가 섞였다. 단편 집필은 프로젝트 루트·한 단계 위에서만 `短篇扫榜结论.md`를 찾아 “같은 수준 디렉터리에서도 보임”이라는 안내와 달랐다.
- 작가 폴더의 `扫榜聚合.md` 끝에 `--sample … --n 5` 명령이 있고 수집 상황에는 `[OK]`, `[标题解析异常]` 같은 표식이 있었다. OpenCode 버전 관문은 “첫 행에 미배포”를 요구해 “지금 할 수 있는 일부터 설명” 보고와 충돌했다. 수동 모델 설정 안내는 경로·필드 이름으로 배포 내역 안에 있었다.

## Decision

- **추천 소재 없는 결정 문서**: story-long-write 방향 확정은 “추천 소재” 없는 `选题决策.md`를 아직 소재를 고르지 않은 상태로 보고 일반 질문을 한다. story-long-analyze는 갱신을 건너뛰고 파일 무효로 판단하지 않는다. 추천 소재가 있는데 “성공 가능 이유” 같은 항목이 없을 때만 계약 오류다.
- **호스트 판단**: sentinel의 호스트는 다시 선택받지 않고 재배포하되 단계 4에서 현재 호스트도 판단한다. 알 수 있고 배포 목록에 없으면 “함께 설치할까요?”라고 묻고 동의 시 `target_cli`에 더한다. 판단 불가이면 프로젝트 표식은 후보일 뿐이다. 하나면 “지난번에는 X용으로 설치했는데 이번에도 같은가요?”, 그 외에는 어느 프로그램에서 대화하는지 묻는다. `check-story-setup-deployment.sh`에 두 기준을 추가한다.
- **수집 실패 집계**: 판체 순위·서고 모드 모두 한 채널/순위에서 0권, CDP 무응답, 검증 페이지 이동이면 오류를 내고 파일을 쓰지 않으며 실패로 센다. 주 절차는 `runCli`의 `{planned, written, failed, partialReasons}`로 보고한다. 일부 실패는 종료 2와 채널·사유, 전체 실패는 종료 1이다. 집계기는 첫 행이 순위표처럼 보이지만 항목이 없는 파일을 “수집 실패: 전체 순위표에 한 권도 없음”으로 표시하고 장르 통계에서는 제외한다. 빈 순위표만 남으면 파일명을 나열하며 실패한다.
- **상세 페이지는 해당 책만 추출**: 자립적인 `parseDetailHtml` 함수로 분리하고 함수 소스를 브라우저 스크립트에 넣는다. 먼저 `bookId`를 감싸며 `bookName`이 있는 가장 안쪽 JSON 객체를 문자열 인식 괄호 매칭으로 찾고, 없으면 `<title>`의 작품명으로 찾는다. 제목·작가·소개·장르·숫자·최신 장은 그 객체에서만 읽고 최신 장은 JSON 문자열 이스케이프를 해제한다. 모두 못 찾으면 제목·작가는 `<title>`/meta로 보완하고 숫자는 비운다.
- **조사 디렉터리**: 장·단편 모두 매번 `扫榜/{YYYYMMDD}/`를 새로 만들고 같은 날 재실행하면 `-2`를 붙인다. 이전 디렉터리에 추가하지 않고 비교는 이전 날짜의 `扫榜聚合.md`를 읽는다. 단편 집필은 프로젝트 루트와 상위 디렉터리에서 아래 세 단계까지 `短篇扫榜结论.md`를 찾아 최신 것을 선택한다. 장편의 `选题决策.md` 탐색과 같은 기준이다. 전달 안내는 “소설 프로젝트를 조사할 때의 폴더 안이나 그와 같은 수준에 만들기”로 바꾼다. 단편 집계에는 `--scale short`를 고정 추가한다.
- **작가 가독성**: `扫榜聚合.md`에서 명령 인수를 제거한다. 수집 품질 표식은 정상·대부분 작품명 해독 실패·데이터 없음 같은 쉬운 표현으로 바꾸고 `--json`의 `quality` 값은 유지한다. OpenCode 버전 차단 시 “지금 할 수 있는 일”에는 설치된 호스트만 쓰고 “추가로 해야 할 일”에는 미설치와 이유를 쉽게 설명한다. 모델 목록을 못 읽을 때의 안내도 후자로 옮겨 따라 할 수 있는 작가용 템플릿으로 바꾸며 경로·필드명은 배포 내역 한 줄에만 남긴다.
- **테스트**: `test-scan-aggregate.py`에 서고 `--channel all`의 여성향 검증 페이지 이동(종료 2, 남성향만 저장), 서고 0권(종료 1, 파일 없음), 빈 순위표 표시·품질 표식 쉬운 표현, 집계 파일 명령 인수 없음을 추가한다. `vm`의 가짜 `XMLHttpRequest`에 픽스처 HTML을 주고 `buildDetailJS` 생성 스크립트를 실제 실행한다. 추천 책이 앞에 있어도 현재 책 숫자 선택, 숫자·문자열 두 형태의 `readCount`/`wordNumber`, 최신 장의 이스케이프 따옴표, `bookId` 없을 때 제목 탐색, 위치를 못 찾으면 숫자 빈 값을 검증한다.

## Alternatives considered

- **조사만 해도 빈 “추천 소재” 절 작성**: 소비자를 바꾸지 않고 형식을 유지한다. 그러나 새 책 시작은 이를 소재가 있다고 오인해 첫 항목을 찾고 분석 갱신도 대상이 없는 이유를 알 수 없다. 절 존재 여부로 판단하는 편이 직접적이다.
- **sentinel 값이 있으면 호스트 판단 생략(기존)**: 재배포가 작가를 방해하지 않고 skills-only 세 호스트도 탐지할 수 없다. 그러나 프로그램 변경은 실제 상황이며 새 호스트가 빠지면 본문 보호 등 전체 기능이 안내 없이 사라진다. 판단 불가면 그대로 sentinel 배포·무질문을 유지하고 새 호스트를 실제로 알 때만 질문한다.
- **서고 0권이면 `[无数据]` 파일을 쓰고 집계에서만 표시**: 실행 흔적을 작가가 볼 수 있다. 그러나 수집 성공 코드 때문에 주 세션이 실패를 놓친다. 파일 미작성과 종료 1/2로 수집 때 알리고 집계도 빈 파일을 표시해 두 단계 모두 조용히 실패하지 않게 한다.
- **단편 탐색은 그대로 두고 전달 문구만 수정**: 진입 예산이 빠듯하다. 그러나 결과가 `扫榜/{日期}/`에 들어가면 루트·상위만 검색해선 못 찾는다. 탐색 설명은 열몇 자만 늘어 여전히 예산 안이다.

## Consequences

- 이점: 소재 미선택 조사, 호스트 변경 재배포, 채널 차단, 추천 책 숫자 혼동이 조용히 실패하지 않는다. 재조사에 예전 순위가 섞이지 않고 작가용 집계·설치 보고에 명령 인수·내부 표식이 나오지 않는다.
- 비용: 판체 일부 실패 코드는 0 대신 2이므로 호출자가 “결과는 있지만 불완전”으로 처리해야 한다. 상세 페이지가 `bookId`도 없고 `<title>`도 맞지 않게 바뀌면 독자 수·글자 수는 잘못된 값 대신 “알 수 없음”이다. 날짜 디렉터리 한 단계가 늘고 예전 평면 결과는 작가가 직접 옮겨야 한다. 새 책 방향 확정, 배포 진입점·OpenCode 배포, 장단편 조사 진입 파일에서는 새 규칙만큼 기존 글자를 줄여 예산을 올리지 않았다.
