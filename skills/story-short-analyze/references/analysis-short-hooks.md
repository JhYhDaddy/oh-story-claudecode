# 단편 원문의 훅 분석 기준

> 원문이 단락·소절·유료 전환 지점에서 독자의 예상을 어떻게 바꾸는지 관찰한다. 실제로 등장한 훅, 약속, 후속 응답만 보고한다. 장의 시작·끝 템플릿을 제공하거나 연재 반복 구조·고정 글자 수를 적용하지 않는다.

## 훅의 성립 조건

단락이나 소절의 경계에 훅이 있는지 판단하려면 먼저 ‘독자가 다음에 무엇을 기다리는가’를 어떻게 바꾸는지 본다. 문장 끊기, 감정 고조, 인물의 경악, 예고도 구체적인 질문과 연결해 판단한다.

후보 지점마다 다음을 기록한다.

```markdown
위치: {단락/소절/유료 전환 지점}
경계 이전에 아는 것: {사실과 판단}
경계에서 추가된 것: {행동·증거·관계·위험·선택}
독자의 새 질문: {구체적인 질문}
후속 응답: {위치와 제공 내용}
```

## 기능 유형

| 유형 | 관찰 가능한 변화 | 흔한 오탐 |
|---|---|---|
| 미완료 행동 | 인물이 위험한 행동을 시작했으나 결과는 아직 나오지 않음 | ‘그는 결심했다’고만 하고 다음 절에 행동이 없음 |
| 증거의 귀속 | 새 증거가 나오고 소지자·진위·해석권이 바뀜 | 배경 정보 하나만 추가함 |
| 신분/동기의 균열 | 행동이 표면의 신분이나 동기와 모순되며 되짚어 확인할 수 있음 | 끝에서 곧바로 ‘그에게는 비밀이 있다’고 선언함 |
| 관계 전환 | 신뢰·동맹·통제·책임이 바뀜 | 감정적으로 다투기만 하고 관계상 위치는 그대로임 |
| 양자택일의 딜레마 | 두 선택에 실제 대가가 있고 아직 선택하지 않음 | 한쪽이 명백히 불가능한 가짜 선택 |
| 위험의 구체화 | 추상적 위협이 구체적 기한·손실·책임 추궁으로 바뀜 | 형용사만 과장하고 행동 조건은 그대로임 |
| 단계적 답 | 부분 문제에 믿을 만한 답을 주면서 설명의 빈틈을 드러냄 | 답 직후 인과 없이 다시 뒤집음 |
| 결과의 역습 | 막 끝낸 행동이 예상 밖이지만 추적 가능한 결과를 낳음 | 이전 행동과 무관한 새 위기가 갑자기 생김 |
| 미결 감정 | 관계나 윤리적 선택이 아직 결산되지 않음 | 작가의 요약으로 인물에게 생길 결과를 대신함 |

## 강도 판단

주관적 등급이나 ‘반드시 누르게 된다’는 수식어로 판단하지 않는다. 검증 가능한 세 항목을 비교한다.

1. **예측 변화**: 경계가 독자의 혐의·관계·결과·대가에 대한 예측을 갱신하게 하는가.
2. **행동 견인**: 다음 단락/절이 새 화제를 여는 대신 이 변화에 반드시 응답해야 하는가.
3. **약속 이행의 질**: 응답이 질문을 반복하는 데 그치지 않고 증거·선택·결과를 제공하는가.

세 항목을 종합해 견인력의 강약과 이유를 설명한다. 일부만 성립하면 충족 항목과 빠진 점을 각각 기록하고 강약 꼬리표만 붙이지 않는다.

## 훅의 연결 사슬

앞 질문에 대한 응답이 다음 질문의 원인이 되는 인과 연결을 추적한다.

| 시작 위치 | 질문 | 응답 위치 | 응답의 제공 내용 | 다음 질문이 생기는 방식 |
|---|---|---|---|---|

다음 질문과 앞 답 사이에 인과가 없으면 ‘별도 질문 시작, 연결 끊김’으로 보고한다. 여러 질문이 연속해서 부분적인 답조차 받지 못하면 ‘질문만 하고 답하지 않음’으로 보고한다.

## 유료 전환 지점

유료 전환 지점은 상업적 위치이고 훅은 서사 기능이므로 서로를 증명할 수 없다. 각각 다음을 점검한다.

- 전환 지점이 미완료 행동, 증거 귀속의 변화, 관계 전환, 실제 딜레마에 놓이는가.
- 결제 이후 전환 지점의 약속에 신속히 응답하는가.
- 곁가지로 지연하지 않고 핵심 질문을 진전시키는가.
- 핵심적인 큰 쾌감이 전환 지점 전에 이미 모두 해소되었는가.
- 플랫폼 정보가 없으면 ‘강한 전환 지점 후보’만 보고하고 실제 과금 위치를 추측하지 않는다.

## 보고 형식

```markdown
핵심 훅: {위치·유형·경계 전후 변화}
독자의 새 질문: {구체적인 질문}
후속 응답: {위치·제공 내용}
훅의 연결 사슬: {인과 연결 또는 단절}
유료 전환 지점: {확인됨/후보/증거 부족}
약한 경계 또는 가짜 훅: {위치와 이유}
```

## 범위

- `structure_counts.hooks`는 위 기능 유형이 성립하는 훅을 센다. 실제 수를 기록하며 0도 가능하다. 고정 수량을 원문 품질의 문턱으로 삼지 않는다.
- 이웃한 소절의 견인력을 비교할 수 있으나 모든 절에 강한 훅을 요구하지 않는다.
- 고정 글자 수로 장의 시작·끝을 검사하지 않는다. 경계의 길이는 정보와 행동에 따른다.
- 구경꾼의 경악, 시스템 보상, 새 무대를 자동으로 훅이라 판단하지 않는다. 독자의 질문을 바꾼다는 증거가 필요하다. 주변 반응은 새 정보를 주거나 대중의 평가를 바꾸거나 행동을 끌어낼 때만 기록한다.
