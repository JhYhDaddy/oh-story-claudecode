# Agent Note: 영감 라이브러리 등록 파이프라인 강화: 유출 검사 위치, 전체 오류 일괄 보고, 증분 안내

Status: implemented
Related(인수 마무리): [2026-09-23-inspiration-library-takeover](../simplification/2026-09-23-inspiration-library-takeover.md) — 장별 연결과 부분 문자열 유의어 판정은 이 후속 기록에서 철회했다.

최초의 실제 규모 라이브러리(20권, 원자 150개 이상) 구축 실측에서 드러난 파이프라인 결함을 #439 브랜치에서 마무리한다.

## Problem

- 유출 검사가 `root.parent`에서 인물 목록을 암묵적으로 가져왔다. 영감 라이브러리가 `拆文库/`와 같은 수준이 아니면 목록이 늘 빈 집합이라 고유명사 검사가 아무 작업도 하지 않았다. 샌드박스에서는 모두 통과하고 실제 작업 공간으로 옮기면 즉시 차단되어 같은 책들에 결과가 달랐다.
- `角色/` 디렉터리가 없는 책은 검사를 완전히 우회해 카드에 고유명사가 가득해도 통과했다.
- 인물 카드가 “검객”, “대부인” 같은 역할명으로 되어 있으면 추상 구조의 일반 단어를 부분 문자열 일치로 고유명사라 판단했다. 다만 같은 유형의 실제 유출도 있었다. 카드의 “그대로 가져오면 안 되는 요소”에서 그 단어를 지목하고 다른 필드에서는 그대로 사용했다.
- 필드명 다음 행에 값이 있는 자연스러운 목록 형식은 빈 문자열로 파싱되어 “필드 누락”을 보고하고 조사를 엉뚱한 방향으로 이끌었다.
- `可替换项`에 “원작 고유명사→임의의 X”를 많이 썼다. 교체 가능성을 선언하는 듯하지만 실제로 검사 대상 추상 필드에 고유명사를 넣어 실측 유출의 주요 원인이 됐다.
- 첫 오류에서 즉시 raise하여 한 곳 수정·재실행·다음 오류 보고를 반복해야 했다. 읽기 전용 검사 모드도 없었다.
- `SKILL.md` Stage 3가 임의로 만든 필드명 일곱 개는 스크립트의 관문 필드 다섯 개와 하나도 맞지 않았다. 집필자가 최상위 문서대로 카드를 만들면 책 전체를 등록하지 못했다.
- 라이브러리 구축 이후 책 간 집계 계층에는 새 원자와 이미 반영한 원자를 알려 주는 기계적 신호가 없어 LLM이 전체를 다시 훑어야 했다.
- 태그 값의 통제 어휘 목록이 파일로 없었다. 첫 집계에서 정한 목록은 세션 합의에만 있어 세션·호스트가 바뀌면 어긋났다. query는 문자열 정확 일치라 어긋나면 조용히 일치 0개가 된다. validate는 값 검사를 하지 않았고 집필 쪽도 태그를 임의로 만들었다.

## Decision

- `--root`에서 위로 올라가며 `拆文库/`를 가진 작업 공간을 찾고 `--workspace`로 명시할 수도 있게 한다. 실패하면 `workspace_not_located`를 보고한다. 출력에는 항상 `character_roster` 수를 포함하며 책 디렉터리는 있지만 `角色/`가 없으면 `character_roster_missing` warning을 낸다. `validate`의 EM 집합 검사도 같은 위치 탐색을 사용한다.
- 고유명사 검사를 두 단계로 나눈다. 카드의 “그대로 가져오면 안 되는 요소”에서 지목한 단어를 추상 필드에서 사용하거나 `可替换项`이 “고유명사→임의의 X” 반패턴(`replaceable_antipattern`)이면 error를 유지한다. 카드 파일명 부분 문자열만 맞고 뒷받침할 증거가 없으면 `leak_suspect` warning으로 낮추고 해당 필드를 나열한다. 판단은 카드 내부의 모순에 근거하고 역할명 사전은 도입하지 않는다.
- 굵은 필드 이름의 여러 행 값을 다음 필드·제목까지 받아들인다. `em_field_value_empty`와 `em_fields_missing` 오류를 구분한다.
- `register-atoms`는 모든 카드의 문제를 `errors` 배열로 한꺼번에 보고하며 error가 하나라도 있으면 파일에 쓰지 않는다. Stage 3 저장 후 자체 검사 진입점으로 읽기 전용 `check-atoms`를 추가한다.
- 읽기 전용 `coverage`는 어떤 active CBA 연결 집합에도 들어가지 않은 원자와 기존 단일 책 가설 카드를 나열한다. 책 간 집계의 LLM 작업은 uncovered 증분만 처리한다.
- 태그 값은 라이브러리의 `灵感库/标签词表.md`(축별 절, 한 줄에 값 하나)로 통제한다. 목록이 있으면 validate는 목록 밖 값(`tag_value_not_in_vocabulary`), 같은 축에서 서로 부분 문자열인 유사 값 쌍(`tag_vocabulary_near_duplicate`, 유의어 증가를 기계적으로 차단), 필수 축 누락(`vocabulary_axis_missing`)을 거부한다. 목록이 없으면 검사하지 않아 기존 라이브러리를 지원한다. 확장 전에는 의미가 겹치거나 포함되면 기존 값을 쓰고 새로운 차원일 때만 추가한다. `query`는 `unmatched_tags`와 `axis_inventory`를 반환하며 일치 0개면 용어를 수정해 한 번 재조회한다. 집필 쪽(cross-book-recall, story-explorer 템플릿)의 태그 값도 목록에서만 가져오며 어댑터를 다시 생성했다.
- 기준 통일: 관문 필드 다섯 개를 `SKILL.md`에 명시하고 동의어 이름은 인식하지 않는다. 색인 절 제목은 리터럴 `## 其他机制索引`으로 고정한다. 파서에서 제목을 완화하면 방금 금지한 불일치를 다시 수용하므로 완화하지 않는다. 전체 카드 수는 사용자의 결정에 따라 “가장 강한 세 개”에서 “최소 상위 세 개 포함, 상한 없음”으로 바꿔 스크립트와 맞춘다.
- 실제 분석 표본에 맞춰 파싱 형식을 넓힌다. EM 번호는 두 자리부터, `·/-/—` 구분자, 표의 굵은 필드 이름, 굵은 목록 형식, 동의어 필드명 정규화를 허용한다.

## Alternatives considered

- **색인 절 제목 파싱 완화**(“나머지 구조(색인)” 같은 변형 허용): 입력을 넓게 받아들이고 엄격히 출력하며 기존 파일 수정을 줄일 수 있다. 그러나 제목을 리터럴로 고정한 기준과 모순되므로 파일의 제목을 수정한다. 향후 바꾸려면 기준과 파서를 함께 바꿔야 한다.
- **유출 의심을 모두 error로 유지**: 실제 유출을 놓치지 않는다. 그러나 장편 인물 카드의 역할명은 흔해 오탐이 계속 등록을 막는다. 실측 실제 유출은 카드 내부 모순이나 반패턴 화살표라는 두 고신뢰 기준으로 포착되므로 나머지는 warning과 수동 검토로 처리한다.
- **역할 단어 허용 목록**: 구현이 가장 간단하다. 그러나 다양한 명명 방식을 따라갈 수 없고 인물 이름이 실제로 그 일반 단어인 유출을 놓치므로 포기한다.
- **coverage를 validate에 통합**: 하위 명령을 줄인다. 그러나 validate는 오류 시 실패하는 관문이고 coverage는 안내이며 uncovered는 오류가 아니므로 분리한다.

## Consequences

이점: 샌드박스와 실제 작업 공간의 동작이 일치하고 유출 검사를 신뢰할 수 있다. 책의 모든 문제를 한 번에 확인한다. 읽기 전용 자체 검사와 증분 안내로 라이브러리 구축·확장을 위해 임시 스크립트를 만들 필요가 없다. 집필자가 최상위 기준대로 카드를 만들면 등록할 수 있다.

비용: 근거 없는 인물 목록 일치는 강제 차단에서 warning으로 낮아져 수동 검토가 필요하다. `check-atoms`가 일치 위치를 제공해 비용을 줄인다. 다양한 형식을 허용하므로 템플릿 밖 표현의 여지가 늘어나며 관문 필드와 고정 제목으로 최소 기준을 지킨다.
