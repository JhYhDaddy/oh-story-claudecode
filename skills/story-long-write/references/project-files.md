# 프로젝트 파일과 산출물 계약

#### 프로젝트 파일 구조

저장이 필요할 때 사용자 지정 디렉터리에 아래 구조로 정리한다. 논의만 할 때는 프로젝트를 만들지 않는다. 계획만 할 때는 이번 산출물에 필요한 디렉터리만 만들며 트리를 채우려고 본문이나 추적 자료를 생성하지 않는다.

```
{书名}/
├── 설정/
│   ├── 세계관/
│   │   ├── 배경설정.md        # 시대 배경·지리·역사
│   │   ├── 능력체계.md        # 수련/능력/등급 체계
│   │   └── ...
│   ├── 인물/
│   │   ├── 沈栀.md            # 인물마다 파일 하나, 파일명은 인물 이름
│   │   └── ...
│   ├── 세력/
│   │   ├── 天机阁.md          # 세력/조직마다 파일 하나
│   │   └── ...
│   ├── 관계.md                # 인물 관계 대응
│   ├── 소재방향.md            # 장르 핵심 아이디어+벤치마크 분석+결말용 비장의 패/성장 단계(쓸거리 고갈 방지)
│   ├── 문체.md                # 작품의 맞춤 문체(선택)
│   └── 소재본문안내.md       # 장르 본문 핵심: 경계/기대/쾌감/리듬/이탈 금지
├── 개요/
│   ├── 개요.md                # 작품 전체의 권 단위 구조
│   ├── 권개요_제1권.md         # 권마다 하나: 권 계약+이야기 선+플롯 단위 카드+감정 곡선+인물 변화+복선+반전
│   ├── 개요초안_L1-01.md      # 단위마다 하나: 공급 자체 점검+개요 작성 추가 사항
│   └── 상세개요_제001장.md        # 장마다 하나: 필수 필드 9개+소절 4개+마무리 설정과 후킹
├── 본문/
│   ├── 제001장_장제목.md
│   └── ...
├── 비교작품/                          ← 분석에서 나온 구조화 자산
│   └── {对标书名}/
│       ├── 원문/제001장_장제목.md
│       ├── 장별분석/제K장_요약.md
│       ├── 인물/                  ← 작품분석실/구조화 출력에서 동기화
│       │   └── {角色名}.md
│       ├── 플롯/                  ← 작품분석실/구조화 출력에서 동기화
│       │   ├── {剧情单元名}.md
│       │   ├── 이야기선.md
│       │   ├── 리듬.md             # 핵심 정보 전진+감정 자극점+폭발 리듬(권위 있는 리듬 색인)
│       │   └── 감정모듈.md         # 독자 욕구/감정 엔진+재현 가능한 모듈(권위 있는 모듈 색인)
│       ├── 설정/                  ← 작품분석실/구조화 출력에서 동기화
│       │   ├── 세계관/{主题}.md
│       │   └── 세력/{势力名}.md
│       ├── 문체.md
│       └── 작품분석보고서.md
├── 추적/
│   ├── _tracking-state.json        ← 유일한 구조화 권위 상태
│   ├── 문맥.md                  ← 파생 이어쓰기 상태 카드(고정 7칸), ≤12KB
│   ├── 장별기록/제NNN장.md          ← 향후 관련성이 있는 압축 기록, ≤3072바이트
│   ├── 인물상태/{角色名}.md         ← 파생 핵심 인물 현재 스냅샷
│   ├── 복선.md                    ← 파생 복선 현재 뷰
│   └── 시간선/{작가용진실.md,독자가아는사실.md}
├── 참고자료/
│   └── {topic}.md             # story-researcher가 출력한 조사 자료
├── .story/work/제NNN장/        ← 이번 장 임시 파일(묶음 segment·prompt 보관본·트랜잭션 JSON), 커밋 후 자동 삭제
```

**누락 파일 처리:** 먼저 진행 상태·보고서 총 장 수·장별 분석 범위로 자료 세대를 판별한다. 현재 계약 항목이 없으면 명시적으로 복구하며 격하된 결과를 조립하지 않는다.

1. **인물 상태 파일 누락**: 현재 프로토콜 프로젝트는 먼저 `tracking_commit.py check`를 실행하고 해당 상태를 만든 전체 트랜잭션을 다시 실행한다. 본문이 있는데 `_tracking-state.json`이 없으면 `/story-import`를 다시 수행한다. 앞부분을 임시 추론해 스냅샷을 직접 쓰지 않는다.
2. **인물·일반 플롯 단위·설정 같은 비주요 산출물 하위 디렉터리 누락**: 벤치마크 작품 경로 찾기에 따라 프로젝트 뷰와 루트 자료원을 찾고 그래도 없으면 해당 선택 모듈을 건너뛴다. `플롯/감정모듈.md`와 `플롯/리듬.md`에는 적용하지 않는다.
3. **전체 검색에서 `플롯/감정모듈.md` / `플롯/리듬.md` 누락**: 집필 전 준비를 반드시 멈추고 `missing_primary_contract: true`와 `repair_action`을 제시한다. `/story-long-analyze` Stage 3+ 또는 `/story-import`를 다시 실행한다. 요약 파일로 권위 있는 모듈을 검색한 것처럼 꾸미지 않는다. 성숙한 프로젝트의 짧은 경로는 benchmark-recall.md 조건으로 판정한다.
4. **벤치마크 작품은 있으나 `문체.md` 누락**: 실질적인 내용이 있는 `설정/문체.md`가 있으면 맞춤 문체 모드로 계속한다. 없으면 일일 집필 문체 검색을 즉시 중단하고 작가에게 해당 작품의 `/story-long-analyze` Stage 6 문체 분석을 보충하도록 요청한다. 이후 첫 집필 참조 때 `비교작품/`로 동기화한다. **벤치마크가 전혀 없는 프로젝트**는 문체 검색을 건너뛰고 막지 않는다. `설정/문체.md`가 있으면 그것으로 쓴다. 전체 검색의 감정/리듬 축(`missing_primary_contract`)은 독립적이며 맞춤 문체 모드 자체가 그 즉시 중단 조건을 면제하지 않는다.
5. **복선/시간선 파일 누락**: 현재 상태가 손상된 것으로 보고 본문 집필을 멈춘다. 먼저 `tracking_commit.py check` 후 트랜잭션으로 복구한다. 권 개요·전체 개요의 계획은 이미 일어난 사실을 대신할 수 없다.
6. **`설정/소재본문안내.md` 누락**: 막지 않는다. 집필 전에 `설정/소재방향.md`로 `references/genre-prose-cards.md` 색인을 정확히 맞추고 `references/genre-prose-cards/`의 해당 단일 장르 카드만 읽는다. 높음/중간/낮음 확신도는 원래 카드 표시를 따른다. 일치하지 않으면 `references/style-genre-modules.md`의 일반 장르 모듈로 짧은 `genre_prose_card`를 즉시 만든다. `설정/소재방향.md`까지 없을 때만 상세 개요·목표 플랫폼으로 낮은 확신도의 장르 카드를 만들고 의도 확인 때 명시한다.

**벤치마크 분석의 권위 우선순위(읽기 순서):**

1. `플롯/감정모듈.md`는 독자 욕구/감정 엔진·쾌감 서사의 패턴 틀·재현 가능한 모듈·재조합 지침의 권위 자료다.
2. `플롯/리듬.md`는 핵심 정보 전진(확장 방식 포함)·감정 자극점·폭발 리듬의 권위 자료다.
3. `문체.md`는 문장 길이·문장부호·대사 속뜻·원문 근거 조각 같은 스타일만 담당하며 감정 모듈·리듬 의도를 덮어쓸 수 없다. **사용자가 직접 쓰고 가져오기/분석이 덮어쓰지 않는 맞춤 문체 `설정/문체.md`가 벤치마크 `문체.md`보다 우선한다.** 실질적 내용이 있으면 권위 있는 스타일 기준으로 삼고 벤치마크 문체는 참고와 문장 길이 수치의 대체값으로 내린다. 문장 길이·멈춤 문장부호·시점·수사는 `references/style-resolution.md`로 판정한다. 문단 사이 빈 줄 같은 파일 구조는 계속 납품 계약을 따르며 일반 표현 금지를 하드 안전선이라 부르지 않는다.
4. `장별분석/제K장_요약.md`는 구체적인 장의 근거다. 권위 색인을 검증·보충하지만 거꾸로 `감정모듈.md` / `리듬.md`를 덮어쓰지 않는다.
5. `작품분석보고서.md`와 `플롯/이야기선.md`는 투영/요약이다. `플롯/감정모듈.md` 또는 `플롯/리듬.md`와 충돌하면 집필은 두 권위 파일을 따르고 집필 전 준비의 `gaps.conflict`에 충돌 출처를 기록한다.
6. **공용 영감 검색**은 작업공간에 `영감자료실/`가 있을 때 작업 태그로 active CBA 상위 3–8개를 고른다. IA/NM을 전달하지 않고 영감 카드를 문체 샘플로 삼지 않는다. 카드는 설계 선택에만 영향을 주며 위 권위 파일이나 상세 개요의 사실과 충돌하면 후자를 따른다.

**파일 구성 원칙:**

- **인물마다 파일 하나:** `인물/角色名.md`로 필요할 때 읽기 쉽게 한다.
- **세력마다 파일 하나:** 조직·문파·가문·국가 등을 `세력/势力名.md`에 둔다.
- **세계관은 주제별 분리:** 배경·힘의 체계·사회 구조 등을 독립시킨다.
- **상세 개요는 장마다 파일 하나:** `상세개요_제XXX장.md`에 후킹 설계를 포함하고 본문과 일대일 대응시킨다.
- **본문은 장별 분리:** `제XXX장_장제목.md`로 장마다 파일 하나를 쓴다.
- 장을 완성하면 먼저 대화에 출력하지 말고 바로 `본문/`에 저장한다.

`/story-long-analyze`는 `작품분석실/`에 출력하며 첫 참조 때 프로젝트의 `비교작품/`로 동기화한다.
