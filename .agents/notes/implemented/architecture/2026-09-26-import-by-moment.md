# Agent Note: 가져오기를 작가 시점별 파일로 나누고 결정을 가져오기 기록에 저장

Status: implemented
Date: 2026-09-26
Related: [35K 로드 상한](2026-09-26-per-call-load-ceiling-35k.md), `skills/story-long-write/references/workflow-setup.md`의 새 책 시작 시점 표, [나머지 스킬 재구성](2026-10-17-other-skills-by-moment.md)(권 줄거리 사건 단위를 단위 카드로 변경하고 200장 초과 간소화 요약 모드를 삭제하여 이 노트의 해당 두 결정을 대체)

## Problem

story-import의 SKILL.md는 공백 제외 20.3K로 출처 확인부터 마지막 보고까지 모든 단계가 상주한다.

- 절차 문답·옛 추적 이전·200장 초과 등 조건부 절 약 1.8K가 진입부에 있다. 추적 초기화는 tracking-transaction.md 7.7K 전체를 읽지만 절반 이상이 이어쓰기의 장별 트랜잭션이다.
- 미완 원고 처리·집필 환경 선설치·권 구분을 문맥에 기록하게 해 작가의 결정이 대화에만 남고 문맥 교체 시 사라진다.
- 장별 요약으로 세부 줄거리를 한꺼번에 역산하며 템플릿도 진입부에 있다. 부하가 장 수에 비례해 긴 책은 한 문맥에서 감당해야 한다.
- long-analyze의 분석 라이브러리 구조와 Stage 0–6 약 2.2K를 다시 쓰고 자체 references의 세부 줄거리 템플릿·추적 절차·색인도 중복한다.
- 장편 구조 이전은 진입부+structure-mapping-long+추적 세 파일로 약 40.4K, 심층 분석은 진입부+long-analyze 진입부+pipeline-ops로 약 36.2K여서 35K를 넘는다.
- 작가에게 hooks/agents/AGENTS 배포라고 말해 이해하기 어렵다.

## Decision

- SKILL.md는 역할·Agent 호환성·용어 경계·시점 표·인계 규칙·Phase 1 다섯 Step·시점별 안내만 남긴다(6.0K). 표는 Phase 1 출처·범위 확인 → Phase 2 심층 분석 → Phase 3 구조 이전(장편 끝에서 세부 줄거리 배치별 역산) → Phase 4 추적 초기화(장편만) → Phase 5 보고·활성화이며 각 행에 작가 확인·읽을 자료·저장 위치를 적는다.
- 시점 사이에는 저장 파일만으로 인계한다. Phase 1에서 `{书目录}/.story/work/导入记录.md`를 만들고 원문 위치·분량·범위(첫 심층 분석 범위 포함)·마지막 장 상태와 미완 원고 결정·장르와 플랫폼·외부 비교 작품·집필 환경·권 구분·작가 지시·시점별 진행 체크를 저장한다. 매 시점 시작에 읽고 전달 전에 갱신하며 붙여 넣은 원문도 같은 디렉터리에 저장한다. 작가가 가져오기 계속을 요청하면 첫 미완료 항목부터 한다. 작가 지시는 구조 이전 때 `设定/题材定位.md`의 새 작가 확정 사항 절(단편은 이어쓰기 기준)에 옮겨 이어쓰기에서도 보게 한다.
- 심층 분석·세부 줄거리 각 배치·추적 초기화는 많이 읽으므로 전달 후 새 대화에서 가져오기 계속을 요청하도록 권한다.
- 시점 파일을 추가한다. `deep-analysis.md`는 가져오기에서 long/short-analyze를 구동하는 방법만 쓰며 구조·절차·복구·품질은 analyze에 맡긴다. `import-tracking.md`는 초기화 트랜잭션 의미 준비·항목 형식과 용량·복선/시간선 추출·검수를 담아 tracking-transaction.md 전체 읽기를 대체한다. `import-report.md`는 마무리 검사·작가 보고 템플릿 둘·활성화, `import-special-cases.md`는 절차 문답·옛 추적 이전, `outline-reverse.md`는 배치별 세부 줄거리 배정, `outline-reverse-rules.md`는 역산 원칙·필드 대응·템플릿으로 작업 묶음 본문에만 쓰인다.
- structure-mapping-long.md가 구조 이전의 유일한 파일이다. 처음에 기존 Phase 3-L의 이전 10단계를 넣고 권 구분을 작가 확인 지점으로 삼는다. 추적·세부 줄거리 규칙은 뺀다. v0.8.1 진입부의 `大纲/大纲.md` 템플릿을 전체 줄거리 역산 규칙으로 돌려 장편 집필과 같은 형식(전체 규모·단계 개요+권 줄거리)을 쓰되 근거 있는 항목만 채운다. 장르 선정·비교 작품 동기화·문체 동기화를 권 구분 앞으로 옮겨 권 구분으로 마무리 확인한다. structure-mapping-short.md에도 이전 절차를 앞에 넣는다.
- **세부 줄거리 배치**: `skills/story-import/scripts/build_outline_brief.py --project {书目录} --chapters A-B`는 10–20장(전체 마지막 배치는 더 적어도 됨)을 요청받아 역산 규칙·각 장 본문 경로·`visible_chars_v1`로 잰 기존 길이(자체 wordcount_core 재사용, 집필 장 검사와 동일)·분석 요약의 필요한 필드·범위가 겹치는 권 줄거리 사건 단위 카드를 `.story/work/排纲/导入细纲_第AAA-BBB章.md`로 조립한다. 추출 필드는 핵심 사건·인과·상황 결과·관련 대상·정보 변화·상태 변화·장 끝 훅이며 사건 노드는 제목｜유형｜기조만 쓴다. 옛 요약의 “出场人物”, “卡点与伏笔”는 별칭으로 인식한다. 실행자는 장당 약 4K인 요약 전체를 읽지 않는다. 카드는 자체 `outline_view.py`로 파싱하며 집필의 `outline_view.py --unit`과 같은 규칙이다. 배치 첫 장에는 이전 장의 끝 훅도 넣는다. 묶음과 요약이 없어 본문을 읽어야 하는 장의 총량이 약 25K를 넘으면 뒤에서 장을 줄인다(10장 미만 가능). stdout `chars`는 그 총량, `chapters`/`next`는 실제 범위·다음 시작이다. 요약이 없으면 해당 본문으로 역산하라고 묶음에 표시한다. story-architect가 있으면 묶음을 주고(명령 실행 권한이 없어 길이는 스크립트가 미리 측정), 없으면 주 세션이 작성한다. `check-outline-contract.js` 검수는 주 세션이 한다. 기록에는 B장까지 검수 완료라고 쓰며 재개는 B+1부터 배치 전체를 다시 작성하여 미검수 파일을 덮는다. Phase 5는 모든 세부 줄거리를 다시 계약 검사한다. 20장 초과·마지막 아닌 배치 10장 미만·이전된 본문 범위 초과·권 줄거리 없음·배치를 덮는 단위 카드 없음은 종료 코드 2다.
- 심층 분석 전달 때 분석 스킬 자체의 완료 보고(장편 전체 분석 완료, 단편 /story-short-write로 다음 작품 작성)는 쓰지 않고 deep-analysis.md의 전달 문장으로 대체한다.
- 검사는 삭제하지 않고 내용에 맞춰 기준점을 옮긴다. 작가 보고 템플릿은 SKILL.md 최소 1블록에서 import-report.md 최소 2블록으로, schema_version 회귀는 SKILL.md에서 deep-analysis.md로 옮긴다. story-setup 배포 검사는 진입부의 가져오기→이어쓰기 순서를 유지하고 특수 상황의 권장 순서·추적만 재생성·진입부 가져오기 기록·총량별 세부 줄거리 배치 네 검사를 더한다. test-writer-pipeline.py의 ImportOutlineBriefTests는 필드 추출·옛 별칭·이전 장 훅·총량별 축소·범위별 카드 선택·집필 측에서 가져올 수 없는 카드 차단을 검증한다.

주 세션 규칙의 공백 제외 문자 수: 출처 확인 22.6K→8.3K, 심층 분석 가져오기 부분 20.3K→8.4K(long-analyze 진입부·pipeline-ops 포함 36.2K→24.4K), 장편 구조 이전 40.4K→15.2K, 세부 줄거리 배치 주 세션 9.4K+묶음(약 25K 상한, 현재 요약 20장 실측 약 24.7K·옛 요약 약 17K, 이전에는 실행자가 20개 요약 약 73–80K를 별도 읽음), 추적 초기화 12.0K, 단편 구조 이전 27.8K→14.4K, 보고 29.4K→7.6K다.

## Alternatives considered

- **중복 절만 삭제**: 새 파일 없이 진입부를 약 11K로 줄인다. 그러나 구조 이전에 추적 세 파일이 계속 겹치고 작가 결정은 대화에만 남으며 세부 줄거리도 배치가 없어 문맥 교체 시 유실·긴 책의 선형 증가가 해결되지 않는다.
- **story-long-write의 build_architect_brief.py 재사용**: 같은 story-architect·묶음이므로 관리가 간단하다. 그러나 스킬 간 파일 참조는 저장소 규칙 위반이고 가져오기는 요약으로 과거 장을 역산하며 측정 길이가 필요해 앞으로 설계하는 새 책 흐름·템플릿과 다르다. 자체 스크립트를 둔다.
- **요약 경로만 넣고 실행자가 전체 읽기**: 간결한 묘사·인용·확장 기법까지 증거가 풍부하다. 그러나 장당 4K, 10–20장이 40–80K라 35K를 넘는다. 역산에 필요한 필드는 일부이며 묘사·인용은 불필요하다. 누락 필드는 본문 해당 부분을 보면 된다.
- **묶음 초과 때 오류를 내고 호출자가 축소**: 단순하며 범위를 호출자가 통제한다. 그러나 요약 상세도를 미리 몰라 재시도가 필요하다. 이미 장별 측정을 마친 스크립트가 끝에서 줄이고 다음 시작을 알리면 한 호출로 이어간다.
- **기록을 분석 라이브러리·프로젝트 루트에 저장**: 라이브러리는 analyze 산출물이라 진행 기록이 기존 결과 감지를 방해하고 루트에는 여러 책이 있을 수 있다. 책의 `.story/work/`에 추적 트랜잭션·계획 묶음과 함께 두는 것이 기존 규칙과 같다.
- **tracking-transaction.md에서 초기화 분리**: story-long-write 공유 사본이라 세 사본·이어쓰기 흐름을 바꿔야 한다. 가져오기에 필요한 초기화 필드·항목 형식·용량만 import-tracking.md에 적는 편이 작다. 전체 파일은 오류 조사용으로 남긴다.

## Consequences

- 매 시점의 주 세션 규칙은 35K 이하이며 가장 큰 장편 구조 이전은 15.2K다. 세부 줄거리 부하는 전체 장 수와 무관한 배치 단위이고 총량을 스크립트가 제한해 요약 상세도에 따라 커지지 않는다.
- 확인 지점의 미완 원고·환경·권 구분·취향과 금지 사항을 저장해 다른 대화·다음 날에도 잇는다. 가져오기 계속이 새 진입 요청이다.
- 동작 변화: 장르·비교 작품 동기화가 권 구분보다 앞서고 추적 초기화는 구조 이전에서 독립한 Phase 4로 모든 세부 줄거리 뒤에 온다. 세부 줄거리는 일괄에서 10–20장 요청 배치로 바뀌며 상세 요약이면 더 줄어든다. 하위 에이전트가 없으면 매 배치 새 대화를 권해 긴 책의 대화 횟수가 늘어난다. 묶음은 추출 필드만 담으므로 없으면 본문 관련 부분을 다시 봐야 하고 요약의 묘사·인용이 직접 들어오지 않는다.
- 비용: reference 6개와 스크립트 1개가 늘었다. import-tracking.md가 초기화 제약을 발췌하므로 추적 용량·필드 변경 시 함께 갱신해야 한다.
- 시점별 경로를 `scripts/doc-budget.json`에 등록했다. 세부 줄거리 묶음 데이터는 문서 예산에서 제외하고 스크립트의 25K 총량 제한으로 보호한다.
