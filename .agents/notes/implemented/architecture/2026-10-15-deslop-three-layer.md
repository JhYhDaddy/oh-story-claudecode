# Agent Note: AI 문체를 표현·서술·이야기의 세 계층으로 진단

Status: implemented
Date: 2026-10-15
Related: [이전 등급 결정](../../implemented/bug-fix/2026-09-27-deslop-one-grading.md), [Gate와 탐지 설명](../../implemented/bug-fix/2026-10-14-deslop-doc-contract-gaps.md)

## Problem

독립적인 AI 문체 제거 작업은 표면 밀도 지표 여섯 개로 Gate를 선택했으므로, 표현이 깔끔한 원고는 서술 방식과 이야기 진단을 건너뛸 수 있었다. 단어 목록, 전체 가이드, Gate 상세 규칙은 수정법과 검수 기준을 중복 규정했고, 감정을 직접 쓰는 방식과 Show/Tell 예시도 서로 충돌했다. 집필 방식 표본 검사에는 상세도, 인물의 입장, 핵심 과정의 기준이 있었지만 쾌감 지점과 스크립트 표시 부분만 확인했다. 일부 수정 예시는 인물의 전략을 바꿨으며, 문단 전체 삭제 금지와 고정 삭제 비율은 기능 없는 내용의 압축을 제한했다.

## Decision

독립적인 AI 문체 제거는 표현, 서술의 초점과 분량 배분, 이야기의 인과관계와 변화를 각각 기본 검사한다. 단어·문장 밀도 지표 여섯 개로 등급을 정하지 않는다. `expression.md`, `narrative-focus.md`, `story-logic.md`는 세 계층 방법의 유일한 원본이며 story-deslop에 둔다. 공유 매니페스트로 장편·단편·원고 검토·배포 디렉터리에 동기화한다. 이전 `anti-ai-writing.md` 네 개는 삭제하고 단어 목록은 신호 색인으로 축소한다. `deslop-gates.md`에는 현재 사용하는 정밀 수정 범위 매핑과 실행 인터페이스만 남긴다. 집필자의 읽기 표, 집필 위임 프롬프트, 단독 원고 검토, 단편 어댑터, OpenCode/Codex 생성물도 함께 갱신한다.

작가는 오랫동안 모은 어휘와 문형 자료의 보존을 요구했다. 주 브랜치의 이전 단어 목록과 전체 가이드를 항목별로 대조한 결과, 압축된 색인에서 핵심 어휘 23개와 일부 문형 분기·복합 원문 예시가 빠졌음을 확인했다. 기존 핵심 어휘 64개를 모두 유지하고, 암묵적 단정, 숨은 뜻의 노골적 해설, 논설체, 신체 반응, 장면·날씨·전투 등의 표본을 복원했다. 이전의 기계적 치환 자료도 잘못된 수정의 반례로 남겼다. 자료는 기존 `banned-words.md`에 모으고 story-long-write의 기준 원본에서 다섯 복사본을 동기화하며 별도 중복 색인은 만들지 않는다. 탐지 후에는 여전히 문맥으로 판단한다. 등장 즉시 삭제, 고정 빈도, 감정을 보면 동작으로 치환하던 규칙은 되살리지 않는다. 자료 보존을 위해 색인 예산을 공백 제외 1,800자에서 4,600자로 명시적으로 늘리고 관련 로드 경로 세 개에 전체 파일을 반영했다. 35K 상한과 예외는 그대로다.

이후 작가는 전보체와 짧게 끊기는 문장을 중점적으로 고치라고 명시했고, 자동 평가에서 만점을 받은 발췌문도 거부했다. 표현 방법 첫 절과 집필자 진입점에서 이를 표현 계층의 최우선 과제로 둔다. 행동을 중심으로 문장을 조직하고 배경·조건·원인을 동작에 녹이며 정보의 주종 관계를 나누고 추론 가능한 반복 설명을 지운다. 주어 보충과 문장 합치기는 필요한 기초 수정일 뿐, 독립 절로 항목을 차례로 방송하는 글은 여전히 미달이다. 첫 절은 화물차 문단을 예시로 사용하며 대화의 조건도 하나씩 문답 한 줄로 바꾸지 않는다. 작가는 문장 간 주종 관계 처리를 인정했지만 이어서 논리만 보면 여전히 혼란스럽다고 지적했다. 예시에서 양측 위치를 더 명확히 하고 전화 문답을 대응 행동으로 요약해 ‘그녀를 데리러 온다’가 사람을 태운다는 뜻으로 읽히지 않게 했다. 동결했던 점수는 역사 기록으로 보존하고, 작가가 거부한 발췌문은 이후 평가의 실패 반례로 넣는다. 만점을 근거로 자연스러운 표현이라고 주장하지 않는다. 반복 설명을 삭제·병합해 공간을 확보했으며 예산은 늘리지 않았다.

일반적인 AI 문체 제거는 원문이나 확정된 설계에 근거한 표현, 연결, 상세도를 직접 고친다. 동기·사건·결정·결과·정보 공개 시점을 바꿔야 한다면 최소 설계안을 제시하고, 작가가 이미 허용한 부분은 바로 실행한다. 서사 기능에 따라 본문을 보호하며 기능 없는 문단 전체의 삭제를 허용하고 고정 삭제율은 두지 않는다. 특정 부분만 고치는 작업에서는 파일 전체의 문장부호를 수정하지 않는다. 보고서는 미검사, 문제 미발견, 자료 부족, 추가 설계 필요를 명확히 구분한다.

장편 장 마무리와 단편 4단계는 계속 이번 점검 목록과 탐지 결과에 따라 특정 부분을 수정한다. 전체 세 계층 진단은 독립적인 AI 문체 제거 절차가 맡으며, 작가에게 새 대화를 열거나 추가 확인을 하도록 강제하지 않는다. 실제 전체 진단 경로에서는 방법 문서 세 개의 전량을 예산에 포함한다. 35K 상한은 유지하며 예외를 추가하지 않았다. 배포 검사는 이전 Gate의 특정 문구 단언 대신 세 방법의 읽기 가능한 경로, 기준 원본과 배포본의 일치, 이전 가이드 퇴출을 확인한다. 집필 동작은 독립적인 원고 수정 평가로 검수한다.

주 브랜치에 병합된 작가 기억의 중앙 관리에 맞춰 독립적인 AI 문체 제거는 호출자가 이미 가진 선호만 받고 기억을 조회하거나 관리하지 않는다. 구조화된 집필 위임 프롬프트도 이 경계를 따른다. 병합 전 재검토에서는 story-review 탐지기 진입점과 구조 검토 프롬프트를 보완했다. 표현의 blocking과 advisory 모두 먼저 의미 재검토 후보로 보고, 구체적인 읽기 손실을 확인한 뒤 실제 영향으로 등급을 정한다. 탐지 결과를 일괄 S2로 올리거나 탐지기의 수정법을 그대로 적용하지 않는다. 결정론적 퇴화 항목은 계속 별도로 처리하며 full·lean·solo 모두 보고만 하고 본문을 수정하지 않는 경계를 유지한다.

0.8.6 출시 전 독립 재검토에서 공개 AI 문체 제거 가이드가 여전히 여섯 지표 등급, 고정 삭제율, 삭제된 전체 가이드를 소개하는 문제를 발견했다. 세 계층 진단과 허용 범위로 맞추고 영어 스킬 개요도 갱신했다. 표현 예시의 ‘오류를 바로잡는 기능이 있으면 보존 가능’ 조건은 원문 그대로 보존하려면 작가의 선택과 기존 허용 목록이 필요하다는 설명으로 보완했다. 면제가 없으면 그 기능은 살리되 자연스럽게 고쳐 다시 검사한다. 설명으로 호출자의 커밋 검수를 대신할 수 없으며 양립이 불가능하면 남은 차단 항목을 보고한다. 런타임 조건과 허용 목록 권한은 그대로 유지해 집필자가 같은 탐지 문장을 남기고 상위 절차가 계속 재위임하는 상황을 막는다.

평가 프로토콜, 합성 원고, 이전 스킬은 먼저 `~/.oh-story-bench/prereg/2026-10-15-deslop-three-layer/`에 동결했고 산출물은 같은 이름의 runs 디렉터리에 둔다. 주 장면과 탐지만 하는 사례의 설계 파일에서 명시적인 진단 힌트를 발견했다. 어느 실험군의 출력이나 점수도 읽기 전에 힌트를 제거하고 새 실행자 두 명이 다시 수행했다. 첫 실행은 예비 실험으로 남기고 주 평가는 `2026-10-15-deslop-three-layer-unprompted`의 산출물 두 개를 사용한다. 조용한 배웅과 허용된 재작성은 첫 실행을 유지하며 양쪽 실험군에 똑같이 적용한다. 판단 기준, 합격선, 강제 실패 조건은 처음 동결한 프로토콜 그대로다.

## Alternatives considered

- Gate와 경·중·심 등급을 유지하고 심층 규칙 몇 개만 추가: 호출 변경이 적고 기존 삭제 보호를 이어갈 수 있지만 표면 등급으로 뒤 두 계층을 여전히 건너뛸 수 있어 세 계층 독립 진단을 택했다.
- 기존 참조를 한 파일로 합치기: 탐색 비용은 줄지만 단어 목록, 서술, 이야기 설계가 같은 로드 단위에 섞인다. 검사 대상별로 나누고 각 기준은 한 번만 설명한다.
- 모두 플롯 재작성으로 바꾸기: 저항이나 인과관계가 부족한 원고를 바로 고칠 수 있지만, 일반적인 AI 문체 제거 요청이 인물 결정과 정보 공개 순서 변경까지 허용한 것은 아니다. 진단 깊이와 실행 권한을 분리한다.

## Consequences

표현이 깔끔한 원고에서도 상세도 불균형과 이야기의 빈틈을 드러내며 방법과 예시의 중복이 사라진다. 대신 공유 호출, 문서 예산, 집필자 어댑터를 함께 이전해야 한다. 의미 평가는 모델 판단에 의존하고 작은 표본은 이번 장면만 검증할 수 있어 모든 소재의 개선을 증명하지 못한다.

## 검증

- 정적 검사 13/13, 문서 359개의 번호 검사, 공유 파일과 유사 복사본 검사, 현재 계약, 작가 보고, Python 호출, 문서 예산과 예산 회귀 17개가 통과했다.
- 공유 참조 회귀, story-setup 전체 배포 검사, 호스트 7개의 어댑터 검사가 통과했다. OpenCode/Codex를 재생성하고 Antigravity는 임시 배포 디렉터리에서 실제 생성해 검증했다.
- 문체 우선순위 동작 회귀 7개가 통과했다. 신구 범용 skill-creator 검증기는 모두 저장소 기존 `version` 프런트매터를 거부했다. 이 검증기에 맞춰 저장소 형식을 바꾸지 않고 저장소 자체의 구조화된 프런트매터 검사로 검수했다.
- 리팩터링 초기 비교에서 독립 AI 문체 제거의 주 세션 직접 수정 시 전체 규칙 로드량은 공백 제외 34,080자에서 17,244자로 줄었고, 위임 전은 17,694자였다. 현재 주 브랜치의 작가 기억 경계, 역사 자료 복원, 원문 보존 인터페이스 보완을 반영한 현재 전체 진단은 19,354자, 위임 전은 19,799자다. 표현 색인은 4,237/4,600자, 단독 원고 검토 최대는 28,104자, 단편 연속 집필의 정밀 수정 최대는 32,453자다. 모든 로드 경로가 35K 상한을 통과했다. 두 차례 독립 항목별 검토로 이전 단어 목록과 전체 가이드를 대조해 핵심 어휘 64개, 주요 문형 분기, 복합 원문 예시가 모두 보존됐음을 확인했다. 자리표시자나 문장부호 차이를 누락으로 세지 않았다.
- 우선순위 조정 전 후보의 개발 중 의미 비교: 작업 4개와 합성 원고 2개를 사용했다. 익명 평가자 두 명이 버전 순서를 바꿔 평가했으며 구버전은 둘 다 15/16, 신버전은 둘 다 16/16이고 강제 실패는 없었다. 차이는 이야기 설계 제안이 ‘근거 하나 추가’에서 검토 가능한 구체적 대안으로 바뀐 것뿐이다. 두 버전 모두 부녀의 대립을 복원하고 조용한 일상을 보존했다. 읽기 선호는 모두 주 장면에서 신버전 약우세, 조용한 장면 동률, 허용된 재작성에서 구버전 약우세였다(후자는 마무리가 더 간결함). 이를 근거로 신버전이 전반적으로 낫다고 주장하지 않았다.
- 탐지만 하는 두 버전의 본문/개요/문체/요청은 파일별로 동일했다. 추가 특정 부분 스모크 테스트는 3행만 바꿨고 범위 밖 문장부호와 줄바꿈은 그대로였다. 작가 작업은 총 13개 실행했다. 산출물 8개를 평가하고 힌트가 있던 예비 실행 4개는 제외했으며 특정 부분 스모크 테스트 1개는 별도 집계했다.
- 전체 프로토콜, 익명 평가, 비교 원고, 종합 결과는 `~/.oh-story-bench/runs/2026-10-15-deslop-evaluation/评估报告.md`에 있다. 같은 모델 계열, 적은 표본, 한 번의 생성이므로 다른 소재나 모델까지 효과를 확대 해석하지 않는다.
