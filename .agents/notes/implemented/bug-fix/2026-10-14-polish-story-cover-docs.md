# Agent Note: 표지 프롬프트와 플랫폼 내보내기 설명 정합성

Status: implemented

## Problem

표지 진입점은 프롬프트를 전부 영어로 쓰라고 하지만 문자 레이어에는 중국어 책 제목·필명을 유지해야 한다. 스타일 라이브러리의 공통 수식은 2:3으로 고정되어 있으나 진입점의 판치에 3:4 규칙과의 교체 관계가 설명되지 않았다. 진입점은 중앙 자르기를 하면 글자가 잘리지 않는다고 설명하지만 기존 Step 6은 실제 자르기 결과를 확인하도록 요구한다. 제목·필명이 없을 때 지정한 AskUserQuestion도 모든 호스트에 있는 도구명이 아니다.

## Decision

story-cover 진입점과 스타일 라이브러리를 prose-gap-polish의 다섯 단계로 각각 정리한다. 프롬프트 지시문은 영어로 쓰되 제목·필명은 작가 원문을 유지한다. 스타일 라이브러리의 2:3은 기본값이며 실제로는 Step 1에서 정한 플랫폼 비율로 바꾼다. 내보내기 설명은 기존 중앙 자르기 명령과 Step 6 검사를 유지하고 중앙 자르기가 글자를 반드시 보존한다고 보장하지 않는다. 필수 정보가 없으면 호스트에서 가능한 질문 방식을 사용한다. 기존 보완 요구는 유지하고 새 확인 절차는 추가하지 않는다. 기존 edits 예시는 multipart로 로컬 이미지를 올리는 방식이며 인터페이스가 multipart만 허용한다고 오해하지 않도록 설명을 해당 예시에 한정한다.

사실의 근거는 이 파일의 생성·편집·내보내기 명령, 로컬에 설치된 ImageGen 스킬의 입력·저장 규약, [OpenAI 이미지 편집 인터페이스](https://developers.openai.com/api/reference/resources/images/methods/edit), [이미지 프롬프트 지침](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)이다. 모델 기본값·base64 디코딩·기존 크기 요청을 유지한다.

## Alternatives considered

- **스타일 라이브러리의 모든 예시를 판치에 3:4로 변경**: 해당 플랫폼에서 예시를 바로 사용할 수 있다. 그러나 다른 플랫폼의 기본 세로 비율까지 바꾸게 되므로 예시를 유지하고 교체 위치를 안내하는 것이 기존 다중 플랫폼 흐름에 맞다.
- **‘중앙 자르기는 글자를 자르지 않는다’는 보장 유지**: 설명이 짧다. 그러나 프롬프트의 안전 영역은 실제 배치 결과와 다르며 기존 품질 검사와 중복·충돌하므로 내보낸 뒤 기존 검사로 글자 보존 여부를 확인한다.

## Consequences

프롬프트 언어·플랫폼 비율·내보내기 검사의 연결이 분명해지고 호스트에 특정 질문 도구가 없어도 정보를 보완할 수 있다. 대신 실행자는 플랫폼에 맞게 기본 비율을 바꾸고 내보낸 이미지를 확인해야 한다. 명령·변수·인터페이스 인자·번호·모델 기본값은 바꾸지 않으며 배포 패키지 버전과 지문은 기존 규칙대로 갱신한다.

## 검증

정적 검사, 워크플로 번호, 문서 예산, 공유 파일, 의사결정 기록, 작가 보고서 검사를 모두 통과했다. 진입점 frontmatter, 모든 제목·명령·예시 코드 블록은 원고와 글자 단위로 같다.
