# Agent Note: 다듬기 병합 전 재검토와 README 동기화

Status: implemented

## Problem

스킬 13개의 다듬기가 #472–#484 의존성 묶음으로 준비되었다. 병합 전 재검토에서 장편 감정 자료가 아직 단편의 고정 비율·간격을 일반 요구로 설명하고 관통 소품 자료도 단위마다 세 번 반복하도록 요구함을 확인했다. 장편 분석 Stage 5의 문체 자리표시자도 Stage 6이 채우도록 인계되지 않았다. README의 호스트 수·추적 읽기 범위·hook 차단 능력·업그레이드 단계가 기존 구현과 달랐다.

## Decision

중국어·영어 README를 prose-gap-polish의 언어·간결화·모호함 해소·사실 대조·논리 순서로 정리한다. 작업대의 중복 소개를 합치고 호스트 7종과 일반 환경을 구분한다. 상태 카드 읽기 범위·12 KiB 상한·hook 지원 경계·검출과 수정의 역할을 바로잡고 기획/배포/업그레이드 순서를 통일하며 스캔 검출 건수를 정정한다. 실제 화면 녹화·원문 인용·Mermaid 외 모든 코드 블록·AI 문체 실패 예시는 원문을 유지한다.

장편 감정 자료의 원리·사례는 유지하고 단편의 고정 비율·소절 간격은 제거한다. 소품 세 번 등장은 선택 예시로 남긴다. 도입 사건 사슬은 장르와 장의 임무에 맞춰 선택하고 고정 횟수를 보편적 의무로 삼지 않는다. 형식은 호출자가 지정하며 관리되는 배포 사본과 집필자 어댑터도 함께 갱신한다.

전체 파이프라인이나 재개 실행의 Stage 6은 완료 표시 전에 `_progress.md`의 기존 단계 표와 보고서의 미완성 구간에 따라 ‘문체 한 문장’을 채운다. 기존 프로젝트의 문체만 보완할 때는 여전히 기존 보고서를 보존한다. 마무리 검사에서 채움 여부를 명시적으로 확인하며 런타임 필드·산출물은 추가하지 않는다.

병합 전 실패 예시 보호, 자료 소비 경로, 누적 동작 변경을 독립적으로 확인하고 확정된 문제를 하나씩 수정했다. 파일 전체를 삭제할 만큼 중복된 자료는 찾지 못했다.

누락 보완에서는 현재 Issue 양식의 사람이 읽는 문구도 같은 다섯 단계로 재검토했다. 피드백 도입부와 일정 설명을 줄이고 Bug·출력 품질 양식에 이미 지원하는 Google Antigravity 옵션을 추가했다. 다른 호스트의 상대 순서·필드 ID·필수 여부·링크·품질 사례 placeholder는 원문을 유지한다.

## Alternatives considered

- 겹치는 reference를 삭제하면 자료 디렉터리를 줄일 수 있다. 그러나 확인된 품질 규칙·플랫폼 rubric·배포 사본에는 각각 독립 소비자가 있어 파일 전체를 중복으로 볼 수 없으므로 파일은 남기고 실제로 섞인 규칙만 바로잡는다.
- 감정 자료 처음에 ‘비율은 참고용’이라고만 쓰면 변경이 가장 적다. 그러나 뒤의 검사 항목은 여전히 고정 박자를 의무로 설명하여 전체를 읽는 소비자는 상충한 요구를 받으므로 실행 문구를 각각 고친다.

## Consequences

집필 방법·사례는 계속 사용할 수 있고 장편 작업이 단편의 고정 간격을 물려받지 않으며 세션을 넘기는 작품 분석 마무리도 명확히 인계된다. README가 구현과 일치한다. 대신 배포 사본 동기화·어댑터 재생성이 필요하며 의존성 묶음의 각 PR이 엄격한 CI를 만족할 때까지 기다린 뒤 병합해야 한다.

## 검증

- 실패 예시와 대조 예시 단위 112개를 누적 확인해 모두 원문을 유지했다. 중국어·영어 README의 Mermaid 외 코드 블록 각 6개도 그대로다. 새 소품·도입 규칙은 실행 지침만 바꾸고 금 자물쇠 예시와 낮은/높은 밀도 예시는 원문을 보존했다.
- demo 검사를 실제 실행했다. 수정 전은 8건(7 blocking / 1 advisory), 종료 1이고 수정 후는 0건, 종료 0이다. 실제 demo는 문구 변경에 맞춰 바꾸지 않았다.
- 로컬 정적·번호·예산·공유 자료·현재 계약·reference gates·작가 보고서·장편 분석 런타임·7개 호스트 어댑터·배포 전체 검사를 통과했다. Stage 6 채움에 필요한 글자 수는 중복 설명을 줄여 상쇄하고 예산을 조정하지 않았다.
- Issue 양식 누락 보완은 정적 검사·문서 353개의 번호·문서 예산·공유 파일 네 검사를 통과했다. YAML이 파싱되고 필드 ID·필수 여부·기존 옵션 순서·사례 placeholder를 유지했다. 독립 재검토도 통과했다.
