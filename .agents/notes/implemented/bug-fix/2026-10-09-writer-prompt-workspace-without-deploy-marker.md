# Agent Note: 장 집필의 작가 기억 대리 조회에서 배포 표시만으로 작업 공간을 판정하지 않고 불명확하면 작품 디렉터리로 조회하지 않기

## Problem

장편 장 집필의 작업 묶음 생성 스크립트는 작가 기억을 대리 조회할 때 ‘작품 디렉터리와 조상 중 `.story-deployed`가 있는 첫 디렉터리’를 작업 공간으로 삼고 없으면 작품 디렉터리를 사용했다. DSH는 이 표시를 의도적으로 쓰지 않으므로 다음 문제가 생겼다.

- 작품이 `长篇/` 아래에 있으면 스크립트는 작품 디렉터리로 조회한다. 작가 기억 도구는 다중 작품 작업 공간 속 작품임을 알아보고 오류를 내며 쓰지 않는다. 대리 조회가 실패하여 주 세션의 수동 조회·입력으로 돌아가고 전역·장르·작업 흐름 항목은 주 세션이 직접 채워야 한다.
- 아무 표시가 없는 작업 공간 아래에 작품이 바로 있고(`.active-book`, `长篇/` 등이 없고 루트의 프로젝트 수준 기억도 아직 없음) 작품 수준 기억만 있으면, 작품 디렉터리를 작업 공간으로 쓰는 것은 ‘단일 작품 배치’라고 선언하는 셈이다. 도구는 작품명이 든 기억을 잘못 놓인 구버전 단일 작품 기억으로 보고 그대로 `书级/`로 옮긴 뒤 원래 자리에 빈 프로젝트 수준 기억을 만든다. 이후 올바른 작업 공간으로 조회하면 모두 `state.book must be a string` 오류가 난다. 로컬에서 재현해 확인했다.

## Decision

- 묶음 생성 스크립트는 `author-memory.md`의 ‘저장과 라우팅’에 따라 순서대로 작업 공간을 판정한다. 작품 디렉터리나 조상의 `.story-deployed`; 작품의 바로 위 폴더가 `长篇` / `短篇`이면 그 위 폴더; 작품 자체에 프로젝트 수준 기억이나 `书级/` 하위 폴더가 있으면 작품 디렉터리(단일 작품 배치); 가장 가까운 `.active-book`, `长篇/`, `短篇/`, `拆文库/`, 프로젝트 수준 기억이 있는 조상 순이다. 사용자 홈 디렉터리 직전까지만 올라가며 홈 자체는 포함하지 않는다.
- 어느 방식으로도 식별하지 못하고 작품 폴더에 작품명이 든 기억이 있으면 대리 조회를 하지 않으며 아무것도 쓰지 않는다. 확인 보고서에 ‘창작 작업 공간을 식별할 수 없다’고 쓰고 주 세션이 ‘저장과 라우팅’에 따라 `--workspace`를 정해 수동 조회하도록 맡긴다. 식별할 수 없더라도 작품 폴더에 기억이 없거나 프로젝트 수준 기억만 있으면 기존처럼 작품 폴더를 단일 작품 작업 공간으로 삼는다.
- 작가 기억 도구 자체는 바꾸지 않는다. `--book-root {工作区}`를 사용하는 모든 명령(`query` 포함)은 단일 작품 배치에서 잘못 놓인 구버전 기억을 여전히 올바른 위치로 옮긴다.
- 회귀 테스트는 다음을 다룬다. `长篇/` 아래 작품, `.active-book`이 있는 배치, `拆文库/`가 있는 배치의 세 다중 작품 형태는 루트에 프로젝트 수준 기억이 없어도 식별해 해당 작품 항목을 조회하고 이후 전역 항목을 기록해도 함께 가져온다. `长篇/` 아래 작품 폴더에 `书级/`가 추가되어도 두 단계 위를 판정한다. 단일 작품 배치 바깥에 우연히 `拆文库/`가 있어도 작품 폴더를 선택한다(작품 수준 기억만 있는 경우와 두 수준 모두 있는 경우). 홈의 `.active-book` 때문에 홈을 작업 공간으로 판정하지 않는다. 표시 없는 배치에서는 대리 조회와 기억 파일 변경을 하지 않으며 올바른 조회는 계속 작동한다. 각 규칙에 변이 검증을 수행했다. 홈 경로를 얻지 못하면 파일 시스템 루트까지 탐색하고 묶음 생성 스크립트 전체를 중단시키지 않는다.

## Alternatives considered

- **읽기 전용 조회는 절대 위치를 복구하지 않기**: `query`는 명목상 읽기 전용이므로 조회 한 번으로 기억이 옮겨지는 문제를 근본적으로 없앨 수 있다. 그러나 구버전 단일 작품 기억의 위치 복구는 읽기 전용 조회에서도 자가 복구되도록 의도한 기능이다([단일 작품 배치 복구](2026-09-24-author-memory-single-root.md)). 바꾸면 다른 이전 시점을 찾아야 한다. 이번 오류는 묶음 생성 스크립트가 주 세션 대신 작업 공간을 추측한 데 있으므로 그 추측 단계만 고친다.
- **작가 기억 도구의 `enclosing_workspace`를 직접 가져오기**: 도구의 단일 작품 오용 오류와 같은 판정 근거를 쓸 수 있다. 그러나 그 함수는 ‘이 디렉터리가 어느 작업 공간 속 작품인가’에 답하며 파일 시스템 루트까지 탐색하고 홈도 포함한다. 작업 공간 선택에는 범위가 너무 넓으므로 문서 정의대로 별도 구현하고 홈에서 멈춘다.
- **식별하지 못해도 작품 디렉터리로 계속 조회**: 장 집필 중 구버전 단일 작품 기억도 함께 복구할 수 있다. 그러나 ‘구버전 단일 작품 기억’과 ‘표시 없는 다중 작품 작업 공간 속 작품’을 구분할 수 없어 추측을 틀리면 후자를 망가뜨린다. 대리 조회를 생략하면 주 세션이 한 번 수동 조회하면 되고, 단일 작품 배치로 수동 조회할 때 위치 복구도 여전히 수행된다.

## Consequences

- 이점: DSH의 다중 작품 배치에서 장을 쓸 때 전역·해당 작품의 작가 습관을 자동으로 가져오며 조용히 수동 조회로 돌아가지 않는다. 표시 없는 배치도 대리 조회 때문에 손상되지 않는다.
- 비용: 구버전 기억이 잘못 놓인 단일 작품 배치에 작업 공간 표시가 전혀 없으면 장 집필 중 자동 복구하지 않고 주 세션이 한 번 수동 조회해야 한다(이때 위치 복구도 수행). 조상에 우연히 `拆文库/`, `长篇/` 등이 있고 자체 작가 기억은 전혀 없는 단일 작품 작업 공간은 바깥 작업 공간으로 판정된다. 바깥에 기억이 없으면 영향이 없지만 기억이 있는 다른 작업 공간이면 그곳의 전역 습관을 가져오게 된다.
