# 단편 순위 조사 결론: 저장과 인계

이번 출력 디렉터리의 `단편순위조사결론.md`에 결론을 쓴다. 보고할 때 머리말과 「扫榜结论」, 소재를 정할 때 「选题匹配」를 쓴다. `/story-short-write`는 목표 감정을 정할 때 이 파일의 「选题匹配」와 「复扫日期」를 읽어 선택 결과를 이어받는다.

## 단편순위조사결론.md 템플릿

제목·필드·열거값은 후속 집필 계약으로 보존한다.

```md
# 短篇扫榜结论：{플랫폼/방향}
- 扫榜日期：{YYYYMMDD}
- 复扫日期：{YYYYMMDD}
- 数据来源：{순위 파일명 / 작가 제공 / 내장 지식}
- 聚合表：{순위조사집계.md, 내장 지식 모드는 「无」}

{「## 扫榜结论：{플랫폼명}」 행부터 시작하는 순위 조사 보고서 전체}

## 选题匹配

### 方向 1：{한 문장 방향}
- 目标情绪：{意难平 / 反转震撼 / 爽感释放 / 治愈温暖 / 细思极恐 / 共鸣感动, 하나 선택}
- 题材与设定：{장르 + 핵심 설정}
- 差异化：{같은 방향 표본이 쓰는 것과 이 방향이 바꾸는 지점}
- 开头钩子：{첫 3문장에서 세우는 갈등·신분 차이·감정 후킹}
- 传播引擎：{反转 / 强共鸣 / 强话题 / 强余韵}
- 写作难度：{低/中/高, 조사 감정표의 난이도에 따름}
- 可行性：{高/中/低} — {같은 방향 표본 편수 + 추세 + 작가 소재의 지속 가능성}
- 失败风险：{가장 유력한 실패·중복 지점}
- 篇幅/平台：{권장 글자 수 + 목표 플랫폼, 플랫폼명은 아래 대응표 사용}
- 验证动作：{집필 전 저비용 검증법, 아래 참조}

### 方向 2 ...
```

방향 2-3개를 실현 가능성이 높은 순으로 제시한다.

## 목표 플랫폼 표기

집필 절차는 오른쪽 열의 플랫폼명만 받으므로 목표 플랫폼은 해당 원문 값을 그대로 쓴다.

| 순위 조사 플랫폼 | 집필 목표 플랫폼 |
|---|---|
| 知乎盐言 | 知乎盐言 |
| 番茄短篇 | 番茄 |
| 七猫短篇 | 七猫 |
| 黑岩 | 黑岩 |
| 点众 | 小程序 |

## 저비용 검증

- 도입 시험 집필: 목표 플랫폼에 맞는 150-300자 도입을 쓰고 자체 평가하거나 독자 두세 명에게 읽혀 본문을 열고 싶은지 확인한다.
- 같은 발상으로 도입 두 버전: 감정이나 플랫폼 분위기를 바꾸어 각각 첫 500자를 쓰고 어느 쪽이 더 끄는지 비교한다.
- 편집자 시험 투고: 모집 창구가 있으면 도입과 개요를 먼저 보내 의견을 물은 뒤 전체를 쓴다.

## 규칙

- 재조사 날짜: 단편 유행은 짧으므로 보통 조사 뒤 2-4주로 정한다. 지나면 결론은 참고만 한다.
- 가능성 상한: 집계에 「少」가 표시되거나 표본이 10편 미만이거나 작가 제공 제목 목록만 있으면 「高」 금지. 내장 지식 모드는 최고 「中」. 소재·조건이 버티지 못하거나 모집 조건에 맞지 않으면 「低」.
- 재실행은 「扫榜结论」과 「选题匹配」를 각각 교체하고 머리말을 보존한다. 중복 절을 추가하지 않는다.
- 전달 시 경로를 알린다. ‘집필할 때 소설 프로젝트를 순위 조사 폴더 안이나 같은 단계에 만들면 `/story-short-write`가 자동으로 찾습니다. 멀리 있으면 `단편순위조사결론.md`를 프로젝트 루트에 복사하세요.’
