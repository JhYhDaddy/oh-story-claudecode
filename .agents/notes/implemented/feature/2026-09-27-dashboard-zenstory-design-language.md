# Agent Note: 집필 작업대에 ZenStory 디자인을 적용하고 디자인 변수를 tokens.css로 분리

Status: implemented

## Problem

로컬 집필 작업대(`/story dashboard`)는 차가운 회청색의 일반 관리 화면이었다. 색·글꼴·모서리 값을 `styles.css`의 전용 변수와 수십 개 원시 색상값에 직접 적고 밝은 테마만 제공했다. 형제 프로젝트 drama-skills 단편 드라마 작업대 v2는 따뜻한 종이 바탕, 명조 제목·본문, 사각 글자 로고, 가는 선 카드, 밝고 어두운 테마의 ZenStory 디자인을 확정해 두 제품이 서로 달라 보였다. 브랜드 색 통일도 스타일시트 곳곳을 고쳐야 했다.

## Decision

- **시각만 변경**: 분석 라이브러리/집필 프로젝트 탭, 파일 트리, 검색, 편집/미리보기, 저장·상태 표시줄, 충돌 대화상자의 구조·동작은 유지한다. 요소 id, `data-*` 상태와 키보드 동작도 같다.
- **`skills/story/assets/tokens.css`로 변수 분리**: `--zs-*` 이름을 쓰며 형제 작업대의 `tokens.css`와 바이트가 같다. 브랜드는 `--zs-brand-navy #081431`, `--zs-brand-cream #F7EDD8`, `--zs-brand-cyan #22D3EE`다. 브랜드 크림을 밝게 조정한 페이지 `--zs-bg`, 원고지 `--zs-paper`, `--zs-surface / -2 / -3`, `--zs-line / --zs-line-strong`을 둔다. 글자는 브랜드 남색인 `--zs-ink-900`부터 `--zs-ink-300`, 어두운 바탕 글자는 `--zs-on-ink`다. 강조는 `--zs-accent / -ink / -wash / --zs-focus / --zs-selection`, 다음 행동 안내는 `--zs-signal`, 의미 색은 `--zs-ok / --zs-warn / --zs-danger`와 각 `-wash`다. 글꼴·크기·굵기·간격·모서리·그림자·초점 링·동작 시간·상단/탭 높이와 형제 프로젝트의 순서 색조·어두운 패널 변수도 포함한다. 어두운 값은 밝은 모드 강제가 아닐 때 `prefers-color-scheme: dark`, 그리고 `:root[data-theme="dark"]`에 적용해 남색 바탕·크림 글자를 쓴다. `styles.css`는 색·글꼴·모서리·그림자를 `var(--zs-…)`로만 읽고 원시 색상·글꼴 스택은 없다. 틀(상단·사이드바·문서 머리말·상태줄)은 `--zs-bg`, 편집·미리보기는 `--zs-paper`, 저장·알림·이동 링크의 어두운 바탕 글자는 `--zs-on-ink`다. 간격·글자 크기·동작 변수는 이 작업대에서 아직 참조하지 않는다.
- **청록 강조는 일부에만**: 초점 링, 현재 탭 밑줄, 현재 파일, 현재 행 번호, 커서에 쓴다. 밝은 종이에서 `#22D3EE` 대비는 약 1.7:1로 비텍스트 3:1에 못 미쳐 밝은 `--zs-accent`는 `#0891B2`(약 3.4:1), 글자에는 `--zs-accent-ink #0E7490`을 쓴다. 어두운 테마는 브랜드 청록 그대로다. 저장 버튼은 v2처럼 먹색 바탕·종이색 글자이며 강조색을 쓰지 않는다. 성공·주의·위험 의미색은 유지한다.
- **글자 로고**: 남색 둥근 사각형, 크림 명조 “文”, 우상단 청록 네 꼭짓점 별(CSS `clip-path`)이다. `tokens.css`의 공통 `.zs-mark`를 쓰고 페이지는 클래스·글자만 둔다. 옆에는 OH STORY와 “집필 작업대”를 쓴다. 책뿐 아니라 원고·웹소설·분석 보고서를 열기 때문에 “书” 대신 “文”을 골랐으며 드라마 작업대의 “场”처럼 한 글자다.
- **글꼴·밀도**: UI는 시스템 산세리프, 원고·빈 상태·충돌 제목과 편집·미리보기 본문은 시스템 명조 스택(Songti SC / STSong / Noto Serif CJK SC / Source Han Serif SC, 이후 Georgia / serif)이다. 웹 글꼴은 다운로드하지 않는다. 본문 17px / 1.9, UI 작은 글자 10–12→12–14px, 상단 56px, 탭 48px다.
- **구성 요소**: 상단 수직 구분선은 없애고 아래 가는 선만 남긴다. 아이콘 버튼은 34px 가는 테두리다. 검색은 v2의 ⌘K 트리거 모양(가는 테두리·밑변이 두꺼운 키 안내)을 빌리되 사이드바에서 트리를 필터한다. 탭은 회색 라벨·무배경 개수·현재 항목 진한 글자와 2px 밑줄이다. 연결 상태는 상태 점이 있는 작은 라벨, 편집/미리보기는 분할 컨트롤, 빈 상태는 점선 카드, 알림은 먹색 둥근 떠 있는 막대와 성공·실패 점이다.
- **테마 전환**: 상단 새로고침 옆에 `#themeButton`을 추가한다. 미선택이면 시스템을 따르고 선택 뒤에는 `light` / `dark`를 로컬 브라우저 `localStorage`의 `story_dashboard_theme`에 저장해 새로고침에도 유지한다. 저장 실패 시 현재 페이지만 적용한다. CSS가 달·해 아이콘을 바꾸고 접근 가능한 이름도 어두운/밝은 테마 전환으로 바꾼다.
- **서버**: `dashboard-server.mjs` 정적 자원 허용 목록에 `tokens.css`를 추가하고 두 `<link>`로 `tokens.css`, `styles.css` 순서로 로드한다.
- **동반 레이아웃 수정**: 자동 너비 grid인 파일 트리 루트에서 긴 이름이 열을 넓혀 가로 스크롤·잘림을 만들었다. 열을 패널 너비로 고정하고 긴 이름 끝은 말줄임표로 표시한다.
- **스크린샷**: `demo/story-dashboard.png`를 같은 구도로 재촬영했다(1440×900, 집필 프로젝트 탭의 장편 제1장 끝부분). 임시 상단 경로는 이전 이미지처럼 `~/stories/demo`로 바꿨다.

## Alternatives considered

- **v2 초안의 주홍 강조·로고 유지** — 검토된 초안을 복사하면 간단하고 바로 같은 제품처럼 보인다. 그러나 두 프로젝트가 이후 공식 ZenStory 남색·크림·청록으로 함께 바뀌어 공통 `tokens.css`를 쓰면 다시 불일치한다.
- **밝은 모드에도 브랜드 청록 `#22D3EE` 직접 사용** — 파생색 없이 브랜드와 일치한다. 그러나 크림 바탕 대비 약 1.7:1은 초점 링·밑줄이 잘 안 보이고 3:1 기준도 못 채운다. 같은 색조를 어둡게 하며 어두운 바탕에서는 브랜드 색이 충분히 뚜렷하다.
- **`<head>` 인라인 스크립트로 테마를 미리 설정** — 시스템 반대 테마를 선택한 사람에게 로드 순간 다른 배경이 보이지 않는다. 그러나 CSP `script-src 'self'`는 인라인을 금지하며 20줄을 위해 자원·허용 목록을 추가할 가치가 작다. `app.js` 시작에서 적용하므로 그런 사용자는 잠깐 배경 전환을 볼 수 있다.
- **`styles.css`에서 `@import`로 변수 로드** — `index.html` 변경 없이 링크 하나만 유지한다. 그러나 스타일 다운로드 뒤 변수를 받는 직렬 로드다. 두 `<link>`는 병렬이며 변수 교체도 파일 하나면 된다.
- **검색을 상단 ⌘K 명령 패널로 이동** — v2처럼 전역 접근이 가능하다. 그러나 여기서는 파일명으로 사이드바 트리를 거르는 기능이며 이동은 정보 구조 변경이다. 시각만 바꾸므로 모양·단축키 안내만 빌린다.
- **편집은 산세리프, 제목만 명조** — Markdown 표·코드·목록 정렬이 낫다. 그러나 주로 소설·분석 보고서를 읽어 원고지 느낌이 맞고 v2의 대본 명조와 같다. 코드·인라인 코드는 고정폭을 유지하고 긴 문단 행 번호 정렬 E2E도 통과한다.

## Consequences

- 이점: 두 작업대가 같은 제품군처럼 보인다. 브랜드 색·모서리는 공통 `tokens.css`만 바꾸며 어두운 테마와 브라우저별 선택 저장을 제공한다. 긴 파일명도 가로 스크롤을 만들지 않는다.
- 비용: 명조는 시스템에 의존한다. macOS에는 있지만 Linux에 Source Han Serif / Noto Serif CJK가 없으면 기본 serif로 내려가 기기별로 다르다. Windows는 브라우저 중국어 serif 대체를 따른다. 정적 파일 하나가 늘어 허용 목록·자원 접근 테스트를 함께 관리해야 한다. 새 변수는 밝고 어두운 두 값 모두 필요하다.
- 동작 변화: 테마 버튼 하나와 `localStorage` 키 하나가 추가되고 나머지 상호작용은 유지한다.

## 검증

`npm run test:dashboard` 27개, 로컬 Chrome 채널·영상 기록 끈 Playwright E2E 24개를 통과했다. 시스템 기본 테마와 수동 선택 후 새로고침 유지를 추가했고 저장 행을 지우면 실패한다. 1440×900 밝은·어두운 화면과 390×844 모바일을 육안 확인했다. `styles.css`에 원시 색상·글꼴 스택은 없다. 형제 프로젝트 확정 `tokens.css`로 교체한 뒤 참조한 모든 `--zs-`가 정의되어 있었고 밝은 화면 픽셀 비교는 로고 모서리 7px→8px의 수십 픽셀만 달랐다.
