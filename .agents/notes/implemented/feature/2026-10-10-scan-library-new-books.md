# Agent Note: 치뎬·치마오 서고 신작 페이지 수집을 추가하고 인기 지표 없는 목록이 플랫폼 집계 기준을 바꾸지 않도록 수정

Status: implemented
Date: 2026-10-10
Related: [순위 조사 집계와 인계](2026-09-26-scan-aggregate-and-handoff.md), [순위 조사·설치 검토 수정](../bug-fix/2026-09-26-scan-setup-review-fixes.md)

## Problem

작가는 “최근 떠오르는 신작”을 보고 싶어 했다. 치마오에는 순위표만 있고 치뎬 신작 순위는 20만 자 도달, 계약 후 30일 경과 또는 3일 넘게 연재 중단 시 빠져 계속 갱신하며 막 성장하는 신작을 두 곳 모두 온전히 볼 수 없었다. 작가는 두 서고 필터 화면의 앞 몇 페이지 수집을 지정했다. 치마오 https://www.qimao.com/shuku/a-a-a-1-1-a-0-click-1/ 는 전체 채널·30만 자 미만·3일 이내 갱신·연재 중·클릭순, 치뎬 https://www.qidian.com/all/action0-size1-update1/ 는 남성향·연재 중·30만 자 미만·3일 이내·인기순이다.

수집 조건은 다르다. 치마오는 서버 렌더링이라 일반 HTTPS로 읽지만 하위 분류만 있고 인기 지표가 없다. 치뎬 PC는 직접 요청하면 위험 관리에 차단되어 Chrome을 사용해야 하며 글자 수는 매번 바뀌는 수집 방지 글꼴로 암호화되고 총 추천 수도 없다. 집계기는 인기 지표 기준의 분모를 플랫폼 전체 중복 제거 작품 수로 삼아 지표 없는 서고 책이 지표 있는 책의 2.33배를 넘으면 플랫폼 전체가 조용히 순위 기준으로 내려가 실제 인기 값도 잃었다.

## Decision

- 치마오: `qimao-rank-scraper.js --source library --pages N`(기본 3, 1–10)은 Node https를 쓰며 Chrome이 필요 없다. 첫 페이지 제목에서 세 필터와 클릭순을 확인한다. 하위 분류 링크의 상위 분류 id로 분류 페이지를 한 번 요청해 제목에서 상위 분류명을 보충하고 실행 내 캐시를 사용한다. 순위표의 장르 표기와 정확히 맞춘다. 응답 헤더 줄바꿈 때문에 해당 요청에는 `insecureHTTPParser`를 켠다.
- 치뎬: `qidian-rank-scraper.js --type library --pages N`(기본 3, 1–10)은 CDP만 사용하며 `--type all`에는 넣지 않는다. 각 페이지에서 보이는 필터 패널, 남성향 채널, 인기순, 현재 페이지 번호를 확인한다. `qd_anti_spider` 글꼴(qdfepccdn.qidian.com만 허용)을 내려받아 순수 Node로 cmap과 post 글리프 이름을 파싱해 글자 수를 해독한다. 사설 사용 영역 문자는 출력하지 않는다. 계약·유료 여부, 갱신 시간과 예비 글자 수는 모바일 작품 페이지에서 보충하고 실패하면 `[待补]`를 쓴다. 총 추천 수는 “신작 총 추천”으로 따로 표시한다. 신작은 수천~수만이므로 집계기가 인식하는 “총 추천”에 넣으면 월표·베스트셀러의 기존 책과 섞여 장르 인기 중앙값이 두 자릿수 규모로 떨어진다. 따라서 치마오 서고처럼 인기순 순위로 집계한다. CAPTCHA 차단 판단은 먼저 다수의 작품 링크가 있는지 보며 소개문·장 제목의 “검증”, “드래그” 같은 단어로 오판하지 않는다.
- 두 출처 모두 모든 페이지를 파일 하나에 쓴다. 첫 줄의 “플랫폼 · …신작”으로 집계의 “신작 순위” 열에 포함한다. 순위는 페이지 간 연속이며 bookId로 중복 제거하고 새 작품 없는 페이지에서 멈춘다. 첫 페이지 실패 또는 0권이면 파일 없이 exit 1, 뒤 페이지 실패면 수집분을 보존하고 exit 2다. 파일명은 각 스크립트의 유일한 날짜 포함 대입문을 사용한다.
- 장편·단편 공유 집계기는 적어도 하나의 지표 포함 목록에 나온 책만 인기 기준 분모에 넣는다. 지표가 전혀 없는 목록은 순위표로 취급한다. 일부 책만 값이 있으면 장르 인기 중앙값에 “(n권 값 있음)”을 붙이고 3권 미만이면 표시하지 않는다. 순위표가 있으면 중앙값은 인기 값이 있는 책만 계산한다고 한 줄 설명한다. 글자 수 중앙값은 유지하되 서고가 30만 자 미만만 수집해 이를 낮춘다고 플랫폼 참조에 명시한다.
- 두 출처 모두 기본 조합에는 넣지 않고 “신작”, “최근 떠오르는”, “무엇이 성장하는지” 요청 때 추가한다. 치뎬 참조는 Chrome 필요를 명시한다. 진입 파일의 여섯 “사용법은 참조 파일 확인” 스크립트 설명을 한 줄로 합쳐 치뎬 절에 공간을 주고 판체·진장 여유를 고정하며 치마오 예산 분기를 추가한다. 설명과 라우팅 표에 “치마오”, “신작” 트리거를 추가한다.

## Alternatives considered

- **치뎬 글꼴만 해독하고 모바일 상세 정보 제외**: 페이지마다 브라우저 한 번만 열고 20회 추가 요청을 피할 수 있다. 그러나 계약·유료 여부는 필수이며 글꼴 실패 시 글자 수 보완도 필요하다. 모바일 페이지는 실측 가능했고 3페이지에 약 30–40초가 추가되어 채택하지 않는다.
- **신작 총 추천을 일반 “총 추천”으로 집계**: 기존 숫자를 같은 기준으로 사용할 수 있다. 그러나 실제 출력 검사에서 서고 혼합 후 치뎬 라이트노벨 인기 중앙값이 135만→5455, 도시물이 195만→5.5만으로 떨어져 인기 대신 서고 책 수를 반영했다. 기존 기본 조합의 신작 순위 혼합은 이전 동작이며 이번에는 확대하지 않는다.
- **모바일 상세 정보만 사용하고 글꼴 해독 생략**: 글꼴 파서를 만들지 않아도 된다. 그러나 상세 요청은 제한·실패할 수 있고 글자 수는 핵심 필드다. 목록 글꼴 해독은 추가 요청에 의존하지 않으므로 상세 정보는 보완용으로만 쓴다.
- **치마오 하위 분류를 장르로 직접 사용**: 분류 페이지 추가 요청이 없다. 그러나 순위표는 상위 분류를 사용해 장르 표가 두 층으로 갈라짐을 픽스처로 확인했다.
- **페이지의 `__NUXT__` 실행으로 분류 트리 복구**: 매핑을 한 번에 얻을 수 있다. 그러나 이름이 변수로 압축돼 사이트 스크립트를 실행해야 하므로 안전하지 않고 불안정하다. 분류 페이지 제목은 요청 한 번으로 상위 이름을 제공한다.
- **집계기를 그대로 두고 페이지 수만 제한**: 공유 파일을 건드리지 않는다. 그러나 작가는 앞 몇 페이지를 원하고 페이지가 늘면 기준이 조용히 사라진다. 분모 수정이 가장 작고 설명 가능한 해법이다.

## Consequences

- 이점: 작가는 두 사이트에서 최근 3일간 계속 갱신되는 30만 자 이내 신작을 볼 수 있다. 클릭·인기 순위로 기존 순위표와 함께 신작 열에 집계한다. 치마오는 Chrome이 시작되지 않아도 수집할 수 있다.
- 비용: 치마오는 매번 분류 페이지 5–8회가 추가되고 제목 형식에 의존한다. 치뎬은 약 60회 모바일 요청이 추가되며 새로고침마다 글꼴이 바뀐다. 치마오 전체 사이트·치뎬 남성향 필터는 고정하고 채널·정렬 변경은 지원하지 않는다. `test-scan-runtime.js`는 약 6초에서 45초가 된다. “(n권 값 있음)”은 기존 데이터에도 나타난다(판체 일부 작품명 파싱 실패, 뎬중 평가가 1권뿐인 경우).
- 미검증: 치뎬 전체 흐름을 실제 CDP Chrome에서 실행하지 않았다. 앱 내장 브라우저의 실제 1·2페이지에서 페이지 읽기 스크립트를 확인했고 글자 수 해독은 렌더링과 40권을 항목별 대조했다.
