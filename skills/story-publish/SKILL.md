# story-publish: 게시 자료 준비

작품의 기존 설정·개요와 작가의 결정을 플랫폼 작품 등록 양식에 넣을 자료로 정리합니다. 플랫폼 규칙을 확인한 뒤 `发布资料-<平台>.md`로 저장합니다. 줄거리 기획과 본문 집필은 `story-long-write` 등 집필 스킬이 맡으며, 작가가 단순히 “책 시작”이라고 할 때도 그쪽으로 연결합니다. 이 스킬은 작가 대신 관리자 화면에 로그인하거나 양식을 입력하거나 게시하지 않습니다.

## 원칙

- **작가가 확인한 것만 확정본입니다.** 각 필드에 상태 하나를 붙입니다. `已确认`(확정: 작가가 명시적으로 지정하거나 수락), `建议`(제안: 작품 자료에서 추론하거나 새로 작성), `待确认`(확인 대기: 누락·모호함·모순), `待平台核实`(플랫폼 확인 필요: 규칙이 불명확하거나 화면과 불일치). 침묵은 동의가 아닙니다. 작가가 후보안 전체를 수락하면 나열된 각 항목을 확인한 것으로 봅니다. 작가가 제공한 줄거리·개요는 소재이며 자동으로 플랫폼의 “작품 소개”가 되지는 않습니다.
- **작가가 정한 값을 임의로 바꾸지 않습니다.** 제목·소개·필명에 문제가 있으면 지적하고 대안을 제시하되 원래 값을 유지합니다.
- **플랫폼 후보는 이 스킬의 플랫폼 참고 파일에서만 가져옵니다.** 기억에 의존하거나 순위 조사·작품 분석·소재 선정 자료에서 옮겨 오거나 플랫폼 간 공유하지 않습니다. 이야기 사실이 없으면 먼저 묻고 인물·사건·판매 포인트를 지어내지 않습니다.
- **준비 완료는 게시 완료가 아닙니다.** 자료가 갖춰지면 “게시 자료 준비 완료”라고만 말하고 “제출 완료”, “심사 중”, “게시 완료”라고 하지 않습니다.

## 작품 자료 읽기

책 디렉터리는 작가가 지정한 곳이 우선이며 다음은 `.active-book`입니다. 대상이 불명확하거나 여러 책을 구분할 수 없으면 작가에게 묻고 디렉터리 이름으로 추측하지 않습니다. 읽기만 하며 설정을 바꾸거나 집필 단계를 시작하지 않습니다.

- 장편: `설정/소재방향.md`의 기본 정보와 `作者已定`(작가 확정 사항). 주인공 확인이 필요하면 `설정/인물/`의 인물 카드를 읽습니다. 소개에 줄거리 근거가 필요하면 `개요/개요.md`와 관련 권별·장별 세부 개요를 읽습니다.
- 단편: `설정.md`와 `구간개요.md`. 투고용 도입문은 본문 시작이며 플랫폼 소개로 취급하지 않습니다.
- `소재선정.md`, 작품 분석, 순위 조사 자료는 제안의 근거로만 사용합니다. 가제나 인물 카드의 이름이 자동으로 확정본이 되지는 않습니다. 설정에 제목이 없으면 책 디렉터리 이름을 현재 제목으로 사용합니다.

## 플랫폼

현재 판체 소설을 지원합니다. `references/fanqie.md`를 읽고 안내에 따라 필요한 후보 파일을 읽습니다.

다른 플랫폼은 “현재 미지원”이라고 명확히 알리고 날짜가 표시된 작품 등록 양식 스크린샷이나 공식 설명을 요청합니다. 받기 전에는 플랫폼에 특화되지 않은 제목·소개 초안만 제공하고 판체 규칙을 적용하지 않습니다. 플랫폼을 추가할 때는 `fanqie.md` 구조를 따라 참고 파일을 작성하며 확인 날짜와 범위를 명시합니다.

## 작업 절차

1. 대상 플랫폼과 작품 유형(장편/짧은 이야기)을 확인합니다. 답변 첫머리에 플랫폼, 지원 상태, 플랫폼 참고 자료의 확인 날짜·범위를 명시합니다.
2. 작품 자료를 읽고 작가가 정한 값을 기록합니다. 작가가 요청한 필드에 대해서만 후보를 만듭니다. 후보 제목은 플랫폼 참고 자료의 제목 규칙에 따라 글자 수와 기호를 먼저 검사하고 글자 수를 표시합니다.
3. 플랫폼 참고 자료에 따라 필드별 허용 값, 개수 상한, 길이를 확인합니다. 자료에 없는 제한은 “자료에 명시되지 않음”으로 표시합니다.
4. 제목과 소개가 확정되면 「표지」 항목에 따라 처리합니다.
5. 이번에 요청한 모든 필드에 결론이 나면(확정 또는 작가가 미입력 결정) 파일을 저장합니다. 아직 저장하지 않았으면 답변에 전체 초안을 제공합니다. 저장 후에는 이번에 기록한 내용, 남은 내용, 파일 경로만 알리고 전체를 다시 붙이지 않습니다.
6. 게시 자료는 플랫폼 입력 값의 기준입니다. 확정 제목이 `설정/소재방향.md`(단편은 `설정.md`)의 제목과 다르면 저장 후 알립니다. 설정과 책 디렉터리 변경은 집필 스킬에 맡기며 이 스킬은 변경하지 않습니다.

## 표지

현재 세션에서 실제로 호출할 수 있는 이미지 생성 도구를 먼저 확인합니다(모델 이름으로 판단하지 않음). 작가에게 “바로 생성”, “프롬프트만”, “보류” 중 선택하게 합니다. 이미 선택했고 여전히 실행 가능하면 다시 묻지 않습니다. 도구가 없다는 이유로 유료 API를 자동 사용하지 않습니다.

확정 제목·소개·필명·플랫폼·장르와 인물·장면의 사실을 `story-cover`에 전달합니다. 필명이 없으면 추가로 묻습니다. 바로 생성은 전체 절차, 프롬프트만은 Step 1-3을 따릅니다. 두 방식 모두 전체 프롬프트 원문을 `封面`(표지) 항목에 기록하고 생성에 성공하면 이미지 경로도 기록합니다. `story-cover`를 사용할 수 없거나(예: OpenClaw에서 키가 없어 발견되지 않음), 실패하거나, 작가가 보류하면 이유를 `待作者确认`(작가 확인 대기)에 쓰고 다른 필드를 막지 않습니다. 생성 실패 후 프롬프트 전용으로 바꾸려면 작가의 동의가 필요합니다. 프롬프트만 있거나 이미지를 저장하지 않았다면 “표지 준비 완료”라고 하지 않습니다. `story-cover`의 스타일·크기 제안은 플랫폼 규격을 대신하지 않습니다.

## 게시 자료 파일

파일명은 `发布资料-<目标平台>.md`이며 대상 플랫폼은 참고 메타정보의 `platform` 원문을 사용합니다(예: `发布资料-番茄小说.md`). 책 디렉터리에 둡니다. 장편은 `본문/`의 상위, 단편은 `본문.md`가 있는 디렉터리이며 본문이 없으면 책 디렉터리 바로 아래에 둡니다. 같은 이름의 파일이 있으면 먼저 읽고 작가가 수동 수정한 내용과 충돌하면 덮어쓰지 말고 묻습니다. 기존 파일은 아래 형식으로 재정렬하되 작가의 수동 작성 내용을 보존합니다.

이 파일은 향후 프로그램이 관리자 양식을 채우기 위해 읽으므로 형식은 고정 계약입니다. 아래 중국어 필드명·제목·상태 값은 번역하지 않고 그대로 씁니다.

- 처음에는 메타정보를 한 줄에 하나씩 `> 格式版本：1`, `> 目标平台：<platform>`, `> 作品类型：长篇` 또는 `短故事`, `> 核验：<확인 날짜와 범위>` 순서로 씁니다.
- 바로 다음은 `# 书本名称：<제목>`이며 이후 기본 필드, `## 封面`, 플랫폼 태그·분류 항목, `## 作品简介`, `## 待作者确认`, `## 待平台核实`, `## 来源说明` 순서입니다. 기본 필드와 태그 항목은 플랫폼 참고 메타정보에서 해당 유형의 `basics`, `tag_sections`를 따릅니다. 각 필드는 한 줄 `- 필드：값`이며 한 필드의 여러 값은 `、`로 구분합니다.
- 필드 값은 세 가지뿐입니다. 확정된 값, 작가가 미입력하기로 한 `（不填）`, 아직 정하지 않아 비워 둔 값. 미정 항목은 `待作者确认`에 나열합니다. 제목이 미정이면 `# 书本名称：`만 쓰고 소개가 미정이면 해당 항목을 비웁니다. 제안·설명·자리표시자를 필드 값에 넣지 않습니다.
- 제목·소개·태그 후보 등의 제안 초안과 작가가 관리자 화면에서 확인해야 할 사항은 `待作者确认`에 넣습니다. 규칙 누락이나 적용 범위가 불명확한 사항은 `待平台核实`에 넣습니다. 두 항목에 내용이 없으면 `无`(없음)를 씁니다. 출처와 확인 근거는 마지막 `来源说明`에 넣습니다.

장편 예시(판체, 기계가 읽는 제목·필드는 원문 유지):

```markdown
> 格式版本：1
> 目标平台：番茄小说
> 作品类型：长篇
> 核验：2026-10-29; 태그는 웹의 작품 만들기 팝업과 대조했으며 앱과 제출 결과는 확인하지 않음

# 书本名称：<제목>

- 作者/笔名：
- 签约模式：
- 目标读者：
- 主角1：
- 主角2：

## 封面

- 模式：<바로 생성/프롬프트만/보류. 선택 전에는 비움>
- 状态：<프롬프트와 이미지 상태를 따로 작성>
- 提示词：<전체 프롬프트 원문>
- 图片：<저장된 이미지 경로>

## 阅读标签

- 主分类：
- 主题：
- 角色：
- 情节：

## 内容标签

- 情节：
- 情感：
- 人设：
- 世界观：

## 作品简介

## 待作者确认

## 待平台核实

## 来源说明
```

긴 프롬프트는 코드 블록에 넣어도 됩니다. 작가가 요청하지 않으면 전체 후보 목록을 나열하지 않습니다.

## 형식 검사

저장 후 `python3`, `python`, `py` 순서로 사용 가능한 실행기를 찾고 이 스킬 루트의 `scripts/check-publish-format.py <게시 자료 파일>`을 실행합니다. 스크립트는 읽기 전용입니다. FAIL은 계약 위반 또는 플랫폼에 없는 옵션·태그이므로 수정 후 재실행합니다. WARN은 확정 값이 플랫폼에서 거부될 수 있다는 뜻(제목·길이 등)이므로 작가에게 알리되 대신 바꾸지 않습니다. 환경에서 스크립트를 실행할 수 없으면 파일을 다시 읽고 항목별로 확인하며 자동 검사를 실행하지 않았다고 알립니다.
