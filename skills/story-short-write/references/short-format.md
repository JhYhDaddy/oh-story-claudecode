# 단편 본문 형식

> 본문 작성 전 필독. 이 규약에 따라 소절 표기, 문단, 대화, 문장부호, 메타 정보를 처리한다. 표현의 기본값은 [style-resolution.md](style-resolution.md)를 따르며, 파일명, 제목/소절 구조, 글자 수 검수는 이 규약을 따른다. 사용자나 플랫폼의 명시적 납품 요구가 우선한다. 감정, 훅, 반전, 마무리는 `short-craft.md`와 장르 묶음을 따른다.

---

## 소절 표기

전체에서 한 가지 형식만 쓰고 섞지 않는다. 소절 표기와 따옴표 종류는 `설정.md`의 「平台基调」(플랫폼 기조)를 따른다. 기록이 없으면 `본문.md`의 기존 방식을 유지하고, 본문도 없으면 `###1.` + `""`를 쓴다.

| 형식 | 예시 |
|------|------|
| `###1.` | `###1.` `###2.` `###3.` |
| `###第N章` | `###第一章` `###第二章` |
| `1.`(숫자만, `###` 없음) | `1.` `2.` `3.` |

## 문단: 두 가지 템플릿

플랫폼에 맞춰 문단 형태를 고르고 `short-craft.md`에 따라 자세히 쓸 곳과 간략히 쓸 곳을 배분한다. **「문단당 ≤ 3문장」「소절당 800-1500자」라는 일률적 제한은 두지 않는다**. 각 소절 길이는 내용에 따른다.

### 헤이옌: 한 문장에 한 문단, 여백으로 빠르게 읽기

- 한 문장에 한 문단을 기본으로 하고 잦은 줄바꿈으로 낙하감과 멈춤을 만든다. 문단 사이에는 줄바꿈 문자 하나만 둔다.
- 리듬이 촘촘하고 소절 분량은 대체로 작다. 소절 끝은 미완료 행동, 새 정보, 부분적 약속 이행, 명확한 다음 행동으로 이어도 되며 매번 별도의 서스펜스 훅을 만들 필요는 없다.
- 한 문장이 한 문단을 이루는 것이 보통이다. 「글자 수를 채우려고」 문장을 긴 문단으로 붙이지 않는다.

템플릿 예시:

```
###1.

우리 집에는 해마다 청명절에 "복화반"에 절하는 규칙이 있다.
접시 하나에 절반은 산해진미를, 절반은 멀건 국물을 담는다.
오빠가 고기를 뽑자 부모님은 두둑한 용돈 봉투를 상으로 주었다.
내 차례가 되자 나는 또 그 멀건 국물을 뽑았다.
```

### 판체 / 치마오: 짧은 문단을 바탕으로 서술과 대화를 교차

- 모바일 독서의 바탕은 짧은 문단이지만 **여러 문장으로 이루어진 회상 서술과 대화의 교차를 허용한다**. 한 문단에 내적 독백, 상처를 더하는 회상, 행동을 담고 대화를 이을 수 있다.
- 사극 로맨스/세태물은 완결된 감정의 연쇄와 장면 전개를 담도록 더 긴 서술 문단을 써도 된다.
- 통쾌함, 망신 주기, 반전에서는 짧게 압축한다(한 문장에 한 문단도 가능). 전환과 정보 설명은 한 문장으로 넘긴다.

템플릿 예시:

```
###第一章

뜨거운 국을 그의 앞에 놓았을 때 그는 고개를 숙인 채 휴대전화를 보고 있었다. 화면에는 첫사랑의 이름이 떠 있었다. 3년이었다. 가장 힘든 날들을 견뎌 냈다고 생각했는데, 견디고 있던 건 나 혼자였구나.
"앞으로 이런 건 네가 안 해도 돼." 그는 고개도 들지 않았다. "그 애는 기름 냄새를 싫어해."
그릇을 든 내 손이 잠깐 멎었다.
```

### 두 방식의 공통 필수 제약(모든 플랫폼)

- 본문에서 인접 문단 사이에는 **줄바꿈 문자 하나 `\n`만 허용**한다. 빈 줄이나 연속 줄바꿈 `\n\n`을 넣지 않는다(촘촘히 배열). 소절 표기 앞뒤는 별도다.
- **들여쓰기 없음**: `　　`(전각 공백)이나 반각 공백으로 들여쓰지 않는다. 플랫폼 렌더러가 처리한다.
- **본문 문단의 Markdown 금지**: 통일한 소절 표기(예: `###1.`) 외에 본문 문단에서는 굵게 `**`, 기울임 `*`, 제목 `#`, 구분선 `---` 등을 쓰지 않는다.
- 길고 짧음을 교차하고 전체를 같은 길이로 만들지 않는다. 문단을 같은 글자 수로 자르는 것이 바로 AI 말투의 원인이다.

## 대화

### 따옴표

`설정.md`의 「平台基调」를 따른다. 기록이 없으면 반각 `""`가 기본이다. 즈후 옌옌이나 사용자가 지정한 경우 `「」`를 쓰며 전체에서 통일한다.

### 규칙

1. 대화는 **독립된 줄**에 쓰고 서술 문단 안에 끼워 넣지 않는다.
2. 대화 태그 대신 행동을 쓴다. 「그가 말했다」「그녀가 말했다」「그가 살짝 웃으며 말했다」를 줄이고 행동 비트 + 대화로 바꾼다. 평범한 「말했다」는 맥락에 따라 남겨도 된다.
3. 두 사람의 연속 대화에서는 태그를 생략하고 내용으로 화자를 구별한다.

올바른 예:

```
그녀가 컵을 내려놓았다.
"가."
그는 움직이지 않았다.
"가라고 했어."
```

잘못된 예:

```
그녀가 컵을 내려놓으며 말했다. "가." 그는 움직이지 않았고 그녀는 다시 말했다. "가라고 했어."
```

## 글자 수 계산

각 소절을 마칠 때와 전체를 납품하기 전에 반드시 기계로 계산한다. 모델의 추정에 맡기지 않는다.

```bash
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done
"$PYBIN" -c "from pathlib import Path; print(len(''.join(Path('본문.md').read_text(encoding='utf-8').split())))"
```

소절별 분포(소절 표기로 나누고 각 소절의 공백 제외 문자 수를 보고):

```bash
"$PYBIN" -c "
import re
from pathlib import Path
pat = re.compile(r'###\s*\d+\.|###\s*第[一二三四五六七八九十百千万两〇零0-9]+章|\d+\.')
cur, buf, out = None, [], []
for line in Path('본문.md').read_text(encoding='utf-8').splitlines():
    if pat.fullmatch(line.strip()):
        out.append((cur, buf)); cur, buf = line.strip(), []
    else:
        buf.append(line)
out.append((cur, buf))
for name, body in out:
    if name is not None:
        print(name, len(''.join(''.join(body).split())))
"
```

분포는 이상 소절을 찾는 데만 쓴다. 어떤 소절이 이웃 소절보다 뚜렷하게 짧으면 개요로 돌아가 승인된 플롯 지점, 행동, 결과가 모두 쓰였는지 확인한다. 다 썼다면 그대로 두며 길이를 맞추려고 장면을 보태지 않는다.

위의 `python3→python→py` 순서로 사용 가능한 인터프리터를 먼저 탐색해 Windows의 Microsoft Store 자리표시자 프로그램을 직접 호출하지 않는다. `wc -m`은 macOS / Linux의 대안으로만 쓰고 바이트를 세는 `wc -c`는 금지한다. 전체 납품은 `scripts/check-delivery-contract.js`의 공백 제외 문자 수를 기준으로 한다. 기계 계산을 끝낼 수 없으면 “기계 글자 수 검증 미완료”라고 밝힌다. 행 수 추정은 임시 참고일 뿐이며 필수 검증에 통과했다고 주장하면 안 된다.

## 문장부호 기본 요구

본문에서는 기본적으로 `……` / `——` / `—` / `--`를 쓰지 않는다. 서술, 대화, 심리 묘사에 모두 적용한다. 작가가 허용한 구체적 표현과 장르 예외는 문체 판정에 따르며 파일 구조와 글자 수 검수에는 영향을 주지 않는다.

멈춤, 울먹임, 말끝 흐리기, 중단, 여백은 기본적으로 다음 수단으로 구현한다.

- 짧은 문장, 마침표, 쉼표로 끊기.
- 행동 비트(「그녀가 잠깐 멈췄다」「그가 주먹을 꽉 쥐었다」).
- 줄바꿈 / 한 문장에 한 문단.

나머지 문장부호는 어조에 맞춘다.

| 어조 / 기능 | 문장부호 | 방어선 |
|---|---|---|
| 압박 / 냉정 / 절제 | 짧은 문장, 쉼표, 마침표. 필요하면 쌍점으로 판단을 강조 | 억지로 느낌표를 더하지 않고 모든 문장을 마침표로만 끝내지도 않음 |
| 추궁 / 반문 | 물음표 + 짧고 날카로운 재질문 | 모든 문장을 `？`로 끝내지 않음 |
| 폭발 / 망신 주기 | 실제 폭발 지점에 느낌표 1개. 연속 폭발은 최대 1-2곳 | `!!!` 금지, 문단 전체를 고함처럼 느낌표로 채우기 금지 |
| 정보 공개 / 판단의 귀결 | 쌍점, 한 문장에 한 문단으로 강조 | 논문처럼 쌍반점을 이어 쓰지 않음 |

장르 예문을 본문에 쓸 때도 이번 문체 판정을 따른다.

## 본문에 장 메타 정보 혼입 금지

장 번호와 집필 공정 용어는 제목 / 소절 표기 / 파일명 / 추적 기록에만 허용한다. 본문 서술, 대화, 심리 묘사에 다음을 **넣지 않는다**(검사 패턴 원형 유지).

```
第[一二三四五六七八九十百千万两0-9]+章 | 上一章 | 上章 | 前一章 | 本章 | 这一章 | 前文 | 后文 | 伏笔 | 细纲 | 读者
```

인물이 인지할 수 있는 사건 기준점이나 상대적 시간으로 바꾼다. 예: 「1장의 그 3초간의 사격보다 더 아팠다」를 「그 3초간의 사격보다 더 아팠다」로 바꾼다.

예외: 인물이 이야기 세계 안에서 실제로 「제 X장」 텍스트를 읽거나 논의하는 경우, 또는 실제 작가/독자인 인물이 독자로서의 정체성을 이야기하는 경우에는 남겨도 된다.
