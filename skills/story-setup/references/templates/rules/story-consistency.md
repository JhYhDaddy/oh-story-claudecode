# 이야기 일관성 규칙

설정, 개요, 추적 정보를 수정할 때 다음 규칙을 따릅니다.

## 규칙

1. **설정 변경 시 반드시 추적/ 확인**: 인물 설정이나 세계 규칙을 바꾸면 반드시 `tracking_commit.py check`를 실행해 `_tracking-state.json`과 모든 파생 뷰가 일치하는지 확인합니다. 이어 현재 복선 표, 관련 인물 스냅샷, 작가/독자 시간선을 대조해 모순이나 조기 공개가 생기지 않는지 확인합니다.

2. **새 주요 인물은 개별 파일 작성**: 주요 인물마다 독립된 설정 파일이 있어야 하며, 관계 파일 관계.md가 있으면 함께 갱신합니다.

3. **시간선 변경은 트랜잭션으로 처리**: 시간 순서, 객관적 사실, 독자 인식에 영향을 주는 변경은 해당 장의 `mode=revision` 트랜잭션에서 사건을 갱신합니다. 도구가 `작가용진실.md`와 `독자가아는사실.md`를 일괄 생성합니다.

4. **설정 변경은 의미 단위 트랜잭션 한 번으로 제출**: 영구적으로 유효한 결정은 트랜잭션의 `delta.constraints`와 현재 전체 값인 `context.long_term_constraints`에 기록합니다. 다음 장에서 반드시 이행할 사항은 `delta.next_chapter_commitments`에 기록합니다. 도구가 간결한 증분과 이어쓰기 상태 카드(고정 7개 항목)를 생성합니다. `장별기록/`, `문맥.md`, 인물 스냅샷, 복선 표, 시간선 뷰나 요약을 직접 편집하면 안 됩니다.

5. **일관성 검사는 grep 사용 필수**: 기존 기록을 검색해 대조합니다. 자주 쓰는 명령은 다음과 같습니다.
   - 인물 속성: `grep -rn "角色名" 설정/ 본문/ | grep "属性关键词"`
   - 시간선: `grep -rn "第.*天\|.*日后\|过了.*时" 본문/` 실행 후 `추적/시간선/작가용진실.md` 및 `독자가아는사실.md`와 대조
   - 능력 체계: `grep -rn "体系关键词" 설정/ 본문/`
   - 복선 상태: `grep -rn "F[0-9]" 추적/복선.md`

## 예시

### 올바른 예
```
데모 제10장 ‘전문 팀이 찍은 영상이 그가 찍은 것보다 못하다고?’를 수정한 후:
1. F027, 장천의 스냅샷, 제10장 관련 시간선 사건을 확인합니다.
2. 제10장의 `mode=revision` 트랜잭션을 구성하고, ‘전문 팀의 재촬영본에는 혼이 빠져 있어 장요조가 휴대전화 원본을 계속 쓰기로 했다’는 본문 사실을 보존합니다.
3. 작가 측 진실에는 중가가의 비공개 육성 계획을 남길 수 있습니다. 독자 뷰에는 시사회에서 이미 공개된 결론만 남깁니다.
4. 제출 후 `tracking_commit.py check`를 실행해 장별 증분, 인물 스냅샷, 복선, 두 시간선 뷰의 일치를 확인합니다.
```

### 잘못된 예
```
`복선.md` 끝에 두 번째 F027을 직접 추가하고 `작가용진실.md`, `독자가아는사실.md`, `문맥.md`를 각각 수동 수정합니다.
결과: 같은 복선에 여러 ‘현재 상태’가 생기고, 독자 뷰에 중가가의 비공개 계획이 유출됩니다. 체크포인트는 어떤 파생 파일이 더 이상 유효하지 않은지 알 수 없습니다.
```
