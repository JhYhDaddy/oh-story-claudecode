# 심층 분석: 가져오기에서 분석 파이프라인 실행하기

Phase 2에서 먼저 이 파일을 읽고 해당 analyze 스킬로 들어갑니다. 분석·산출물 구조·묶음 처리·재개·품질 검사는 그 스킬이 담당합니다. 분량 유형·원문 위치·장르·집필 환경은 가져오기 기록(`{书目录}/.story/work/가져오기기록.md`)에서 읽습니다.

| 분량 | 진입 경로 | 산출물 디렉터리 |
|------|------|---------|
| 장편 | `/story-long-analyze` 통합 파이프라인(기존 결과 직접 사용 / 필요한 분석 보강 / 신규 또는 부분 재개) | `작품분석실/{导入书名}/` |
| 단편 | `/story-short-analyze` 분석 파이프라인(Stage 2-6) | `작품분석실/{导入书名}/` |

## 장편: 호환성 식별 후 재개 여부 결정

먼저 story-long-analyze Phase 1의 읽기 전용 검사기 `inspect_existing_assets.py`를 실행해 실제 파일·분석 범위를 등록합니다. 검사기의 권고가 아래 의미 규칙보다 우선하지 않습니다.

새로 만들거나 현 계약에 따라 재개하는 장편 진도는 `schema_version: 2`를 유지합니다. 옛 결과를 직접 쓸 때는 이 필드가 없다는 이유로 실패시키지 않습니다.

- **옛 결과가 완성됐고 집필 프로젝트 복원에 충분함**: 바로 Phase 3으로 갑니다. 옛 `_progress.md` 버전, `chapter_index.csv` 누락, 이번에 추가한 필드 누락만으로 재분석하면 안 됩니다.
- **옛 결과로 가져올 수 있지만 현재 집필·비교 기능에 필요한 `플롯/리듬.md`·`플롯/감정모듈.md` 등이 부족함**: 기존 장별 자료·줄거리·관계·보고서·문체로 Stage 3+를 필요한 만큼 보강합니다. 원문을 다시 읽거나 완료된 장을 재실행하지 않으며 빈 파일로 검증을 통과시키지 않습니다.
- **일부만 완료됐거나 신·구 산출물이 섞임**: 완료 부분을 검증·보존하고 첫 누락 연속 장 묶음부터 재개한 뒤 마지막에 통합합니다. 진도 기록과 실제 파일이 다르면 검증 가능한 파일을 따르고 충돌을 기록합니다.
- **신규 가져오기**: Stage 0-6 전체 파이프라인을 실행합니다.

이번에 확인한 분석 범위를 자동 완료합니다. 신규는 ‘전체 분석을 한 번에 끝내기’로, 기존 보강·부분 재개는 빠진 Stage·장 묶음만 처리합니다. 현재 용도가 새 분석에 의존하지 않으면 누락 필드로 인한 기능 제한만 기록하고 가져오기를 막지 않습니다.

- 신규 안내 예: ‘전체 분석을 한 번에 마치고 중간에 멈춰 묻지 않는 방식으로 이 작품을 분석하며 Stage 2-6 산출물을 모두 만듭니다.’
- 기존 결과 안내 예: ‘기존 결과를 먼저 재사용·검증하고 이번 가져오기에 부족한 장·분석만 채웁니다. 사용자의 기존 결과를 덮어쓰지 않습니다.’
- **보완 동작**: 신규가 실제로 Stage 1에서 멈추면 자동으로 계속합니다. 기존 결과 작업이 멈추면 등록한 누락 범위만 계속하며 전 작품 재실행으로 확대하지 않습니다.
- 분담: 기록상 분석 보조 에이전트를 사용할 수 있으면 자동 재개에 해당하므로 story-long-analyze의 제한 병렬 방식으로 `chapter-extractor`를 배정합니다(라운드당 3묶음). 연속 장 묶음마다 한 번만 호출하고 같은 호출에서 장별 사실·장간 관찰을 함께 만듭니다. 작가가 명시하면 직렬 또는 묶음 수 제한 없는 순차 방식으로 바꿉니다. 장 수에 관계없이 전 작품 분석을 끝냅니다. 보조 에이전트를 쓸 수 없고 작가가 주 세션 직렬을 택해도 Stage 2는 같은 연속 장 묶음 계약을 따르며 장마다 독립 호출로 후퇴하지 않습니다. 산출물은 여전히 완전하며 속도만 느려집니다.

## 단편: 단일 전체 파이프라인

story-short-analyze의 Stage 2-6 파이프라인에는 **Stage 1 정지 지점이 없습니다**. 한 번에 끝냅니다. Phase 1의 Step 네 개를 모두 수행하되 아래 가져오기 상황에 맞춰 처리합니다. 단계를 통째로 생략하지 않습니다.

| Phase 1 단계 | 가져오기에서의 처리 |
|-------------|----------------|
| Step 1: 원문 확보 | 기록의 원본 파일을 사용하고 다시 묻지 않음 |
| Step 2: 글자 수 검사·장단편 분기 | 가져오기 Phase 1에서 작가가 유형을 확인했으므로 정확히 「按短篇继续」(단편으로 계속)라고 답하고 다시 분기하지 않음 |
| Step 3: 장르 식별 | **정상 수행**하며 장르 기준을 반드시 로드. 기록에서 확정한 유형은 다시 묻지 않음. `genre_detected`는 장르 분기 표의 가장 가까운 유형 또는 「通用」, 작가의 원래 표현은 보조 유형·요소 태그에 기록 |
| Step 4: 재개 검사(`작품분석실/{导入书名}/_meta.json`이 있으면 세 가지 중 선택) | 먼저 재사용 가능 여부 확인: `stages_completed`에 6이 포함되고 `작품분석보고서.md` / `사건노드.md` / `집필기법.md` / `원문/`이 모두 비어 있지 않으며 출처가 이번 원본과 같으면 바로 Phase 3으로 가고 재실행·보관 이동하지 않음. 그렇지 않고 이번 가져오기의 첫 Phase 2 진입이면 (a) 덮어쓰기: 옛 산출물을 먼저 `작품분석실/{导入书名}/_archive_{时间戳}/`에 보관한 뒤 Stage 2부터 재실행. 같은 가져오기 회차에서 같은 작품을 재시도하면 (b) 재개. 작가에게 세 가지 중 고르라고 떠넘기거나 보관을 생략하지 않음 |

Step 3은 `_meta.json.genre_detected`를 기록합니다. 분석 검증의 필수 필드이며 후속 장르 기준 선택에도 쓰므로 생략할 수 없습니다.

- 시작 안내에는 확정된 분량 유형·장르·원문 경로를 설명합니다. Step 2는 단편으로 계속, Step 3은 정상 장르 식별, Step 4는 위 표에 따라 재사용·보관 후 재실행·같은 회차 재개를 선택합니다.
- **보완 동작**: 실행 환경이 여전히 ‘{N}자로 길어 `/story-long-analyze`를 권장한다’거나 ‘장단편 중간인데 어느 쪽으로 분석할까?’라고 물으면 기록의 확정 판단에 따라 정확히 「按短篇继续」라고 답합니다. **분기 질문을 작가에게 넘기지 않습니다.**

## 전달

해당 파이프라인의 품질 검사를 통과하고 `작품분석실/{导入书名}/`에 산출물을 저장하면 「深度分析」를 표시합니다. 분석 완료 템플릿 대신 가져오기 진도를 보고합니다. 분석한 장·주요 인물·주선을 한두 문장으로 설명하고 끝에 [SKILL.md의 맥락 전환 규칙](../SKILL.md#시점별-일정과-인계)에 따라 새 대화를 권합니다. 중단되면 같은 파이프라인에 다시 들어가 진도 파일 기준으로 재개합니다.
