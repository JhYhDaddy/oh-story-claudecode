# 가져오기의 특수 상황

절차 질문에 답하거나 옛 추적 구조를 이전할 때 읽습니다.

## 절차 질문

‘이어쓰려면 환경 설치와 가져오기 중 무엇부터 하나요?’, ‘기존 소설은 어떻게 이어 쓰나요?’, ‘가져오기 절차는 무엇인가요?’ 같은 질문에는 먼저 결론을 직접 답한 뒤 원문을 받습니다. 절차만 확인하려는 사용자에게 바로 원문을 붙여 달라고 하지 않습니다.

1. **권장 순서**: `/story-setup`으로 환경을 설치하고 대화를 새로 열거나 새로고침한 뒤 `/story-import`를 실행합니다. 마지막으로 `/story-long-write 写第N章`으로 이어 씁니다(N은 아직 쓰지 않은 첫 장).
2. **바로 `/story-import`를 실행해도 됩니다**: 심층 분석 전에 환경을 확인하며 미설치면 ‘먼저 설치’와 ‘조금 느리지만 바로 가져오기’ 중 선택하게 합니다.
3. **현 프로토콜 프로젝트**(작품 디렉터리에 `추적/_tracking-state.json` 있음): 가져오기 기록부터 확인합니다. 미완료 항목이 있으면 그 항목부터 이어갑니다. 이미 가져오기가 끝났으면 루트 `.active-book`의 대상이 맞는지 확인하고 `/story-long-write 写第N章`으로 이어 씁니다. 중복 가져오기하지 않습니다.
4. **옛 추적 프로젝트**(`추적/`·본문은 있으나 `추적/_tracking-state.json` 없음): 일일 연재는 멈추고 다시 가져오도록 요청하지만 **전 작품 분석을 다시 할 필요는 없습니다**. 추적만 재구축하며 다음 절을 따릅니다.

## 옛 추적 프로젝트 이전

작품 디렉터리에 `추적/`와 본문은 있지만 `추적/_tracking-state.json`이 없으면 옛 추적 구조입니다. 본문·`설정/`·`개요/`·`작품분석실/`는 영향을 받지 않으며 **`추적/`만 재구축**합니다. 심층 분석을 다시 하거나 본문을 수정하지 않습니다.

1. 가장 큰 장 번호의 `본문/제NNN장_*.md`가 완전한지 확인하고 마지막 완결 장 번호 `N`을 정합니다. 가장 큰 파일명만 보고 판단하면 안 됩니다.
2. 옛 `추적/`의 기존 파일(인물 상태·복선·시간선 등, 실제 파일명 사용)과 최근 3-5장 본문에서 현재 상태를 복원합니다. 핵심 인물 스냅샷·미회수 복선·공개된 시간선 사건·장기 제약·다음 장 약속을 포함합니다. 인물 상태 역추론은 [character-state-reverse.md](character-state-reverse.md) 참조.
3. [import-tracking.md](import-tracking.md)에 따라 초기화 트랜잭션을 만듭니다. 거기서 지정한 tracking-initialization.md는 전문을 읽습니다. `last_chapter`는 `N`으로 쓰며 제1..N장의 개별 기록을 꾸며내지 않습니다. `tracking_commit.py init`을 실행합니다.
4. `init`은 옛 추적 구조 전체를 원형대로 `추적/_이전추적보관/`로 옮긴 뒤 현 프로토콜을 만듭니다. 옛 내용은 삭제·파싱하지 않고 작가가 볼 수 있게 보관합니다.
5. `tracking_commit.py check` 통과를 확인한 뒤 `/story-long-write`로 돌아가 제N+1장을 이어 씁니다.

복원은 2번 근거를 따릅니다. 불확실한 필드는 비우거나 `continuity_risks`에 기록하며 지어내지 않습니다. 사용자가 전 작품 재분석을 명시적으로 요청한 경우에만 전체 가져오기를 수행합니다.
