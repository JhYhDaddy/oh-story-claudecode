# 수집 스크립트가 없는 플랫폼: 작가가 순위 제공

즈후 옌옌·판체 단편·치마오 단편 등에는 수집 스크립트가 없으므로 작가가 순위를 제공해야 한다. 작가가 이 플랫폼을 선택했을 때만 읽는다.

## 작가에게 요청할 것

‘순위 스크린샷·텍스트·링크를 보내 주세요. 가능하면 제목·작가·장르·글자 수·인기를 포함하고 좋아요·소장·현재 읽는 수 중 무엇인지 밝혀 주세요. 소개도 있으면 함께 보내 주세요. 편집자의 원고 모집·청탁 조건이 있으면 함께 보내 주세요.’

- 링크는 열리면 읽고, 열리지 않으면 스크린샷이나 텍스트로 다시 요청한다.
- 제목 목록만 있어도 바로 분석할 수 있으나 보고서의 신뢰도를 한 단계 낮춘다.

## 파일로 정리한 뒤 집계

작가가 준 순위를 아래 형식으로 정리하여 이번 출력 디렉터리의 `{平台}{榜单}_{YYYYMMDD}.md`에 저장한 뒤 스크립트로 수집한 순위와 함께 집계한다. 아래 중국어 표식과 필드 순서는 집계 계약이다.

```markdown
# 知乎盐言 · 热门榜

- 抓取时间：{순위 스크린샷 또는 페이지 날짜，YYYY-MM-DD}
- 数据质量：作者提供

### #1 {제목}
*{작가} · {장르} · {상태} · {글자 수}字 · {인기 숫자}{측정 기준}*
**标签：** {태그1}、{태그2}

> {소개}
```

- 집계 스크립트는 위치로 필드를 식별한다. 첫 칸은 작가, 둘째는 장르다. 스크린샷에 작가가 없으면 `佚名`을 넣고 순서를 바꾸지 않는다. 「未知」는 빈값으로 건너뛰어 장르를 작가로 오인하므로 쓰지 않는다.
- 인기는 `2.3万收藏`·`8000赞同`처럼 ‘숫자 + 측정 기준’으로 써야 집계가 인식한다. 파일 하나에는 기준 하나만 쓰며 기준이 다른 순위는 파일을 나눈다.
- 상태·글자 수·태그·소개가 없으면 생략하고 지어내지 않는다.

## 확인할 내용

| 차원 | 확인할 내용 |
|---|---|
| 장르와 태그 | 순위에 집중된 장르와 반복 태그 |
| 글자 수 | 중앙값과 분포 |
| 소개 작성법 | 갈등을 앞세우고 의문을 남기는 방법(소개를 제공했을 때) |
| 작가 분포 | 상위 계정과 새 작가가 각각 쓰는 것(작가명을 제공했을 때) |
