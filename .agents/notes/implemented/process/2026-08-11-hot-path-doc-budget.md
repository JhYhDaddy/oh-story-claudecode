# Agent Note: 자주 로드되는 문서의 글자 수 예산 검사

Status: implemented

## Problem

스킬 텍스트는 사용자가 세션마다 지불하는 토큰이다. 규칙을 하나씩 추가할 때는 비용이 조금씩만 늘지만 누적되면 일일 연재 경로의 비용이 두 배가 된다. PR #228에서 한 번에 32.9KB를 순감소시킨 뒤에도 자주 로드되는 경로의 분량이 다시 늘었다. 증가를 조용한 누적이 아니라 명시적 결정으로 만들어야 한다.

## Decision

- `scripts/check-doc-budget.sh` + `scripts/doc-budget.json`을 CI 필수 목록에 넣는다. 측정값은 모든 공백을 제거한 문자 수다. 중국어·영어 모두 세며 문장부호·줄바꿈·들여쓰기 변경은 측정값에 영향을 주지 않는다.
- ‘세션마다 또는 장마다 모델 컨텍스트에 들어가는’ 파일만 등록한다. 드물게 읽는 경로(story-setup 배포·UPGRADING·분석 라이브러리 템플릿)는 등록하지 않고 제한하지 않는다. 자주 로드되는 새 파일은 반드시 등록해야 하며, 그렇지 않으면 아무 제약도 받지 않는다.
- `files` 각 항목에 `budget`과 `why`를 둔다. `paths`는 한 세션에서 실제로 지불하는 경로 합계이며 `branches`로 서스펜스·반전 참고 자료 같은 조건부 분기를 나타낼 수 있다. 밖으로 옮긴 파일도 보수적으로 전체 분량을 포함하며 분할 자체를 같은 단계의 총량 절감으로 보지 않는다.
- 예산을 넘으면 실패하며 처리 순서는 고정한다. ① 같은 파일의 기존 텍스트를 같은 양만큼 먼저 삭제한다(중복 지시, 스크립트가 이미 확정적으로 막는 규칙, 설계 이유 해설, 극소수 상황에서만 쓰는 분기). ② 새 규칙이 꼭 필요하면 `doc-budget.json`의 budget을 높이고 모든 사용자가 매 세션 비용을 낼 가치가 있는 이유를 PR에 쓴다. budget 조정은 허용하지만 명시적 결정이어야 한다.
- 여유가 5% 이상이면 스크립트가 budget을 낮춰 이번 경량화를 고정할 수 있다고 안내한다(다시 늘지 않도록 고정하는 장치이며 차단하지 않음).
- 예산 때문에 집필 기법 규칙(상세 개요 경계·쾌감의 밑작업·AI 문체 제거 Gate)을 절대 삭제하지 않는다. PR #228의 블라인드 평가에서 이를 삭제하면 품질이 떨어짐을 확인했다.

## Alternatives considered

- **PR 검토에 의존**: 도구 비용이 없고 검토자가 규칙의 가치를 판단할 수 있다는 점이 가장 큰 장점이다. 그러나 개별 규칙은 모두 타당해 보여도 누적 효과는 검토에서 보이지 않는다. 1eae178 전에도 바로 이런 방식으로 늘어났다.
- **한 번 크게 줄이고 검사 장치는 두지 않기**: #228에서 이미 시도했지만 다시 늘었다. 1eae178은 ‘증가를 명시적 결정으로 만들기’를 명확히 요구했다.
- **행 수나 바이트로 측정**: 기존 도구를 그대로 쓸 수 있다는 점이 가장 큰 장점이다. 그러나 문장부호·줄바꿈·들여쓰기에도 측정값이 달라지는 반면 공백 제거 문자 수는 본문 증감에만 민감하다.

## Consequences

- **이점**: 자주 로드되는 규칙을 추가할 때마다 같은 분량을 삭제하거나 명시적으로 설명해야 한다. 여러 차례 경량화(신작 시작 -30% / 재작업 -41%, 단편 단계별 로드)의 효과가 다시 늘지 않도록 고정된다.
- **비용과 알려진 한계**: 규칙을 추가할 때 `doc-budget.json`도 바꿔야 하며 `why` 필드가 두 번째 변경 설명이 된다. 예산은 사람이 정하므로 증가만 막을 뿐 충분히 간결함을 증명하지 않는다. 조건부 분기가 많으면 `paths` 표 자체도 커진다. 팀이 텍스트를 줄이지 않고 budget만 습관적으로 높인다면 검사 장치가 형식적으로만 작동하는 것이므로 경로별 검토로 돌아가야 한다.

## 검증

`bash scripts/check-doc-budget.sh`(`--root` / `--manifest`로 임시 프로젝트 지정 가능), `python3 scripts/test-doc-budget.py`로 경로 합계·초과·파일 누락 시 실패를 검증한다.
