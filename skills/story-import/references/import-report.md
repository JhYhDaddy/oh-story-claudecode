# 보고와 활성화 단계

Phase 5에서는 이 파일과 가져오기 기록(`{书目录}/.story/work/가져오기기록.md`)만 읽습니다. 앞 단계는 각자의 점검을 통과한 뒤 진도를 표시했으므로 여기서 이전 규칙을 다시 읽지 않습니다.

## Step 1：收尾自检

마무리 내부 점검을 먼저 합니다. 통과하지 못하면 해당 단계로 돌아가 복구하고, 그래도 완료할 수 없을 때 작가에게 영향·대안을 설명합니다.

- 가져오기 기록의 이전 진도 항목이 모두 표시됐는지 확인합니다(단편은 상세 개요·추적 생략). 「汇报与激活」는 이 단계 Step 3 완료 후 표시합니다.
- **장편**: `본문/`의 장 파일 수가 가져온 장 수와 같아야 합니다. 매 장에 `개요/상세개요_제XXX장.md`가 있고 전체에 `node {story-import skill 根}/scripts/check-outline-contract.js --json {书目录}/개요/상세개요_第*.md`를 다시 실행해 통과해야 합니다. `{PYTHON} {story-import skill 根}/scripts/tracking_commit.py check --project {书目录}`도 다시 통과해야 합니다(`python3` → `python` → `py -3` 순으로 탐색). 원문에 권 구분이 없었다면 작가가 분권을 확인했어야 합니다. `작품분석실/{导入书名}/`가 `비교작품/`로 복사되지 않았는지 확인합니다.
- **단편**: `본문.md`·`설정.md`·`구간개요.md`가 모두 있어야 하며 `추적/`·`개요/`·`본문/`를 잘못 만들지 않았는지 확인합니다.

## Step 2：导入完成报告

무엇을 가져왔는지, 무엇을 대조·결정해야 하는지, 다음에 어떻게 요청할지 설명합니다. 필드명·스크립트명·검증 결과·글자 수 기준·복선/사건 번호는 보고에 넣지 않습니다. 번호는 ‘옥패의 유래(F003)’처럼 이야기 설명 뒤에만 붙일 수 있습니다. 확인 항목은 구체적 인물·사건으로 쓰고 한 번에 최대 5개입니다. 보조 기능 대체 사용·버전 안내가 있었다면 보고 블록 끝에 「技术备注：」 한 줄을 붙여 원문을 넣습니다.

**장편**:

<!-- author-report -->
```md
=== 《{导入书名}》 가져오기 완료 ===
가져온 내용: 제1–{N}장, 약 {Y}만 자{; 제{N+1}장은 절반만 작성되어 결정하신 대로 {미완 장에서 계속 집필 | 먼저 마무리}}. 프로젝트는 `{项目目录}`에 있습니다.

정리한 내용:
- 인물: {M}개 카드. 제{N}장까지 주요 인물의 처지를 기록했습니다(예: ‘{인물}: {현재 상태 한 문장}’).
- 개요: 전체 개요, {V}개 권 개요, 장별 상세 개요.
- 아직 회수하지 않은 이야기선: {K}개(예: ‘{복선의 이야기 설명}’).
- 시간선: 진실과 독자가 아는 내용을 분리해 이어 쓸 때 일찍 누설하지 않게 했습니다.
- 설정: 세계관 자료 {설정 파일 수}개.
- 문체: {요청대로 이 작품의 문체로 저장해 이어쓰기에도 적용 | 저장하지 않아 비교 작품 또는 기본 작법 적용}.
- 비교 작품: {연결 없음 | 《{对标书名}》 연결 완료 | 연결 실패: 이유와 보완 방법}.

확인해 주세요:
1. {가장 불확실한 점을 구체적 질문으로. 예: ‘제5장의 검은 옷 인물과 제2장의 마부가 같은 사람인가요?’}
2. {예: ‘미회수 이야기선에 누락이 있나요? 제가 찾은 것은 …입니다.’}

결정이 필요한 사항: {아직 확인하지 않은 것만. 이미 확정한 분권·미완 원고 처리는 다시 묻지 않음}

다음 단계: {미완결: `/story-long-write`로 ‘제{N+1}장 집필’을 요청하면 해당 장 개요부터 보완하고 집필 | 완결: 수정하려면 ‘검토해 줘’라고 요청}.
```

**단편**:

<!-- author-report -->
```md
=== 《{导入书名}》 가져오기 완료 ===
가져온 내용: 전체 약 {Y}자, {N}개 절. 프로젝트는 `{项目目录}`에 있습니다.

정리한 내용:
- 설정: 핵심 틀과 이어쓰기에서 지킬 인물·감정 기조.
- 절별 개요: {N}개 절의 사건.
- 비교 작품: {연결 없음 | 《{对标书名}》 연결 완료 | 연결 실패: 이유와 보완 방법}.

확인해 주세요:
1. {[待补充] 표시 부분을 질문으로. 예: ‘여주인공이 마지막에 그를 용서했나요? 원문에는 명시되지 않았습니다.’}
2. {핵심 반전 전 단서로 찾은 것은 …입니다. 빠진 것이 있나요?}

다음 단계: {미완결: `/story-short-write`로 ‘구상 보완’을 요청하고 먼저 {설정에 보충 표시한 사항을 쉬운 말로 열거. 예: 장르 작법·남은 절 수·유료 전환 위치}를 정한 뒤 제{N+1}절부터 계속 집필 | 완결: 수정하려면 ‘검토해 줘’라고 요청}.
```

## Step 3：项目激活

프로젝트를 활성화합니다.

- `.active-book`이 가져온 작품 제목 디렉터리를 가리키게 하고 가져오기 기록의 「汇报与激活」를 표시합니다.
- 해당 집필 스킬의 식별 규칙에 맞는지 확인합니다. 장편은 `본문/`·`개요/`, 단편은 `본문.md`·`설정.md`·`구간개요.md`입니다.
- 선택 검증: SKILL.md 상단의 현재 호스트별 역할 출처로 story-explorer 사용 가능 여부를 확인합니다(ZCode는 플러그인 등록 역할 확인). 가능하면 spawn해 이전 자료 완전성을 교차 검증할 수 있습니다. Antigravity는 `.agents/agents/story-explorer/agent.md`를 확인하고 `invoke_subagent` + `TypeName: "story-explorer"`를 사용합니다. 프롬프트: `项目目录：{dir}\n查询类型：progress\n查询参数：导入验证`.
