# workflow-setup.md: 작품 시작·기획 순서와 방향·설정 확정

작품 시작은 작가가 확인해야 할 단계들의 연속입니다. 각 단계는 자기 파일만 읽으며 다음 단계는 대화 기억이 아닌 저장 파일로 앞 단계를 이어받습니다. 먼저 SKILL.md의 집필 흐름에 따라 전달 범위를 정합니다. 논의만 한다면 필요한 기법만 사용하고 파일을 만들지 않습니다. 나머지는 요청 범위에 필요한 선행 요소만 보완하며 기존 설정을 다시 만들지 않습니다.

| 단계 | 작가의 확인 사항 | 읽을 자료 | 저장 산출물 |
|---|---|---|---|
| 방향 확정 | 장르·매력 포인트·비교 작품 | 이 파일 Phase 1 | 작품 디렉터리와 `.active-book`; `설정/소재방향.md`의 기본 정보·비교 작품 등록·작가 확정 사항 |
| 설정 확정 | 주인공·세계·핵심 갈등 | 이 파일 Phase 2 | 장르 포지셔닝 보완; 관계; 주인공·핵심 인물 카드; 전체 작품에 영향을 주는 세계관(Phase 2 참조) |
| 권 개요 | 전체 구간과 제1권 | [workflow-volume.md](workflow-volume.md) | `개요/개요.md`, `개요/권개요_제X권.md` |
| 상세 개요 | 첫 묶음의 장별 진행 | [workflow-outline.md](workflow-outline.md) | `개요/상세개요_제XXX장.md`, 개요 배치 초안 |
| 제1장 확인 | 본문 | workflow-chapter.md(새 대화) | `본문/` |

**인계는 저장 파일로만**: 각 단계 전달 전에 작가가 대화에서 확정한 방향·선호·금지선·거절한 안을 `설정/소재방향.md`의 해당 절에 기록한 뒤 진행합니다. 다음 단계에서는 이전 대화를 되짚지 않습니다. 이 작품의 사항은 설정에만 기록하며 작품 전반에 적용할 작가의 집필 습관만 작가 기억에 기록합니다.
**맥락 전환**: 방향은 주 세션과 작가가 논의합니다. 설정·권 개요·상세 개요 묶음은 읽을 방법론이 가장 많으므로 story-architect가 배포되어 있으면 과제 패키지로 새 맥락에서 작성하게 합니다([agent-calls.md](agent-calls.md) 참조). 주 세션은 제안을 작가에게 확인받고 의견대로 파일을 고쳐 보고합니다. 하위 에이전트가 없으면 주 세션이 같은 확인 순서로 수행합니다. 하위 에이전트가 없으면 각 단계 전달 후, 있으면 상세 개요 전달 후 보고 본문의 마지막 문장에 ‘새 대화에서 “설정 확정”/“권 개요 작성”/“제1-10장 상세 개요”/“제1장 집필”이라고 요청하면 더 집중해서 진행할 수 있습니다’라고 권합니다(기술 비고는 그 뒤 맨 마지막 줄 유지). 작가가 이 대화에서 계속하기를 원하면 그대로 수행합니다.

---

**한국 시장 기본값**: 새 작품은 목적부터 확인한다. 직접 연재는 문피아·네이버 웹소설·노벨피아, 시장 조사는 네이버 시리즈·카카오페이지·리디도 후보, 단편·개인 발행은 포스타입을 먼저 제시한다. 특정 플랫폼은 자동 확정하지 않는다. 기존 목표와 작가의 명시적 선택을 우선하고 중국 플랫폼은 선택 기능으로 유지한다. 한국 작품에 중국 플랫폼의 분량·태그·유료 전환·평가 기준을 대신 적용하지 않는다.

한국 장르명은 작가가 쓰는 판타지·현대판타지·무협·로맨스·로맨스판타지·BL·SF·미스터리 등을 그대로 기록한다. 기존 중국 장르 카드는 필요한 서사 기법만 참고하며 한국 플랫폼의 공식 분류로 취급하지 않는다. 회차 분량·공백 포함 여부·연재 주기는 작가와 정하고 플랫폼 규칙과 구분한다.

### Phase 1：确认选题方向

소재 방향을 확인합니다.

**작가가 방향을 제시한 경우**: 작가의 방향을 따르고 소재 결정 자료 찾기와 아래 방향 질문은 생략합니다. 장르에 맞는 아래 파일만 읽고 비교 작품 맥락을 불러옵니다.

**먼저 소재 결정 확인**(작가가 방향을 제시하지 않았을 때): 프로젝트 루트에 `소재선정.md`(story-long-scan Phase 5 산출물)가 있으면 가장 앞에 있는, 실현 가능성이 가장 높은 추천 소재를 읽습니다. ‘순위 조사에서는 X를 권했습니다(성공 가능성 Y, 차별점 Z). 이것으로 시작할까요?’라고 확인합니다. `扫榜日期`가 오래됐으면 시장 자료가 낡았을 수 있으니 재조사를 권합니다. 동의하면 해당 장르·매력 포인트·차별점을 가지고 Phase 2로 갑니다. 「推荐选题」가 없고 순위만 조사했다면 소재를 정하지 않은 것으로 보고 아래 일반 질문을 합니다.
파일이 없으면 프로젝트 루트와 상위 디렉터리에서 시작해 아래로 최대 3단계까지 `소재선정.md`를 찾습니다(숨김 디렉터리 제외). mtime 기준 최신 2개를 고릅니다. 찾으면 AskUserQuestion에 후보의 경로·`扫榜日期`, ‘직접 경로 입력’, ‘모두 사용 안 함’을 제시합니다. 선택된 파일을 루트로 복사해 위 절차대로 읽습니다. 직접 입력이면 경로를 받아 똑같이 복사하고, 모두 거절하면 일반 질문으로 갑니다. 찾지 못하면 ‘이전에 조사한 순위나 소재 제안이 있으면 위치를 알려 주세요. 없으면 아래 질문에 답해 주세요’라고 묻습니다. 여전히 없으면 일반 질문을 합니다.

사용자가 방향을 정하지 않았다면 **‘독자가 어떤 감정을 느끼길 바라나요? 비교하고 싶은 좋아하는 작품이 있나요?’**라고 묻습니다.

#### 비교 작품 맥락 불러오기

> **비교 작품 경로 찾기**는 SKILL.md의 경로·용어 규칙 참조.

**비교 작품 발견(아래 요청 대응 조회보다 먼저)**: 사용자가 작품명을 말했는지와 관계없이 `작품분석실/`를 먼저 훑어 장르에 맞게 추천합니다. 사용자가 먼저 말하기만 기다리지 않습니다.

1. `ls 작품분석실/`(자료 원본)와 프로젝트 `비교작품/`(참조 뷰)에서 작품 목록을 확인합니다. 현재 디렉터리명·`.active-book`·`설정/소재방향.md`의 작품 정보로 현재 작품을 식별하고 동명이거나 출처가 현재 본문인 `작품분석실/{当前书}/`를 제외합니다. story-import가 프로젝트 복원을 위해 만든 현재 작품 분석은 비교 후보가 아니며 `비교작품/`로 복사해서도 안 됩니다. 제외 후 둘 다 비면 4번으로 갑니다.
2. 작품마다 장르를 읽습니다. 단편은 `작품분석실/{书}/_meta.json`의 `genre_detected`, 장편은 `개요요약.md` 상단 또는 `작품분석보고서.md`의 「基本信息」 중 「题材」를 봅니다. 이 작품의 장르·방향과 비교해 같은 장르/약한 연관/무관으로 표시합니다.
3. 같은 장르나 약한 연관 후보가 있으면 AskUserQuestion으로 후보·‘모두 사용 안 함’·‘다른 작품 분석’을 제시합니다. 주 비교 작품 1개를 문체·본문 기준으로 삼고 나머지는 보조로 둡니다. 결정하면 `설정/소재방향.md`의 「对标登记」에 `主对标书`·`对标书列表`를 기록합니다(방향 확정 전달 시 저장). 첫 참조 시 `작품분석실/{书}/`에서 관련 하위 디렉터리(장별분석/인물/플롯/设定), `플롯/리듬.md`, `플롯/감정모듈.md`, `문체.md`, `작품분석보고서.md`를 `비교작품/{书}/`로 복사합니다. 이미 있으면 중복 복사하지 않습니다.
4. 후보가 없으면 비교 작품 없이 진행합니다(권 개요는 8개 지점으로 직접 구성, workflow-volume.md 참조). 사용자가 비교 작품을 원하면 먼저 `/story-long-analyze`로 하나 분석할 수 있습니다.

사용자가 비교 작품을 언급했거나 작업 디렉터리에 `비교작품/`가 있으면:

1. 위 발견 절차 1번과 같은 기준으로 현재 작품을 식별하고 동명이거나 출처가 현재 본문인 `비교작품/{当前书}/`를 제외합니다. 예전 가져오기 프로젝트에는 잘못 만든 자기 비교 디렉터리가 남아 있을 수 있습니다. 제외 후 외부 비교 작품이 없으면 다음 단계는 수행하지 않고 비교 작품 없이 진행합니다.
2. 자료 세대는 두 주 산출물 `플롯/감정모듈.md`·`플롯/리듬.md`만으로 판별합니다. 하나라도 없으면 중지하고 `missing_primary_contract` + `repair_action`을 반환합니다. 작가에게는 ‘비교 작품 X의 감정·리듬 분석이 부족하므로 /story-long-analyze로 추가 분석을 권합니다’라고만 말합니다. 요약·보고서로 대신 만들어내면 안 됩니다. 둘 다 있으면 정상 조회하며 예전 분석에 새 필드가 없어도 차단하지 않습니다.
3. 권위 순서에 따라 두 주 산출물을 읽습니다. `작품분석보고서.md`는 개요로만 사용합니다.
4. 인물·일반 줄거리 단위·설정 하위 디렉터리가 있으면 집필 중 필요한 모듈만 조회합니다.

답변에 따라 필요한 자료를 각각 한 번만 읽습니다. 장르 세분화는 `references/long-genre-catalog.md`, 여성향 장편은 대신 `references/female-audience-writing.md`를 읽습니다(여성향 장르 틀 포함, 여성향은 이 파일만 읽고 장르 목록은 읽지 않음). 독특한 발상·팬픽·시뮬레이션 등 특수 장르는 목록의 해당 절만 읽습니다. 플랫폼·분야·제목과 소개·비교 작품 선택은 `references/genre-readers.md`를 봅니다.

**방향 확정 전달 전**: 작품 디렉터리가 없으면 작가가 준 제목으로 `{书名}/`를 만듭니다. 제목이 없으면 가제를 정하고 설정 확정 때 바꿀 수 있습니다. 작가가 위치를 지정했다면 그곳에 만들고 작업 공간 루트의 `.active-book`이 가리키게 합니다. 제목을 바꾸면 디렉터리와 `.active-book`을 함께 바꿉니다. `설정/소재방향.md`를 만들고 선택한 장르·매력 포인트·비교 작품, 대화에서 나온 선호·금지선·거절한 안을 「基本信息」「对标登记」「作者已定」에 기록합니다(아래 템플릿 참조). 나머지는 설정 확정 때 채웁니다.

#### 에이전트 호출: story-architect

간단한 장르 포지셔닝은 주 세션이 우선 처리합니다. 복잡한 세계관·여러 줄거리·강한 반전 설계이거나 사용자가 명시적으로 요청한 경우에만 호출합니다. [agent-calls.md](agent-calls.md) 참조. 사용할 수 없으면 주 세션이 직접 수행합니다.

### Phase 2：核心设定

핵심 설정을 정합니다. 먼저 `.active-book`을 확인하고 이전 단계에서 빠졌으면 방향 확정 전달 전 절차로 만듭니다. Phase 1의 목표 감정에서 출발해 장르 틀의 줄거리 유형을 찾고, 비교 작품에서 재사용할 모듈을 뽑습니다(구체적인 인물을 기능적 자리로 봄). 사용자의 인물·설정으로 채웁니다.

작품 전체를 시작할 때는 아래 설정을 전달합니다. 기획만 요청했다면 해당 구조에 관련된 확정 설정만 저장합니다. 템플릿은 아래에 있습니다.
- `설정/소재방향.md`: 방향 확정 때 쓴 내용에 「核心设定」(한 문장 줄거리·주인공·세계관 뼈대·핵심 갈등·최종 장애물), 독자와의 약속, 최종 자원, 핵심 발상의 세 층위, 비교 분석을 보완합니다. 분석 표는 2-3행 요약만 두고 상세는 `비교작품/` 참조. 작가 확정 사항은 지우지 않습니다.
- `설정/관계.md`.
- 주인공·핵심 인물의 `설정/인물/{名}.md`(character-basics.md의 주인공·조연 카드). 나머지는 상세 개요 단계에서 점진적으로 보완합니다.
- 전체 작품에 영향을 주는 `설정/세계관/{主题}.md`. 힘의 체계·사회 구조 등 주제마다 파일 하나, 장르 포지셔닝에는 뼈대 한 문장만 둡니다.
- `설정/소재본문안내.md`는 개시 때 만들지 않습니다. 제1장 집필 전 자료 조회가 생성합니다.

**수치는 먼저 작가에게 확인**: 물가·소득 규모, 경지·힘의 단계, 특전 능력의 상한처럼 전체 작품에 영향을 주는 척도는 SKILL.md의 새 요소 3단계 규칙상 작가에게 먼저 물어야 합니다. 제안에 후보 1-2개를 넣고 결정받은 뒤에만 설정에 씁니다. 임의 확정하고 보고에서 요약만 해서는 안 됩니다.

#### Agent 调用：story-architect + character-designer

에이전트 호출: story-architect + character-designer (절명은 자료 추출 계약 원형 유지).

### 定设定时建的文件模板

설정 확정 때 만드는 파일 템플릿 (절명은 자료 추출 계약 원형 유지).

중국어 제목·필드·열거값은 저장 형식과 후속 조회의 계약 표식입니다. 관계 파일은 관계 개요·변화·핵심 갈등을, 장르 포지셔닝은 기본 정보·작가 확정 사항·핵심 설정·독자와의 약속·최종 자원·비교 작품 등록을 기록합니다.

## 설정/관계.md

```markdown
# 角色关系图

## 关系总览

| 角色 A | 角色 B | 关系类型{亲情/爱情/友情/敌对/师生/主从/利益} | 情感倾向{正面/负面/中性/复杂} | 当前状态 | 起始章节 | 变化节点 |
|--------|--------|---------------------------------------------|-----------------------------|---------|---------|---------|
| {名} | {名} | {类型} | {倾向} | {설명} | 第{N}章 | {사건} |

## 关系演变

{角色A}<->{角色B}：
- 起点：{초기 관계}
- 转折：{장·사건·변화}
- 当前：{현재 상태}

## 核心冲突关系

{줄거리를 추진하는 핵심 대립·협력 관계 2-3쌍}
```

작성 참고: `character-relations.md`「人物关系类型」
