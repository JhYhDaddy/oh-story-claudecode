# 묶음별 상세 개요 역추론(장편 가져오기)

권 개요를 확정한 뒤 장별 요약에서 상세 개요를 역추론하며 묶음마다 과제 패키지를 하나 만듭니다. 진도는 가져오기 기록(`{书目录}/.story/work/가져오기기록.md`)의 「细纲：已验收到제 B 장」에 기록합니다. 재개는 제B+1장부터 묶음 전체를 다시 처리합니다. 해당 묶음에 이미 있지만 검증하지 않은 상세 개요는 새 패키지로 다시 써서 덮어씁니다.

## Step 1：生成本批任务包

과제 패키지를 생성합니다. 현재 플랫폼에서 Python 3을 `python3` → `python` → `py -3` 순서로 찾습니다. 제B+1장부터 20장을 요청하며 남은 장이 20장보다 적으면 마지막 장까지 요청합니다.

```text
{PYTHON} {story-import skill 根}/scripts/build_outline_brief.py --project {书目录} --chapters {A-B}
```

스크립트가 [outline-reverse-rules.md](outline-reverse-rules.md) 전문, 측정한 과거 길이, 요약 요점, 묶음 범위의 권 개요 단위 카드를 `{书目录}/.story/work/개요작성/가져오기상세개요_제AAA-BBB장.md`로 합칩니다. 길이는 `visible_chars_v1` 기준입니다. 실행자가 읽을 총량이 약 25K자를 넘으면 장 수를 자동으로 줄이며 10장 미만일 수도 있습니다. stdout JSON의 `chapters`가 실제 범위이고 `next`가 다음 묶음 시작점입니다. `null`이면 마지막 장까지 도달했습니다. 요약이 없는 장은 본문을 읽으며 필요한 본문량도 총량에 포함합니다.

길이는 반드시 스크립트가 측정해야 합니다. 모델이 추산하거나 알리지 않고 생략하면 안 됩니다. Python 3을 찾지 못하거나 스크립트가 실패하면 멈추고 ‘제12장 본문을 읽을 수 없으니 본문 이전을 먼저 마쳐야 합니다’처럼 문제를 한 문장으로 알립니다. 오류 원문은 기술 비고에 둡니다. 권 개요가 없거나 해당 묶음을 포함하는 카드가 없으면 구조 이전으로 돌아가 보완합니다.

## Step 2：写本批细纲

묶음의 상세 개요를 작성합니다.

- **story-architect 사용 가능**: 가져오기 기록에 사용 가능으로 적혀 있고 SKILL.md 상단의 호스트별 역할 출처로 확인합니다(ZCode는 플러그인 등록 역할). 주 세션은 패키지 경로만 받고 내용을 읽지 않습니다. 프롬프트: `项目目录：{dir}\n任务包：{任务包路径}\n먼저 과제 패키지 전문을 읽고 그 규칙과 템플릿에 따라 완료합니다. 작가 확정 사항은 .story/work/가져오기기록.md에 있으며 대화는 전달되지 않습니다.\n전달 후 패키지 첫머리가 요구한 항목만 반환합니다.` Antigravity는 `invoke_subagent` + `TypeName: "story-architect"` 사용.
- **사용 불가**: 주 세션이 패키지 전문을 읽고 규칙대로 작성합니다. 패키지 밖의 작법을 추가로 읽거나 분석 서고의 요약 전체를 읽지 않습니다.

## Step 3：验收与交接

묶음 완료 후 주 세션이 `node {story-import skill 根}/scripts/check-outline-contract.js --json <本批细纲路径...>`를 실행합니다. exit 1이면 보고서의 누락 필드·소절만 보완합니다. story-architect를 사용했다면 같은 에이전트에게 오류 원문을 돌려보내 한 번 수정하게 합니다. 통과하면 진도를 「已验收到제 B 장」으로 바꿉니다. 다음 묶음이 있으면 몇 장까지 마쳤는지 한 문장으로 알리고 [SKILL.md의 맥락 전환 규칙](../SKILL.md#시점별-일정과-인계)에 따라 새 대화에서 ‘가져오기 계속’을 요청하도록 권합니다. 하위 에이전트가 없으면 매 묶음마다 권합니다. 모든 장의 상세 개요를 마쳐야 Phase 4로 갑니다.
