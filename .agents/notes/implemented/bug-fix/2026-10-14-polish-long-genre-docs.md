# Agent Note: 장편 장르 자료를 다듬고 장르 카드의 로드 방식과 판단 기준을 일치시킨다

Status: implemented

## Problem

장편 장르 카드 32개에 '见结果一个', '小见结果', '钱、账资源' 같은 비문이 있었고, 일부 장면과 단계 설명은 행동 주체를 생략했다. 장르 색인과 소재 선정 자료 세 개에도 확인 가능한 충돌이 있었다. 색인은 본문 집필 전에 색인 전체를 읽으라고 했지만 실제 조립 스크립트는 이미 카드 헤더로 직접 매칭했다. 색인에서는 작품 문체보다 장르 카드를 우선하여 기존 문체 판단 기준과 반대였다. 아내를 되찾는 서사 프레임워크는 돌아가지 않는 결말만 핵심이라고 하면서 결말 선택지에는 재회를 허용했다. 서양 판타지 빠른 참조의 외형 교체 제안은 해당 카드의 제도 중심 서술과 반대였다. 독자 자료는 남성향 도시물의 연애 감정 보조 줄거리 요구를 모든 도시물로 확대했고, 소개문의 성공 약속을 실패형과 미스터리형에도 적용했다.

## Decision

문서 35개를 각각 prose-gap-polish의 다섯 단계로 정리했다. 웹소설 용어, 장르 기법, 표본 기록, 실행 가능한 필드, 앵커, 단계별 비중은 유지하면서 비문, 조각난 설명, 불분명한 지시 대상을 고쳤다. 본문 로드는 기존 build_writer_prompt.py의 카드 헤더 매칭 결과를 진입점으로 삼고, 사람이 읽는 색인은 소재 선정이나 수동 참조에 사용한다. 작품의 표현 방식에는 style-resolution.md의 우선순위를 적용하며 사실과 플롯 제약은 유지한다. 아내를 되찾는 서사는 냉정한 거절을 유지하는 주 흐름과 재회 변형을 구분한다. 서양 판타지는 기사·마법사·영주 등의 방식을 유지하면서 해당 장르 카드와 맞춘다. 독자 특성과 플랫폼 차이는 표본으로 검증할 포지셔닝 가설로 취급한다. 도시물의 연애 감정 요구는 해당 보조 줄거리로 한정하고 소개문의 약속은 기존 문안 유형과 맞춘다. 출처 없는 정밀한 유입 비중은 통계 결론으로 사용하지 않는다. '민족주의에 기반한 성주의 평등'이라는 표현은 0d555cf의 부모 커밋에 있는 genre-frameworks-unified.md:2063–2069까지 추적할 수 있지만 출처가 표시되지 않은 자료 표지다. 압축되어 독립적으로 이해할 수 없는 표지는 삭제하고, 인의와 혜택으로 충성을 얻고 입장을 일치시키는 구체적 방식은 유지하되 해당 역사 쾌감물 노선으로 한정한다.

기존 [예산 합산과 solo 읽기 결정](../../implemented/architecture/2026-09-26-budget-stacking-and-solo-reads.md)과 연결하며 스크립트, 색인 읽기 절약, 주·보조 카드 두 개를 쓰는 설계는 바꾸지 않는다.

## Alternatives considered

- **장르 카드를 공통 장면 판단 체계로 바꾼다**: 반복 표현을 많이 없앨 수 있지만 장르별 쾌감, 리듬, 장면 구성 수단이 사라진다. 구체적인 방식은 유지하고 설명만 정리한다.
- **본문 집필 전에 색인 전체를 읽도록 되돌린다**: 사람이 경로를 선택하기에는 직관적이지만 기존 스크립트와 로드 예산 설계에 어긋난다. 현재 매칭 진입점을 설명하는 것으로 충분하다.

## Consequences

장르 카드를 본문 집필에 계속 바로 활용할 수 있고 자료 간 로드 방식, 표현 판단, 변형 범위가 일치한다. 비용은 각 카드에 필요한 독립 설명과 기존 매개변수를 유지해야 한다는 점이다. 원래 표본 목록이 없는 통계는 재추산하거나 전체 장르의 결론으로 확대하지 않는다. 이번에는 실행 스크립트, 공유 목록, 예산, 다른 장편 자료를 바꾸지 않는다. 배포 사본은 루트 담당자가 일괄 동기화한다.

## 검증

- 35/35개 문서 전문을 문장 연결과 표현 정리, 중복 제거, 모호함 해소, 사실 재확인, 논리 검사 순으로 검토했다. 문서별 증거는 `/tmp/prose-long-write-genres-coverage.json`에 출력했다.
- HEAD와 비교하여 문서 35개의 제목 앵커와 코드 블록, 카드 32개의 frontmatter, 표본 설명, 본문 참조 행이 그대로임을 확인했다. 전문 용어 개수는 줄지 않았다. 색인의 여섯 가지 8단계 비중은 각각 합계 100%였다.
- `build_writer_prompt.py`의 카드 헤더 매칭, 주·보조 정렬, 매칭 없음 분기와 `workflow-chapter.md`, `style-resolution.md`, 기존 예산 아키텍처 기록을 재확인했다. 독자 특성 검증은 `commercial-core-methods.md`의 댓글 감정 키워드 방법을 다시 확인했고 소개문 유형은 이 파일의 다섯 유형 표와 맞췄다.
- `static-check.sh`, `skill-numbering.py check`, `check-current-skill-contracts.py`, `check-doc-budget.sh`, 장르 카드 매칭·매칭 없음 회귀 검사, `git diff --check`가 통과했다. 예산 상한은 바꾸지 않았다.
- `check-shared-files.sh`는 이번에 수정한 실제 원본 34개에 대응하는 배포 사본의 예상된 불일치만 보고했다. 이 작업 트리에서는 동기화하지 않았다. `genre-readers.md`가 속한 `analysis-reader-profile`은 의도적 차이를 허용하는 그룹이므로 루트 담당자가 배포 용도에 맞춰 사본을 확인한다.
