# Agent Note: CDP 문서의 재사용·재생성 분기 일치

Status: implemented

## Problem

browser-cdp 문서는 `CDP_STATUS=ready`를 항상 바로 재사용하고 setup을 금지한다는 뜻으로 설명했다. 그러나 실행 스크립트는 `--reset` 또는 `--profile`을 명시적으로 전달하면 재사용을 건너뛰고 디버깅 인스턴스를 다시 만든다. 문서는 일반 Chrome 종료를 첫 실행에서 반드시 일어나는 일처럼 썼고, 원본 profile이 존재해야 한다는 조건을 누락했으며, 사용자에게 물어야 한다는 요구를 모든 호스트에 있지도 않은 AskUserQuestion 도구에 묶었다.

## Decision

기존 명령·필드·옵션·종료 코드는 유지하고 스크립트의 실제 조건에 따라 재사용과 재생성을 설명한다. 일반 연결에서 ready를 만나면 즉시 재사용하고 reset이나 profile을 명시적으로 요청하면 재생성하며, 기존 Chrome 프로세스 종료 동의 요구를 따른다. Chrome을 한 번 이상 사용했고 원본 profile이 존재해야 한다는 전제를 보완한다. 기존 질문 요구는 호스트에서 가능한 질문 방식으로 표현한다. 중복 설명은 합치고 디버깅 인스턴스 PID로만 정리하는 기존 경계를 유지하며, 새로운 일반 안전 규칙은 추가하지 않는다. OpenCode의 시간 제한은 전경 명령 상황으로 설명하며 백그라운드 실행 도구가 항상 없다고 단정하지 않는다.

근거는 `setup-cdp-chrome.js`의 `main`, `ensureConsentToKill`, `verifyPortOwnedByLaunch`와 로컬 `agent-browser 0.38.2`의 `--help`, `eval --help`이다. 실행기의 일반·reset 두 dry-run 모두 0을 반환했으며 Chrome을 실행하거나 종료하지 않았다.

## Alternatives considered

- **모든 ready 상태를 계속 재사용**: 경로가 가장 짧다. 그러나 로그인 만료 후 reset과 profile 전환을 문서가 잘못 건너뛰게 하여 기존 스크립트 분기와 반대가 된다.
- **스크립트를 문서의 무조건 재사용 규칙에 맞춰 수정**: 문서의 조건을 줄일 수 있다. 그러나 스크립트가 이미 지원하는 명시적 재생성 의미를 없애므로 이번 문서 유지보수에서는 실제 구현을 따른다.

## Consequences

첫 연결·재사용·재생성 설명이 현재 스크립트와 일치하고 profile이 없을 때의 문제 해결 방향이 분명해진다. 대신 문서에 필요한 분기가 남고 실행은 현재 플랫폼의 Chrome과 프로세스 조회 도구에 계속 의존한다. 이번에는 실행기, 브라우저 조작 명령, 기존 동의 조건, 배포 설정을 변경하지 않는다.

## 검증

정적 검사, 워크플로 번호, 문서 예산, 공유 파일, 의사결정 기록, 작가 보고서, scan/browser 소스 정책 검사를 모두 통과했다. frontmatter, 제목, 실행 명령, 예시 코드 블록은 원고와 글자 단위로 같다.

## 검토 범위

`skills/browser-cdp/SKILL.md` 전체를 읽고 문장 합치기, 편집 과정 설명 제거, 모호함 해소, 스크립트 대조, 분기 논리의 다섯 단계를 순서대로 완료해 수정했다. 명령·필드·번호·예시 코드 블록을 유지했다.
