# 본문 형식과 절 구조

> 기본 본문 전달 형식이다. 사용자나 목표 플랫폼의 명시적 요구를 우선한다.
>
> **범위**: 문단 형식(극적 단위/숏 우선, 짧은 문단 기본, 긴 문단은 완결된 추론·분위기·감정 사슬용)과 대화 형식은 모든 장르에 적용한다. 절(beat) 구조는 단편 전용이며 일률적 최소 글자 수는 없다. 장편은 동일 기준 상세 개요의 `字数目标`를 `visible_chars_v1`로 측정한다. 내부 범위 ±12%, 사용자 범위 ±15%.

---

## 장 표기

목표 플랫폼에 따라 고르며 미지정이면 단편 기본값을 쓴다.

| 형식 | 플랫폼 적용 | 예시 |
|------|----------|------|
| `###1.` | 단편 기본값 | `###1.` `###2.` `###3.` |
| `###第一章` | 일부 플랫폼 | `###第一章` `###第二章` |
| `1.`(숫자만) | 즈후 | `1.` `2.` `3.`(### 접두사 없음) |

**규칙**: 전체를 한 형식으로 통일하고 섞지 않는다. 단편은 간결한 `###1.` 또는 숫자만 쓰기를 권한다.

## 문단 형식

### 핵심: 극적 단위 우선

기본 전달 배치는 **극적 단위/숏에 따라 자연스럽게 나누고 문단을 붙여 배치**한다. 고정 글자 수로 강제 분할하지 말고 하나의 사건/추론 사슬/감정 변화가 끝났는지 먼저 판단한다.

- 한 문단은 하나의 극적 단위, 즉 행동 사슬·단서 발견·시선 전환·심리 판단·연속된 분위기/추론/감정 사슬을 담는다.
- 장면이나 사건 종료, 새 행동·물건·정보·대화에서 새 문단을 시작한다. 같은 순간의 발생·감지·반응은 함께 엮고 행동층/감지층/반응층으로 나누지 않는다.
- 본문의 이웃 문단 사이에는 **줄바꿈 `\n` 하나만** 허용한다. 빈 줄이나 연속 줄바꿈 `\n\n`은 금지한다(밀착 배치).
- 들여쓰지 않는다. 플랫폼이 처리하므로 `　　` 또는 공백이 필요 없다.
- 길이는 진단에만 쓴다. 답답하거나 여러 박자가 섞이거나 휴대전화에서 따라 읽기 힘들 때만 나눈다. 추론·분위기·감정 전진이 끝나지 않았다면 조금 긴 문단으로 연결성을 유지해도 된다.

### 문단 리듬(길고 짧음 + 밀도 차이)

짧은 문단의 빠른 읽기는 모바일 웹소설의 기본이다. 긴 문단은 완결된 추론·분위기·감정의 침전을 담는다. **전체가 같은 길이가 되는 것**, 모든 문단을 같은 글자 수로 자르는 것을 피한다.

- **길고 짧음 교대**: 절정·응징·반전의 결정점은 한 문장 문단이어도 된다. 추론·환경 압박·감정 침전·수습은 조금 길게 유지하여 변화 전체를 읽게 한다.
- **밀도 차이(상세/간략)**: 쾌감·전환 beat는 필요한 감각·행동·세부를 펼치고 이동 구간은 짧게 쓴다. 서사 역할에 따라 정하며 모든 beat를 같은 길이로 만들지 않는다.
- **과도한 파편화 금지**: 연속된 극단적 단문단이 같은 숏/사건이면 자연스러운 문단으로 합쳐 개요나 시 행처럼 보이지 않게 한다.

### 주어와 인물명 리듬

인물명을 계속 생략하지도 매 문장마다 부르지도 않는다. 주어 재설정에 따라 쓴다.

- 문단 첫머리·장면 전환·여러 인물 동석·주어 혼동 가능성이 있으면 주인공/인물명으로 시점을 세운다.
- 같은 문단·행동 사슬에서는 대명사·행동 연결·적절한 생략을 섞어 모든 문장이 같은 이름으로 시작하지 않게 한다.
- 주요 전환·감정 폭발·신분 대비·주인공 재집중이 필요하면 다시 이름을 불러 강조할 수 있다.
- 읽다가 걸리는지로 판단하며 장 전체 이름 횟수로 일괄 제한하지 않는다. 연속 문장/문단에서 주어 재설정 필요 없이 이름을 반복할 때만 과밀이다.

## 대화 형식

### 대화 표기

목표 플랫폼/사용자 요구를 따르며 없으면 기본값을 쓴다.

| 우선순위 | 형식 | 적용 플랫폼 |
|--------|------|----------|
| 우선 | `"대사"` | 단편 기본값·판체 |
| 플랫폼/프로젝트 지정 | `「대사」` | 즈후 옌옌 단편·일부 시대 로맨스·일본식·사용자 지정 |

**기본은 `""`**. 사용자/플랫폼이 옌옌 스타일을 지정하면 `「」`로 바꾸며 이를 오류로 보지 않는다.

### 대화 규칙

1. 대화는 **독립된 줄**에 쓰고 서술 문단에 섞지 않는다.
2. 화자 표시가 필요할 때만 대화 태그를 쓴다. 잦고 공식적인 ‘그가 말했다’·‘그녀가 말했다’·‘그가 웃으며 말했다’는 행동이나 맥락으로 대체할 수 있고 평범한 ‘말했다’는 유지해도 된다.
3. 두 사람이 이어 말하며 화자가 분명하면 태그를 생략해도 된다. 혼동될 때는 화자를 명시한다.

**올바른 예**:
```
그녀가 잔을 내려놓았다.
"가세요."
그는 움직이지 않았다.
"가라고 했어요."
```

**이것도 허용(평범한 ‘말했다’를 드물게 사용)**:
```
그녀가 잔을 내려놓았다.
"가세요." 그녀가 말했다.
그는 움직이지 않았다.
"가라고 했어요."
```

**잘못된 예**:
```
그녀가 잔을 내려놓으며 말했다. "가세요." 그는 움직이지 않았고 그녀가 다시 말했다. "가라고 했어요."
```

## 말투별 문장부호 체계

문장부호는 말투·인물 목소리·감정 리듬을 돕는다. 전체를 마침표로 평평하게 만들거나 다양해 보이려고 기호를 무작위로 쌓지 않는다. 현재 문장의 기능을 먼저 정하고 선택한다.

| 말투/기능 | 문장부호 전략 | 경계 |
|---|---|---|
| 압박/냉정/절제 | 단문·쉼표·마침표, 필요하면 콜론으로 판단 강조 | 느낌표를 인위적으로 추가하지 않음. 절제는 모든 문장에 평평한 마침표를 붙인다는 뜻이 아님 |
| 추궁/탐색/반문 | 물음표 + 짧은 추가 질문, 행동 멈춤과 결합 | 모든 문장을 `？`로 끝내지 않음 |
| 놀람/폭발/응징 | 실제 폭발점에는 느낌표 1개, 연속 폭발은 최대 1-2곳 | `!!!`와 문단 전체 고함식 감탄 금지 |
| 망설임/삼킴/미완 발언 | 기본은 쉼표·마침표·문장 길이 변화·행동 beat | 말줄임표의 기능적 사용은 작품 문체 규약을 따름 |
| 끊김/늘인 소리 | 기본은 행동 끼어들기·줄바꿈·단문·미완 행동 | 줄표의 기능적 사용은 작품 문체 규약을 따름 |
| 정보 공개/판단 결정점 | 콜론·세미콜론·한 문장 문단으로 강조 | 모바일 친화성을 유지하고 논문식 세미콜론 연쇄 금지 |

실행 규칙:

- 대화는 인물 관계와 권력 위치부터 본다. 강한 인물은 단문으로 마무리하고 탐색하는 인물은 물음표·반 문장을 많이 쓴다. 무너지는 인물에게만 소량의 감탄/생략을 허용한다.
- 서술은 문장 길이·쉼표 멈춤·한 문장 문단으로 리듬을 만든다. 기본적으로 줄표로 억지 리듬을 만들지 않으며 작품 문체가 명시 허용한 기능적 사용은 유지한다.
- 퇴고 시 **전체 마침표화**(말투가 전부 평평해짐)와 **무작위 기호 쌓기**(물음표/느낌표의 감정 기능 없음, 말줄임표/줄표로 억지 멈춤)를 확인한다.
- 인용부호는 프로젝트/플랫폼 규약을 따른다. 즈후 옌옌의 `「」`는 유효하며 `quote-mode keep`일 때 임의로 바꾸지 않는다.

## 절(beat) 구조

### 기본 규칙

- 숫자(`1` `2` `3`)로 나누며 각 절은 완결된 서사 beat다.
- 절 길이는 서사 역할에 따르고 일률적 최소 글자 수는 없다. 작품 전체는 확정된 전달 범위, 장편 장은 상세 개요 「字数目标」로 관리한다.
- 절 수는 플롯 단계와 장면 전환 필요로 정한다. 글자 수 균등 배분을 위해 완결된 행동 사슬을 나누거나 역할이 다른 절을 억지로 합치지 않는다.
- 각 절은 분명한 플롯 지점 하나를 전진시킨다.

### 절 내부 구조

각 절은 적어도 1번을 완수하고 나머지는 역할에 따라 선택한다.

1. **주 사건 하나** + **실제 전진 하나 이상**: 위험·정보·관계·자원·결정·행동·독자 이해 중 하나 이상 변화. 관련 지점은 같은 행동 사슬/대화로 동시에 실현할 수 있다. 수를 채우려고 장애물·대화·갈등을 추가하지 않는다.
2. **감정/압박의 결정점**: 실제 변화가 있으면 독자 감정의 변화를 명확히 쓴다. 임무·추론·기술·대기 사슬에 감정 전환을 억지로 붙이지 않는다.
3. **독자 인식 또는 다음 단계 변화**: 새 정보·옛 정보 재해석·결정·행동·결과 모두 가능하며 새 사실을 강제하지 않는다.
4. **대화의 기능적 사용**: 필요할 때 정보·전략·권력·관계·다음 행동을 바꾼다. 혼자 발견·증거 검증·대기·기술 장면은 대화가 없어도 된다.
5. **전진 단위에 필요한 정보 차원을 섞기**: 발생이 중심이며 감지·반응은 새 정보를 줄 때만 같은 숏에 엮는다(writing-craft.md 장면 작성 참조).

### 절 사이 연결

- 절 끝에 의문/미해결 감정/새 문제의 후킹을 남긴다.
- 다음 절은 빠르게 이어받고 다시 밑작업하지 않는다.
- 감정의 고조·완충·하강은 모두 앞 절 행동과 결과를 이어받아야 한다. 매 절 강도 상승을 요구하지 않는다.

## 플랫폼별 대화 형식 보완표

| 플랫폼 | 장 표기 | 대화 형식 | 특수 요구 |
|------|----------|----------|----------|
| 즈후 옌옌 | `1.` | `「」` | 도입은 본문 첫 몇 문단이며 별도 표기하지 않음 |
| 판체 | `###第一章` | `""` | 첫 문단이 매력적이어야 함 |
| 훙궈 | `###1.` | `""` | 없음 |

**공통 원칙**: 플랫폼 미지정이면 단편 일반 형식 `###1.` + `""`. 사용자/플랫폼이 옌옌 스타일을 지정하면 `「」`를 허용한다.

## 형식 규칙 8개

파일 첫머리의 우선순위를 따른다. 문장부호 기본값은 작품의 명시적 문체 규약으로 바꿀 수 있다.

1. **글자 수로 기계적 분할 금지**: 일정 수를 넘었다고 강제로 자르지 않는다. 하나의 완결된 극적 단위인지 먼저 본다. 여러 행동/정보/시선 전환이 섞일 때 나누며 완결된 추론·분위기·감정 사슬은 조금 길어도 된다.
2. **문단 사이 빈 줄 금지**: 이웃 문단 사이에는 `\n` 하나만 허용하며 빈 줄·`\n\n`은 금지한다.
3. **대화 태그 기계화 회피**: 잦고 공식적인 화자 태그는 행동/맥락으로 대체하고 평범한 ‘말했다’는 유지해도 된다.
4. **들여쓰기 금지**: `　　`(전각 공백) 또는 반각 공백으로 들여쓰지 않는다.
5. **본문 문단 Markdown 렌더링 금지**: 통일된 절/장 표기(예: `###1.`) 외에는 굵게 `**`·기울임 `*`·제목 `#`·구분선 `---` 등 Markdown을 본문에 쓰지 않는다.
6. **기본 멈춤 표현**: 마침표·쉼표·줄바꿈·행동 beat·단문을 쓴다. 작품이 명시 선택한 기능적 줄표/말줄임표는 호출자의 문체 판단과 작품별 허용 목록에 따라 유지한다. 문장부호 취향은 변경 불가 파일 구조 계약이 아니다.
7. **전체 마침표화·무작위 기호 쌓기 금지**: 기호는 말투·목소리·감정 기능에 맞춰야 한다. 추궁에는 물음표, 폭발에는 적은 느낌표를 쓴다. 망설임·삼킴·미완 발언은 행동이나 문장 길이로 표현하며 `……` / `——`로 억지 멈춤을 만들지 않는다. 기능 없이 `？`/`！`를 흩뿌리지 않는다.
8. **본문에 장 메타 정보 금지**: 장 번호는 제목/절 표기/파일명/추적 기록에만 둔다. 서술·대화·심리 묘사에 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 같은 집필 작업 용어를 넣지 않는다. 인물이 인지할 사건 기준점·상대 시간으로 바꾼다. 예를 들어 ‘1장의 그 3초 발포보다 아팠다’를 ‘그 3초 발포보다 아팠다’로 고친다. 예외: 인물이 이야기 속에서 실제 ‘제X장’ 텍스트를 읽거나 논의하거나, 실제 작가/독자로서 독자 신분을 논할 때는 해당 말을 유지할 수 있다.
