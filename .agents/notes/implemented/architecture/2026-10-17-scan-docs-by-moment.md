# Agent Note: 장·단편 순위 조사 자료를 작가 시점과 읽는 주체별로 재구성하고 스크립트와 정렬

Status: implemented
Date: 2026-10-17

## Problem

집필·분석 재구성 뒤 순위 조사 두 스킬에도 같은 문제가 드러났다.

- 문서와 수집 동작이 달라 집계가 오해된다. 치뎬 모바일의 신인 계약 신작·계약 작가 신작은 같은 페이지인데 둘 다 수집해 전부 두 순위 중복으로 센다. 판체는 장르별 상위 20권인데 세 장르 모두 “20권 / 33% / 충분”이라 표본 상한을 규모로 오인한다. 치뎬 순위·츠웨이마오·헤이옌 머리말에는 데이터 품질이 없어 품질 미표시만 나온다. 헤이옌 API나 수동 순위에서 작가가 없으면 메타정보 한 칸이 빠져 장르를 작가로 읽고 책을 그룹명에 분류한다. 헤이옌 페이지 수는 실제가 아닌 계획값이다. 수집기 다섯 개 주석은 플랫폼 참조에 없는 형식 설명을 가리킨다.
- reader-profiling·publishing-guide는 어느 Phase도 읽지 않는다. genre-trends는 집필 강좌·단편 제목을 섞고 단편 real-market-data는 인칭·문단·따옴표 형식을 섞어 집필의 헤이옌 따옴표와 충돌한다.
- 판정에 근거가 없다. 장편 첫 조사·내장 지식은 실제로 높음을 못 주지만 설명이 없고 낮음 기준도 없다. 남녀 채널·신작/전체 시장을 안 묻고 오래된 인기작 비중도 낮추지 않으며 인계에 비교 작품 필드도 없다. 단편 경쟁 정도·진입 문턱·유행 경보는 출처 없이 emoji까지 있고 감정 분류도 별개다. 반전 충격 난도를 낮음으로 쓰지만 집필은 높음이다. 내장 지식은 무조건 중간이며 모집 요건·작가 조건을 받지 않는다.
- 검사는 파일명·Phase만 보호한다. 장편 소재 결정 필드명, 단편 결론 절명·감정 값이 바뀌면 조용히 끊긴다.

## Decision

**장편 순위 조사(story-long-scan)**

- `aggregate-rank.js`는 같은 플랫폼 두 순위의 순번·제목·작가가 항목별로 같으면 하나만 센다. 수집 상황에 X와 완전히 같은 데이터라 한 번만 센다고 쓰고 JSON에 `duplicateOf`를 넣는다. 제목 미해독 순위는 비교에서 제외한다. `--sample`도 중복본을 건너뛴다. 머리말에 장르별 상한이 있으면 권수·비율은 표본 결과이고 인기는 인기 중앙값으로 보라는 행을 더한다. 표본 열은 충분 대신 표본 추출, JSON은 `perGenreCap`이다. 장르 정렬은 유지한다.
- 기본 표본 기준은 15권, 순위당 상위 10권인 츠웨이마오는 10권이다. 표 머리말에 장르당 15권(츠웨이마오 10권) 미만은 적음이라고 쓰고 플랫폼별 JSON `sparse`를 둔다. `--sparse`를 주면 모두 그 값이다. 다중 플랫폼에서도 츠웨이마오만 별도 호출하거나 다른 플랫폼 기준을 낮출 필요가 없다.
- 이름에 “新手”가 있는 진장 신인 골드 순위도 신작으로 분류해 다른 순위와 함께 수집하면 신작 순위 열을 표시한다.
- 츠웨이마오 1위는 작가·나머지는 장르라는 규칙은 문자 필드가 하나인 수집기 항목에만 적용한다. 수동 작가·장르 두 필드는 일반 위치로 읽는다.
- `qidian-rank-scraper.js`는 `rankQualityLines`를 내보내고 장르·분량 절반 초과 누락은 문제로 표시한다. `ciweimao-rank-scraper.js`는 `renderRankFile`을 분리하고 품질 판정을 더한다. 각 수집기 `const filename` 대입은 여전히 한 곳이다. 주석은 `aggregate-rank.js` 머리말을 가리킨다.
- reader-profiling·publishing-guide를 삭제한다. 독자·기조는 플랫폼 참조의 이 플랫폼 독자 절로 옮기고 근거 없는 적합 장르를 쓰지 않는다. 치마오 여성향 원고 선호는 옛 자료라고 표시한다. 플랫폼 선택·순위로 추론 가능한 독자 차원은 topic-decision에 넣고 출간 운영·소개 작성은 집필 시점이라 옮기지 않는다. genre-trends는 내장 지식에서만 읽고 제목 표본은 mongo 치마오 장편 원제목이다. 2026-10-17에 `novel.qimao_detail`의 `is_short_story` 거짓, `words_num` ≥80만 자인 책을 `category_channel` 남성향(1, 2072권)·여성향(2, 1643권)으로 나누어 제목마다 `我`, `[：:]`, `重生`, `开局`, `从.+开始`, `总裁|大佬|霸总`, `离婚` 정규식 비율을 구했다. 기존 오래된 책의 제목 습관임을 명시한다.
- 플랫폼 참조 첫머리에 `--outdir` 기본 명령과 수집 불가 절을 둔다. 치뎬 기본에서 계약 작가 신작을 뺀다. Phase 1은 플랫폼·채널·신작/전체 시장·장르 방향을 함께 묻는다. 스크립트 남녀 구분은 판체·치마오만 가능하고 치뎬 여성향은 작가에게 순위를 요청한다. Phase 3는 판체 권수는 표본 상한, 오래된 상위작은 기존 독자만 나타낸다고 설명한다. 장르 인기는 중앙값순이며 전체 비교는 P75 대신 쉬운 말로 쓴다. 주목 방향은 같은 방향 몇 권·신작 존재 여부만 쓰고 높음/중간/낮음은 소재 선택에서 정한다. 플랫폼 요약 표·WebFetch 경로는 없앤다.
- topic-decision은 첫 조사·내장 지식 최대 중간, 낮음은 작가 자료 부족·플랫폼 불일치·출처 있는 반례만 인정한다. 상한 때문에 중간이면 이유를 쓴다. 동급은 같은 방향 신작 표본, 그다음 작가 자료순이다. 판체 방향 표본은 세부 소재·태그별 권수로 센다. 템플릿에 분석 추천 비교 작품을 더하고 인라인 주석을 뺀다.

**단편 순위 조사(story-short-scan)**

- `heiyan-booklist-scraper.js`는 작가가 없으면 `佚名`, 페이지 수는 실제 항목 기준이다. `dataQuality()`를 내보내고 목록 전용은 `[仅列表-无核心指标]`, `--detail`은 상세 확보 비율별 세 등급이다. 플랫폼 기본은 `--pages 3 --detail`이며 최근 등록 분포 수집·헤이옌 관리 계정 필요를 설명한다.
- manual-rank-input도 작가 누락 시 `佚名`을 요구하고 수집 시간·데이터 품질: 작가 제공 두 행을 더한다.
- SKILL Phase 3에 집필 Phase 1과 같은 감정 여섯 종류·난도 표를 넣는다. topic-match 목표 감정은 이 중 하나, 복잡도는 집필 난도로 바꾸고 차별점·실패 위험과 저비용 검증 세 방법을 더한다. 내장 지식은 최대 중간이다. 보고의 경쟁 정도·문턱 열은 지우고 유행 경보는 같은 기준의 이전 표본이 있을 때만 쓰는 변화 절로 바꾼다. Phase 1은 모집 요건·남녀 채널을 받고 Phase 2는 플랫폼과 무관하게 `征稿要求.md`에 요건을 저장한다. Phase 5는 플랫폼·자료·계획 분량부터 묻는다. 뎬중·헤이옌은 인기 순위가 아니라 판매 중 목록이므로 이것만 있으면 판매 중 수량, 뎬중은 평점 중앙값, 헤이옌 대표작은 태그 적합도로 쓴다. 감정 인기 순위는 감정 순위로, 쓸 만한 방향은 같은 방향 몇 편으로 바꾼다. real-market-data의 집필 형식 행·빈 분량 열은 지우고 short-scan에만 둔다.

**스킬 간 연결·등록**

- `scripts/test-handoff-contracts.py`에 `check_short_scan_handoff`(SKILL에서 모집 요건 저장 포함), `check_long_scan_handoff`, 실패 여덟 사례를 더한다. `test-scan-aggregate.py`는 동일 페이지 한 번 계산·표본 추출, 판체 상한 안내·표본 열, 수동 작가 누락, 진장 신인 신작 분류, 츠웨이마오 수동·플랫폼별 표본 기준의 다섯 묶음이다. `test-scan-runtime.js`는 치뎬·츠웨이마오 품질 머리말, 헤이옌 작가 누락·페이지·네 품질 등급을 검사한다.
- shared-assets로 `aggregate-rank.js`를 단편에 동기화한다. 장편 필수 예산은 SKILL·topic-decision만, 츠웨이마오 분기 추가, genre-trends는 내장 지식 분기다. 실측은 6340–6997(이전 약 13.5K), 단편 두 분기 예산은 7600·7750이다.
- docs/knowledge-base 중·영문과 docs/scan-charts-and-deconstruct-bestsellers의 기본 순위·인기 기준·세 데이터 출처를 동기화한다.

## Alternatives considered

- **URL로 중복 제거**: 간단하지만 츠웨이마오 모든 순위 URL이 rank-index여서 전부 합쳐진다.
- **판체를 인기도순 재정렬**: 표본 상한인 권수보다 실제 인기에 가깝다. 그러나 실제 순위로 결과 악화 여부를 검증하지 못해 위험하면 바꾸지 않는 원칙으로 안내만 추가했다.
- **집계기가 작가 누락 추정**: 모든 출처의 위치 오류를 해결할 수 있다. 그러나 필드 유형 표시가 없어 복수·학대 연애라는 장르와 작가명을 구분할 수 없고 추정은 새 오류를 만든다. 두 생산 측에서 `佚名`으로 맞춘다. 츠웨이마오는 내용 추측 없이 문자 필드 수로 수집·수동을 구별할 수 있는 예외다.
- **츠웨이마오를 별도 집계**: 스크립트 변경은 없지만 호출·표가 늘고 놓치기 쉽다. 플랫폼별 기준은 작은 표 하나면 된다.
- **고아 파일을 필요 시 참조로 유지**: 내용이 틀린 것은 아니며 이동 비용을 아낀다. 그러나 어느 Phase에도 읽을 시점이 없다. 유용한 부분은 실제 읽는 플랫폼 참조·topic-decision으로 옮겼다.

## Consequences

- 이점: 치뎬 중복 과대계산·판체 권수의 규모 오해를 막고 치뎬·츠웨이마오·헤이옌 문제를 수집 상황에서 본다. 장편 분기 로드 약 절반, 집필·분석 인계의 필드·절·감정 값은 이름을 바꾸면 테스트가 즉시 실패한다.
- 비용: 실제 순위 조사는 실행하지 않았다. 판체 세부 소재/태그 수·오래된 상위작 비중 감소·첫 조사 최대 중간·단편 감정 통합은 판정을 바꾸므로 적용 전 실제 순위로 각각 실행해 전후 소재 결론을 비교해야 한다. 단편 두 분기 여유는 34–51자라 추가 전에 삭제가 필요하다.
- 알려진 미수정(오프라인 재현 불가): 수집 시간은 UTC인데 집계가 앞 10자를 날짜로 써 베이징 0–8시 조사 날짜가 하루 이르다. 장편 원본에서 통일 수정해야 한다. 뎬중 정규식은 “连载”만, “连载中”은 인식하지 않는다. 헤이옌 요청의 고정 `language:'zh_TW'` 의미는 유지보수자 확인이 필요하다.
- 배포: 두 조사 패키지가 바뀌어 `.clawhub/publish.json` 버전·digest를 절차대로 갱신해야 한다. skills-only 호스트는 사용자 업그레이드·재배포 후 적용된다.
