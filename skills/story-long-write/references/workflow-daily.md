# workflow-daily.md: 일일 연재·이어쓰기 절차

SKILL.md가 일일 연재·이어쓰기로 연결하면 이 파일로 배치를 관리합니다. 각 장 본문은 [workflow-chapter.md](workflow-chapter.md)를 따르고 파일·상세 개요 누락은 그 문서 첫머리대로 처리합니다. 회수 범위를 줄이는 조건이 성립하지 않을 때만 [benchmark-recall.md](benchmark-recall.md)를 읽습니다. 기존 본문·추적 정보가 있고 작가가 일일 연재·이어쓰기·N–M장 집필을 명시한 프로젝트에 적용합니다. 인수 없는 호출, 기획만, 상세 개요 수정만으로는 진입하지 않습니다.

---

## Step 1：快速上下文加载

한국어 안내: 빠른 맥락 로드.

`tracking_commit.py check`의 `last_committed_chapter + 1`을 첫 장 N, `state_revision`을 수정 번호로 쓰고 `추적/문맥.md`의 현재 위치와 대조합니다. 장 번호가 다르면 먼저 복구하며 본문을 훑어 추측하지 않습니다. 각 장의 맥락은 workflow-chapter의 2번 단계를 따릅니다. `추적/복선.md`, `시간선/`, `장별기록/`는 기본적으로 통째로 읽지 않고 부족한 과거 정보는 아래 검색 절차로 찾습니다.

`추적/문맥.md`는 `tracking_commit.py`가 생성하는 고정 7항목의 이어쓰기 상태 카드이며 수동 수정은 금지합니다. 스키마·수정·복구는 [tracking-transaction.md](tracking-transaction.md)를 오류 때만 읽습니다.

**state 누락·뷰 불일치**: 멈추고 [stop-and-fix.md](stop-and-fix.md)로 복구한 뒤 시작합니다.

범위를 정하면 계속할지 묻지 않고 Step 2로 갑니다. K의 기본값은 2–3장이고 작가가 다르게 지정하면 따릅니다. 장 번호 충돌·개요 범위 초과·기존 이야기 계획 변경이 필요할 때는 확인을 위해 멈춥니다. 장별 정상 추적 제출에는 따로 묻지 않습니다.

## Step 2：串行批量写作

한국어 안내: 여러 장 순차 집필.

**주 세션 안에서 한 장씩 순차적으로 씁니다.** 추적 정보가 서로 덮어써지므로 여러 장을 여러 보조 에이전트에 동시에 맡기지 않습니다. ‘계속/이어쓰기/일일 연재’에 장별 재확인을 요구하지 않습니다. 이번 K(최대 3장)에 도달하면 반드시 Step 3/4로 마무리하고 멈추며 상세 개요가 더 있다고 다음 배치를 쓰지 않습니다.

1. **집필 계획 읽기**: 권의 약속 → 현재 줄거리 단위 → 장별 상세 개요 순서로 정합니다. `outline_view.py --unit {单元ID}`로 권·단위 정보를 한 번 추출해 이번 배치에서 재사용하고 권별 개요 전체를 읽지 않습니다. 집필 전 배치 목표, 공개 가능·조기 공개 금지 정보, 장 끝 훅의 경계를 정하며 현재 단계에서 풀면 안 되는 최종 비밀을 쓰지 않습니다. 완료 후 단계 리듬보다 앞서거나 느려지거나 벗어났는지 봅니다. 세부 조정은 제외하되 권의 약속·단위 약속·진행 흐름·보상 귀속이 달라졌다면 본문을 수정하거나 후속 상세 개요를 다시 계획합니다. 다음 장 보완은 `next_chapter_commitments`, 장 간 위험은 `continuity_risks`에 적고 후반 정보를 미리 공개해 속도를 높이지 않습니다.
2. **장별 실행**: workflow-chapter의 단일 장 집필 1–13단계를 마친 뒤 다음 규칙도 적용합니다.
   - **이전 장의 미해결 문제**: 이번 장을 쓰기 전 이전 장의 blocking 문장 패턴을 모두 해결해야 합니다. 집필 전 훅이 차단하며 훅이 없으면 이전 장에 `chapter check`를 한 번 실행합니다. `<!-- 去味:跳过 -->` 표식은 예외입니다.
   - **상태 출처**: 전체 `_tracking-state.json`을 맥락에 넣지 않습니다. 빠진 정보만 찾아 읽고 출처 불명의 대화 기억으로 대체하지 않습니다. 오랜만에 등장한 핵심 인물은 `추적/인물상태/{名}.md`를 읽고 다시 활동하면 이번 트랜잭션의 `context.active_character_names`에 넣습니다.
   - **이번 장 기법**: 주 세션이 직접 쓰면 배치당 자료 한 개만 읽습니다(SKILL.md의 선택 규칙). 집필자에게 맡기면 장마다 분류를 적습니다.
   - **story-explorer 회수**: `gaps`는 [agent-calls.md](agent-calls.md)의 「story-explorer：写前对标召回」(집필 전 비교 자료 회수)에 따라 처리합니다.
   - **집필 후 즉시 해결**: 훅이 반환한 발견 사항은 같은 차례에 해결하고 배치 끝까지 미루지 않습니다.
   - **장 완료 즉시 추적 제출**: workflow-chapter 12번 단계로 제출에 성공해야 다음 장으로 갑니다. 이후 장에 영향을 주는 변화만 기록하고 과정 로그·품질 검사 수·AI 문체 제거 통계는 트랜잭션에 넣지 않습니다. narrative-writer는 `추적/`를 쓰지 않습니다.
3. **불필요하게 멈추지 않되 동시 집필 금지**: 추적 제출 후 다음 장으로 갑니다. 분량 부족 또는 1회 압축 후에도 초과이면 workflow-chapter의 글자 수 질문으로 작가가 선택하게 하며 조용히 진행하지 않습니다.

### 旧信息查找步骤

한국어 안내: 과거 정보 검색 절차. 상태 카드에 없지만 이번 장에 필요한 정보만 가까운 곳부터 찾아 발견 즉시 멈춥니다.

1. **추적 자료의 필요한 부분 읽기**: 복선은 `grep -n "F007" 추적/복선.md`, 인물은 `추적/인물상태/{名}.md`, 독자 인지는 `시간선/독자가아는사실.md`, 작가 진실은 `시간선/작가용진실.md`를 봅니다.
2. **변화 이유·이력**: story-explorer의 `foreshadow_status / character_status / timeline`을 호출합니다. 없으면 `grep -R -n --include='第*.md' "F007" 추적/장별기록/ | tail -5`로 최근 5개만 봅니다.
3. **원본 파일 하나 읽기**: 해당 장별 기록이나 복선을 심은 장의 본문 중 하나만 읽습니다. 전량 읽기는 `/story-review`나 작가가 요구한 전체 감사에서 하며 일일 연재에서는 하지 않습니다.

한 장에서 2단계 검색이 3회를 초과하면 상세 개요에 필요한 과거 정보가 불명확한 것입니다. story-explorer에 여러 항목을 한 번에 조회시키고 배치 끝 보고에서 회수 항목을 개요에 명확히 보완해야 한다고 알립니다.

## Step 3：日更批末核对

한국어 안내: 일일 연재 배치 끝 대조.

장별 검사는 Step 2에서 마쳤으므로 여기서는 **장 사이**만 확인합니다.

1. **제목 중복 제거**: 새 장 제목이 기존과 같거나 명백히 중복되면 상세 개요와 본문 파일명을 함께 바꿉니다.
2. **약속·개요 양방향 대조**: 장별 약속 4질문은 workflow-chapter 9번에서 마쳤습니다. 여러 장을 연결했을 때 주인공의 공로·숨겨 둔 수·기존 기대가 누적 불균형인지 봅니다. 문제는 같은 9번 방식으로 고치며 보강 필요·약속 위반은 배치 끝 보고에 적습니다. 본문이 개요의 내용 요약·줄거리 구성·관계 변화·이익 귀속을 구현했는지 확인합니다. 쾌감 앞에는 식별 가능한 준비가 있고 반격·폭로 장에는 현장 조연의 차별화된 반응이 있어야 하며 상세도는 목적별로 배분하고 균등하게 부풀리지 않습니다. 미달이면 Step 2로 돌아가 승인된 내용만 고칩니다.
3. **복선 점검(이번 증분만)**: 이번에 추가·진행·회수한 각 ID가 `추적/복선.md`의 현재 상태 한 행에만 존재하고 해당 장 기록에서 이번 변화를 찾을 수 있어야 합니다. 전체 복선 감사는 하지 않습니다.
4. **일관성 검사(배치 끝 한 번)**: 아직 별도 검사하지 않은 장만 확인합니다. 프롬프트는 agent-calls.md, 신고 항목은 장별 신고 합계를 씁니다. 에이전트가 없으면 주 세션이 workflow-chapter의 해당 절로 검사합니다. 충돌은 새 요소 처리 표를 따릅니다.

이 단계에서 바꾼 장만 `chapter check --fix-punctuation`을 다시 실행합니다. 수정이 후속 사실·상태·복선·약속에 영향을 주면 Step 4 전에 workflow-revision에 따라 해당 장 수정 트랜잭션을 제출합니다(`draft` 사전 채움 → 수정 → `chapter commit`). 단순 문구 수정은 재제출하지 않습니다.

## Step 4：批末收尾

한국어 안내: 배치 마무리.

**이 단계에서는 추적 내용을 다시 쓰지 않습니다.** 다음만 수행합니다.

1. `tracking_commit.py check`가 통과하고 각 장의 장별 기록이 있어야 합니다. 누락·상한 초과는 해당 장 트랜잭션으로 돌아가 고쳐 재실행하며 파일을 수동 보충하지 않습니다.
2. **「本章没写成的」(이번 장에서 쓰지 못한 것) 취합**: 신고 표 마지막 줄을 두 갈래로만 나눕니다. 「细纲没给」(개요에 없음)는 개요 작업 초안의 「建纲追加」에 추가합니다. 기존 설정 관련이면 먼저 확인하고 이미 정한 값은 다음 장 프롬프트에 넣습니다. 「先问作者」(작가에게 먼저 질문)는 workflow-chapter의 「新增物处置（主会话）」 표에서 같은 행으로 합칩니다. 작업 초안에서 아직 결정되지 않은 같은 유형의 항목과 함께 배치 끝 보고에 냅니다. 모두 `0`이면 「无」(없음)로 적습니다.

이후 SKILL.md의 작가 대상 보고에 따라 별도 파일을 만들지 않고 대화로 보고합니다. 내부 검사는 이야기 용어로 바꿔 설명합니다.
