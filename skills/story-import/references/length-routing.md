# 장편·단편 분기 판단 규칙

Phase 1의 기본 정보 확인에서 가져올 작품이 장편인지 단편인지 판단합니다. 결과에 따라 이후 이전 경로를 정합니다.

## 판단 우선순위

작가가 분량 유형을 명시하면 바로 확정합니다. 명시하지 않으면 아래 신호로 일차 판단하고, 충돌하면 Phase 1에서 한 번 확인한 뒤 다시 판단하지 않습니다.

| 우선순위 | 신호 출처 | 판단 규칙 |
|--------|---------|---------|
| 1 | 사용자의 명시적 선언 | 작가의 선언대로 확정하며 탐지 결과로 뒤집지 않음 |
| 2 | 구조 신호 + 글자 수 검증 | 장 구분자와 글자 수를 함께 보고 아래 세칙에 따라 일차 판단 |
| 3 | 글자 수 보조 판단 | 앞의 두 항목 모두 불명확할 때만 사용. 아래 우선순위 3 참조 |
| — | 충돌 처리 | 작가가 유형을 선언하지 않았고 탐지 신호가 모순되면 Phase 1에서 차이를 설명하고 작가에게 결정 요청 |

## 우선순위 1: 사용자의 명시적 선언

Phase 1에서 분량 유형이 아직 불명확하면 **‘장편인가요, 단편인가요?’**라고 묻습니다.

- 명확한 답변 → 유형을 확정하고 후속 탐지를 생략합니다.
- 답변이 없거나 ‘잘 모르겠다’ → 우선순위 2 구조 신호 탐지로 갑니다.

## 우선순위 2: 구조 신호 + 글자 수 검증

### 장 구분자 식별

아래 패턴으로 구분자를 식별합니다. 실제 인식 예시의 표기는 유지합니다.

| 구분자 패턴 | 예시 |
|-----------|------|
| `第X章` / `第X章 ` / `第X章：` / `第X章 XXX` | 第1章 初入江湖(제1장 강호에 첫발을 들이다) |
| `Chapter X` | Chapter 1 |
| 숫자 번호 + 제목 | 1. 각성 |

### 판단 규칙

| 탐지 결과 | 판단 |
|---------|------|
| 명확한 장 구분자가 있고 탐지한 장 수 ≥ 5 | **장편**으로 일차 판단. 총 글자 수 < 30000이면 ‘장을 나눈 단편 연재’ 가능성을 설명해 작가에게 확인 |
| 전체에 장 구분자가 없고 단일 파일·단일 작품이며 총 글자 수 < 20000 | 강한 단편 신호 → **단편** |
| 전체에 장 구분자가 없고 단일 파일·단일 작품이며 20000 ≤ 총 글자 수 < 30000 | **단편**. 다만 Phase 1 설명에서 단편 분석 파이프라인의 권장 상한 20000자를 넘었다고 알리고 여전히 단편으로 가져올지 확인 |
| 전체에 장 구분자가 없고 단일 파일·단일 작품이지만 총 글자 수 ≥ 30000 | 구조와 글자 수 신호가 반대 → 자동 판단하지 않고 아래 충돌 처리에 따라 사용자에게 결정 요청 |
| 장 구분자는 있으나 장 수 < 5 | 구조 신호 불명확 → 우선순위 3 글자 수 보조 판단 |
| 구분자 패턴이 모호함(예: 제목 행 하나뿐) | 구조 신호 불명확 → 우선순위 3 글자 수 보조 판단 |

## 우선순위 3: 글자 수 보조 판단

**우선순위 1·2 모두 명확한 판단을 내릴 수 없을 때만 사용합니다.** 30000자는 이 가져오기 흐름의 권장 경계이며 플랫폼 투고 상한이 아닙니다.

| 조건 | 판단 | 비고 |
|------|------|------|
| 총 글자 수 < 30000이고, 장 구조가 불명확하거나 장 수 < 5 | **단편** | Phase 1에서 확인 |
| 총 글자 수 ≥ 30000 | **장편** | — |

### 장을 나눈 단편 연재

총 글자 수 < 30000이지만 장 수 ≥ 5이면 확인 단계에서 다음과 같이 설명합니다.

> ‘총 {N}장의 분장 구조가 있지만 전체 분량은 약 {X}자로 30000자 미만입니다. 장을 나눈 단편 연재일 수 있습니다. 장편으로 가져올까요, 단편으로 처리할까요?’

사용자가 결정하면 유형을 확정합니다.

## 충돌 처리

서로 다른 신호가 모순되면 **자동 결정하지 않고** Phase 1으로 돌아가 탐지 결과를 설명합니다.

| 대표 충돌 상황 | 처리 |
|------------|---------|
| 사용자는 ‘단편’이라고 했으나 20장 탐지 | ‘20장의 구조가 있어 보통 장편에 해당합니다. 단편으로 가져오는 것이 맞나요?’라고 확인하고 사용자 결정에 따름 |
| 사용자는 ‘장편’이라고 했으나 장 구분이 없고 총 글자 수 < 30000 | ‘장 구분이 없고 약 {X}자로 보통 단편에 해당합니다. 장편으로 가져오는 것이 맞나요?’라고 확인하고 사용자 결정에 따름 |
| 사용자가 선언하지 않았고 장 구분 없는 단일 파일·단일 작품이지만 총 글자 수 ≥ 30000 | ‘장 구분은 없지만 약 {X}자로 단편의 일반적 상한을 넘습니다. 장편 프로젝트로 가져올까요, 단편으로 처리할까요?’라고 묻고 사용자 결정에 따름 |
| 구조 신호와 글자 수 신호가 반대 | 두 신호를 보여 주고 사용자에게 결정 요청 |

확정 결과를 가져오기 기록(`{书目录}/.story/work/가져오기기록.md`의 「篇幅」 필드)에 씁니다. 이후에는 이 결과를 따르고 다시 판단하지 않습니다.
