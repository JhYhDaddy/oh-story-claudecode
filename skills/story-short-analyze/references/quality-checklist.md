# 품질 점검과 검수 목록

각 Stage 작성 후 해당 절로 자체 점검한다. Stage 6 뒤의 ‘BLOCK 항목 검사’는 이 파일의 모든 `[BLOCK]` 항목을 확인한다.

## 품질 점검 필수 항목

Stage 완료 전에 하나씩 확인한다. **`[BLOCK]`은 필요한 내용을 작성했는지만 검사하며 원문에 고정 수량을 요구하지 않는다**. 원문에 실제로 없는 항목은 ‘원문에 없음’과 근거를 쓰면 작성한 것으로 본다. 노드 밀도·대화 비중 등은 구조화된 설명으로만 사용하고 보편적인 수치 기준을 두지 않는다.

**표시 규칙**:

- `[BLOCK]`: 필수 산출물. 없으면 차단하고 `_meta.json.stages_completed`에 `6`을 추가하지 않는다. 해당 부분으로 돌아가 보충한다.
- `[WARN]`: 정성적·보조 항목. 없으면 `작품분석보고서.md` 끝의 ‘보충 필요’ 목록에 기록하고 **차단하지 않는다**.

**Stage 2(구조+사건 노드)**:
- [ ] 소재 기준에 따라 보고했고 주 유형은 원문 유형 이름 13개 중 하나 또는 `通用`(일반)이다. `[BLOCK]`
- [ ] 이야기 핵심을 한 문장으로 추출했다. `[BLOCK]`
- [ ] 발단/전개/절정/결말을 구분하고 구간별 글자 수 범위·비율·기능을 썼다. `[BLOCK]`
- [ ] 결말 유형을 표시했다. `[WARN]`
- [ ] POV를 판별했다. `[WARN]`
- [ ] 서사 시간선을 표시했다. `[WARN]`
- [ ] 사건 노드가 원문 전체의 실제 변화를 포괄하며 수를 채우려고 같은 사건을 중복 기록하지 않았다([stage2-3-structure-emotion.md](stage2-3-structure-emotion.md)의 ‘사건 노드 추출 규칙’ 참조). `[BLOCK]`
- [ ] 모든 노드에 위치(절 번호 + 대략 몇 번째 글자인지)와 감정 표시(유형 + 강도)가 있다. `[BLOCK]`

**Stage 3(감정선+폭발 지점)**:
- [ ] 감정 곡선이 감정적 입장·기대·압박의 모든 변화를 포괄하고 도입·결말을 포함한다. 각 점에는 글자 위치·강도·방향(고통 -9~통쾌함 +9)이 있다. `[BLOCK]`
- [ ] 각 점에 훅의 기능 유형(‘없음’ 포함)을 표시했다. `[WARN]`
- [ ] 곡선 특징 다섯 항목(시작/흐름/극값/방향 차이/반전 횟수)이 모두 있다. `[BLOCK]`
- [ ] 폭발 분석 여섯 항목(사전 배치/축적/지연/폭발 지점/여파/인상)이 모두 있다. `[BLOCK]`
- [ ] 훅과 유료 전환 지점을 훅 기준으로 보고했다. 훅이나 전환 지점 정보가 없으면 명시했다. `[BLOCK]`
- [ ] 기대감 표를 완성했다. `[WARN]`

**Stage 4(반전+작법 기법)**:
- [ ] 선행 반전을 확인했다(있음/없음). `[WARN]`
- [ ] 반전 유형을 판별했다(‘반전 없음’ 포함). `[BLOCK]`
- [ ] 사전 단서마다 원문 위치를 적고 수량은 사실대로 썼다. 반전 없음/응보형이면 ‘원문에 없음’이라고 썼다. `[BLOCK]`
- [ ] 오도 방향을 설명했다. `[WARN]`
- [ ] 작법 기법을 ≥5개 항목에서 분석했다. `[BLOCK]`
- [ ] POV 전략을 분석했다(선택 효과+대가+전환). `[WARN]`
- [ ] 대화 지표를 정량화했다(비중+함축 의미 비율). `[WARN]`

**Stage 5(인물+도입·결말)**:
- [ ] 이름 있는 모든 인물을 추출하고 두 축으로 분류했다(서사 역할: 주인공/중요 조연/기능 인물 + 행동 역할: 능동형/수동형/변화형). `[BLOCK]`
- [ ] 인물 기능 평가를 마쳤다. `[BLOCK]`
- [ ] 대비가 있는 인물마다 행동 비교를 붙였고 없으면 명시했다. `[WARN]`
- [ ] 인물 관계에 변화 경로를 표시했다. `[WARN]`
- [ ] 첫 3문장을 원문 그대로 인용했다. `[BLOCK]`
- [ ] 첫 50자/첫 100자 점검을 마쳤다. `[WARN]`
- [ ] 도입·결말 감정 강도(1-10)를 증거와 함께 표시했다. `[WARN]`
- [ ] 결말 유형과 감정의 최종 도달점을 설명했다. `[WARN]`
- [ ] 수미상관 분석을 마쳤다. `[WARN]`
- [ ] 모든 훅에 회수 상태(회수 완료/여백/누락)를 표시했다. `[WARN]`

**Stage 6(종합 평가)**:
- [ ] 한 문장 평가는 막연한 칭찬이 아니라 구체적인 작동 원리다. `[WARN]`
- [ ] 다섯 평가 항목마다 일반론이 아닌 구체적인 설명을 붙였다. `[BLOCK]`
- [ ] 폭발력·화제성을 분석했다. `[BLOCK]`
- [ ] 공감을 최소 3개 층위에서 분석하고 각각 촉발 증거를 붙였다. `[BLOCK]`
- [ ] 주 구조를 구조 관찰표에 작성했다. `[BLOCK]`
- [ ] 투고 측면(도입 요약·유료 전환 지점·제목과 소개글·플랫폼 문체)을 작성하고 없는 자료를 명시했다. `[WARN]`
- [ ] 재사용 구조마다 적용 상황·실패 조건·그대로 옮길 수 없는 점이 있다. 옮길 구조가 없으면 이유를 밝혔다. `[BLOCK]`
- [ ] `_meta.json.structure_counts`에 모든 필드를 기록했다([output-contract.md](output-contract.md)의 ‘structure_counts 검증’ 참조). `[BLOCK]`
- [ ] 전개 리듬 요약을 넣었다. `[WARN]`
