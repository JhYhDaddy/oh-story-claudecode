# 추적 초기화 단계(장편 전용)

Phase 4에서는 이 파일, [tracking-initialization.md](tracking-initialization.md)의 트랜잭션 골격, [character-state-reverse.md](character-state-reverse.md)의 스냅샷 규칙을 전문으로 읽습니다. 종료 장·미완 원고 처리 결정·권 구분은 가져오기 기록에서, 근거는 저장된 분석 서고와 프로젝트 `개요/`에서 가져옵니다. 원문은 다시 읽지 않습니다.

반드시 이 스킬의 `scripts/tracking_commit.py init`으로 추적 상태를 한 번에 생성합니다. 모델이 최종 파일을 따로 작성하면 안 됩니다.

## 내용 준비 순서

1. **가져오기 종료 장**: 마지막 완결 장 N을 `last_chapter`에 씁니다. 도구가 `_tracking-state.json`에 `imported_through_chapter=N`을 기록합니다. 제1..N장의 일일 트랜잭션을 꾸며내거나 현재 상태를 중복한 서사 기준 파일을 따로 쓰지 않습니다.
2. **핵심 인물 현재 스냅샷**: 분석 산출물에서 주인공·악역·핵심 조연의 N장 기준 상태를 역추론해 인물별 `character_snapshots`에 씁니다. 도구가 `추적/인물상태/{角色名}.md`를 생성합니다. 방법은 character-state-reverse.md 참조.
3. **복선 현재 행**: 본문 근거가 있는 사전 배치·회수 사건에서 `foreshadow`를 만듭니다(아래 식별법 참조). ID마다 현재 상태 한 행만 둡니다. 아직 실제로 심지 않은 미래 설계는 개요에 남기고 `복선.md`에 쓰지 않습니다.
4. **사실과 독자 인식**: 핵심 사건을 `timeline_events`로 만듭니다(아래 추출법 참조). 같은 사건에 객관적 사실·N장까지 독자가 아는 내용·실제 공개 상태를 함께 씁니다. 미래 공개 예정 장을 이미 일어난 사실처럼 기록하지 않습니다.
5. **이어쓰기 상태 카드 입력**: 현재 위치·장기 제약·활성 핵심 인물·최근 세 장 메모·다음 장 약속·연속성 위험을 준비합니다. 도구가 `문맥.md`를 고정 7영역으로 생성합니다. 문체·파일 색인·일반 할 일·품질 검사 횟수는 넣지 않습니다.
6. **초기화 실행**: 트랜잭션은 `{书目录}/.story/work/init.json`에 저장하고 성공 전까지 보존합니다. 시스템 `/tmp`·작품 루트·`개요/`·`본문/`에는 쓰지 않습니다. Python 3을 `python3` → `python` → `py -3` 순으로 찾아 실행합니다.

   > `추적/`에 현 프로토콜이 아닌 초기 파일이 있어도 수동 정리할 필요가 없습니다. `init`이 원형 그대로 전체를 `추적/_이전추적보관/`로 옮긴 뒤 현 프로토콜을 만듭니다. 옛 내용은 작가 열람용으로 보존하며 파싱하지 않습니다. 현재 상태는 이번 가져오기 입력만으로 정합니다. 검증에 실패한 `init`은 파일을 옮기지 않습니다. `_tracking-state.json`이 없을 때만 `init`하며 초기화된 프로젝트를 절대 덮어쓰지 않습니다.

   ```text
   {PYTHON} {story-import skill 根}/scripts/tracking_commit.py init --project {书目录} --input {书目录}/.story/work/init.json
   {PYTHON} {story-import skill 根}/scripts/tracking_commit.py check --project {书目录}
   ```

마지막 장이 미완이면 `last_chapter`·인물 스냅샷·현재 의미 상태 기준은 모두 마지막 완결 장까지입니다. 미완 원고 처리 전략(기록에 있는 작가의 결정)은 `continuity_risks`에 쓰고 미완성 행동을 기정사실로 등록하지 않습니다.

demo 《让你管账号，你高燃混剪炸全网》 제10장까지 가져오는 예: 상태 카드에는 전문가가 장천의 휴대전화 원본 《诸君，且听龙吟》을 고화질로 재촬영했으나 고위층이 ‘영혼이 없다’고 판단해 원본을 계속 쓰기로 했다는 사실을 명시합니다. 장천 스냅샷에는 저우보선·장야오쭈가 군 홍보 창작 가치를 인정한 상태를 반영합니다. 독자 시간선에는 이미 본 시사회 결론만 기록합니다. 중자자의 ‘절반만 맞혔다’ 뒤에 있는 육성 계획이 아직 공개되지 않았다면 작가의 진실에만 두고 독자 뷰에 누설하지 않습니다.

## 항목 형식·용량

tracking-initialization.md의 트랜잭션 골격에 내용을 채우고 `last_chapter`는 N으로 씁니다. 아래는 복선·시간선·최근 장 메모만 보인 예이며 전체 초기화 트랜잭션을 대체하지 않습니다. 상태 열거값·인물 식별 키는 원문을 유지합니다.

```json
{
  "foreshadow": [
    {"id": "F027", "summary": "전문 팀도 장천 원본의 영혼을 담지 못함", "planted_chapter": 10,
     "planned_resolution_chapter": null, "status": "已埋", "importance": "中"}
  ],
  "timeline_events": [
    {"id": "E010", "story_time": "실탄 훈련 이틀 뒤",
     "objective_fact": "문공단 고위층이 전문 재촬영본을 거절하고 장천의 휴대전화 원본 영상을 계속 쓰기로 결정",
     "reader_knowledge": "독자는 저우보선이 전문판에 영혼이 없다고 지적하고 장야오쭈가 즉시 원본 사용을 결정하는 장면을 봄",
     "reveal_status": "已揭示", "reveal_chapter": 10, "characters": ["江晨", "周薄森", "张耀祖"]}
  ],
  "context": {
    "recent_chapters": [{"chapter": 10, "summary": "전문 재촬영본은 영혼이 없다는 평가를 받아 고위층이 휴대전화 원본 사용을 결정"}]
  }
}
```

- 복선 `id`는 `F001` 형식. `status`는 已埋/已回收/已过期/放弃(심음/회수/만료/포기), `importance`는 高/中/低(상/중/하). `planted_chapter`는 N보다 늦으면 안 됩니다. 사건 `id`는 `E001` 형식이며 `reveal_status`는 未揭示/部分揭示/已揭示(미공개/부분 공개/공개). `未揭示`의 `reveal_chapter`는 반드시 `null`이며 부분·전체 공개는 이미 실제 발생한 장만 씁니다.
- init의 `context` 입력은 6개: `position`, `long_term_constraints`, `active_character_names`, `continuity_risks`, `recent_chapters`(최대 3장, 장 번호 오름차순), `next_chapter_commitments`.
- `character_snapshots`의 인물이 핵심 인물입니다. 네 목록은 항목 수 제한이 없고 인물 파일 목표는 ≤4096바이트, 절대 상한은 8192바이트입니다. 초과하면 어떤 쓰기도 하기 전에 거부합니다. `active_character_names`는 종료 장 다음 장의 활성 인물이며 핵심 인물 전체가 아닙니다. 최대 20명이고 기존 스냅샷이 있어야 합니다. `long_term_constraints`는 최대 6개.
- `문맥.md`는 ≤12288바이트, 최상위 7영역만 둡니다. 현재 위치·장기 제약·핵심 인물 상태·활성 복선(최대 8개)·최근 세 장 메모·다음 장 약속·연속성 위험입니다.
- 오류 안내에 따라 트랜잭션 자체를 고쳐 재실행합니다. 필드 형식은 tracking-initialization.md 골격과 이 절이 기준입니다.

## 복선 추출

| 사건 유형 | 복선 가능성 | 추출법 |
|-----------|-----------|---------|
| 사전 배치 | 높음 | 복선으로 직접 추출 |
| 부분 정보 공개 | 중간 | 이후 호응 여부 확인 |
| 물건 첫 등장 | 중간 | 이후 사용 여부 확인 |
| 인물의 비밀 | 높음 | 인물 복선으로 표시 |
| 미해결 궁금증 | 높음 | 장 끝 표식에서 추출 |

후속 사건이 실제로 같은 복선에 답했으면 `已回收`, 아직 답하지 않았으면 `已埋`로 추론합니다. 항목 이름이 ‘공개’·‘해결’이라는 이유만으로 회수 판정하지 않습니다. 미완 작품 끝에서 아직 답하지 않은 준비는 ‘중단 지점에 가까움’이라고 덧붙일 수 있습니다.

## 시간선 추출

사건 항목·시간 표식에서 추출합니다. 명시 날짜는 그대로 기록하고 상대 시간은 믿을 만한 기준점이 있을 때 계산합니다. 계절만 알면 계절까지만 적습니다. 장·장 내부 사건 순서로 정리합니다. 기준점이 없으면 「时间未明」(시점 불명), 근거 있는 추론은 `[推断]`으로 표시합니다.

## 검증

초기화 성공 후 구조:

```text
추적/
├── _tracking-state.json
├── 문맥.md
├── 장별기록/                 # 옛 장의 파일을 꾸며내지 않으며 제N+1장부터 이어쓰기
├── 인물상태/{角色名}.md
├── 복선.md
├── 시간선/
│   ├── 작가용진실.md
│   └── 독자가아는사실.md
```

- [ ] `tracking_commit.py check` 통과, `_tracking-state.json`과 모든 파생 뷰 일치
- [ ] `_tracking-state.json.imported_through_chapter`가 마지막 완결 가져오기 장과 같음
- [ ] `추적/복선.md`에서 ID당 최대 한 행, 아직 심지 않은 미래 설계가 섞이지 않음
- [ ] `_tracking-state.json.timeline`에 핵심 사실·독자 인식을 등록했고 `독자가아는사실.md`에 진실 누설 없음
- [ ] 모든 핵심 인물의 `추적/인물상태/{角色名}.md`가 있고 character-state-reverse.md 준수
- [ ] 빈 `추적/장별기록/` 디렉터리가 있으며 가져온 장의 일일 기록을 꾸며 넣지 않음
- [ ] `추적/문맥.md` 최상위 영역이 정확히 7개이고 ≤12288바이트

통과하면 가져오기 기록의 「追踪初始化」를 표시하고 `init.json`은 삭제할 수 있습니다. 보고 끝에 [SKILL.md의 맥락 전환 규칙](../SKILL.md#시점별-일정과-인계)에 따라 새 대화를 권합니다.
