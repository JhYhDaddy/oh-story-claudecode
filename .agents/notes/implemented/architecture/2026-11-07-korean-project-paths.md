# Agent Note: 한국어 프로젝트 경로

Status: implemented

## Problem

설명 문서의 한국어화 뒤에도 실제 생성 프로젝트의 폴더·파일명이 중국어로 남았다. 사용자는 설정·개요·본문·추적을 비롯한 사용자 관리 경로까지 한국어로 생성하고 기존 프로젝트도 전환하도록 요청했다. 이전 [현지화 결정](../../implemented/process/2026-11-02-korean-localization.md)의 경로 보존 범위를 이번 요청으로 확장한다.

## Decision

사용자 관리 경로의 한국어 표기를 고정하고 CLI·템플릿·대시보드·훅·검사를 함께 갱신한다. `_tracking-state.json`과 영문 내부 스키마 키는 유지한다. 기존 프로젝트는 명시적 변환 명령으로 새 목적지에 복사하며 원본은 변경하지 않는다. 이름 충돌·심볼릭 링크·목적지 중첩을 거부하고 검증 전에는 목적지를 공개하지 않는다. 원고 본문은 재번역하지 않고 파일 이름과 경로 참조만 변환한다.

## Alternatives considered

- README에만 한국어 이름을 표시하면 변경량이 작지만 실제 파일 이름이 달라져 사용자 요청을 충족하지 못한다.
- 기존 폴더를 즉시 제자리에서 바꾸면 복사 공간이 적지만 실패나 이름 충돌 시 원본을 복구하기 어렵다. 새 목적지 변환으로 원본을 보존한다.
- 모든 중국어 문구를 치환하면 일관돼 보이지만 원고·출력 스키마까지 변경된다. 프로젝트 경로에 한정한 대응표와 경로 패턴을 사용한다.

## Consequences

새 프로젝트는 한국어 이름으로 운영된다. 이전 중국어 프로젝트에는 한 번의 명시적 전환이 필요하다. 변환은 원고와 내부 상태 형식을 보존해야 하며 집필·추적·훅·대시보드의 통합 회귀 검증이 필요하다.

## Verification

명령별 최신 회귀 결과 61개 중 54개 통과, 기존 Windows 환경 실패 7개 유지. 변환 독립 테스트 10개, 대시보드 23개 통과(플랫폼 조건 4개 제외). 원고·원문 바이트, JSON 키·상태 값, CSV 위치 참조, 상대·절대 링크, 추적 파생 뷰를 확인했다. 한국어 예제 경로 124개와 색인 링크를 갱신했다. 파일명 길이에 따라 실측 문서 예산 66개를 조정하고 기존 상한·예외·읽기 조합은 유지했다.

후속 [Windows 검증 수정](../bug-fix/2026-11-07-windows-validation.md)에서 실패 7개를 해소해 전체 61개 검사가 통과했다. 위의 ‘기존 환경 실패 7개’ 분류에는 OpenCode 기대 문구 오류도 섞여 있었음을 정정한다.
