# Agent Note: 작품 분석을 작가가 이해할 말로 전달: 보고서·답변 템플릿과 중국어 관계도

## Problem

실제 작품 분석 보고에 `classification: current_complete`, `final_state: completed`, `recommended_path: direct_use`, `stage_repairs: []`, “plan --intent continue가 batches: [] 반환”, “공개 인용과 삼차원 설명 100% 완전”, “B급 추론”, “REL-001/004”가 섞였다. 원인은 문서다. Stage 5 템플릿은 “품질 평가: 신뢰도/범위 충족률/중복률”, “B/C급 추론”, `EV-*`/`RV-*`/`AX-*` 인용을 요구하지만 대화의 진행·중단 질문·완료·오류 보고 템플릿은 없어 모델이 스크립트 JSON을 옮겨 말할 수밖에 없었다.

같은 실행의 `人物关系图/*.png` 인물명은 모두 병음 머리글자였다. 환경에 중국어 글꼴이 없어 모델이 임시 작성한 matplotlib 스크립트가 병음으로 대체했다. 고정된 관계도 생성 방식이 없고 SKILL에는 “안정적으로 렌더링할 수 없으면 이유 기록”만 있었다.

## Decision

- **`references/author-facing.md` 추가**: 작가가 보는 모든 출력은 이를 따른다. 총규칙 일곱 개는 시스템이 아닌 책을 설명하기, 스크립트·명령·필드·상태값·배치 번호·내부 파일·품질 지표명·증거 등급 문자·“삼차원”을 내세우지 않기, 번호는 이름과 함께 쓰기, 증거 강도를 쉬운 말로 설명하기, 작가 결정은 질문 하나＋추천＋기본값으로 제시하기, 개발 세부는 끝의 기술 비고 한 줄 이내로 제한하기, 스크립트 `author_message`는 JSON을 붙이지 말고 풀어 설명하기다. 첫 세 장 후 중단 질문, 진행, 전체 완료, 중단·오류의 대화 템플릿과 파일 템플릿 두 개도 추가한다.
- **작품 분석 완료 보고**는 분석한 책·범위, 가장 배울 만한 세 가지, 빌려 쓸 패턴, 배우지 말아야 할 점, 용도별 파일 위치(“리듬은 剧情/节奏.md”), 작가가 결정할 사항(질문＋추천)으로 고정한다.
- **`快速预览.md`와 `拆文报告.md` 템플릿을 author-facing.md로 이동하고 재작성**한다. 품질 평가 절과 A/B/C 등급을 삭제한다. “증거 경계와 확인할 항목”은 “아직 불확실한 점”, 시간선·리듬은 “독자가 아는 것과 인물이 아는 것”, “리듬”의 쉬운 설명으로 바꾼다. 활용할 패턴은 “모듈 이름(EM-번호)”으로 이름을 붙여 인용한다. 가져오기·집필·소재 선택 갱신이 읽는 절 이름(기본 정보, 핵심 발견, 황금 첫 세 장 점수, 쾌감 포인트 밀도, 핵심 구조, 활용할 패턴, 집필 기법, 모방 비권장 등)은 보존한다. `output-templates.md`의 해당 절은 연결 안내로 바꾸고 기계적 추적 정보는 리듬·감정 모듈·사건 단위·관계 파일에 남긴다.
- **정적 검사**: `check-current-skill-contracts.py`는 author-facing.md의 코드 블록을 작가가 그대로 읽을 문구로 취급한다. 필드·상태명, snake_case, 배치 번호, 스크립트명·명령 인수, Stage/Phase 번호, 신뢰도·범위 충족률·중복률·삼차원, 증거 등급 문자, 이름 없는 EM/REL/EV/RV/AX 번호, 내부 파일과 hash/JSON을 차단하고 SKILL.md가 이 파일로 연결되는지 요구한다. 회귀 검사는 실제 실행에서 나온 원문을 하나씩 넣어 차단을 확인한다.
- **관계도 스크립트 `scripts/render_relation_chart.py`**는 `角色/角色关系.md`만 입력으로 삼는다. 주 산출물은 `人物关系图/人物关系图.md`(Mermaid＋텍스트 목록＋핵심 관계 변화)다. 모든 Markdown 뷰어에서 중국어를 볼 수 있고 PNG 시도 전에 저장해 그림 실패에도 남는다. 관계 열은 `→`/`->` 단방향, `↔`/`<->` 양방향(두 개로 분리), “갑 → 을 → 병” 사슬(구간별 분리)을 인식한다. 셀의 이스케이프 `\|`는 열로 나누지 않으며 인식 못 한 행 수를 반환해 작가에게 알린다. Mermaid 라벨에서 `%%`를 제거하고 정리 후 비면 “이름 없음”, “관계”로 대체해 파싱 실패를 막는다. `--png`는 PingFang SC, Hiragino Sans GB, Microsoft YaHei, SimHei, Noto Sans CJK, WenQuanYi, Source Han Sans 등과 `fc-list :lang=zh`로 글꼴을 찾는다. 모든 문자에 사각형을 반환하는 LastResort·Adobe Blank는 제외하고 FT2Font로 그릴 각 문자의 글리프를 검사한다. macOS PingFang.ttc의 첫 글꼴 면은 번체 HK판이라 간체가 없어 이름만 보면 네모가 생긴다. 이모지·기타 기호는 이미지에서 제외하고 나머지 문자 글리프가 모두 있을 때만 PNG 두 개를 그린다. 중국어 글꼴 없음, 일부 글리프 없음(어떤 문자인지 명시), matplotlib 없음이면 그림을 생성하지 않고 쉬운 한 문장 `author_message`를 반환한다. 병음·머리글자로 대체하지 않는다.
- 검사기와 색인 생성 스크립트의 중단·원문 변경 안내도 작가가 이해할 표현으로 바꾼다(Related 버그 수정 기록 참조).

## Alternatives considered

- **SKILL.md에 “쉬운 말 사용” 규칙만 추가**: 변경이 가장 작다. 그러나 보고서 템플릿이 범위 충족률과 B/C급을 요구해 충돌하면 모델은 템플릿을 따른다는 것이 실제 실행으로 확인됐다.
- **보고서에서 EM 번호 전부 삭제**: 가장 읽기 깔끔하다. 그러나 영감 라이브러리·집필 쪽에서 번호로 감정 모듈을 역조회해야 하므로 이름을 붙인 번호가 양쪽을 만족한다.
- **PNG를 주 산출물로 유지하고 글꼴 없으면 자동 다운로드**: 그림이 가장 직관적이다. 그러나 런타임 다운로드는 느리거나 차단될 수 있고 작가 대신 시스템에 설치해서도 안 된다. Mermaid Markdown은 일반 편집기에서 의존성 없이 중국어를 렌더링한다.
- **글꼴 없으면 병음·영어 이름으로 그림 생성**: 그림은 남는다. 그러나 작가가 못 읽는 그림은 없는 것보다 나쁘며 바로 이번에 고칠 문제다.

## Consequences

이점: 작가는 대화 보고·보고서·관계도를 바로 읽을 수 있다. 개발 용어가 되돌아오면 검사가 차단한다. 모든 환경에 중국어로 읽을 관계도가 있고 글꼴이 있으면 이미지도 제공한다.

비용: 보고서 절 구조가 바뀌지만 이전 보고서는 Stage 5를 다시 실행할 때만 바뀐다. 판룡 데모의 보고서는 여전히 이전 형식이다. 검사는 author-facing.md 코드 블록만 대상으로 하며 대화의 모델 준수는 템플릿에 의존한다. PNG는 matplotlib가 필요하다. 기본 CI는 실제 그림 없이 글꼴 없는 경로만 시험하고 글꼴 선택은 가짜 객체로 시험한다. 이미지에는 이모지 등 기호가 없지만 Markdown은 원문을 보존한다. story-import 장편 가져오기는 관계도를 예전 방식으로 설명하며 동기화하지 않았다.
